# 分派与契约措辞参考

角色卡要能被任何宿主执行，前提是措辞只依赖**能力**而不是**工具**。本文件给出可直接复制的措辞模板。

---

## 1. 能力抽象措辞

| 不要写 | 改写为 |
|--------|--------|
| 宿主专属的提问工具名 | 使用宿主的交互式提问能力（常见别名 AskUserQuestion / question） |
| 宿主专属的子代理调用名 | 派发子代理（若宿主支持子代理派发能力） |
| 宿主专属的文件搜索工具名 | 使用宿主的文件搜索能力 |
| 宿主专属的命令执行工具名 | 使用宿主的命令执行能力 |
| 宿主专属的浏览器驱动命令 | 使用宿主的浏览器自动化能力 |
| 宿主专属的路径或配置目录 | 技能目录 / 项目目录 / 用户主目录 |
| 宿主专属的 frontmatter 字段 | 角色卡段落（职责 / 触发条件 / 输入契约 / 输出契约 / 工作流） |
| 宿主专属的占位符 | 用户输入 / 本次任务的输入 |

判断标准：**换一个宿主，这句话还成立吗？** 不成立就说明写的是工具而不是能力。

---

## 2. 并行分派与顺序降级

### 2.1 标准段落（直接复制）

> 若宿主支持子代理派发能力，将下列角色卡**并行**分派，每卡一份独立上下文；
> 若不支持，则在当前会话内**顺序**执行同一批角色卡，产出格式不变。

### 2.2 带依赖关系的变体

> 若宿主支持子代理派发能力，先并行分派第一组角色卡，合并其产出后再分派第二组；
> 若不支持，则在当前会话内按同样的分组边界顺序执行，产出格式不变。

### 2.3 措辞检查表

- [ ] 只描述能力，没有工具名。
- [ ] 并行与顺序两条路径产出同一种格式。
- [ ] 明确"每卡一份独立上下文"，避免角色之间互相污染。
- [ ] 有依赖时写清分组边界与先后顺序。
- [ ] 写明"角色卡由技能正文提供，脚本或外部工具不负责分派"。

## 3. 输入契约怎么写

输入契约要让执行方**判断自己能不能开工**。按三行写：

```markdown
## 输入契约

- 输入：<内容 + 格式>（例：设计文档正文 + 关联需求条目编号）
- 前置条件：<缺少就无法开工的最小条件>
- 缺失处理：<输入不足时的回报方式，例：回报缺失项清单，不猜测结论>
```

常见错误：

| 写法 | 问题 | 改法 |
|------|------|------|
| "输入：相关文件" | 范围不清 | 写清文件范围或由编排层提供 |
| "输入：用户需求" | 不稳定 | 写清需求来源（条目编号、文档路径） |
| 不写缺失处理 | 执行方会自行猜测 | 明确"缺什么就回报什么" |

---

## 4. 输出契约怎么写

输出契约要让合并层**能直接拼接多个角色的结果**。按三行写：

```markdown
## 输出契约

- 输出：<结构 + 字段 + 顺序>（例：按严重级别排序的问题清单，字段：位置 / 风险 / 证据 / 整改方向）
- 证据：<每条结论必须附带的依据>（例：引用文档中的具体段落）
- 禁止：<本角色不允许做的动作>（例：不改文件、不代替编排层下结论）
```

要点：

1. **结构化**：字段名固定，多个角色产出同一类结构时字段名保持一致。
2. **可排序**：写清排序依据，避免合并层二次猜测。
3. **有证据**：没有证据的条目在合并阶段会被丢弃，白写。
4. **有禁止项**：把"不做什么"写进契约，角色才不会越界。
5. **空结果有说法**：写明"没有问题时返回空集合"，否则执行方会硬凑内容。

---

## 5. 汇总与合并层的措辞

多角色并行执行后需要一个汇总口径。措辞同样只依赖能力：

> 汇总阶段合并全部角色卡产出，按输出契约中的字段对齐，去除重复项，冲突项保留双方并标注分歧，最后按契约中的排序依据输出统一结果。

禁止在汇总措辞里出现具体聚合工具名；需要脚本辅助时，写"若宿主支持脚本执行能力，运行技能自带的合并脚本"，并让脚本路径以技能内相对路径描述。
