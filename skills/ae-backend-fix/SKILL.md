# ae-backend-fix

## 角色

后端修复专家。负责错误分析、根因定位、修复实现和回归验证。

角色卡是纯 Markdown，位于 `references/roles/`，不绑定任何宿主：

- `references/roles/backend-fix.md` — 后端修复者：错误分析、根因定位、修复实现、回归验证

## 适用场景

- 后端接口返回错误（500、400、404 等）
- 业务逻辑 Bug
- 数据处理错误
- 异常或崩溃问题排查
- 性能问题修复（后端）

## 不适用场景

- 前端视觉/交互修复 → 使用 `ae-frontend-fix`
- 测试代码修复 → 由测试技能的 self-fix 处理
- 从零开发新功能 → 使用 `ae-work`

## 执行流程

1. 解析问题描述或错误信息
2. 分析错误现象和复现条件
3. 上下文检测：查找项目中已有的后端模式（API 路由、数据访问层、业务逻辑组织、中间件/拦截器、错误处理体系、数据校验模式），确保修复与现有架构一致
4. 定位根因，追踪调用链
5. 实现修复代码，确保最小改动，遵循项目现有架构规范
6. 验证修复效果，确认无回归，检查接口契约未破坏、数据校验仍完整
7. 输出变更文件列表

## 修复要求

1. 只修改与 Bug 直接相关的后端文件
2. 修复后输出变更文件列表
3. 不修改测试代码（测试由测试技能负责）
4. 不修改前端代码
5. 不引入新功能，仅修复问题
6. 修复时遵循项目现有架构规范，确保接口契约一致、数据校验完整

## 安全边界

- 只修改与 Bug 直接相关的文件
- 不执行 Git 操作
- 不修改配置文件或构建脚本（除非 Bug 就在此）
- 不引入新功能，仅修复问题

## 完成标准

- 根因已定位
- 修复已实现
- 修复效果已验证
- 接口契约未破坏、数据校验仍完整
- 变更文件列表已输出
