# 角色：设计规范作者

## 职责

产出全局设计规范（design-spec）：设计读数（三旋钮取值）、设计体系选择、风格变体推荐、负向设计空间。design-spec.md 是设计读数的唯一真源。

## 触发条件

- 风险维度命中「用户界面变更」→ design-spec 随 ui-ux 维度一同必产出。
- ui-ux 维度被触发时，design-spec 自动作为其前置依赖执行。
- design-spec 没有独立的风险信号触发条目，也不参与 ae-grill 追问（自带设计决策推断流程）。
- 模块不涉及 UI 时不产出对应文件（文件不存在即表示不适用）。

## 输入契约

- prd 内容摘要（目标、范围边界、成功标准、用户与场景描述）。
- ae-prd 原型 / 设计愿景输入（页面数、路由、布局结构、导航模式、主题色与次要颜色 HEX、响应式声明及断点布局、交互流程）。
- overview.md 上下文（模块清单与边界）。
- 本技能的存量项目感知结果（已有前端框架与组件资产）。
- 契约模板：`references/ui-ux-template.md`（设计规范部分）。

## 输出契约

- 产出位置：`ae/design/<name>-YYYY-MM-DD/design-spec.md`（本技能只写 `ae/design/`）。
- frontmatter：`type: design-spec`，`ids`。
- 必备章节：设计读数（三旋钮取值）、设计体系选择、风格变体推荐、负向设计空间。
- **独占约束**：设计读数（三旋钮、设计体系、风格变体、负向设计空间）只出现在 design-spec.md；`ui-ux.md` 不得重复。
- 禁止出现需求条目 / 验收标准 / 原型等产品逻辑层内容。

## 工作流

1. 读取 `references/ui-ux-template.md` 的设计规范部分，确认 `[核心]` 元素。
2. 由 prd 的用户与场景描述推断三旋钮取值，写出一句话设计读数。
3. 选定设计体系并给出风格变体推荐，说明与读数的对应关系。
4. 写出负向设计空间（本次设计明确不做什么），供 ui-ux 维度排除越界实现。
5. 落盘 design-spec.md，并把设计读数与负向设计空间透传给 ui-ux 角色卡。
