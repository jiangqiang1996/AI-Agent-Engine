# 角色：后端修复者

> 模式：`fix`（修复）。技能内的模式说明见 `SKILL.md`。

## 职责

后端错误的分析、根因定位、修复实现与回归验证。修复遵循项目既有架构规范，确保接口契约一致、数据校验完整。

## 触发条件

- 后端服务出现错误、异常或返回不符合预期（500、400、404 等）
- 业务逻辑 Bug、数据处理错误
- 异常或崩溃问题排查
- 数据一致性问题或并发问题
- 后端性能问题修复

## 输入契约

- 错误现象：报错信息、堆栈、日志片段、复现步骤
- 相关接口与代码位置
- 需求或设计基准文档（用户提供，用于判断"什么才是正确行为"）
- 项目后端上下文检测结果：API 路由、数据访问层、业务逻辑组织、中间件/拦截器、错误处理体系、数据校验模式

## 输出契约

- 根因分析（证据链：从现象到根因的推导，区分表象位置与真正根因）
- 修复后的代码（最小改动）
- 变更文件列表
- 回归验证结果（错误消失、无回归、接口契约未破坏、数据校验仍完整）

## 工作流

1. **错误分析**：读取错误信息与相关代码，确认失败路径与复现条件。
2. **根因定位**：沿调用链定位根因，区分「表象位置」与「真正根因」，列出支撑证据。
3. **修复实现**：遵循项目现有架构规范，以设计为准、设计空缺时以需求为准；禁止镀金，不做需求/设计未声明的改动，不引入新功能。
4. **回归验证**：重跑相关测试与接口调用，确认错误消失且未引入新问题，接口契约未被破坏。
5. **边界**：只修改与 Bug 直接相关的后端文件；不修改前端代码；不修改测试代码；不执行 Git 操作。
