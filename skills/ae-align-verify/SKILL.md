# 对齐与验证流水线

依次执行「设计对齐需求 → 源码对齐设计 → 单元测试 → 接口测试 → E2E 测试」。
**全程禁止镀金，一步到位，不考虑过渡版本与兼容迁移。**

## 何时使用

- 用户要求把设计、代码、测试串成一条流水线跑通
- 用户说"对齐并验证""从接口测试开始""只跑 E2E""到单元测试为止"

## 何时不使用

- 只需要审查 → 使用 `ae-review`
- 只需要执行已有测试而不做对齐 → 使用 `ae-unit-test` / `ae-api-test` / `ae-e2e-test`

## 输入

| 参数 | 说明 |
|---|---|
| `<范围描述>` | 可选。自然语言，如"跳过设计对齐""从接口测试开始""到单元测试为止" |
| `<key=value>` | 可选。透传给步骤内调用的技能，如 `browser=chrome` |
| `<路径>` | 可选。设计或需求文档路径；含 `design` 归为 `design=`，含 `prd` 归为 `prd=` |
| `<裸提示词>` | 可选。需求真源内容 |

## 步骤定义

| 步骤 | 编号 | 核心词 | 说明 |
|------|------|--------|------|
| 定位 | 0 | 定位、locate | 定位最新设计与对应需求 |
| 设计对齐 | 1 | 设计对齐、design、对齐需求 | 用 `ae-design` 让设计对齐需求 |
| 源码对齐 | 2 | 源码对齐、source、对齐设计 | 用 `ae-work` 让源码对齐设计 |
| 单元测试 | 3 | 单元测试、unit | 对齐并执行单元测试 |
| 接口测试 | 4 | 接口测试、api | 对齐并执行接口测试 |
| E2E 测试 | 5 | E2E 测试、e2e、端到端 | 对齐并执行 E2E 测试 |

## 参数自动推测

按优先级依次匹配，命中后消费对应内容，从剩余继续：

| 优先级 | 匹配条件 | 推测为 | 示例 |
|--------|----------|--------|------|
| 1 | `key=value` 形式 | 显式绑定，不做推测 | `browser=chrome` |
| 2 | 自然语言范围短语（见下表） | 推断执行范围 | `跳过设计对齐` → 从步骤 2 开始 |
| 3 | 裸值含路径分隔符或以 `ae/` 开头 | 含 `design` → `design=`；仅含 `prd` → `prd=`；都不含但物理存在于 `ae/design/` 或 `ae/prd/` 下 → 按物理位置归类；都不命中 → 不消费 | `ae/design/xxx` → `design=ae/design/xxx` |
| 4 | 以上均未命中的裸文本 | 拼接为裸提示词需求内容 | `优化登录页面` → 需求真源 |

### 自然语言意图表

匹配含意图关键词且步骤核心词成功匹配的短语，推断执行范围。意图关键词存在但步骤核心词匹配失败时，不消费该内容，继续尝试后续优先级。**默认执行全部步骤（0-5）。**

| 意图模式 | 推断规则 | 示例 |
|----------|----------|------|
| `跳过<步骤>` | 从该步骤下一编号执行到 5 | `跳过设计对齐` → 2-5 |
| `从<步骤>开始` | 从该步骤编号执行到 5 | `从接口测试开始` → 4-5 |
| `只跑<步骤>` / `只执行<步骤>` | 只执行该步骤 | `只跑E2E测试` → 5-5 |
| `到<步骤>为止` / `到<步骤>结束` | 从 0 执行到该步骤 | `到单元测试为止` → 0-3 |
| `<步骤>到<步骤>` | 从前者执行到后者 | `源码对齐到接口测试` → 2-4 |

多个意图短语组合时采用**边界合并**：取所有短语起始编号的最大值与结束编号的最小值作为最终范围。
例：`跳过设计对齐` → 2-5，`到单元测试为止` → 0-3，合并后取 max(2,0)=2、min(5,3)=3 → 执行 2-3。
合并后起始编号大于结束编号时，提示范围矛盾并停止执行。

## 参数优先级

1. 本技能自身消费的内容（范围描述、`design`、`prd`、裸提示词）不透传给内部技能。
2. 其余 `key=value` 视为额外参数，在对应步骤执行时透传给该步骤调用的技能。
3. 额外参数与步骤内部默认值冲突时，**以额外参数为准**。
4. 额外参数仅对实际接受该参数的技能生效；技能不识别的参数忽略。
   例：`browser=chrome` 覆盖 E2E 步骤默认的 Edge 浏览器。

## 执行流程

按推断出的范围依次执行，**前一步骤未通过不进入下一步骤**，范围外步骤直接跳过。

| 步骤 | 动作 | 调用的技能 | 产物目录 |
|------|------|------------|----------|
| 0 定位 | 确定设计真源与需求真源 | — | `ae/design/`、`ae/prd/` |
| 1 设计对齐 | 重新生成与需求对齐的设计 | `ae-design` | `ae/design/` |
| 2 源码对齐 | 把源码对齐到设计 | `ae-work` | `ae/work/` |
| 3 单元测试 | 对齐并执行单元测试 | `ae-unit-test`、`ae-backend-fix` | `ae/unit-test/` |
| 4 接口测试 | 对齐并执行接口测试 | `ae-api-test`、`ae-backend-fix` | `ae/api-test/` |
| 5 E2E 测试 | 对齐并执行 E2E 测试 | `ae-e2e-test`、`ae-frontend-fix` | `ae/e2e-test/` |

各步骤的详细执行规则见 `references/steps.md`，**执行每个步骤前先读取对应章节**。

## 执行约束

- 任何步骤发现问题都必须用对应修复技能修复后继续。
- 所有修复**以设计为准，设计空缺时以需求为准**。
- 额外参数透传给对应步骤调用的技能；与内部流程默认行为冲突时以参数为准。
- 范围不含步骤 0 时，跳过定位步骤的跳转判定，但仍需确定设计/需求真源；无法确定时停止并提示用户补齐或通过 `design=`/`prd=` 显式提供。
- 全程禁止镀金，一步到位，不考虑过渡和迁移。

## 完成标准

- 范围内所有步骤均已执行且通过
- 每一步的验证证据（测试报告、截图、日志）已落盘到对应 `ae/<slug>/` 目录
- 未引入需求或设计未声明的功能
