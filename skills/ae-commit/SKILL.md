# 智能提交变更

生成符合项目规范的提交信息并完成本地提交。**只做本地提交，不提供推送远程仓库的能力。**

## 何时使用

- 用户说"提交代码""提交一下""commit""帮我生成提交信息"
- 当前工作区有已暂存或未暂存的变更需要归档

## 何时不使用

- 用户要求推送、建 PR、发版 → 直接说明本技能不提供远程写操作
- 工作区没有任何变更 → 提示无需提交，不创建空提交

## 输入

| 参数 | 说明 |
|---|---|
| `<文件>` | 可选。限定提交范围；不传则提交当前会话产生的全部变更 |
| `<描述>` | 可选。用户对本次提交的意图描述，用于生成更准确的提交信息 |

---

## 执行流程

### 步骤 1：检测与筛选

使用宿主的命令执行能力运行：

```bash
git status
git diff
git diff --staged
```

识别变更来源：优先使用**已暂存**的变更；未暂存时使用本次会话产生的变更；用户未指定范围时使用全部未暂存变更。

**禁止提交的文件**：

| 类别 | 规则 |
|---|---|
| 敏感文件（硬阻断） | `.env*`、`*.pem`、`*.key`、`credentials*`、`secret*`，以及内容疑似含密钥/Token/密码/私钥的文件 |
| 缓存与临时文件 | `*.tmp`、`*.cache`、`node_modules/`、构建产物（除非项目规范明确要求） |
| 调试代码 | 残留的 `console.log`、`debugger`、临时打印（除非项目本身在用） |

> 命中敏感文件时**必须硬阻断**：先向用户报告具体文件与风险，要求移除或脱敏后再继续。不得静默跳过。

### 步骤 2：生成提交信息

- 提交信息使用**中文**。
- 优先遵循项目已声明的 Git 提交规范（如 `AGENTS.md`、`CONTRIBUTING.md`、`.gitmessage` 中声明的格式）。
- 项目未声明规范时使用：`<类型>(<范围>): <简短描述>`
  - 类型：`feat` 新功能 / `fix` 修复 / `refactor` 重构 / `docs` 文档 / `test` 测试 / `chore` 构建工具 / `perf` 性能
- **提交粒度**：每次提交只做一件事，内容可独立运行；禁止 WIP 与调试代码。变更涉及多个独立关注点时，拆分为多次提交。
- 描述控制在 50 字以内，祈使句开头，不以句号结尾。

### 步骤 3：执行提交与验证

> **授权要求**：执行 `git add` / `git commit` 前必须取得用户明确授权。授权需覆盖：目标仓库、目标分支、工作区、完整命令参数。未授权时停止流程并说明将要执行什么。

```bash
git add <筛选后的文件>
git commit -m "<类型>(<范围>): <简短描述>"
```

提交后运行 `git status` 验证：

- 预期文件已提交
- 未预期文件未被提交
- 工作目录状态正确

## 输出要求

- 报告提交结果：commit 短哈希、提交信息、包含的文件数
- 若有任何文件被排除，明确列出排除原因

## 安全边界

- 禁止修改 `git config`
- 禁止跳过 hooks（`--no-verify` 等）
- 禁止修改提交者的用户名与邮箱；无用户信息时提示用户自行配置，不得代替设置
- 禁止在提交信息或代码注释中出现任何 AI 生成标识
- 仅支持本地提交

## 完成标准

- 变更已提交且 `git status` 验证通过
- 提交信息符合项目规范
- 未泄露任何敏感内容
