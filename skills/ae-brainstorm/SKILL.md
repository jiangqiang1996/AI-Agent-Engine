# ae-brainstorm — 多视角头脑风暴

用五张固定角色卡对同一个主题各自独立作答，再把五份答案收敛成一张观点表。

**这是一个纯提示词技能**：不执行任何脚本、不创建会话、不依赖任何特定宿主的界面或扩展点。它只做两件事——按角色卡产出五段独立视角，以及把它们汇总成结构化观点表。

## 何时使用

- 用户想在一个方向定下来之前，从多个角度把问题想清楚（"帮我想想这个方案还有哪些可能"、"有哪些反对意见"、"发散一下"）。
- 用户提供了方案，希望听到不同立场的独立评价，而不是单线程的自问自答。
- 用户明确要求"多视角""头脑风暴""碰撞一下"。

## 何时不使用

- 需求还不清楚、连要做什么都没定 → 先用 `ae-prd` 澄清目标。
- 方案已经定稿，只要逐项检查 → 用 `ae-grill` 或 `ae-review`。
- 只需要一份实现计划 → 用 `ae-design` / `ae-work`。
- 用户只想听一个直接答案 → 直接回答，不必发散。

## 功能描述

<用户输入>

（用户输入为本次讨论主题。若为空，先用宿主的交互式提问能力询问："你想讨论什么？请描述你正在考虑的主题、问题或想法。"）

**如果主题为空，先问清楚再继续。** 主题过于宽泛时（例如"做个平台"），先用一两轮提问把边界收窄到可以发散的程度。

## 五个视角

| 角色卡 | 视角 | 一句话定位 |
|--------|------|-----------|
| `references/roles/optimist.md` | optimist 乐观者 | 找到这件事最大的价值与最值得赌的理由 |
| `references/roles/critic.md` | critic 批评者 | 找到最可能让它失败的假设与证据 |
| `references/roles/pragmatist.md` | pragmatist 务实者 | 找到下周就能开始的第一步与成本 |
| `references/roles/innovator.md` | innovator 创新者 | 找到被默认忽略的另一种解法 |
| `references/roles/systems.md` | systems 系统观察者 | 找到它放进现有系统后的连锁影响 |

每个角色卡包含五段固定结构：**职责 / 触发条件 / 输入契约 / 输出契约 / 工作流**。执行时逐字遵循角色卡，不要临场改写它的职责边界。

## 执行流程

### 阶段 1：确定主题

1. 读取用户输入作为讨论主题。
2. 主题为空 → 用宿主的交互式提问能力问一次，等回答再继续。
3. 主题宽泛 → 先补一到两个关键约束（目标用户、硬性限制、时间窗），让五份视角落在同一个问题上。
4. 明确本轮采用的视角组合。默认五个全用；用户只要"正反两面"时用 optimist + critic；用户要"能落地的方案"时用 pragmatist + systems。

### 阶段 2：跑五张角色卡

**若宿主支持子代理派发能力**：把五个角色卡**并行**分派，每卡一份独立上下文（每张卡只看到主题 + 自己的角色卡，不看其他卡的内容，避免互相污染）。

**若宿主不支持子代理派发能力**：在当前会话内**顺序**执行同一批角色卡——每张卡独立成段作答，写完一段再写下一段，过程中不引用其他视角的结论。

两种方式产出的格式完全一致，下游无需区分。

**每个视角的作答必须使用下面的固定块结构**（标题层级、字段顺序、条目数量都一样）：

```markdown
### 视角：<角色中文名>（<英文名>）

- 立场：<一句话>
- 要点：
  1. <要点一>
  2. <要点二>
  3. <要点三>
- 最大机会 / 最大风险：<一句话>
- 关键假设：<一句话>
- 一句话结论：<一句话>
```

规则：

- 每个视角 3~5 条要点，每条不超过两句话。
- "立场""关键假设""一句话结论"都必须针对**本轮主题**，不能是放之四海皆准的套话。
- 五个视角之间必须真的不同：乐观者不许写风险，批评者不许写鼓励，务实者不许谈愿景。
- 不引用其他视角的内容（不写"正如批评者所说"），保证独立性。

### 阶段 3：汇总成观点表

读完五份视角后，产出下面这张表（表头与行序固定）：

```markdown
## 观点汇总

| 视角 | 核心立场 | 关键要点 | 最大风险 / 代价 |
|---|---|---|---|
| 乐观者 optimist | | | |
| 批评者 critic | | | |
| 务实者 pragmatist | | | |
| 创新者 innovator | | | |
| 系统观察者 systems | | | |
```

表后接四个小节，每节 2~5 条：

```markdown
### 一致点（agreements）
- <观点> —— 涉及视角：xxx、yyy

### 分歧点（disagreements）
- <观点> —— optimist 说……，critic 说……，分歧的根因是……

### 碰撞洞察（collision insights）
- <由两个视角的张力产生的新想法>

### 盲区（blind spots）
- <五个视角都没覆盖、但会影响结论的问题>
```

- **一致点**：至少两条视角都认可、可以直接当作共识的判断。
- **分歧点**：写清"谁和谁冲突"，并指出冲突的根因（目标不同 / 事实假设不同 / 时间尺度不同）。
- **碰撞洞察**：必须来自两个视角的**交集**，是原文里没有的新判断；写不出来就少写，不要凑数。
- **盲区**：五个视角共同漏掉的问题（例如合规、成本归属、迁移路径、谁来运维）。

### 阶段 4：落盘与呈现

1. 在对话里呈现上面那张观点表与四个小节（先结论，后细节）。
2. 同时把同样的内容写入 `ae/brainstorm/<主题>-<时间戳>.md`（主题取 kebab-case，时间戳格式 `YYYYMMDD-HHMMSS`）。
3. 落盘文件结构：

```markdown
# 头脑风暴：<主题>

- 时间：<YYYY-MM-DD HH:MM:SS>
- 视角：optimist / critic / pragmatist / innovator / systems
- 主题原文：<用户输入>

## 各视角结论

<五段固定块结构，原样保留>

## 观点汇总

<观点表 + 四个小节，原样保留>
```

4. 结束时给出下一步选项（用户可直接选）：继续深挖某个视角、加入新视角重跑、把结论转成需求文档（`ae-prd`）、或就此结束。

## 交互方式

- 用宿主的交互式提问能力（常见别名 AskUserQuestion / question）收集主题与边界。
- 一次只问一个问题，等回答再继续。
- 五张角色卡跑完后一次性呈现结果，不要跑一张报一张。

## 边界

- 不执行任何脚本，不创建会话，不改动代码库文件。
- 不替用户拍板：给结构化的多视角输入，决策权留给用户。
- 不虚构数据：角色卡里不编造具体的用户数、营收、基准数据；缺数据时明写"需要数据支撑"。
- 一轮默认只跑一次；需要第二轮时由用户明确要求，并说明要换掉哪张卡或换什么主题角度。
