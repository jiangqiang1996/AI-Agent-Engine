依次执行对齐与测试流程。全程禁止镀金，一步到位，不考虑过渡和迁移。`$ARGUMENTS` 支持自然语言范围描述、显式 `key=value`、路径自动归类和裸提示词需求内容，可混合传入。

## 步骤定义

| 步骤 | 编号 | 核心词 | 说明 |
|------|------|--------|------|
| 定位 | 0 | 定位、locate | 定位最新设计与对应需求 |
| 设计对齐 | 1 | 设计对齐、design、对齐需求 | 设计对齐需求 |
| 源码对齐 | 2 | 源码对齐、source、对齐设计 | 源码对齐设计 |
| 单元测试 | 3 | 单元测试、unit | 单元测试 |
| 接口测试 | 4 | 接口测试、api | 接口测试 |
| E2E 测试 | 5 | E2E测试、e2e、端到端 | E2E 测试 |

## 参数自动推测

按以下优先级依次匹配，命中后消费对应 token 从剩余继续：

| 优先级 | 匹配条件 | 推测为 | 示例 |
|--------|----------|--------|------|
| 1 | `key=value` 形式 | 显式绑定，不做推测 | `browser=chrome` |
| 2 | 自然语言范围短语（见下方意图表） | 推断执行范围 | `跳过设计对齐` → 从步骤 2 开始 |
| 3 | 裸值含路径分隔符（`/` 或 `\`）或以 `ae/` 开头 | 路径含 `design` 优先于 `prd` → `design=`；仅含 `prd` → `prd=`；均不含但物理存在 → 检查是否在 `ae/designs/` 或 `ae/prds/` 下自动归类；均不命中 → 不消费，降级到优先级 4 | `ae/designs/xxx` → `design=ae/designs/xxx` |
| 4 | 以上均未命中的裸文本 | 拼接为裸提示词需求内容 | `优化登录页面` → 需求真源 |

### 自然语言意图表

匹配含意图关键词且步骤核心词成功匹配的短语，推断执行范围。意图关键词存在但步骤核心词匹配失败时，不消费该 token，继续尝试后续优先级。默认执行全部步骤（0-5）。

| 意图模式 | 推断规则 | 示例 |
|----------|----------|------|
| `跳过<步骤>` | 从该步骤下一编号开始执行到 5 | `跳过设计对齐` → 执行 2-5；`跳过定位` → 执行 1-5 |
| `从<步骤>开始` | 从该步骤编号执行到 5 | `从接口测试开始` → 执行 4-5 |
| `只跑<步骤>` / `只执行<步骤>` | 只执行该步骤 | `只跑E2E测试` → 执行 5-5 |
| `到<步骤>为止` / `到<步骤>结束` | 从 0 执行到该步骤 | `到单元测试为止` → 执行 0-3 |
| `<步骤>到<步骤>` | 从前者执行到后者 | `源码对齐到接口测试` → 执行 2-4 |

多个意图短语可组合，采用边界合并：取所有短语推断范围的起始编号最大值和结束编号最小值作为最终范围。如 `跳过设计对齐` → 2-5，`到单元测试为止` → 0-3，组合后取 max(2,0)=2 和 min(5,3)=3 → 执行 2-3。组合后起始编号大于结束编号时，提示用户范围矛盾并停止执行。

## 参数优先级

1. 命令自身消费的参数（范围描述、`design`、`prd`、裸提示词）不透传给内部技能。
2. 其余 `key=value` 视为额外参数，在对应步骤执行时透传给该步骤调用的技能。
3. 当额外参数与某步骤内部流程定义的默认值或行为冲突时，以额外参数为准。
4. 额外参数仅对实际接受该参数的技能生效；技能不识别的参数忽略。例如 `browser=chrome` 覆盖第五步默认的 Edge 浏览器，`mode=only` 覆盖第五步默认的 `mode=script`。

## 第零步：定位最新设计与对应需求

若范围不含步骤 0 则跳过本步的跳转判定（第 4 条），但仍需确定当前设计真源和需求真源：使用 `design=` 指定的路径或 `ae/designs/` 最新目录作为当前设计真源，按第 1-3 条规则确定需求真源。若 `design=` 未指定且 `ae/designs/` 目录不存在或为空，停止执行并提示用户先运行 `ae:design` 创建设计或通过 `design=` 显式提供。

1. 若 `$ARGUMENTS` 含 `design=<路径>`，直接使用该路径作为当前设计真源；否则扫描 `ae/designs/` 目录，按目录名日期后缀（`-YYYY-MM-DD`）降序排列，取最新设计目录作为当前设计真源。若 `ae/designs/` 目录不存在或为空，提示用户先运行 `ae:design` 创建设计或通过 `design=<路径>` 提供设计目录路径，并停止执行。
2. 若 `$ARGUMENTS` 含 `prd=<路径>`，直接使用该路径作为当前需求真源；否则从当前设计的 `overview.md` 或 frontmatter 中提取其引用的需求路径；若未显式引用，按名称前缀在 `ae/prds/` 中匹配对应需求目录。
3. 提取所有 `key=value` 参数、自然语言范围短语和路径参数后，剩余非 `key=` 形式的纯文本视为裸提示词需求内容，将其作为当前需求真源，并标记为非全量需求。
4. 范围含步骤 0 时：存在对应需求 → 进入第一步；不存在需求 → 跳过第一步，直接进入第二步。范围不含步骤 0 时：本条不执行，直接进入范围内的首个步骤。

## 第一步：设计对齐需求

使用 `ae:design` 技能，以当前需求目录为输入重新生成设计。`ae:design` 从标准位置 `ae/prds/` 和 `ae/designs/` 自动发现产物；若使用了自定义路径，需确保产物已置于标准位置或通过 `design=`/`prd=` 指定。额外参数透传给 `ae:design`。

- 对齐前必须判断需求是否为当前项目的全量需求：若需求仅覆盖部分模块（含裸提示词需求），则只对齐该需求提及的模块和内容，禁止删除或修改需求未提及的模块。
- 对齐后设计即为后续所有步骤的唯一设计真源。
- 禁止镀金，不新增需求未声明的设计内容。
- 一步到位，不保留过渡版本。

## 第二步：源码对齐设计

使用 `ae:work` 技能，以当前设计目录为输入，将当前项目源码对齐到设计。额外参数透传给 `ae:work`。

- 对齐前必须判断设计是否为当前项目的全量设计：若设计仅覆盖部分模块，则只对齐该设计提及的模块和内容，禁止删除或修改设计未提及的模块及其源码。
- 修复过程中以设计为准，设计空缺时以需求为准。"设计空缺"指当前设计目录中不存在对应模块的设计文件，或设计文件中未覆盖该模块/维度的内容。
- 禁止镀金，不实现设计未声明的功能。
- 一步到位，不考虑兼容更新。

## 第三步：单元测试

使用 `ae:unit-test` 技能编写单元测试并执行，确保全部通过。额外参数透传给 `ae:unit-test`。

- 测试失败时使用 `ae:backend-fix` 技能修复，修复以设计为准，设计空缺时以需求为准。
- 禁止镀金，不为设计未声明的场景编写测试。
- 一步到位，确保全部单元测试通过后进入下一步。

## 第四步：接口测试

使用 `ae:api-test` 技能编写接口测试并执行，确保全部通过。额外参数透传给 `ae:api-test`。

- 测试失败时使用 `ae:backend-fix` 技能修复，修复以设计为准，设计空缺时以需求为准。
- 禁止镀金，不编写设计未声明的接口测试。
- 一步到位，确保全部接口测试通过后进入下一步。

## 第五步：E2E 测试

使用 `ae:e2e-test` 技能（默认 mode=script）编写端到端测试脚本并执行，默认使用 Edge 浏览器。额外参数透传给 `ae:e2e-test`，可覆盖默认浏览器和 mode。

- 测试失败时使用 `ae:frontend-fix` 技能修复，修复以设计为准，设计空缺时以需求为准。
- 禁止镀金，不编写设计未声明的页面流程测试。
- 一步到位，确保全部 E2E 测试通过。

## 执行约束

- 按推断的执行范围依次执行，范围内前一步骤未通过不进入下一步骤；范围外步骤跳过。
- 范围不含步骤 0 时，跳过定位步骤的跳转判定（第 4 条），但仍执行第 1-3 条确定设计/需求真源；若真源无法确定，停止并提示用户补齐或通过 `design=`/`prd=` 显式提供。
- 任何步骤发现问题都必须使用对应修复技能修复后继续。
- 所有修复以设计为准，设计空缺时以需求为准。
- 额外参数透传给对应步骤调用的技能，与内部流程默认行为冲突时以参数为准。
- 全程禁止镀金，一步到位，不考虑过渡和迁移。
