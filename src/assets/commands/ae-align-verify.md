依次执行对齐与测试流程。全程禁止镀金，一步到位，不考虑过渡和迁移。`$ARGUMENTS` 支持以下参数格式：`design=<设计目录路径>`、`prd=<需求目录路径>`，或直接传入裸提示词需求内容（无 `key=` 前缀时视为裸提示词）。

## 第零步：定位最新设计与对应需求

1. 若 `$ARGUMENTS` 含 `design=<路径>`，直接使用该路径作为当前设计真源；否则扫描 `ae/designs/` 目录，按目录名日期后缀（`-YYYY-MM-DD`）降序排列，取最新设计目录作为当前设计真源。若 `ae/designs/` 目录不存在或为空，提示用户先运行 `ae:design` 创建设计或通过 `design=<路径>` 提供设计目录路径，并停止执行。
2. 若 `$ARGUMENTS` 含 `prd=<路径>`，直接使用该路径作为当前需求真源；否则从当前设计的 `overview.md` 或 frontmatter 中提取其引用的需求路径；若未显式引用，按名称前缀在 `ae/prds/` 中匹配对应需求目录。
3. 若 `$ARGUMENTS` 不含 `design=` 或 `prd=` 前缀且非空，则视为裸提示词需求内容，将其作为当前需求真源，并标记为非全量需求。
4. 存在对应需求 → 进入第一步；不存在需求 → 跳过第一步，直接进入第二步。

## 第一步：设计对齐需求

使用 `ae:design` 技能，以当前需求目录为输入重新生成设计。`ae:design` 从标准位置 `ae/prds/` 和 `ae/designs/` 自动发现产物；若使用了自定义路径，需确保产物已置于标准位置或通过 `design=`/`prd=` 指定。

- 对齐前必须判断需求是否为当前项目的全量需求：若需求仅覆盖部分模块（含裸提示词需求），则只对齐该需求提及的模块和内容，禁止删除或修改需求未提及的模块。
- 对齐后设计即为后续所有步骤的唯一设计真源。
- 禁止镀金，不新增需求未声明的设计内容。
- 一步到位，不保留过渡版本。

## 第二步：源码对齐设计

使用 `ae:work` 技能，以当前设计目录为输入，将当前项目源码对齐到设计。

- 对齐前必须判断设计是否为当前项目的全量设计：若设计仅覆盖部分模块，则只对齐该设计提及的模块和内容，禁止删除或修改设计未提及的模块及其源码。
- 修复过程中以设计为准，设计空缺时以需求为准。"设计空缺"指当前设计目录中不存在对应模块的设计文件，或设计文件中未覆盖该模块/维度的内容。
- 禁止镀金，不实现设计未声明的功能。
- 一步到位，不考虑兼容更新。

## 第三步：单元测试

使用 `ae:unit-test` 技能编写单元测试并执行，确保全部通过。

- 测试失败时使用 `ae:backend-fix` 技能修复，修复以设计为准，设计空缺时以需求为准。
- 禁止镀金，不为设计未声明的场景编写测试。
- 一步到位，确保全部单元测试通过后进入下一步。

## 第四步：接口测试

使用 `ae:api-test` 技能编写接口测试并执行，确保全部通过。

- 测试失败时使用 `ae:backend-fix` 技能修复，修复以设计为准，设计空缺时以需求为准。
- 禁止镀金，不编写设计未声明的接口测试。
- 一步到位，确保全部接口测试通过后进入下一步。

## 第五步：E2E 测试

使用 `ae:e2e-test` 技能（mode=script）编写端到端测试脚本并执行，使用 Edge 浏览器。

- 测试失败时使用 `ae:frontend-fix` 技能修复，修复以设计为准，设计空缺时以需求为准。
- 禁止镀金，不编写设计未声明的页面流程测试。
- 一步到位，确保全部 E2E 测试通过。

## 执行约束

- 依次执行，前一步骤未通过不进入下一步骤。
- 任何步骤发现问题都必须使用对应修复技能修复后继续。
- 所有修复以设计为准，设计空缺时以需求为准。
- 全程禁止镀金，一步到位，不考虑过渡和迁移。
