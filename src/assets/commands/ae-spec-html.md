使用 `ae:spec-html` 技能处理这次请求，并沿用参数：`$ARGUMENTS`。

## 自然语言意图解析

技能在执行前先解析 `$ARGUMENTS` 的自然语言意图，识别用户是"生成需求"、"翻译为软件"还是"同步软件源码与需求"。意图信号如下：

### 生成需求信号

信号词：需求、规格、生成需求、编写需求、描述功能、我想做、我需要一个、帮我设计、提取需求、从源码生成需求、修改需求、改一下规格

- 用户描述功能需求、问题或改进想法 → 生成需求
- 用户提供源码路径并表达"提取需求"/"反向生成" → 从源码生成需求
- 用户提供规格产物路径并表达"修改"/"改一下" → 修改已有需求

### 翻译为软件信号

信号词：翻译为软件、生成代码、生成源码、实现需求、开发这个、写代码、把这个做出来

- 用户提供规格产物路径并表达"翻译"/"生成代码" → 翻译为软件
- 用户只提供功能描述而表达"开发这个"/"写代码"/"把这个做出来" → 需先生成需求再翻译，按生成需求信号处理

### 同步信号

信号词：同步、对齐、一致、修改源码到指定需求、源码和需求对不上、更新需求到源码、需求同步到源码

- 用户提供规格产物路径 + 源码路径并表达"同步"/"对齐" → 双向同步
- 用户表达"修改源码到指定需求" → 同步软件到需求（spec-to-code）
- 用户表达"更新需求到源码"/"需求同步到源码" → 源码反向同步需求（code-to-spec）

### 显式参数

- `--sync-direction=auto`（默认）：技能自动分析同步方向，不确定时询问用户
- `--sync-direction=spec-to-code`：强制从需求同步到源码
- `--sync-direction=code-to-spec`：强制从源码同步到需求

## 执行约束

将 `$ARGUMENTS` 完整传递给 `ae:spec-html` 技能。技能内部完成意图分析、代理调度和最后一步的需求与源码一致性分析。命令层只做意图预解析和参数透传，不重复技能内部流程。
