智能提交当前变更，自动生成符合项目规范的提交信息。

## 执行流程

### 1. 检测与筛选

运行 `git status`、`git diff` 和 `git diff --staged`，识别当前会话变更（优先）或所有未暂存变更；无变更时提示用户无需提交，不创建空提交。

排除以下文件，禁止提交：
- 敏感文件（硬阻断）：`.env*`、`*.pem`、`*.key`、`credentials*`、`secret*`、密钥/Token/密码等，以及内容疑似包含敏感信息的文件；用户要求提交时必须硬阻断并要求先移除或脱敏
- 缓存/临时文件（`*.tmp`、`*.cache`）、`node_modules/`、构建产物（除非项目规范明确要求）
- 调试代码（含 `console.log` 等需先清理）

### 2. 生成提交信息

提交信息使用中文，优先遵循项目已声明的 Git 提交规范；未声明时使用格式 `<类型>(<范围>): <简短描述>`，类型含 `feat`(新功能)/`fix`(修复)/`refactor`(重构)/`docs`(文档)/`test`(测试)/`chore`(构建工具)/`perf`(性能)。

提交粒度：每次提交只做一件事，内容可独立运行，禁止 WIP 和调试代码；变更涉及多个独立关注点时拆分为多次提交。

### 3. 执行提交与验证

执行 `git add` 或 `git commit` 前，必须取得用户明确授权（覆盖目标仓库、目标分支、工作区、完整命令参数和授权来源），未授权时停止流程。

```bash
git add <筛选后的文件>
git commit -m "<类型>(<范围>): <简短描述>"
```

提交后运行 `git status` 确认预期文件已提交、未预期文件未提交、工作目录状态正确。

## 注意事项

- 禁止修改 git config，禁止跳过 hooks（`--no-verify` 等）
- 禁止修改提交的用户名和邮箱信息；无用户信息时提示用户输入，不得自行设置
- 禁止在提交信息或代码注释中出现"Created by Opencode"、"由 AI 代理生成"等 AI 生成标识
- 仅支持本地提交，不提供推送远程仓库能力
