# UI 设计品味规范

> 反模板化的前端设计工程指南。每条规则都是上下文感知的，不自动触发。先读懂需求，再只取适用的部分。

---

## 1. 需求推断

在写代码之前，先推断用户真正想要什么。LLM 设计输出差的根本原因是模型跳到默认美学，而不是先读懂场景。

### 读取信号

1. **页面类型** — 落地页（SaaS / 消费品 / 代理商 / 活动）、作品集（开发者 / 设计师 / 创意工作室）、改版（保留 vs 翻新）、编辑 / 博客
2. **氛围关键词** — "极简"、"平静"、"Linear 风格"、"Awwwards"、"粗野主义"、"高端消费品"、"Apple 感"、"活泼"、"严肃 B2B"、"编辑感"、"代理商风"、"毛玻璃"、"暗色科技"
3. **参考信号** — 用户链接的 URL、粘贴的截图、提及的产品、竞争品牌
4. **受众** — B2B 采购团队 vs 设计敏感的消费者 vs 扫描作品集的招聘者。受众决定美学，不是你的偏好
5. **已有品牌资产** — logo、色彩、字体、摄影。改版中这些是起始材料，不是可选输入
6. **隐性约束** — 无障碍优先的受众、公共部门、受监管行业、信任优先的电商、儿童产品。这些约束覆盖美学偏好

### 输出"设计读数"

在任何代码之前，用一句话声明：**"将此理解为：\<页面类型> 面向 \<受众>，采用 \<氛围> 语言，倾向 \<设计体系或美学家族>。"**

### 模糊需求处理

如果需求模糊，只问**一个**澄清问题，不要抛出多问题列表。只有当设计读数确实存在分歧时才问。如果能从上下文自信推断，直接声明设计读数并继续。

### 反默认纪律

不要默认使用：AI 紫色渐变、深色网格上的居中 Hero、三张等宽功能卡片、到处都是通用毛玻璃、无限循环微动画、Inter + slate-900。这些是 LLM 默认值。基于设计读数有意识地越过它们。

## 2. 三个旋钮（核心配置）

设计读数之后，设置三个旋钮。后续每个布局、动效和密度决策都由它们控制。

- **`DESIGN_VARIANCE: 8`** — 1 = 完美对称，10 = 艺术混乱
- **`MOTION_INTENSITY: 6`** — 1 = 静态，10 = 电影级 / 物理模拟
- **`VISUAL_DENSITY: 4`** — 1 = 美术馆 / 空旷，10 = 驾驶舱 / 信息密集

**基线值：`8 / 6 / 4`。** 除非设计读数覆盖它们。覆盖通过对话完成，不要求用户编辑文件。

### 旋钮推断表

| 信号 | VARIANCE | MOTION | DENSITY |
|---|---|---|---|
| "极简 / 干净 / 平静 / 编辑感 / Linear 风格" | 5-6 | 3-4 | 2-3 |
| "高端消费品 / Apple 感 / 奢侈 / 品牌" | 7-8 | 5-7 | 3-4 |
| "活泼 / 大胆 / Dribbble / Awwwards / 实验性 / 代理商" | 9-10 | 8-10 | 3-4 |
| "落地页 / 作品集 / 营销站（默认）" | 7-9 | 6-8 | 3-5 |
| "信任优先 / 公共部门 / 受监管 / 无障碍关键" | 3-4 | 2-3 | 4-5 |
| "改版 - 保留" | 匹配现有 | +1 | 匹配现有 |
| "改版 - 翻新" | +2 | +2 | 匹配现有 |

### 用例预设

| 用例 | VARIANCE | MOTION | DENSITY |
|---|---|---|---|
| 落地页（SaaS，主流） | 7 | 6 | 4 |
| 落地页（代理商 / 创意） | 9 | 8 | 3 |
| 落地页（高端消费品） | 7 | 6 | 3 |
| 作品集（设计师 / 工作室） | 8 | 7 | 3 |
| 作品集（开发者） | 6 | 5 | 4 |
| 编辑 / 博客 | 6 | 4 | 3 |
| 公共部门服务 | 3 | 2 | 5 |

### 旋钮技术定义

**DESIGN_VARIANCE（1-10）：**
- 1-3（可预测）：对称 CSS Grid（12 列等宽 fr 单位），等距 padding，居中对齐
- 4-7（偏移）：`margin-top: -2rem` 叠层，混合图片宽高比（4:3 紧邻 16:9），左对齐标题配居中数据
- 8-10（不对称）：瀑布流布局，CSS Grid 分数单位（`grid-template-columns: 2fr 1fr 1fr`），大片留白区（`padding-left: 20vw`）
- 移动端覆盖：4-10 级的非对称布局在 `< 768px` 必须折叠为严格单列

**MOTION_INTENSITY（1-10）：**
- 1-3（静态）：无自动动画。仅 CSS `:hover` 和 `:active` 状态。`prefers-reduced-motion` 本身就是默认模式
- 4-7（流畅 CSS）：`transition: all 0.3s cubic-bezier(0.16, 1, 0.3, 1)`。`animation-delay` 级联入场。聚焦 `transform` 和 `opacity`
- 8-10（高级编排）：复杂滚动触发揭示、视差、滚动驱动动画（CSS `animation-timeline` 或 GSAP ScrollTrigger）。**禁止 `window.addEventListener('scroll')`**

**VISUAL_DENSITY（1-10）：**
- 1-3（美术馆）：大量留白。巨大段落间距（`py-32` 到 `py-48`）。昂贵、干净
- 4-7（日常应用）：标准 Web 应用间距（`py-16` 到 `py-24`）
- 8-10（驾驶舱）：紧凑 padding。无卡片框；1px 线条分隔数据。强制要求：所有数字使用 `font-mono`

## 3. 设计体系选择

### 何时使用真正的设计体系

| 需求读数为... | 使用 | 原因 |
|---|---|---|
| Microsoft / 企业 SaaS / 仪表盘 | Fluent UI | 官方体系，Microsoft tokens，无障碍完善 |
| Google 风格 UI，Material 味产品 | Material Web + M3 tokens | 官方，可通过 Material Theming 主题化 |
| IBM 风格 B2B / 企业分析 | Carbon | 官方 Carbon，成熟的数据密度模式 |
| Shopify 应用界面 | Polaris | Shopify admin UI 必需 |
| Atlassian / Jira 风格产品 | Atlaskit + tokens | 官方 Atlassian DS |
| GitHub 风格开发工具 | Primer CSS / Brand | 官方 Primer；Brand 变体用于营销 |
| 英国公共服务 | GOV.UK Frontend | 法规/监管期望 |
| 美国公共服务 / 信任优先 | USWDS | 同上 |
| 快速本地商家 / 代理商 MVP | Bootstrap 5.3 | 无聊、快速、可用 |
| 现代无障碍 React 基础 | Radix Themes | 原语 + 精致主题 |
| 现代 SaaS（自持组件） | shadcn/ui | 你拥有代码，易于定制；**永不交付默认状态** |
| Tailwind 风格现代 SaaS / AI 营销 | Tailwind v4 + `dark:` 变体 | 独立开发者和小团队默认 |

**诚实规则：** 如果需求读数为上述体系之一，安装并使用**官方**包。不要手工重建其 CSS。不要导入某体系的 tokens 然后 90% 都覆盖掉。

**每个项目一个体系。** 不要在同一组件树中混用 Fluent React 和 Carbon。

### 何时需求是美学而非体系

这些方向没有单一官方包。用原生 CSS + Tailwind + 维护良好的组件库构建。

| 美学 | 诚实实现 |
|---|---|
| 毛玻璃 / "磨砂玻璃" | `backdrop-filter`、分层边框、高光叠层。为 `prefers-reduced-transparency` 提供实色回退 |
| Bento（Apple 风格瓦片网格） | CSS Grid 混合单元格尺寸。无单一库拥有此模式 |
| 粗野主义 | 原生 CSS、等宽字体、原始边框。无库 |
| 编辑 / 杂志 | 衬线字体、不对称网格、慷慨留白。无库 |
| 暗色科技 / 黑客 | 等宽 + 霓虹强调色、终端主题。无库 |
| 极光 / 网格渐变 | SVG 或分层径向渐变。无库 |
| 动态字体 | 原生 CSS 动画、滚动驱动动画、GSAP 用于滚动劫持。无库 |

## 4. 默认架构与约定

除非设计读数选择了真正的设计体系，以下是默认值。

### 技术栈

- **框架：** React 或 Next.js。默认使用 Server Components (RSC)
  - RSC 安全：全局状态仅在 Client Components 中工作。在 Next.js 中，用 `"use client"` 组件包裹 providers
  - 交互隔离：任何使用 Motion、滚动监听器或指针物理的组件必须是带 `'use client'` 的独立叶子组件。Server Components 只渲染静态布局
- **样式：** Tailwind v4（默认）。仅在现有项目要求时使用 v3
  - v4：不要在 `postcss.config.js` 中使用 `tailwindcss` 插件。使用 `@tailwindcss/postcss` 或 Vite 插件
- **动画：** Motion（原 Framer Motion）。从 `motion/react` 导入
- **字体：** 始终使用 `next/font`（Next.js）或通过 `@font-face` + `font-display: swap` 自托管。生产环境永不通过 `<link>` 引用 Google Fonts

### 状态管理

- 局部 `useState` / `useReducer` 用于隔离 UI
- 全局状态仅用于避免深层 prop 钻取 — Zustand、Jotai 或 React context
- **禁止**用 `useState` 跟踪用户输入驱动的连续值（鼠标位置、滚动进度、指针物理、磁性 hover）。使用 Motion 的 `useMotionValue` / `useTransform` / `useScroll`。`useState` 每次变更都触发 React 树重渲染，在移动端崩溃

### 图标

- **允许的库（优先序）：** `@phosphor-icons/react`、`hugeicons-react`、`@radix-ui/react-icons`、`@tabler/icons-react`
- **不推荐：** `lucide-react`。仅在用户明确要求或项目已依赖时可用
- **禁止手绘 SVG 图标。** 缺少字形时，安装第二个库或从原语组合
- **每个项目一个图标族。** 不要在同一组件树中混用 Phosphor 和 Lucide
- **全局标准化 `strokeWidth`**（如 `1.5` 或 `2.0`）

### Emoji 策略

默认不鼓励在代码、标记和可见文本中使用 emoji。用图标库字形替换符号。覆盖：仅在用户明确要求活泼 / 聊天风格 / 社交原生的氛围时允许，且仍需谨慎有意图地使用。

### 响应式与布局机制

- 标准化断点（`sm 640`、`md 768`、`lg 1024`、`xl 1280`、`2xl 1536`）
- 使用 `max-w-[1400px] mx-auto` 或 `max-w-7xl` 容纳页面布局
- **视口稳定性：** 永远不用 `h-screen` 做全高 Hero。始终用 `min-h-[100dvh]` 防止移动端布局跳动（iOS Safari 地址栏）
- **Grid 优先于 Flex 计算：** 永远不用复杂 flexbox 百分比计算（`w-[calc(33%-1rem)]`）。始终用 CSS Grid（`grid grid-cols-1 md:grid-cols-3 gap-6`）

### 依赖验证

导入任何第三方库之前，检查 `package.json`。如果包不存在，先输出安装命令。**永不假设库存在。**

## 5. 排版指令

### 展示 / 标题

默认 `text-4xl md:text-6xl tracking-tighter leading-none`。

### 正文 / 段落

默认 `text-base text-gray-600 leading-relaxed max-w-[65ch]`。

### 无衬线字体选择

- **不推荐作为默认：** `Inter`。选择 `Geist`、`Outfit`、`Cabinet Grotesk`、`Satoshi` 或品牌适配的衬线字体
- **覆盖：** 当用户明确要求中性 / 标准 / Linear 风格，或需求是公共部门 / 无障碍优先站点时，Inter 可用
- **搭配：** `Geist` + `Geist Mono`、`Satoshi` + `JetBrains Mono`、`Cabinet Grotesk` + `Inter Tight`、`GT America` + `IBM Plex Mono`

### 衬线纪律

- 衬线作为任何项目的默认字体**非常不推荐**。"感觉创意 / 高端 / 编辑感"不是使用衬线的理由
- **仅在以下条件之一明确为真时，衬线才可接受：**
  - 品牌简报明确指定了衬线字体，或
  - 美学家族确实是编辑 / 奢侈 / 出版 / 手稿 / 传承 / 复古，且你能说明为什么这个特定衬线适合这个特定品牌
- 其他一切（创意代理商、设计工作室、现代品牌、高端消费品、作品集、生活方式），**默认无衬线展示字体**（Geist Display、ABC Diatype、Söhne Breit、Cabinet Grotesk Display、Migra Sans、GT Walsheim、Inter Display、PP Neue Montreal）
- **强调规则：** 在标题中强调一个词时，使用**同一字体的斜体或粗体**。不要在无衬线标题中注入随机衬线词（或反之）来增加视觉趣味。混族强调是业余的

### 明确禁止的默认衬线

`Fraunces` 和 `Instrument_Serif`（两个 LLM 最爱的展示衬线）。

如果衬线有正当理由（罕见），从此池轮换，不要在连续项目中重复使用同一衬线：PP Editorial New、GT Sectra Display、Cardinal Grotesque、Reckless Neue、Tiempos Headline、Recoleta、Cormorant Garamond、Playfair Display、EB Garamond、IvyPresto、Migra、Editorial Old、Saol Display、Söhne Breit Kursiv、Domaine Display、Canela、Schnyder、Tobias、NB Architekt、ITC Galliard。

### 斜体下伸字符间距

斜体用于展示字体且单词包含下伸字符（`y g j p q`）时，`leading-[1]` 或 `leading-none` 会裁剪下伸部分。使用 `leading-[1.1]` 最小值并在包裹元素上添加 `pb-1` 或 `mb-1` 预留空间。交付前审计每个展示标题中的斜体词。

## 6. 色彩校准

- 最多 1 个强调色。默认饱和度 < 80%
- **LILA 规则：** "AI 紫色 / 蓝色辉光"美学不鼓励作为默认。无自动紫色按钮辉光，无随机霓虹渐变。使用中性基色（Zinc / Slate / Stone）配高对比单一强调色（Emerald、Electric Blue、Deep Rose、Burnt Orange 等）
- **覆盖：** 如果品牌或简报明确要求紫色 / 紫罗兰 / lila，拥抱它。但要有意图地执行：一致的调色板、协调的中性色、克制的渐变。不是通用 AI 渐变糟粕
- **每个项目一个调色板。** 不要在同一项目中混用暖灰和冷灰
- **色彩一致性锁定：** 一旦为页面选择了强调色，它用于整个页面。暖灰站点不会在第 7 节突然出现蓝色 CTA。玫瑰强调站点不会在页脚出现青色状态徽章。选一个强调色，锁定它，交付前审计每个组件

### 高端消费品调色板禁令

对于高端消费品简报（厨具、健康、手工艺、奢侈、传承工艺、DTC 家居等），LLM 默认是**暖米色 / 奶油色 + 黄铜 / 陶土 / 牛血红 / 赭色 + 浓咖啡 / 墨色暗文本**。禁止作为默认使用的 hex 色系：

- 背景：`#f5f1ea`、`#f7f5f1`、`#fbf8f1`、`#efeae0`、`#ece6db`、`#faf7f1`、`#e8dfcb`（所有"暖纸 / 奶油 / 白垩 / 骨色"）
- 强调：`#b08947`、`#b6553a`、`#9a2436`、`#9c6e2a`、`#bc7c3a`、`#7d5621`（所有"黄铜 / 陶土 / 牛血红 / 赭色"）
- 文本：`#1a1714`、`#1a1814`、`#1b1814`（所有"浓咖啡 / 暖近黑"）

**默认替代方案（轮换，不重复）：**
- **冷调奢侈：** 银灰 + 铬 + 烟色
- **森林：** 深绿 + 骨色 + 琥珀强调
- **黑与棕：** 真正的近黑 + 暖棕，锐利对比，无米色
- **钴蓝 + 奶油：** 饱和蓝配单一中性色，无黄铜
- **赤陶 + 石板：** 暖锈色配冷灰，无黄铜
- **橄榄 + 砖红 + 纸色：** 柔和橄榄加砖红强调
- **纯单色 + 单一饱和跳色：** 近白 + 近黑 + 一个亮色（电光蓝、翡翠、热粉等）

调色板轮换规则：如果上一个高端消费品项目使用了米色 + 黄铜色系，这个项目必须使用不同的色系。

**覆盖条件：** 只有当品牌简报明确指定米色 / 黄铜 / 浓咖啡色系，或品牌身份确实是复古、手工艺、暖工艺且能说明为什么适配时，才可使用该色系。仅因为“这是厨具 / 健康 / 手工艺简报”而默认套用，仍然禁止。

## 7. 布局多样化

### 反居中偏见

`DESIGN_VARIANCE > 4` 时避免居中 Hero / H1 段落。强制"分屏"（50/50）、"左对齐内容 / 右对齐资产"、"不对称留白"或滚动固定结构。

覆盖：编辑 / 宣言 / 发布公告简报中，信息本身就是设计时居中 Hero 可用。

### 布局硬性规则

失败任何一条都是交付有问题的作品。

- **Hero 必须适配初始视口。** 标题桌面端最多 2 行，副文本最多 **20 词** 且最多 3-4 行，CTA 不滚动可见。文案太长：减小字号或削减文案
- **Hero 字号纪律。** 字号和图片尺寸一起规划。如果 Hero 资产大且标题超过 6 个词，不要从 `text-7xl/text-8xl` 开始。合理范围：`text-4xl md:text-5xl lg:text-6xl`；标题 3-5 词时才用 `text-6xl md:text-7xl`。4 行 Hero 标题始终是字号错误，不是文案长度错误
- **Hero 顶部 padding 上限：** 桌面端最多 `pt-24`（约 6rem）。更多意味着 Hero 内容漂浮在视口中间，读起来像布局 bug
- **Hero 堆叠纪律（最多 4 个文本元素）：**
  1. 眉标（小号大写标签）或品牌条或都没有 — 选零或一个
  2. 标题（最多 2 行）
  3. 副文本（最多 20 词，最多 4 行）
  4. CTA（1 个主 + 最多 1 个次）
  - **Hero 中禁止：** CTA 下方的小标语、信任微条、定价预告、功能项目列表、社交证明头像行。所有这些移到 Hero 正下方的专属段落
- **"Used by" / "Trusted by" logo 墙在 Hero 下方，不在 Hero 内部。** Hero 是价值主张和主 CTA 的空间
- **导航必须桌面端单行渲染。** `lg`（1024px）放不下时，压缩标签、删除次要项或移到汉堡菜单
- **导航高度上限：** 桌面端最多 80px，默认 64-72px
- **Bento 网格必须有节奏，不是单侧重复。** 不要堆叠 6 个左图 / 右文行。变化构图：交替全宽特色行、不对称瓦片尺寸、垂直中断
- **Bento 单元计数规则：** Bento 网格的单元数等于你有内容的项目数。3 项 = 3 单元。5 项 = 5 单元。中间或末尾有空单元 = 计划错误
- **段落布局重复禁令。** 一旦某个布局家族用于一个段落（如 3 列图片卡、全宽引语、图文分屏），该家族最多在页面中出现一次。8 个段落的落地页必须使用至少 4 个不同的布局家族
- **Z 字形交替上限。** 交替"左图 + 右文"然后"左文 + 右图"最多连续 2 段。第 3 个连续图文分屏是交付失败
- **眉标克制（违反最多的规则）。** 眉标是段落标题上方的小号大写宽字距标签。硬性规则：
  - **每 3 个段落最多 1 个眉标。** Hero 算 1 个。9 段页面最多 3 个眉标
  - 如果段落 A 有眉标，接下来 2 个段落不能有
  - 替代方案：直接删除眉标。标题本身够了
- **分体标题禁令。** "左大标题 + 右小说明段落"作为段落标题的模式禁止作为默认。段落应该有一个聚焦信息。需要标题和说明时，垂直堆叠
- **Bento 背景多样性。** Bento 和特色网格段落不能是 6 个白底白字卡片。至少 2-3 个单元需要真正的视觉变化：真实图片、品牌适配渐变、图案、着色背景
- **移动端折叠必须每段显式声明。** 每个多列布局在组件中声明 `< 768px` 回退。不要假设"Tailwind 会处理"

## 8. 材质、阴影与卡片

- 仅在高度传达真实层级时使用卡片。否则用 `border-t`、`divide-y` 或负空间分组
- 使用阴影时，将阴影着色为背景色相。浅色背景上不要纯黑投影
- `VISUAL_DENSITY > 7`：通用卡片容器禁止。数据指标在朴素布局中呼吸
- **形状一致性锁定：** 为页面选择一个圆角比例并坚持。选项：全锐角（radius 0）、全柔和（radius 12-16px）、全药丸（交互元素全圆角）。混合系统仅在有文档化规则时允许（如"按钮全药丸，卡片 16px，输入框 8px"）且该规则到处遵循

## 9. 交互 UI 状态

LLM 默认"只有静态成功状态"。始终实现完整周期：

- **加载中：** 匹配最终布局形状的骨架加载器。避免通用圆形旋转器
- **空状态：** 精心构图；指示如何填充
- **错误状态：** 清晰、内联（表单），或上下文相关（toast 仅用于瞬态）
- **触觉反馈：** `:active` 时使用 `-translate-y-[1px]` 或 `scale-[0.98]` 模拟物理按压
- **按钮对比检查：** 交付前验证按钮文字在按钮背景上可读。白按钮 + 白文字、透明按钮配页面背景无边框 = 禁止。审计每个 CTA：WCAG AA 最低对比度（正文 4.5:1，大字 18px+ 为 3:1）
- **CTA 按钮换行禁令：** 按钮文字桌面端必须单行。标签如 "VIEW SELECTED WORK" 换行到 2-3 行 = 按钮损坏。缩短标签（主 CTA 最多 3 词，理想 1-2 词）或加宽按钮
- **重复 CTA 意图禁令：** 同一页面上两个相同意图的 CTA = 失败。如 "Get in touch" + "Contact us" + "Let's talk" = 全是"联系"意图，选一个标签全页使用
- **表单对比检查：** 表单输入、占位文字、聚焦环、辅助文字和错误文字都通过 WCAG AA 对比度

### 表单模式

- 标签在输入框上方。辅助文字可选但存在于标记中。错误文字在输入框下方。标准 `gap-2`
- 永不用占位符代替标签

## 10. 图片与视觉资产策略

落地页和作品集是**视觉产品**。纯文本页面配假截图 div 是糟粕。

**视觉资产优先顺序：**
1. **图像生成工具优先。** 如果环境中有任何图像生成工具，必须使用它创建段落特定资产：Hero 摄影、产品照、纹理背景、情绪图。按正确宽高比生成
2. **真实网络图片其次。** 无生成工具时，使用真实摄影来源：
   - `https://picsum.photos/seed/{描述性种子}/{w}/{h}` 用于占位摄影
   - 简报提供的实际图库或品牌 URL
   - 明确允许的开源来源（Unsplash 直接 URL、Pexels）
3. **最后手段：告知用户。** 两种都不可行时，不要用手工 SVG 插图或 div "假截图"填充页面。留下清晰标记的占位槽并在回复末尾说明需要的图片位置

**即使极简网站也需要真实图片。** 纯文本页面不是极简主义，是未完成的工作。即使是编辑感 Linear 风格网站也至少需要 2-3 张真实图片。简报克制时生成黑白极简摄影，不要因为旋钮低就完全跳过图片。

### 社交证明 Logo 墙

当简报要求 "Trusted by / Used by / Customers" logo 墙时，不要默认纯文本 wordmark。使用真实 SVG logo：

- **来源：Simple Icons**（`https://cdn.simpleicons.org/{slug}/ffffff`）。覆盖大多数已知品牌
- **替代：devicon** 用于技术栈 logo
- **虚构品牌名？那也虚构 SVG 标记。** 生成简单字母组合（圆中一个字母、两字母连字、抽象字形）渲染为内联 `<svg>` 匹配页面风格
- **始终**确保 logo 在亮色和暗色模式下都能渲染
- **LOGO-ONLY 规则：** logo 墙 = 只有 logo。不要在每个 logo 下方打印行业 / 类别标签

### 禁止的视觉资产模式

- **禁止 div 假截图。** 用 `<div>` 矩形构建的"手工产品预览"（假任务列表、假仪表盘、假终端窗口）是 Tell
- **Hero 需要真实视觉。** 文字 + 渐变气泡不是 Hero，是占位符
- **手工装饰 SVG 强烈不推荐** 作为默认。仅在简报明确要求或简单几何标记时可用

## 11. 内容密度

落地页靠**第一印象**活着，不是完整阅读。无情削减。

- **每段默认内容形态：** 短标题（≤ 8 词）+ 短副段落（≤ 25 词）+ 一个视觉资产或一个 CTA。更多需由段落职责证明
- **无数据倾泻段落。** 20 行出版表、30 行获奖列表、巨大定价矩阵 = 错误布局。使用：前 3-5 亮点 + "查看完整列表"链接、跑马灯 / 轮播、或不同页面
- **长列表需要不同 UI 组件，不是更长的列表。** > 5 项时使用：2 列分组、卡片网格、标签页 / 手风琴、水平滚动 snap 药丸、轮播、跑马灯
- **规格表（Marrow 厨具模式）。** 每行带 `border-b` 的长产品规格表是 AI 默认。禁止。替代：
  - 2 列卡片网格：每个规格一张卡，含规格名、值（大号展示数字）和一行"为什么重要"
  - 滚动 snap 水平药丸
  - 分组块：将 10 个规格分成 3 个逻辑簇
  - 特色 vs 其余：3-4 个 Hero 规格可视化为大展示瓦片，其余折叠

### 文案自审

交付前重新阅读页面上每个可见字符串。标记以下内容：
- 语法错误
- 指代不清
- 听起来像 AI 幻觉（可爱但错误的文字游戏、不成立的隐喻）
- 读起来像 LLM 试图显得深思熟虑（被动攻击性谦虚、假工匠标签、伪诗意微元数据）

重写每个标记的字符串。不确定时替换为朴素功能句。

### 假精确数字

`92%`、`4.1x`、`48k`、`5.8 mm`、`13.4 lb` 这样的数字：
- 来自真实数据 — 可以
- 明确标记为模拟 — 可以
- AI 发明的规格美学 — 禁止

## 12. 引语与推荐

- 引语正文**最多 3 行**。6 行不可接受。长引语 = 剪切
- 引语文本中**无 em-dash** 作为设计装饰
- 署名：姓名 + 角色 +（可选）公司。永不仅姓名
- 引号：使用真正的排版引号或不用。不用直 ASCII 引号

## 13. 页面主题锁定

页面有一个主题。段落不反转。

- 暗色模式页面，所有段落都是暗色。无暗色段落间夹暖纸亮色段落
- 例外：简报明确要求"色块故事"或"滚动主题切换"设备且是刻意的构图时，每页允许一次
- 默认行为：在页面级别选择亮、暗或 auto 并锁定。同主题族内的段落级背景色调可以（`bg-zinc-950` 紧邻 `bg-zinc-900`）；暗色页面中间翻转到 `bg-amber-50` 是损坏的

## 14. AI Tell（禁止模式）

避免这些签名，除非简报明确要求。

### 视觉与 CSS

- **无霓虹 / 外辉光** 作为默认。使用内边框或微妙着色阴影
- **无纯黑（`#000000`）。** 用近黑、zinc-950 或炭灰
- **无过饱和强调色。** 降饱和以与中性色融合
- **无过度渐变文字** 用于大标题
- **无自定义鼠标光标。** 过时、无障碍不友好、性能差

### 排版

- **避免 Inter 作为默认**
- **无过大 H1** 只会尖叫。用粗细 + 色彩控制层级，不是原始字号
- **衬线约束：** 衬线用于编辑 / 奢侈 / 出版。不用于仪表盘

### 布局与间距

- **数学级精确的** padding 和 margin。避免元素悬浮并留下尴尬间隙
- **禁止 3 列等宽功能卡片。** 通用的"三张相同卡片水平排列"功能行。用 2 列 Z 字形、不对称网格、滚动固定或水平滚动替代

### 内容与数据

- **无通用姓名。** "John Doe"、"Sarah Chan" → 使用创意、真实、地区适配的姓名
- **无通用头像。** 无 SVG"蛋"或 Lucide 用户图标
- **无假完美数字。** 避免 `99.99%`、`50%`。使用有机、杂乱数据
- **无创业糟粕品牌名。** "Acme"、"Nexus"、"SmartFlow" → 发明上下文相关的高端名字
- **无填充动词。** "Elevate"、"Seamless"、"Unleash"、"Next-Gen"、"Revolutionize" → 只用具体动词

### 外部资源与组件

- **无手绘 SVG 图标。** 使用 Phosphor / HugeIcons / Radix / Tabler
- **无 div 假截图。** 使用真实图片、生成图片或跳过预览
- **无失效的 Unsplash 链接。** 使用 `https://picsum.photos/seed/{描述性字符串}/{w}/{h}`
- **shadcn/ui 定制：** 允许，但**永不交付默认状态**。定制圆角、色彩、阴影、排版

### 生产测试 Tell（完全禁止）

这些模式来自真实 LLM 生成的落地页测试。除非简报明确要求，视为硬禁令。

**Hero 与页面顶部：**
- Hero 中无版本标签（`V0.6`、`BETA`、`INVITE-ONLY PREVIEW`）
- 无 "Brand · No. 01" 风格子眉标

**段落编号与微标签：**
- 无段落编号眉标（`00 / INDEX`、`001 · Capabilities`）
- 无 `01 / 4` 风格分页
- 无 `Scroll · 001 Capabilities` 风格滚动提示

**分隔符与点：**
- 间隔号（`·`）配额：每行元数据条最多 1 个
- 默认无装饰性彩色状态点

**Em-dash 与排版装饰：**
- **Em-dash（`—`）完全禁止。** 标题、眉标、药丸、正文、引语、署名、说明、按钮文字、alt 文字中均不可用。使用普通连字符（`-`）
- En-dash（`–`）作为分隔符也禁止。日期范围用连字符
- 无 `<br>` 断行 + 斜体标题作为默认"设计手法"
- 无垂直旋转文字
- 无十字准线 / 细线网格作为装饰

**假产品预览：**
- 无 div 假产品 UI（假任务列表、假终端、假仪表盘）
- 无假版本页脚

**营销文案 Tell：**
- 无 "Quietly in use at" / "Quietly trusted by"
- 无 "From the field" / "Field notes" / "On our desks" 风格诗意标签
- 无天气 / 地区条
- 眉标下无微元数据句子
- 无通用步骤标签（"Stage 1 / Stage 2"）

**药丸、标签与版本戳：**
- 无药丸/标签叠放在图片上
- 无装饰性照片署名
- 营销页面无版本页脚
- 无装饰性库存计数器

**装饰文字条：**
- Hero 底部无装饰文字条（`BRAND. MOTION. SPATIAL.`）
- 段落标题无右上角浮动小说明

**列表、分隔线与评分：**
- 长列表每行无 `border-t` + `border-b`。选一个稀疏使用
- 无填充背景轨道的评分/进度条作为比较视觉

**地区、时间、滚动提示：**
- 地区/城市名/时间/天气条 99% 的简报禁止
- 滚动提示禁止（`Scroll`、`↓ scroll`、`Scroll to explore`、动画鼠标滚轮图标）
- 默认零装饰性状态点

## 15. 暗色模式协议

默认双模式。除非简报是模拟印刷的编辑页面，否则不假设纯亮色。

### Token 策略（选一个，坚持）

- **Tailwind `dark:` 变体**（utility 优先项目默认）：每个颜色 utility 配暗色变体
- **CSS 变量**（用于 shadcn/ui、Radix Themes 或带主题的组件库）：定义语义 token 并在 `[data-theme="dark"]` 或 `@media (prefers-color-scheme: dark)` 下交换值

### 不在此指定具体颜色

简报和品牌决定。本规范仅强制：
- **对比度** — 正文 WCAG AA 最低，Hero 文案 AAA 目标
- **层级对等** — 亮色中有效的视觉层级在暗色中也有效
- **品牌保真度** — 主品牌色保持可识别。不要把品牌去饱和成暗色模式
- **无纯 `#000000` 和无纯 `#ffffff`** — 使用近黑（zinc-950、近黑暖灰）和近白

### 默认模式

尊重 `prefers-color-scheme`，除非品牌坚持。如果任一模式会丢失关键品牌表达，添加手动切换。

### 交付前双模式测试

在两种模式下都打开页面。不要只在一个模式下看过的页面就交付。

## 16. 性能与无障碍护栏

### 硬件加速

- 仅动画 `transform` 和 `opacity`。永不动画 `top`、`left`、`width`、`height`
- 谨慎使用 `will-change: transform` — 仅在确实会动画的元素上

### 减少动效（强制）

- **`MOTION_INTENSITY > 3` 的任何动效必须遵守 `prefers-reduced-motion`。** 不可协商
- Motion 中：用 `useReducedMotion()` 包装并降级为静态
- CSS 中：在 `@media (prefers-reduced-motion: no-preference)` 后面设置动画，或在 `@media (prefers-reduced-motion: reduce)` 下提供禁用覆盖
- 无限循环、视差、滚动劫持和磁性物理必须在减少动效下折叠为静态 / 即时

### Core Web Vitals 目标

- **LCP** < 2.5s。Hero 图片必须 `next/image priority` 或预加载
- **INP** < 200ms。重工作离开主线程
- **CLS** < 0.1。为图片、字体、嵌入预留空间

### DOM 成本

- 噪点/颗粒滤镜仅应用于固定、`pointer-events-none` 伪元素。永不应用于滚动容器
- 注意 bundle 大小。Motion 不小。Three.js 很大。非首屏内容懒加载

### Z-Index 克制

永不乱设 `z-50` 或 `z-10`。z-index 严格用于系统性层上下文（固定导航栏、模态框、叠层、颗粒）。在项目常量文件中记录 z-index 比例。

### 语义化 HTML

- 使用语义化标签表达文档结构：`<header>`、`<nav>`、`<main>`、`<article>`、`<section>`、`<aside>`、`<footer>`。不滥用 `<div>` 做布局容器
- 标题层级 (`<h1>` → `<h6>`) 按文档大纲顺序使用，不跳级。一个页面只有一个 `<h1>`
- 交互元素使用正确的语义角色：按钮用 `<button>` 不用 `<div onclick>`，链接用 `<a>` 不用 `<button onclick="location.href">`
- 表单字段必须有关联的 `<label>`，不依赖 `placeholder` 替代标签文本
- 图标按钮必须有 `aria-label`，装饰性图片用 `alt=""` 隐藏
- 焦点状态不可移除。`:focus-visible` 必须有可见的焦点环（最低 2px 实线或 3px 双环），对比度满足 WCAG AA

## 17. 上下文感知的主动性

这些是工具，不是默认值。设计读数要求时使用。**都不自动触发。**

- **毛玻璃 / Glassmorphism：** 适用于高端消费品、Apple 相邻、奢侈品牌或媒体叠层氛围。不适用于仪表盘、公共部门或"无聊 B2B"。使用时超越 `backdrop-blur`：添加 1px 内边框（`border-white/10`）和微妙内阴影模拟物理边缘折射。为 `prefers-reduced-transparency` 提供实色回退
- **磁性微物理：** `MOTION_INTENSITY > 5` 且简报读数为高端 / 活泼 / 代理商时使用。**仅用** Motion 的 `useMotionValue` / `useTransform` 在 React 渲染循环外实现。永不 `useState`
- **永续微交互**（Pulse、Typewriter、Float、Shimmer、Carousel）：`MOTION_INTENSITY > 5` 且段落主动受益于动效时使用。**不是每张卡都需要无限循环。** 信息段落保持静止。应用弹簧物理（`type: "spring", stiffness: 100, damping: 20`）— 无线性缓动
- **"声称动效，展示动效。"** `MOTION_INTENSITY > 4` 时页面必须真正动起来：Hero 入场过渡、关键段落滚动揭示、CTA hover 物理。声称 `MOTION_INTENSITY: 7` 的静态页面是损坏的。无法在可用范围内交付可用动效时，将旋钮降到 3 并交付干净的静态页面
- **动效必须有动机。** 添加任何动画前问："这个动画传达什么？" 有效答案：层级、叙事、反馈、状态过渡。无效答案："看起来酷"。GSAP 到处用因为 GSAP 可用是业余的
- **跑马灯每页最多一个。** 水平滚动文字跑马灯每页至多一次。两个以上读起来像懒惰填充

## 18. 改版协议

### 检测模式

- **全新构建** — 无现有站点或批准全面翻新。使用基线旋钮
- **改版 - 保留** — 现代化但不破坏品牌。先审计，提取品牌 token，渐进演化
- **改版 - 翻新** — 在现有内容上新视觉语言。视觉上视为全新；保留内容和 IA

### 审计后再动手

记录当前状态后再提议变更：
- **品牌 token** — 主色/强调色、字体栈、logo 处理、圆角
- **信息架构** — 页面树、主导航、关键转化路径
- **内容块** — 存在什么，什么在起作用，什么是填充
- **保留的模式** — 签名交互、可识别的 Hero、文案语气
- **淘汰的模式** — AI-slop tell、损坏布局、死链、通用图库图片
- **现有站点的旋钮读数** — 推断当前 `DESIGN_VARIANCE` / `MOTION_INTENSITY` / `VISUAL_DENSITY`
- **SEO 基线** — 当前排名页面、meta 标题、结构化数据、OG 卡片

### 保留规则

- 除非要求，不改变信息架构。保持页面 slug、锚点 ID、主导航标签稳定
- 提取品牌色后再应用色彩校准。已经紫色的品牌保持紫色 — 应用 LILA 规则的覆盖
- 除非要求重写，保留文案语气。视觉现代化不等于内容重写
- 尊重已有无障碍成果。不退化焦点状态、alt 文字、键盘导航、对比度

### 现代化杠杆（优先序）

1. **排版刷新** — 每单位风险最大视觉提升
2. **间距与节奏** — 增加段落 padding，修复垂直节奏
3. **色彩重新校准** — 降饱和，统一中性色，保留品牌强调色
4. **动效层** — 添加 `MOTION_INTENSITY` 适配的微交互
5. **Hero 与关键段落重构** — 使用模式词汇重组顶部漏斗
6. **完整块替换** — 仅在现有块不可挽救时

### 永不静默变更

未经用户明确批准永不修改：
- URL 结构 / 路由 slug
- 主导航标签
- 表单字段名称或顺序
- 品牌 logo 或 wordmark
- 现有法律 / 同意 / cookie 文案
