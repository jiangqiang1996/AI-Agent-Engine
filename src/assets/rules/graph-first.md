# 图谱优先规则

当当前工作区存在 AE 文件关系图谱时，优先使用图谱理解项目结构，再按需读取文件、搜索源码或运行验证。

## 优先使用图谱的场景

- 统计项目文件数量、关系数量和关系类型分布。
- 快速了解项目目录结构、模块分布和文件关系概况。
- 查询单个文件依赖了哪些文件，以及被哪些文件依赖。
- 修改、删除、移动或重命名文件前评估影响范围。
- 重构、拆分任务或并行工作前识别文件关系重叠和潜在冲突。
- 查找核心模块、高连接度文件、孤立文件、循环依赖和长依赖链。
- 查询两个文件之间是否存在依赖路径。
- 按目录、文件类型或关系类型缩小后续阅读和搜索范围。
- 审查、计划、调试或接手项目时，先用图谱建立结构性上下文。
- 搜索工具不可用、全盘扫描成本较高或问题本身是结构性问题时，用图谱作为首选入口。

## 推荐顺序

1. 如果问题可以由文件清单、依赖关系或结构快照回答，先查询图谱。
2. 如果图谱缺失或疑似过期，先考虑构建或增量更新图谱。
3. 图谱给出候选范围后，再读取相关文件或执行更精确的源码搜索。
4. 代码改动后仍必须运行与改动相关的测试、类型检查、构建或其他验证命令。

## 不可替代的场景

- 图谱是结构快照，不保证反映最新未构建的工作区状态。
- 图谱不替代读取真实文件内容、查看 Git diff、检查未提交变更或确认文件实际存在。
- 图谱不替代类型检查、测试、构建、Lint、浏览器验收或运行时验证。
- 图谱不提供完整 AST、符号级调用链、业务语义判断或动态运行时依赖保证。
- 当安全、权限、数据迁移、生产可靠性或外部契约风险存在时，必须结合真实代码和验证证据判断。

## 结论表达

- 基于图谱得到的结论应说明其来源是图谱快照。
- 若只查询了图谱而未读取源码或运行验证，应明确标注仍需进一步确认的部分。
- 当图谱结果与真实文件、Git 状态或验证命令冲突时，以最新可观察证据为准。
