# 知识图谱优先规则

处理与当前工作区项目有关的任务时，默认先尝试使用项目知识图谱了解结构、依赖关系、影响范围或上下文位置；只有任务明显不需要项目上下文，或知识图谱缺失且无法构建时，才直接降级为读取真实文件、搜索源码或运行验证。只要知识图谱能提供任何定位、筛选、风险判断或阅读顺序价值，就必须优先查询图谱。

## 适用范围

- 当前任务发生在当前工作区内。
- 当前任务需要理解项目已有结构、模块边界、文件关系、依赖路径或影响范围。
- 当前任务涉及审查、计划、调试、重构、修改、删除、移动、重命名文件，或需要先缩小阅读和搜索范围。
- 当前任务可以从文件清单、关系类型分布、核心模块、孤立文件、循环依赖或长依赖链中获得上下文。
- 任务需要寻找候选文件、判断从哪里开始读、评估改动波及面、验证某文件是否处于核心路径或发现可疑依赖模式。
- 搜索工具可用时也应优先把知识图谱作为定位入口；搜索和读取源码用于确认图谱线索，而不是替代第一步图谱查询。

## 不优先使用知识图谱的场景

- 任务与当前仓库、当前项目或当前工作区无关。
- 任务目标位于其他工作区，而不是当前工作区。
- 任务不需要熟悉当前项目已有情况，例如纯聊天、通用知识问答、简单命令说明、文本改写，或用户已提供完整上下文且无需查询项目结构。
- 任务只要求执行一个明确、孤立且无需项目上下文的操作。
- 用户明确禁止使用或更新知识图谱。

## 推荐顺序

1. 先把当前任务映射为图谱查询问题：查候选文件用 `filter`，查单文件上下游用 `deps`，查改动波及面用 `impact`，查模块风险用 `core`、`stats`、`pattern` 或 `health`，查两点关系用 `path`。
2. 先查询知识图谱获取结构性上下文、候选文件、核心模块、依赖路径或影响范围；查询范围过宽时，应收窄 `scope`、`directory`、`file_type` 或 `relation_type` 后再次查询。
3. 如果图谱缺失、过期、范围不匹配或诊断不可用，先提示用户是否调用 `ae:graph-build` 构建、更新或修复图谱；用户同意后再调用。
4. 如果用户不同意构建或当前无法构建图谱，降级为读取真实文件和搜索源码，并在结论中说明未使用图谱的原因。
5. 图谱给出候选范围后，再读取关键文件、查看 Git 状态或执行更精确的源码搜索确认；不得只凭图谱空结果认定文件不存在、代码未引用或风险不存在。
6. 修改代码前优先用图谱查询目标文件的 `deps` 和 `impact`；修改代码后如关系可能变化，优先增量更新图谱或说明未更新原因。
7. 代码改动后仍必须运行与改动相关的测试、类型检查、构建或其他验证命令。

## 降级矩阵

| 知识图谱状态 | 处理方式 |
|--------------|----------|
| 知识图谱不存在 | 提示用户是否调用 `ae:graph-build` 构建；任务涉及多文件理解、重构、审查或影响分析时应强烈建议先构建。用户不同意或无法构建时，改为读取真实文件和搜索源码。 |
| schema 不支持、JSON 损坏、manifest 缺失、chunk 缺失、索引缺失或计数不一致 | 不使用部分结果；说明诊断信息，并提示用户是否按 `recoverBy` 调用 `ae:graph-build` 重建或修复。 |
| scope 或范围不匹配 | 查看 `availableScopes`、`nearestScope` 和重建建议；不要把空结果解释为无依赖，并提示用户是否调用 `ae:graph-build` 构建匹配范围。 |
| 知识图谱早于关键文件修改或 Git diff 未覆盖当前任务 | 提示用户是否调用 `ae:graph-build` 增量或全量更新；用户不同意或无法更新时，直接读取真实文件确认。 |
| 关系置信度低、结果被截断或 `chunksRead` 超过预算 | 收窄 scope、目录或文件后继续查询，并读取关键源码确认。 |
| 安全、权限、数据迁移、生产可靠性或外部契约任务 | 知识图谱只能作为定位线索，必须结合源码、配置、测试和运行验证。 |

## 不可替代的场景

- 知识图谱是结构快照，不保证反映最新未构建的工作区状态。
- 知识图谱不替代读取真实文件内容、查看 Git diff、检查未提交变更或确认文件实际存在。
- 知识图谱不替代类型检查、测试、构建、Lint、浏览器验收或运行时验证。
- 知识图谱不提供完整 AST、符号级调用链、业务语义判断或动态运行时依赖保证。
- 知识图谱空结果、过期结果或范围外结果不能证明文件不存在；声明文件不存在前必须用文件系统证据复核。
- 知识图谱查询成功也只能决定阅读优先级和风险方向，不能替代对关键源码、配置、测试和产物的直接检查。
- 当安全、权限、数据迁移、生产可靠性或外部契约风险存在时，必须结合真实代码和验证证据判断。

## 结论表达

- 基于知识图谱得到的结论应说明其来源是知识图谱快照。
- 结论应区分“图谱显示”“源码确认”“验证命令确认”，避免把图谱线索写成已验证事实。
- 若只查询了知识图谱而未读取源码或运行验证，应明确标注仍需进一步确认的部分。
- 当知识图谱结果与真实文件、Git 状态或验证命令冲突时，以最新可观察证据为准。
- 引用知识图谱诊断时保留 `scopeRoot`、`availableScopes`、`recoverBy`、`truncation` 或 `queryCost` 等关键字段，便于后续恢复。
