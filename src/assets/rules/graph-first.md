# 知识图谱优先规则

处理与当前工作区项目有关的任务时，默认先尝试使用项目知识图谱了解结构、依赖关系、影响范围或上下文位置；只有任务明显不需要项目上下文，或知识图谱缺失且无法构建时，才直接降级为读取真实文件、搜索源码或运行验证。只要知识图谱能在定位、筛选、风险判断或确定阅读顺序方面提供价值，就必须优先查询图谱。

## 适用范围

- 当前工作区内需理解项目结构、模块边界、依赖、影响范围、候选文件或风险模式的任务
- 搜索工具可用时也应优先把知识图谱作为定位入口；搜索和读取源码用于确认图谱线索

## 不优先场景

任务与工作区无关、无需项目上下文（纯聊天/通用问答/单文件操作/用户已提供完整上下文）、或用户禁止图谱。

## 推荐顺序

1. 映射为图谱查询：候选文件用 `filter`，单文件上下游用 `deps`，改动波及面用 `impact`，模块风险用 `core`/`stats`/`pattern`/`health`，两点关系用 `path`
2. 查询图谱获取结构上下文；范围过宽时收窄 `scope`/`directory`/`file_type`/`relation_type`
3. 检查 `freshness`；仅 `freshness.status=fresh` 时空结果可作高影响结论证据
4. 图谱缺失/不 fresh/范围不匹配 → 提示用户 `ae:graph-build`；不同意则降级读源码
5. 图谱给候选后，读关键文件/Git 状态/源码搜索确认；不得只凭图谱空结果认定文件不存在
6. 改代码前查 `deps`/`impact`；改后增量更新图谱或说明未更新原因
7. 改动后仍须跑测试/类型检查/构建

## 降级矩阵

| 知识图谱状态 | 处理方式 |
|--------------|----------|
| 不存在 | 提示用户 `ae:graph-build` 构建；不同意则读源码 |
| schema 不支持/JSON 损坏/manifest 缺失/chunk 缺失/索引缺失 | 不使用部分结果；提示按 `recoverBy` 重建 |
| scope 不匹配 | 查看 `availableScopes`/`nearestScope`；不把空结果解释为无依赖 |
| `freshness.status=updating` | 可读旧版本做低风险定位，但须标注构建中；空结果不得作"无影响"结论 |
| `freshness.status=maybe_stale` 或 `stale` | 可用于候选定位；高影响结论须刷新图谱或用真实文件+验证补证 |
| 早于关键文件修改或 diff 未覆盖 | 提示增量/全量更新；不同意则直接读源码 |
| 置信度低/截断/`chunksRead` 超预算 | 收窄 scope/目录/文件后继续查询，并读关键源码确认 |
| 安全/权限/数据迁移/生产可靠性/外部契约 | 图谱仅作定位线索，须结合源码+配置+测试+运行验证（见不可替代场景） |

## 不可替代场景

- 图谱是快照，不保证最新未构建状态；`freshness.status` 不是 `fresh` 时空结果不得作"无影响、无依赖、完整覆盖或无需修改"结论
- 图谱不替代读真实文件、Git diff、未提交变更检查、类型检查、测试、Lint、浏览器验收或运行时验证
- 图谱不提供完整 AST、符号级调用链、业务语义判断或动态运行时依赖保证
- 图谱空结果/过期结果/范围外结果不能证明文件不存在；声明前必须用文件系统证据复核
- 安全/权限/数据迁移/生产可靠性/外部契约风险存在时，必须结合真实代码和验证证据判断

## 结论表达

- 结论须标注来源（图谱显示/源码确认/验证命令确认），避免把图谱线索写成已验证事实
- 图谱结果与真实文件/Git 状态/验证命令冲突时，以最新可观察证据为准
- 引用图谱诊断时保留 `scopeRoot`/`availableScopes`/`recoverBy`/`freshness`/`truncation`/`queryCost` 等关键字段
