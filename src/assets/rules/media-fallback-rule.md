# 媒体识别自动降级规则

**全局硬约束，适用于任何会话、任何角色需要识别图片、音频或视频内容的场景。无例外。**

AE 插件在系统层自动检测当前模型是否支持图片、音频、视频和 PDF 输入。不支持的媒体类型会在消息进入 LLM 前被自动转换为文件路径文本，LLM 看到路径后按需调用 `ae:image`、`ae:audio`、`ae:video` 技能识别内容。

## 系统自动降级机制

1. **模型能力缓存** — 插件在系统层缓存所有模型的媒体输入能力，定期刷新，支持运行时动态修正
2. **用户消息降级** — 用户消息中的媒体文件在保存前被检查，模型不支持时自动转换为路径文本
3. **命令参数降级** — 命令模板中的 `@file` 参数执行同样的降级
4. **工具结果降级** — 工具结果中的媒体附件在不支持时从附件中移除并追加路径到输出文本

### 降级行为

- **模型支持对应媒体类型** → FilePart 保留，模型直接接收原始内容
- **模型不支持对应媒体类型** → FilePart 移除，替换为文件路径文本
- **文本类文件**（text/*、json、xml、yaml 等）→ 始终保留，LLM 可直接读取
- **无 modality 的二进制**（DOCX/XLSX/PPTX/ZIP 等）→ 始终转换为路径

## 媒体识别技能

当媒体文件被降级为路径文本后，LLM 看到的是文件路径。LLM 应根据需要调用以下技能识别内容：

| 技能 | 场景配置键 | 用途 |
|------|-----------|------|
| `ae:image` | `modelScenarios.vision` | 图片识别 |
| `ae:audio` | `modelScenarios.audio` | 音频识别 |
| `ae:video` | `modelScenarios.video` | 视频识别 |

未配置对应场景时，由 opencode 自行分配当前默认模型。建议为每个场景配置支持对应媒体类型输入的多模态模型。

## 兜底约束

系统降级是首选机制，但可能存在覆盖缺口（如 LLM 主动用 Read 工具读取媒体文件、或 sessionID 未缓存时首条消息）。具体降级动作见下方自动调用决策表。

## 自动调用纪律（硬约束）

### 模型支持时优先直接读取

**当模型支持对应媒体类型输入时，应优先使用 Read 工具直接读取媒体文件，不得调用 `ae:image`/`ae:audio`/`ae:video` 技能。** 媒体技能仅在模型不支持该媒体类型或 Read 读取失败时使用，避免不必要的技能调用开销。

### 模型不支持时自动调用技能

**当检测到模型不支持媒体输入、或 Read 工具读取媒体文件报错时，必须立即自动调用对应的 `ae:image`/`ae:audio`/`ae:video` 技能，不得向用户询问是否调用、不得列出可选方案让用户选择、不得停下来等待用户确认。**

以下情况应使用媒体技能识别内容：

| 触发场景 | 文件类型 | 自动调用的技能 |
|---------|---------|---------------|
| 模型不支持该媒体类型且用户要求"识别/转写/分析/提取" | 对应媒体类型 | 对应技能 |
| 系统降级后需理解媒体内容 | 对应媒体类型 | 对应技能 |
| 文档技能生成 PNG 后需理解内容（ae:pdf to-image / ae:officecli view mode=screenshot） | PNG | `ae:image` |
| Read 读取图片报错 / 模型不支持 vision | JPG/PNG/GIF/WebP/BMP | `ae:image` |
| Read 读取音频报错 / 模型不支持 audio | MP3/WAV/OGG/FLAC/M4A/AAC | `ae:audio` |
| Read 读取视频报错 / 模型不支持 video | MP4/WebM/AVI/MOV/MKV/FLV | `ae:video` |

调用技能时使用 `outputMode=inline` 直接获取内容（除非用户明确要求写文件）。禁止重试 Read 工具读取媒体文件。

### 文件路径要求（硬约束）

**调用媒体技能时，`file` 参数必须传入真实、完整、文件系统中物理存在的文件路径，禁止使用文件名或相对片段。**

1. **必须物理存在**：路径指向的文件必须在文件系统中真实存在。即使文件被 `.gitignore` 忽略，只要物理存在就应正常识别
2. **完整路径**：优先使用绝对路径；路径相对时必须从工作区根目录可解析，禁止仅传文件名（如 `"cover.png"`）
3. **禁止以 Git 状态判断存在性**：`git ls-files`、`git status` 的空结果不能证明文件不存在。被 `.gitignore` 忽略的文件不会出现在 Git 输出中，但物理存在
4. **路径来源不确定时先验证**：若路径来自系统降级的路径文本或推断，调用前应通过文件系统工具（如 `glob` 或 `bash` 中的 `Test-Path`/`ls`）确认文件物理存在，再传入技能
5. **报错提示重新定位**：若技能返回"文件不存在"，应通过 `glob` 搜索文件名定位真实路径后重试，不得直接告知用户失败

## 适用范围

本规则覆盖所有需要识别媒体内容的场景，包括但不限于：内置技能、工作流代理、命令、直接工具调用、子代理，以及未来新增的任何需要读取媒体内容的技能/代理/命令/工具。
