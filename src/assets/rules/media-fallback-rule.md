# 媒体识别自动降级规则

**本规则为全局硬约束，适用于任何会话、任何角色需要识别图片、音频或视频内容的场景。无例外。**

AE 插件在系统层自动检测当前模型是否支持图片、音频、视频和 PDF 输入。不支持的媒体类型会在消息进入 LLM 前被自动转换为文件路径文本，LLM 看到路径后按需调用 `ae:image`、`ae:audio`、`ae:video` 技能识别内容。

## 系统自动降级机制

### 工作流程

1. **模型能力缓存** — 插件在系统层缓存所有模型的媒体输入能力，定期刷新，支持运行时动态修正
2. **用户消息降级** — 用户消息中的媒体文件在保存前被检查，模型不支持时自动转换为路径文本
3. **命令参数降级** — 命令模板中的 `@file` 参数执行同样的降级
4. **工具结果降级** — 工具结果中的媒体附件在不支持时从附件中移除并追加路径到输出文本

### 降级行为

- **模型支持对应媒体类型** → FilePart 保留，模型直接接收原始内容
- **模型不支持对应媒体类型** → FilePart 移除，替换为文件路径文本
- **文本类文件**（text/*、json、xml、yaml 等）→ 始终保留，LLM 可直接读取
- **无 modality 的二进制**（DOCX/XLSX/PPTX/ZIP 等）→ 始终转换为路径

## 媒体识别技能

当媒体文件被降级为路径文本后，LLM 看到的是文件路径。LLM 应根据需要调用以下技能识别内容：

| 技能 | 场景配置键 | 用途 |
|------|-----------|------|
| `ae:image` | `modelScenarios.vision` | 图片识别 |
| `ae:audio` | `modelScenarios.audio` | 音频识别 |
| `ae:video` | `modelScenarios.video` | 视频识别 |

未配置对应场景时，由 opencode 自行分配当前默认模型。建议为每个场景配置支持对应媒体类型输入的多模态模型。

## 兜底约束

系统降级是首选机制，但可能存在覆盖缺口（如 LLM 主动用 Read 工具读取媒体文件、或 sessionID 未缓存时首条消息）。当 Read 工具读取媒体文件报错"model does not support ... input"时，不得重试 Read，必须改用对应媒体技能。

## 触发条件

以下情况应使用媒体技能识别内容：

- 用户明确要求"识别/转写/分析/提取"媒体文件内容时
- 系统降级后 LLM 需要理解媒体文件内容才能完成任务时
- 文档技能（ae:pptx、ae:docx、ae:pdf、ae:xlsx）的 to-image 操作生成 PNG 后，需要理解图片内容时
- Read 工具读取媒体文件报错时

## 适用范围

本规则覆盖所有需要识别媒体内容的场景，包括但不限于：内置技能、工作流代理、命令、直接工具调用、子代理，以及未来新增的任何需要读取媒体内容的技能/代理/命令/工具。
