# AI 执行护栏

本规则用于限制 AI 常见缺陷：目标漂移、未验证断言、跳过步骤、漏跑验证、越权 Git 操作和无证据交付。

## 证据优先

- 声称前必须先读取、搜索或运行工具验证；未验证内容必须明确标注为假设。
- 不得把计划、测试、构建或审查的预期结果描述为已完成事实。
- 只有可观察的工作区状态、工具输出或可引用执行结果可以支撑“已验证”；用户声明或工具参数自报只能算声明证据。
- 正式代码交付的最终回复必须区分：已完成、已验证、未验证/无法验证、Git 操作状态、门禁结果、剩余风险。

## 阶段门禁

- 需求不清时不得直接编码，先澄清或进入 `ae:brainstorm`。
- 多步骤实现不得跳过计划；已有计划时必须先读取计划再改代码。
- 编码后必须运行与改动相关的验证命令；无法运行时必须说明原因和风险。
- `/ae-lfg` 和 `ae:work` 结束前必须调用 `ae-gate` 生成门禁证明。
- 问答和只读审查不强制走完整交付证明，但仍必须标注来源、假设和残余风险。

## Git 权限

- 未经用户明确请求，不得提交、推送、变基、amend、reset、checkout 覆盖文件或跳过 hooks。
- 即使用户授权提交，也不得把未验证代码提交到默认分支。
- 发现工作区存在非本次任务修改时，不得还原或覆盖；只处理当前任务相关文件。
- 用户泛化地说“顺便提交”不构成 push、PR、skip hooks 或改 Git 配置的授权；这些动作都需要单独明确授权。

## 交付证明

- 代码或功能交付必须提供：变更摘要、验证命令与结果、审查状态、Git 操作状态、门禁结果和剩余风险。
- 如果没有代码变更，必须说明为什么没有变更，并不得宣称实现完成。
- 如果门禁阻断，必须先修复阻断项；不能用文字承诺代替验证。
- 完整最终模板以 `ae:work` 的交付参考为准；本规则只保留可检查护栏，不重复维护整份模板。
