# 副作用资源复用规则

**本规则为全局硬约束，适用于任何会话、任何角色需要执行会产生持久副作用的操作的场景。无例外。**

执行任何会产生持久副作用的操作前，必须先检查是否已存在同类副作用资源（已启动的服务、已打开的浏览器、已打开的标签页等）。已存在且仍可用时优先复用，禁止重复创建，除非先移除之前产生的副作用。

## 核心规则

1. **副作用资源优先复用** — 执行会产生持久副作用的操作前，必须先检查是否已有同类副作用资源仍在运行或打开；已存在且仍可用时直接复用，不得重复创建
2. **未检查前禁止重复执行** — 未完成前置检查前，禁止重复启动同一服务、重复打开浏览器、重复新开同一 URL 对应的标签页，或重复执行任何不支持幂等性的操作
3. **重复执行须先清理旧副作用** — 确需重新执行时，必须先移除之前产生的副作用（关闭进程、关闭浏览器、关闭标签页、释放端口等），再重新创建
4. **仅可清理本会话产生的副作用** — 不得以此规则为名终止用户的其他进程或资源；终止操作须在回复中说明被终止的资源与原因
5. **副作用资源失效后可重建** — 旧副作用资源已退出、已关闭或已释放时，可正常重新创建

## 适用范围

本规则适用于一切**不支持幂等性执行**的操作，包括但不限于：

1. **服务启动** — web 服务器、watch 进程、长连接服务、构建服务器、静态文件服务器等
2. **浏览器实例** — chrome-devtools-mcp 启动的浏览器、独立无头浏览器等
3. **浏览器标签页** — 同一 URL 对应的标签页
4. **其他持久副作用** — 占用端口、占用进程、留下持续运行状态的任何操作

> 上述列举仅为示例，凡是"重复执行会产生多个并存实例、占用资源或导致状态冲突"的操作均适用本规则。

## 复用规则

### 1. 服务类操作复用

- 启动前检查：是否已有同一服务在运行（相同命令、相同端口、相同可执行程序+路径）
- 已在运行 → 复用旧实例，引用旧 PID 和日志路径，不再重新启动
- 旧实例异常或需新配置 → 先终止旧实例，再启动新实例
- 检查方式：按 PID 验证进程存活（Windows: `tasklist /FI "PID eq <pid>"`；Unix: `ps -p <pid>`），或读取日志路径确认服务仍就绪

### 2. 浏览器实例复用

- 打开浏览器前检查：是否已有由本会话（或本工具）启动的浏览器实例在运行
- 已在运行 → 复用旧实例，不再启动新浏览器
- 需要新上下文或新配置 → 先关闭旧浏览器，再启动新浏览器
- 检查方式：通过 chrome-devtools-mcp 的 `list_pages` 等只读工具确认浏览器与页面状态

### 3. 标签页复用

- 打开 URL 前检查：是否已有同一 URL 对应的标签页打开
- 已打开 → 复用现有标签页（可刷新或直接使用），不再新开标签页
- 需要干净上下文（如 cookie、缓存） → 先关闭旧标签页，再打开
- 检查方式：通过 chrome-devtools-mcp 的 `list_pages` 列出现有页面与 URL

### 4. 通用幂等性原则

- 任何不支持幂等性执行的操作，禁止在未检查已有副作用的情况下重复执行
- 重复执行前必须先移除之前产生的副作用（关闭进程、关闭浏览器、关闭标签页、释放端口等）
- 仅可移除由本工具或本会话产生的副作用，不得以此规则为名终止用户的其他进程或资源

## 检查方式

| 副作用资源类型 | 检查方式 |
|--------------|----------|
| 进程类 | 按 PID 验证存活（Windows: `tasklist /FI "PID eq <pid>"`；Unix: `ps -p <pid>`） |
| 端口类 | 检查端口占用情况 |
| 浏览器/标签页类 | 通过 chrome-devtools-mcp 的 `list_pages` 等只读工具检查现有页面与 URL |
| 其他 | 通过日志、状态接口或只读探查确认副作用资源是否仍可用 |

## 禁止行为

- ❌ 禁止在未检查的情况下重复启动同一服务
- ❌ 禁止在未检查的情况下重复打开浏览器
- ❌ 禁止在未检查的情况下为新开同一 URL 对应的标签页
- ❌ 禁止以"保险起见"为由重复执行不支持幂等性的操作
- ❌ 禁止以"只试一次"为由跳过前置检查
- ❌ 禁止以"只看一眼输出"为由绕过复用检查

## 复用失败的处理

- 副作用资源**已失效**（进程已退出、浏览器已关闭、标签页已关闭）→ 可正常重新创建
- 副作用资源**仍可用但状态异常** → 先清理旧资源，再重新创建
- **无法确认副作用资源状态** → 向用户报告，由用户决定

## 与现有规则的关系

- `ai-core-guidelines.md` 第 4.2 节"重复启动同一服务的前置检查"是本规则在 `ae-async-bash` 服务启动场景的具体实现；本规则是 4.2 节的泛化扩展，将同一原则推广到浏览器实例、标签页及所有不支持幂等性的副作用资源
- 本规则与 `setup-gate-rule.md`（chrome-devtools MCP 动态注册门禁）配合使用：`setup-gate-rule.md` 负责浏览器 MCP 的注册确认，本规则负责已有浏览器实例与标签页的复用检查
