# G3 步骤摘要

## 目标

用具体测试数据代入 G2 数据模型和状态机，走通核心业务流程，验证模型在真实数据下能自洽运行。

G3 是最重要的"早验证"环节——在进入关联和局部阶段之前，先用数据走一遍，尽早发现模型问题。

## 任务清单

| 任务 | 说明 |
|------|------|
| T1 识别核心场景 | 主流程、关键分支、关键异常三类；场景数参考：主流程×2 + 分支×1 + 异常×1 |
| T2 构造测试数据 | 三段式：given（初始状态）→ when（触发操作+参数）→ then（预期结果+不变量检查） |
| T3 逐场景推演 | 代入数据检查：状态迁移是否符合状态机、字段更新是否符合约束、不变量是否全部守卫通过 |
| T4 计算推演覆盖率 | 每条不变量至少1个场景覆盖、每条状态迁移至少1个场景触发、输出未覆盖清单 |

## 验收关卡

| 编号 | 检查项 | 通过标准 |
|------|--------|---------|
| G3-K1 | 推演全通过 | 所有场景结果为 pass |
| G3-K2 | 不变量覆盖 100% | 每条不变量至少 1 个场景覆盖 |
| G3-K3 | 状态迁移覆盖 100% | 每条合法迁移至少 1 个场景触发 |
| G3-K4 | 失败可定位 | 失败场景已定位到具体 G2 产物的问题条目 |
| G3-K5 | 指纹一致 | upstream_fingerprints 与 G1、G2 产物一致 |
| G3-K6 | 文件行数合规 | 所有产物文件不超过 500 行 |

## 回退规则

- 规则/约束定义错误 → 回 G2 修改受影响子文件
- 不变量本身有问题 → 回 G1 修改受影响子文件
- 场景构造有误（不是模型问题） → 仅重做 G3 受影响子文件

## 通用产物规格

- 单轨格式：YAML Frontmatter 为唯一真源，正文为人类阐释
- 文件行数硬约束：每个产物文件不超过 500 行
