# A2 步骤摘要

## 目标

用具体数据走通跨模块数据流，验证 A1 契约在实际数据流转下能自洽运行。

A2 是 G3 的跨模块升级——G3 验证单模块内数据推演，A2 验证跨模块数据推演。

## 任务清单

| 任务 | 说明 |
|------|------|
| T1 扩展跨模块推演场景 | 从 G3 场景扩展，加入跨模块交互维度 |
| T2 构造端到端测试数据 | 起点模块初始状态、每步传递数据、每个模块状态变更、终点模块断言 |
| T3 逐场景跨模块推演 | 沿 data-flow 路径检查：source 输出符合契约、target 接受后状态正确、共享状态一致性成立 |
| T4 验证冲突和异常场景 | 冲突场景（两端同时写）、超时场景（降级方案）、离线场景（同步策略） |
| T5 计算契约覆盖率 | 每条契约至少1个场景、每个冲突规则至少1个场景、输出未覆盖清单 |

## 验收关卡

| 编号 | 检查项 | 通过标准 |
|------|--------|---------|
| A2-K1 | 推演全通过 | 所有跨模块推演场景 pass |
| A2-K2 | 契约覆盖 100% | 每条契约至少 1 个场景 |
| A2-K3 | 冲突规则覆盖 100% | 每个冲突解决规则至少 1 个场景触发 |
| A2-K4 | 失败可定位 | 失败场景已定位到具体契约或数据模型问题 |
| A2-K5 | 指纹一致 | upstream_fingerprints 与 G1-G3、A1 产物一致 |
| A2-K6 | 文件行数合规 | 所有产物文件不超过 500 行 |

## 回退规则

- 契约设计不匹配 → 回 A1 修改受影响子文件
- 数据模型不支持 → 回 G2 修改受影响子文件
- 推演逻辑问题 → 仅重做 A2 受影响子文件

## 通用产物规格

- 单轨格式：YAML Frontmatter 为唯一真源，正文为人类阐释
- 文件行数硬约束：每个产物文件不超过 500 行
