# A2 关联数据推演

## 角色

跨模块数据推演验证者。沿上游契约和数据流路径，用具体数据走通跨模块场景，确保契约自洽、状态同步正确、冲突解决有效。

## 适用场景

- G3 单模块数据推演已通过，需验证跨模块交互
- 已有 A1 契约和数据流定义，需确认跨模块数据可达
- 需要验证并发、一致性、超时等跨模块冲突场景
- 上游产物（G1/G2/G3/A1）齐全且稳定

## 不适用场景

- 前序技能（G1/G2/G3/A1）产物未就绪时不得执行
- 仅需单模块内验证（使用 G3）
- 尚无契约定义（应先完成 A1）

## 产物根目录

所有产物写入**产物根目录**下。默认根目录为 `docs/ae/galv/<项目名>/`。

`<项目名>` 由以下规则确定：
1. 若产物根目录下已存在 `galv-manifest.yaml`，读取其中的 `project_name` 字段作为项目名
2. 若不存在，提示用户先执行上游技能创建 manifest，或由用户手动提供项目名后由本技能创建
3. 后续所有技能必须读取 `galv-manifest.yaml` 获取项目名，禁止自行推断

整个根目录自包含、可移植：内部所有路径均为相对路径，目录可整体移动到任意位置。读取全部阶段产物后，任何 AI 工具可据此生成功能等价、结构等价的软件系统。

本阶段的产物位于根目录下 `a2/` 子目录。

## 上游依赖（只读）

紧邻前序技能：**A1（ae:a1-contracts）**。本技能的直接前序为 A1，A1 的前序为 G3，G3 的前序为 G2，G2 的前序为 G1。执行顺序：G1→G2→G3→A1→**A2**。

| 前序技能 | 产物 | 用途 |
|---------|------|------|
| G1 | `g1/invariants/`、`g1/boundary.md`、`g1/ambiguities.md` | 不变量定义 |

## 执行流程

### T1 扩展推演场景为跨模块场景

从 G3 场景扩展，加入跨模块交互维度：

- 数据传递符合契约定义
- 跨模块状态同步正确
- 交互延迟在约束范围内

每个跨模块场景必须标注：

- 涉及的源模块与目标模块
- 经过的契约条目
- 数据流路径（引用 data-flow/ 中的路径 ID）

### T2 逐场景跨模块推演

沿 `a1/data-flow/` 路径逐一走通：

1. **source 输出验证**：源模块输出数据是否符合契约定义
2. **target 接受验证**：目标模块接受数据后状态是否正确迁移
3. **共享状态一致性**：跨模块共享状态是否满足一致性约束

推演过程必须使用具体数据值，不得用抽象描述替代。

### T3 验证冲突场景

基于 `a1/shared-state.md` 和 `g1/invariants/` 中的冲突规则，构造并推演：

- **并发写入**：多模块同时写入共享状态，验证冲突解决规则生效
- **数据不一致**：部分写入失败后的状态恢复
- **超时重试**：跨模块调用超时后的重试与幂等性

每个冲突场景必须引用具体的冲突解决规则 ID。

### T4 计算关联覆盖率

统计并验证：

- 每条契约至少 1 个场景覆盖
- 每个冲突解决规则至少 1 个场景触发
- 每条跨模块不变量至少 1 个场景守卫

输出 `a2/assoc-coverage.md` 覆盖率报告。

## 产物格式

### a2/assoc-trace/ 或 a2/assoc-trace.md

场景数 ≤ 3 时使用单文件，场景数 > 3 时使用目录按场景分文件。目录形式时，`index.md` Frontmatter 必须包含 `type: directory_index` 和 `slices` 字段。

每个推演场景格式：

```yaml
scenario:
  id: SCT-<编号>
  name: <场景名称>
  modules: [<源模块>, <目标模块>]
  contract_refs: [<契约条目ID列表>]
  data_flow_path: <a1/data-flow/中的路径ID>
  trace_steps:
    - step: <步骤描述>
      module: <模块名>
      input: <具体输入数据>
      output: <具体输出数据>
      state_before: <执行前状态>
      state_after: <执行后状态>
      pass: true | false
  conflict_rule_refs: [<冲突规则ID列表>]
  invariant_refs: [<不变量ID列表>]
  result: pass | fail
  failure_detail: <失败时定位到具体契约条目>
```

YAML 块为唯一真源，其后可附加人类阐释段落。

### a2/assoc-coverage.md

```yaml
coverage:
  contracts:
    total: <契约总数>
    covered: <已覆盖数>
    items:
      - id: <契约ID>
        scenarios: [SCT-<编号>]
  conflict_rules:
    total: <冲突规则总数>
    covered: <已覆盖数>
  cross_module_invariants:
    total: <跨模块不变量总数>
    covered: <已覆盖数>
  summary:
    contract_coverage: <百分比>%
    conflict_coverage: <百分比>%
    invariant_coverage: <百分比>%
```

## 单轨格式规则

所有产物文件采用 Markdown + YAML Frontmatter 单轨格式：

- Frontmatter 为机器可读的唯一真源，正文为人类阐释
- 正文不允许出现 Frontmatter 中不存在的实体名、字段名、规则名
- 正文只允许包含：Frontmatter 字段的业务含义解释、设计决策的理由、用户确认记录
- 如需补充信息，必须先在 Frontmatter 中添加对应条目，再在正文中解释
- 每条 Frontmatter 条目可标注 `origin` 字段：`derived`（从上游推导，可信度最高）、`inferred`（AI 推断补充，需人工确认）、`asserted`（人类断言，最可靠）

## 验收关卡

| 编号 | 检查项 | 通过标准 |
|------|--------|---------|
| A2-K1 | 推演全通过 | 所有跨模块推演场景 pass |
| A2-K2 | 契约覆盖 100% | 每条契约至少 1 个场景覆盖 |
| A2-K3 | 冲突规则覆盖 100% | 每个冲突解决规则至少 1 个场景触发 |
| A2-K4 | 不变量关联覆盖 | 每条跨模块不变量至少 1 个场景守卫 |
| A2-K5 | 失败可定位 | 失败可定位到具体契约条目 |
| A2-K6 | 文件行数合规 | 所有产物文件不超过 500 行 |
| A2-K7 | 人工审核通过 | 用户确认跨模块推演场景合理、覆盖率达标、冲突解决验证有效 |

## 单模块系统简化规则

当系统仅包含单个模块时：

- A2 仍需执行，但产物可以为空
- 任务是"确认无跨模块数据流"
- 输出 `a2/assoc-coverage.md` 中标注 `single_module: true`，其余产物文件可不创建

## 回退说明

| 失败原因 | 回退目标 |
|---------|---------|
| 契约定义问题 | 回 A1 |
| 数据模型不支持 | 回 G2 |
| 推演逻辑问题 | 仅重做 A2 |

## 安全边界

- 不得修改上游产物；发现上游问题时报告并回退，不自行修正
- 推演失败必须保留失败记录和定位信息，不得静默跳过
- 覆盖率未达 100% 不得标记为通过
- 产物文件超过 500 行时必须拆分或精简
- 本技能禁止读取或引用执行顺序在本技能之后的任何技能产物（L1/L2/L3/V1/V2），以保证回退时后续产物不可见

## 完成标准

所有验收关卡 A2-K1 至 A2-K7 均通过，且覆盖率报告已写入 `a2/assoc-coverage.md`。A2-K7 须由用户确认后方可视为本步骤完成。
