# 考试类课程策略

## 阶段一：获取全部题目

1. 按照点击操作降级策略，在课程列表页面点击该考试课程进入考试详情。
2. 等待考试页面加载完成，调用 `chrome-devtools_take_snapshot` 获取页面结构。
3. 检查页面是否包含题目元素（选择题选项、填空输入框等）：
   - 如果页面不包含题目而是显示考试说明/确认页，按照点击操作降级策略查找并点击"开始考试"或"确认开始"按钮，等待题目加载后再继续。如果确认按钮需要勾选协议，先勾选再点击确认。
4. 向下滚动逐一读取所有题目，确保获取完整题库：
   - 记录每道题的题号、题干、选项（选择题/判断题）或填写要求（填空题）。
   - 如果页面有分页或"下一页"按钮，继续翻页读取所有题目。
   - 将所有题目整理为结构化列表：`[{index, type, question, options?}]`。
5. 确认题目全部读取后，进入阶段二。

## 阶段二：作答策略

根据是否存在历史批改记录（不局限于本会话，包括从考试网站获取的所有历史记录），采用不同作答策略：

**首次考试（无历史批改记录）：**

不调用子代理，由 LLM 自身直接逐题推理作答。每道题给出答案和简要推理，输出格式为：`[{index, answer, reasoning}]`。

**有历史批改记录时（无论是否本会话产生）：**

1. 获取本次考试的全部题目（已在阶段一完成）。
2. 将本次题目与历史批改记录中的题目进行比对：
   - 题干完全一致 → 同一题。
   - 题干相似度 > 80% → 可能是同一题（格式变化），标记为低置信。
   - 无法匹配 → 新题。
3. 对每道题根据历史记录采取不同策略：

    | 题目分类 | 策略 | 说明 |
    |----------|------|------|
    | 在任意一次历史记录中答对的题目 | 采纳该正确答案 | 同一题只要在某次历史记录中答对，直接沿用该正确答案，无需再推理 |
    | 历史批改中有 correctAnswer 的错题 | 直接填入 correctAnswer | 不再推理分析 |
    | 多次历史记录中均错误且无 correctAnswer 的题目 | 排除法 | 收集该题在所有历史记录中选择过的错误答案，构建排除集合，从剩余选项中深入思考选择最合适的答案 |
    | 新出现的题目 | 独立推理作答 | 同首次考试，由 LLM 直接推理 |
    | 题干相似但不完全一致的题目 | 参照历史答案 + 低置信标注 | 参考历史对应题目的答案，标注为低置信 |

4. **排除法细则**（针对多次历史记录中均错误且无正确答案的选择题）：
    - 遍历该题在所有历史批改记录中的作答情况，收集所有选择过的错误答案，构建排除集合。
    - 同一题如果在某次记录中答对，则**不属于排除法范畴**，应直接采纳该正确答案（见上表第一行）。
    - 从当前选项中移除排除集合中的选项。
    - 对剩余选项深入思考，选择最合理的答案。
    - 如果排除后仅剩一个选项，直接选择该选项。
    - 如果排除后无剩余选项（所有选项都曾在不同历史记录中被选错），回退为独立推理作答，标注为低置信。
5. 生成最终答案表：`[{index, answer, confidence, source?}]`，其中 `source` 标注答案来源（历史正确答案 / correctAnswer / 排除法 / 独立推理 / 新题推理）。

## 阶段三：填写答案并提交

1. 根据最终答案表，逐一在页面上选择/填写答案：
   - 高置信题目：直接填入。
   - 低置信题目：填入推理后/排除法后的答案，在汇报中标注为"不确定"。
2. 答完所有题目后，找到并点击提交按钮。
3. 等待提交结果页面加载，调用 `chrome-devtools_take_snapshot` 获取结果。

## 阶段四：考试完成状态检查

1. 从结果页面获取考试信息和课程完成状态：
   - 提取考试成绩、是否通过、是否已完成。
   - 如果页面显示课程已完成（通过/达标），记录成绩，关闭标签页，返回课程列表页面，跳过阶段五和阶段六。
   - 如果课程未完成（未通过/未达标），检查是否可以继续重考：
     - 检查本会话考试次数：本会话已考 ≥ 3 次，在汇报中标注"已达到本会话最大考试次数 3 次，跳过该考试"，关闭标签页，返回课程列表页面，继续下一个课程。
     - 检查考试本身是否有次数限制：如果页面提示"考试次数已用完"、"已达最大考试次数"、"不可重考"等类似信息，说明该考试网站限制了重考次数且已耗尽，在汇报中标注"考试网站限制无法重考，跳过该考试"，关闭标签页，返回课程列表页面，继续下一个课程。
     - 以上两项均未触发（本会话已考 < 3 次且网站允许重考）：记录成绩和未完成原因，进入阶段五。

## 阶段五：采集历史批改记录

1. 尝试在当前结果页面获取批改详情：
   - 查找"查看解析"、"查看错题"、"答题详情"等链接或按钮并点击。
   - 在批改/解析页面，调用 `chrome-devtools_take_snapshot` 获取结构。
   - 提取每道题的批改信息：
     - 正确题目：记录题号和提交的答案（作为历史正确答案）。
     - 错误题目：记录题号、提交的答案（错误答案）、正确答案（如有）。
   - 将批改记录整理为列表：`[{index, myAnswer, isCorrect, correctAnswer?}]`。
   - 将本次批改记录追加到历史批改记录中（按考试课程分组保存）。
2. **获取所有历史考试记录**（核心步骤，排除法的正确性依赖于完整的历史数据）：
    - 返回课程列表页面，重新进入该考试课程。
    - 查找"历史成绩"、"考试记录"、"答题记录"等入口。
    - 如果存在历史考试记录，**逐一查看每一次历史考试的批改详情**，不遗漏任何一次记录：
      - 对每道题提取批改信息：题号、提交的答案、是否正确、正确答案（如有）。
      - 同一题目在多次历史记录中的合并规则：
        - **只要在某次记录中答对，即采纳该正确答案**，后续作答时直接沿用，不再进入排除法。
        - **多次记录中均错误的题目，收集所有选择过的错误答案取并集**，构建排除集合；排除集合越大，剩余候选越少，正确率越高。
      - 将合并后的批改记录追加到历史批改记录中（按考试课程分组保存）。
    - 如果无法进入历史考试记录页面（无入口、权限不足等），仅使用本次批改记录，在汇报中标注"未能获取全部历史记录，排除法可能不完整"。
3. 如果以上方式均无法获取任何批改信息，**必须告知用户**：
   - 输出提示：`"考试 <课程名> 未通过（得分：<分数>），但无法获取批改详情。请手动查看考试记录后决定是否重新考试。"`
   - 关闭标签页，返回课程列表页面，跳过阶段六。

## 阶段六：重新考试（历史记录驱动作答）

1. 递增本会话考试计数（初始为 1，每次进入阶段六时 +1）。
2. 重新进入考试页面，等待加载完成。
3. 检查页面是否允许重新考试：
   - 如果页面提示"考试次数已用完"、"已达最大考试次数"、"不可重考"等类似信息，说明该考试网站限制了重考次数且已耗尽，在汇报中标注"考试网站限制无法重考，跳过该考试"，关闭标签页，返回课程列表页面，继续下一个课程。
4. 获取所有题目（同阶段一流程），进入阶段二的重考策略（利用历史批改记录驱动作答）。
5. 填写完毕后提交考试。
6. 等待结果，再次进入阶段四检查完成状态。

## 考试流程总结

```
[阶段一] 获取全部题目
      ↓
[阶段二] 作答策略
      ├─ 无历史批改记录 → LLM直接推理作答
      └─ 有历史批改记录（不局限于本会话）
           ├─ 任意一次记录答对 → 直接采纳该正确答案
           ├─ 有correctAnswer → 直接填入
           ├─ 多次记录均错误 → 排除法（收集所有错误答案取并集→从剩余选择）
           └─ 新题 → LLM直接推理作答
      ↓
[阶段三] 填写答案并提交
      ↓
[阶段四] 检查完成状态 → 已完成 → 结束
      ↓ 未完成
      ├─ 本会话已考≥3次 → 跳过该考试，进入下一节课
      ├─ 考试网站限制无法重考 → 跳过该考试，进入下一节课
      └─ 可重考
           ↓
[阶段五] 采集历史批改记录 → 无法获取 → 告知用户，结束
      ↓ 获取成功
[阶段六] 重新考试
      ├─ 考试网站限制无法重考 → 跳过该考试，进入下一节课
      └─ 可重考 → 历史记录驱动作答 → 提交
           ↓ sessionAttemptCount++
           └──→ [阶段四] 检查完成状态
```
