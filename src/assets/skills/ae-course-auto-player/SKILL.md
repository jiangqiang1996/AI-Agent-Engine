# ae:course-auto-player

> **chrome-devtools MCP 门禁**：执行任何 `chrome-devtools_*` 工具前，必须先通过 `ae:chrome-devtools` 完成 MCP 动态注册；MCP 注册不能替代门禁检查，未注册或未连接就绪时不得执行任何 chrome-devtools 工具，连接失败时记录"无法验证"并停止。

## 角色

在线课程自动完成器，自动完成在线课程平台的所有课程：连接浏览器、打开课程列表页面、按顺序遍历每节课，根据课程类型自动执行对应操作（文档阅读、视频播放、外链访问、考试智能答题），直至所有课程完成。

## 适用场景

- 用户提供一个课程列表页面 URL，希望自动完成所有课程
- 课程列表包含文档、考试、视频、外链等类型，需要自动化逐个处理
- 用户说"帮我刷课"、"自动完成课程"、"播放课程列表"等

## 不适用场景

- 用户只想打开单个页面浏览，不需要自动化遍历
- 课程平台需要人机验证（如滑块验证码）且无法自动通过
- 用户未提供课程列表页面 URL

## 核心设计原则

- **ae-timer + nextStep 防上下文丢失**：所有 `ae-timer` 调用必须传入 `nextStep` 参数，描述等待结束后应执行的操作。工具返回时原样携带，确保长时间等待后 LLM 无需回溯上下文即可继续。
- **视频 5 分钟分片轮询**：视频播放不使用一次长等待，而是每 5 分钟调用一次 `ae-timer`，返回后检查播放状态，再决定继续等待或关闭。这样即使视频被暂停、弹窗阻断或播放异常，也能及时发现并处理。
- **最小化 LLM 交互**：每种课程类型在等待期间 LLM 挂起不消耗 token，只在状态检查和决策点才恢复推理。

## 检查视频状态的脚本

视频状态检查统一使用以下脚本，通过 `chrome-devtools_evaluate_script` 执行：

```
(function(){const v=document.querySelector('video');return v?{paused:v.paused,duration:v.duration,currentTime:v.currentTime,ended:v.ended,playbackRate:v.playbackRate}:{error:'no video element'}})()
```

返回字段含义：
- `paused`：是否暂停
- `duration`：总时长（秒），可能为 NaN
- `currentTime`：当前播放进度（秒）
- `ended`：是否播放结束
- `playbackRate`：当前倍速
- `error`：页面上未找到 video 元素

## 输入处理

用户通过命令传入 URL 参数，格式为：

```
/ae-course-auto-player <课程列表页面URL>
```

- URL 为必填参数，必须是可访问的课程列表页面地址
- 如果用户未提供 URL，必须先询问，不得自行假设

## 工作流程

### 前置：浏览器连接

1. 调用 `ae-chrome-devtools-mcp action=check` 检查 MCP 是否已注册并连接。
2. 如果未连接，调用 `ae:chrome-devtools` 或 `ae-chrome-devtools-mcp action=register mode=autoConnect` 自动发现并连接已运行的浏览器；如果 autoConnect 失败，改用 `mode=isolated` 启动独立浏览器实例。
3. 连接成功后，调用 `chrome-devtools_list_pages` 确认连接可用。

### 第一步：打开课程列表页面

1. 调用 `chrome-devtools_list_pages` 列出当前标签页。
2. 检查是否已有标签页打开了目标 URL（精确匹配或相同路径匹配）。
   - 如果已存在，选择该标签页并刷新。
   - 如果不存在，调用 `chrome-devtools_new_page` 打开目标 URL。
3. 等待页面加载完成，调用 `chrome-devtools_take_snapshot` 获取页面结构。
4. 从页面快照中识别课程列表，提取每节课的名称、类型和链接。

### 第二步：遍历课程列表

按顺序遍历每节课，根据类型执行对应操作：

#### 文档类课程

1. 在课程列表页面点击该节课的链接，或打开其 URL。
2. 等待文档页面加载完成。
3. 调用 `ae-timer duration=5 label="等待文档阅读" nextStep="文档阅读等待结束，请关闭当前文档标签页，返回课程列表页面，继续处理下一节课"`。
4. ae-timer 返回后，按 nextStep 指示关闭文档标签页，返回课程列表页面。

#### 考试类课程

##### 阶段一：获取全部题目

1. 在课程列表页面点击该节课的链接，或打开其 URL。
2. 等待考试页面加载完成，调用 `chrome-devtools_take_snapshot` 获取页面结构。
3. 检查页面是否包含题目元素（选择题选项、填空输入框等）：
   - 如果页面不包含题目而是显示考试说明/确认页，查找并点击"开始考试"或"确认开始"按钮，等待题目加载后再继续。如果确认按钮需要勾选协议，先勾选再点击确认。
4. 向下滚动逐一读取所有题目，确保获取完整题库：
   - 记录每道题的题号、题干、选项（选择题/判断题）或填写要求（填空题）。
   - 如果页面有分页或"下一页"按钮，继续翻页读取所有题目。
   - 将所有题目整理为结构化列表：`[{index, type, question, options?}]`。
5. 确认题目全部读取后，进入阶段二。

##### 阶段二：多代理深度分析答案

对获取到的所有题目，使用多个子代理并行分析，通过交叉验证提升正确率：

1. **分发分析任务**：调用 3 个 `general` 类型子代理（通过 `task` 工具），每个代理独立分析全部题目：
   - 每个 agent 的 prompt 必须包含完整的题目列表（题号、题干、选项）。
   - 每个 agent 必须逐题给出答案和推理过程，输出格式为：`[{index, answer, reasoning}]`。
   - agent prompt 示例：
     ```
      你是考试答题专家，请独立分析以下题目并给出答案。要求：
      1. 逐题分析，给出答案和详细推理过程
      2. 仅基于题目内容和自身知识推理，不要搜索外部资料
      3. 选择题给出选项字母，判断题给出对/错，填空题给出答案文本
      4. 每道题目均标注置信等级（高/中/低），不确定的题目标注为低置信
      5. 输出 JSON 格式：[{"index": 题号, "answer": 答案, "reasoning": 推理, "confidence": "高|中|低"}]
     
     题目列表：
     <完整题目列表>
     ```
2. **交叉验证与共识决策**：3 个代理返回结果后，逐题比对：
   - **三票一致**：直接采用该答案，标记为"高置信"。
   - **两票一致**：采用多数答案，标记为"中置信"，记录少数派答案作为备选。
   - **三票各异**：标记为"低置信"，记录所有候选答案，暂不采用任何代理答案，进入搜索验证环节。
3. **低置信题目搜索验证**：对三票各异的低置信题目，使用搜索工具辅助决策：
   - 调用 1 个 `web-researcher` 子代理（通过 `task` 工具），对每道低置信题目执行搜索验证。
   - 搜索验证 prompt 示例：
     ```
     你是答案验证专家。以下题目经 3 个代理分析后答案不一致，请通过搜索验证最可能的正确答案。
     
     题目：<题干>
     候选答案：<代理1答案>、<代理2答案>、<代理3答案>
     
     要求：
     1. 搜索题目中的关键知识点，验证每个候选答案的合理性
     2. 给出最可能的正确答案和验证依据
     3. 输出 JSON：{"answer": 最可能答案, "evidence": 验证依据, "confidence": "高|中|低"}
     ```
   - 如果搜索验证返回的答案与某个候选答案一致，采用该答案并标记为"中置信（搜索验证）"。
   - 如果搜索验证返回全新答案，采用该答案并标记为"低置信（搜索推荐）"。
   - 如果搜索验证失败或超时，回退采用第一个代理的答案，标记为"低置信（无搜索验证）"。
4. **生成最终答案表**：汇总为 `[{index, answer, confidence, alternatives?, verifiedBySearch?}]`。

##### 阶段三：填写答案并提交

1. 根据最终答案表，逐一在页面上选择/填写答案：
   - 高置信题目：直接填入。
   - 中置信题目：填入多数答案。
   - 低置信题目：填入搜索验证后的答案（或回退的第一个代理答案），在汇报中标注为"不确定"。
2. 答完所有题目后，找到并点击提交按钮。
3. 等待提交结果页面加载，调用 `chrome-devtools_take_snapshot` 获取结果。

##### 阶段四：考试完成状态检查

1. 从结果页面获取考试信息和课程完成状态：
   - 提取考试成绩、是否通过、是否已完成。
   - 如果页面显示课程已完成（通过/达标），记录成绩，关闭标签页，返回课程列表页面，跳过阶段五和阶段六。
   - 如果课程未完成（未通过/未达标），检查重考次数：
     - 已重考 < 2 次：记录成绩和未完成原因，进入阶段五。
     - 已重考 ≥ 2 次：在汇报中标注并跳过该课程，继续下一节课。

##### 阶段五：获取错题信息

1. 尝试在当前结果页面获取错题详情：
   - 查找"查看解析"、"查看错题"、"答题详情"等链接或按钮并点击。
   - 在错题/解析页面，调用 `chrome-devtools_take_snapshot` 获取结构。
   - 提取每道错题的题号、原答案（我方提交的答案）、正确答案。
   - 将错题整理为列表：`[{index, myAnswer, correctAnswer}]`。
2. 如果无法在当前页面获取错题详情：
   - 返回课程列表页面，重新进入该考试课程。
   - 检查是否有"历史成绩"、"考试记录"等入口，尝试从记录中获取错题。
3. 如果以上方式均无法获取错题信息，**必须告知用户**：
   - 输出提示：`"考试 <课程名> 未通过（得分：<分数>），但无法获取错题详情。请手动查看考试记录后决定是否重新考试。" `
   - 关闭标签页，返回课程列表页面，跳过阶段六。

##### 阶段六：重新考试（错题修正）

1. 递增重考计数（初始为 0，每次进入阶段六时 +1）。
2. 重新进入考试页面，等待加载完成。
3. 获取所有题目（同阶段一流程），按题干文本与上次考试题目进行比对：
   - 题干完全一致 → 同一题。
   - 题干相似度 > 80% → 可能是同一题（格式变化），标记为低置信。
   - 无法匹配 → 新题。
4. 逐题填写答案：
   - **有 correctAnswer 的错题**：直接填入 correctAnswer，不再调用代理分析。
   - **无 correctAnswer 的错题**：采用错题反向提示策略，使用 1 个 `general` 子代理分析：
     - 在 prompt 中注入反向提示："以下是上次答错的题目，已知错误答案为 X，请排除 X 并从剩余选项中推理出最可能的正确答案。"
     - 同时注入课程知识上下文（如该考试对应课程的文档/视频标题、已读内容摘要等），提升推理依据。
     - 如反向提示分析仍不确定，调用 1 个 `web-researcher` 子代理对题干关键词搜索验证，取搜索推荐答案。
   - **非错题**（上次答对的题目）：沿用上次的答案，不做修改。
   - **新出现的题目**：使用多代理分析（同阶段二）。
5. 填写完毕后提交考试。
6. 等待结果，再次进入阶段四检查完成状态（阶段四内含重考次数门禁）。

##### 考试流程总结

```
获取全部题目 → 3代理并行分析 → 交叉验证共识 → 填写提交
     ↓
[阶段四] 检查完成状态 → 已完成 → 结束
     ↓ 未完成 (retryCount<2)
[阶段五] 获取错题 → 无法获取 → 告知用户，结束
     ↓ 获取成功
[阶段六] 重考（有正确答案直接填入 + 无正确答案反向提示+搜索验证）
     ↓ retryCount++
     └──→ [阶段四] 检查完成状态 (retryCount≥2 时跳过该课程)
```

#### 视频类课程

1. 在课程列表页面点击该节课的链接，或打开其 URL。
2. 等待视频页面加载完成，执行视频状态检查脚本获取视频信息。
3. 检查视频状态是否正常：
   - 如果返回 `error:'no video element'`：页面上无视频元素，跳过该课程并在汇报中标注。
   - 如果 `paused=true`：点击播放按钮启动播放，尝试设置 1.5 倍速（倍速不超过 1.5x）。
   - 如果 `paused=false`：视频已在播放，尝试设置 1.5 倍速。
4. 再次执行视频状态检查脚本，确认 `paused=false`，记录 `duration`、`currentTime`、`playbackRate`。
5. 进入 5 分钟分片轮询循环：
   - 构造 nextStep 内容，包含：当前课程名、视频总时长、当前播放进度、播放倍速、课程列表中剩余课程信息。
   - 调用 `ae-timer duration=300 label="等待视频播放: <课程名> (<当前进度>/<总时长>s)" nextStep="<包含播放状态和后续指令的完整描述>"`。
   - ae-timer 返回后，执行视频状态检查脚本：
     - 如果 `ended=true` 或 `currentTime >= duration`：视频已播完，退出轮询。
     - 如果 `paused=true` 且非自然结束：视频被暂停或有弹窗，点击播放/关闭弹窗恢复播放，然后重新调用 ae-timer 继续 5 分钟等待。
     - 如果仍在播放：重新调用 ae-timer 继续 5 分钟等待，更新 nextStep 中的播放进度。
     - 如果返回 `error`：视频元素丢失，跳过该课程并标注。
6. 视频播完后，关闭视频标签页，返回课程列表页面。

##### 视频轮询 nextStep 模板

每次调用 ae-timer 时，nextStep 应包含以下信息（根据实际情况填写）：

```
视频播放等待结束。当前课程：<课程名>。请执行视频状态检查脚本，根据结果：
1. 如果视频已播完（ended=true 或 currentTime>=duration）：关闭当前视频标签页，返回课程列表页面，继续下一节课<下一节课名>。
2. 如果视频被暂停（paused=true）：点击播放按钮恢复播放，然后重新调用 ae-timer duration=300 继续等待。
3. 如果视频仍在播放：重新调用 ae-timer duration=300 继续等待。
```

#### 外链类课程

1. 在课程列表页面点击该节课的链接，或打开其 URL。
2. 等待外链页面加载完成，调用 `chrome-devtools_take_snapshot` 获取页面结构。
3. 判断外链内容是否为另一个课程列表页面：
   - 如果页面结构与课程列表页面类似（包含多节课、有课程类型标识），则递归执行本技能的"第二步：遍历课程列表"流程处理该页面上的所有课程。
   - 如果不是课程列表页面，调用 `ae-timer duration=3 label="等待外链页面" nextStep="外链等待结束，请关闭当前外链标签页，返回课程列表页面，继续处理下一节课"`。
4. 关闭外链标签页，返回原课程列表页面。

### 第三步：完成汇报

所有课程处理完毕后，输出完成摘要：

- 已完成课程数量和列表（按类型分组）。
- 考试类课程的详细信息：
  - 考试名称、考试成绩、是否通过。
  - 重考次数（如重考过）。
  - 每次考试的置信度分布（高/中/低各多少题）。
  - 未能获取错题的考试（如有）。
- 跳过或失败的课程及原因。
- 已关闭的临时标签页数量。

## 标签页管理规则

- 课程列表页面始终保持在一个固定标签页中，不关闭。
- 每节课在单独的新标签页中打开，处理完毕后立即关闭该标签页。
- 每次处理完一节课后，确认回到课程列表标签页再继续下一节课。
- 如果标签页数量超过 10 个，暂停并关闭所有非课程列表标签页后再继续。

## 视频播放注意事项

- 倍速最高 1.5 倍，不得超过。
- 如果视频播放器不支持倍速调节，以默认速度播放。
- 如果视频加载失败或无法播放，跳过该课程并在汇报中标注。
- 每 5 分钟检查一次播放状态，确保能及时处理暂停、弹窗等异常。

## 考试答题注意事项

- 采用 3 代理并行分析 + 交叉验证策略，提升正确率。
- 三票一致为高置信，两票一致为中置信（采用多数），三票各异为低置信（触发搜索验证，搜索失败时回退第一个代理答案）。
- 低置信题目通过搜索验证提升正确率；搜索验证结果在汇报中标注。
- 考试提交后必须检查课程完成状态；未完成时尝试获取错题并重考。
- 重考时有 correctAnswer 的错题直接填入，无 correctAnswer 的错题使用反向提示+排除法+搜索验证，非错题沿用上次答案。
- 重考次数门禁在阶段四入口检查，最多重考 2 次。
- 无法获取错题详情时必须告知用户，不得跳过此步骤直接重考。
- 如果考试有答题时间限制，在时间限制内完成；如果时间不足，优先完成已读题目。
- 不反复修改非错题的已选答案。
- 主分析阶段（阶段二）的子代理仅基于自身知识推理，不使用搜索；搜索验证仅在低置信题目触发。

## 安全边界

- 本技能仅处理用户明确指定的课程 URL，不自动发现或访问未授权的课程。
- 考试答题优先基于题目内容通过多代理推理分析；三票各异的低置信题目允许使用搜索工具验证答案，搜索结果在汇报中标注。
- 视频播放倍速不超过 1.5 倍，遵守课程平台规则。
- 遇到需要登录的页面时，提示用户手动登录后继续，不自动输入凭据。
- 遇到人机验证（验证码、滑块等）时，提示用户手动完成后继续。
- 不修改课程平台的账户设置或个人信息。
- 无法获取错题详情时必须如实告知用户，不得伪造或跳过。

## 验证方式

- 确认所有课程列表中的课程都已处理（完成或跳过并记录原因）。
- 确认所有临时标签页已关闭，仅保留课程列表标签页。
- 确认汇报中的课程数量与列表中识别到的数量一致。
