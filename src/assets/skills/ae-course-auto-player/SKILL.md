# ae:course-auto-player

> **chrome-devtools MCP 门禁**：执行任何 `chrome-devtools_*` 工具前，必须先通过 `ae:chrome-devtools` 完成 MCP 动态注册；MCP 注册不能替代门禁检查，未注册或未连接就绪时不得执行任何 chrome-devtools 工具，连接失败时记录"无法验证"并停止。

## 角色

在线课程自动完成器，自动完成在线课程平台的所有课程：连接浏览器、打开课程列表页面、按顺序遍历每节课，根据课程类型自动执行对应操作（文档阅读、视频播放、外链访问、考试智能答题），直至所有课程完成。

## 适用场景

- 用户提供一个课程列表页面 URL，希望自动完成所有课程
- 课程列表包含文档、考试、视频、外链等类型，需要自动化逐个处理
- 用户说"帮我刷课"、"自动完成课程"、"播放课程列表"等

## 不适用场景

- 用户只想打开单个页面浏览，不需要自动化遍历
- 课程平台需要人机验证（如滑块验证码）且无法自动通过
- 用户未提供课程列表页面 URL

## 核心设计原则

- **ae-timer + nextStep 防上下文丢失**：所有 `ae-timer` 调用必须传入 `nextStep` 参数，描述等待结束后应执行的操作。工具返回时原样携带，确保长时间等待后 LLM 无需回溯上下文即可继续。
- **视频 5 分钟分片轮询**：视频播放不使用一次长等待，而是每 5 分钟调用一次 `ae-timer`，返回后检查播放状态，再决定继续等待或关闭。这样即使视频被暂停、弹窗阻断或播放异常，也能及时发现并处理。
- **最小化 LLM 交互**：每种课程类型在等待期间 LLM 挂起不消耗 token，只在状态检查和决策点才恢复推理。

## 检查视频状态的脚本

视频状态检查统一使用以下脚本，通过 `chrome-devtools_evaluate_script` 执行：

```
(function(){const v=document.querySelector('video');return v?{paused:v.paused,duration:v.duration,currentTime:v.currentTime,ended:v.ended,playbackRate:v.playbackRate}:{error:'no video element'}})()
```

返回字段含义：
- `paused`：是否暂停
- `duration`：总时长（秒），可能为 NaN
- `currentTime`：当前播放进度（秒）
- `ended`：是否播放结束
- `playbackRate`：当前倍速
- `error`：页面上未找到 video 元素

## 输入处理

用户通过命令传入参数，格式为：

```
/ae-course-auto-player [浏览器类型] <课程列表页面URL>
```

- 浏览器类型为可选参数，支持 `Chrome`、`Edge`、`Brave`、`Vivaldi`，默认为 `Chrome`
- URL 为必填参数，必须是可访问的课程列表页面地址
- 如果用户未提供 URL，必须先询问，不得自行假设
- 如果用户提供的浏览器类型不在支持列表中，提示用户选择支持的类型

## 工作流程

### 前置：浏览器连接

1. 使用 `ae:chrome-devtools` 技能完成浏览器 MCP 动态注册并确认连接就绪。`ae:chrome-devtools` 是浏览器 MCP 的唯一管理入口，不应直接调用 `ae-chrome-devtools-mcp` 工具。
2. 传入 `browser` 参数（取自用户输入的浏览器类型，默认 `Chrome`）。如果 autoConnect 失败，使用 `--mode=isolated` 启动独立浏览器实例，同样传入 `browser` 参数。
   - 如果用户希望连接已有浏览器（保留登录态），需先在浏览器中启用远程调试：在地址栏打开对应调试页面并勾选开关，不同浏览器的地址不同：

     | 浏览器 | 远程调试页面 |
     |--------|-------------|
     | Chrome | `chrome://inspect/#remote-debugging` |
     | Edge | `edge://inspect/#remote-debugging` |

   - 如果用户未手动启用远程调试，autoConnect 模式可能会新开浏览器。
3. 连接成功后，调用 `chrome-devtools_list_pages` 确认连接可用。

### 第一步：打开课程列表页面

1. 调用 `chrome-devtools_list_pages` 列出当前标签页。
2. 检查是否已有标签页打开了目标 URL（精确匹配或相同路径匹配）。
   - 如果已存在，选择该标签页并刷新。
   - 如果不存在，调用 `chrome-devtools_new_page` 打开目标 URL。
3. 等待页面加载完成，调用 `chrome-devtools_take_snapshot` 获取页面结构。
4. 从页面快照中识别课程列表，提取每节课的名称、类型和链接。

### 第二步：遍历课程列表

按顺序遍历每节课，根据类型执行对应操作：

#### 文档类课程

1. 在课程列表页面点击该节课的链接，或打开其 URL。
2. 等待文档页面加载完成。
3. 调用 `ae-timer duration=5 label="等待文档阅读" nextStep="文档阅读等待结束，请关闭当前文档标签页，返回课程列表页面，继续处理下一节课"`。
4. ae-timer 返回后，按 nextStep 指示关闭文档标签页，返回课程列表页面。

#### 考试类课程

##### 阶段一：获取全部题目

1. 在课程列表页面点击该节课的链接，或打开其 URL。
2. 等待考试页面加载完成，调用 `chrome-devtools_take_snapshot` 获取页面结构。
3. 检查页面是否包含题目元素（选择题选项、填空输入框等）：
   - 如果页面不包含题目而是显示考试说明/确认页，查找并点击"开始考试"或"确认开始"按钮，等待题目加载后再继续。如果确认按钮需要勾选协议，先勾选再点击确认。
4. 向下滚动逐一读取所有题目，确保获取完整题库：
   - 记录每道题的题号、题干、选项（选择题/判断题）或填写要求（填空题）。
   - 如果页面有分页或"下一页"按钮，继续翻页读取所有题目。
   - 将所有题目整理为结构化列表：`[{index, type, question, options?}]`。
5. 确认题目全部读取后，进入阶段二。

##### 阶段二：作答策略

根据是否存在历史批改记录（不局限于本会话，包括从考试平台获取的所有历史记录），采用不同作答策略：

**首次考试（无历史批改记录）：**

不调用子代理，由 LLM 自身直接逐题推理作答。每道题给出答案和简要推理，输出格式为：`[{index, answer, reasoning}]`。

**有历史批改记录时（无论是否本会话产生）：**

1. 获取本次考试的全部题目（已在阶段一完成）。
2. 将本次题目与历史批改记录中的题目进行比对：
   - 题干完全一致 → 同一题。
   - 题干相似度 > 80% → 可能是同一题（格式变化），标记为低置信。
   - 无法匹配 → 新题。
3. 对每道题根据历史记录采取不同策略：

    | 题目分类 | 策略 | 说明 |
    |----------|------|------|
    | 在任意一次历史记录中答对的题目 | 采纳该正确答案 | 同一题只要在某次历史记录中答对，直接沿用该正确答案，无需再推理 |
    | 历史批改中有 correctAnswer 的错题 | 直接填入 correctAnswer | 不再推理分析 |
    | 多次历史记录中均错误且无 correctAnswer 的题目 | 排除法 | 收集该题在所有历史记录中选择过的错误答案，构建排除集合，从剩余选项中深入思考选择最合适的答案 |
    | 新出现的题目 | 独立推理作答 | 同首次考试，由 LLM 直接推理 |
    | 题干相似但不完全一致的题目 | 参照历史答案 + 低置信标注 | 参考历史对应题目的答案，标注为低置信 |

4. **排除法细则**（针对多次历史记录中均错误且无正确答案的选择题）：
    - 遍历该题在所有历史批改记录中的作答情况，收集所有选择过的错误答案，构建排除集合。
    - 同一题如果在某次记录中答对，则**不属于排除法范畴**，应直接采纳该正确答案（见上表第一行）。
    - 从当前选项中移除排除集合中的选项。
    - 对剩余选项深入思考，选择最合理的答案。
    - 如果排除后仅剩一个选项，直接选择该选项。
    - 如果排除后无剩余选项（所有选项都曾在不同历史记录中被选错），回退为独立推理作答，标注为低置信。
5. 生成最终答案表：`[{index, answer, confidence, source?}]`，其中 `source` 标注答案来源（历史正确答案 / correctAnswer / 排除法 / 独立推理 / 新题推理）。

##### 阶段三：填写答案并提交

1. 根据最终答案表，逐一在页面上选择/填写答案：
   - 高置信题目：直接填入。
   - 低置信题目：填入推理后/排除法后的答案，在汇报中标注为"不确定"。
2. 答完所有题目后，找到并点击提交按钮。
3. 等待提交结果页面加载，调用 `chrome-devtools_take_snapshot` 获取结果。

##### 阶段四：考试完成状态检查

1. 从结果页面获取考试信息和课程完成状态：
   - 提取考试成绩、是否通过、是否已完成。
   - 如果页面显示课程已完成（通过/达标），记录成绩，关闭标签页，返回课程列表页面，跳过阶段五和阶段六。
   - 如果课程未完成（未通过/未达标），检查是否可以继续重考：
     - 检查本会话考试次数：本会话已考 ≥ 3 次，在汇报中标注"已达到本会话最大考试次数 3 次，跳过该考试"，关闭标签页，返回课程列表页面，继续下一个课程。
     - 检查考试本身是否有次数限制：如果页面提示"考试次数已用完"、"已达最大考试次数"、"不可重考"等类似信息，说明该考试平台限制了重考次数且已耗尽，在汇报中标注"考试平台限制无法重考，跳过该考试"，关闭标签页，返回课程列表页面，继续下一个课程。
     - 以上两项均未触发（本会话已考 < 3 次且平台允许重考）：记录成绩和未完成原因，进入阶段五。

##### 阶段五：采集历史批改记录

1. 尝试在当前结果页面获取批改详情：
   - 查找"查看解析"、"查看错题"、"答题详情"等链接或按钮并点击。
   - 在批改/解析页面，调用 `chrome-devtools_take_snapshot` 获取结构。
   - 提取每道题的批改信息：
     - 正确题目：记录题号和提交的答案（作为历史正确答案）。
     - 错误题目：记录题号、提交的答案（错误答案）、正确答案（如有）。
   - 将批改记录整理为列表：`[{index, myAnswer, isCorrect, correctAnswer?}]`。
   - 将本次批改记录追加到历史批改记录中（按考试课程分组保存）。
2. **获取所有历史考试记录**（核心步骤，排除法的正确性依赖于完整的历史数据）：
    - 返回课程列表页面，重新进入该考试课程。
    - 查找"历史成绩"、"考试记录"、"答题记录"等入口。
    - 如果存在历史考试记录，**逐一查看每一次历史考试的批改详情**，不遗漏任何一次记录：
      - 对每道题提取批改信息：题号、提交的答案、是否正确、正确答案（如有）。
      - 同一题目在多次历史记录中的合并规则：
        - **只要在某次记录中答对，即采纳该正确答案**，后续作答时直接沿用，不再进入排除法。
        - **多次记录中均错误的题目，收集所有选择过的错误答案取并集**，构建排除集合；排除集合越大，剩余候选越少，正确率越高。
      - 将合并后的批改记录追加到历史批改记录中（按考试课程分组保存）。
    - 如果无法进入历史考试记录页面（无入口、权限不足等），仅使用本次批改记录，在汇报中标注"未能获取全部历史记录，排除法可能不完整"。
3. 如果以上方式均无法获取任何批改信息，**必须告知用户**：
   - 输出提示：`"考试 <课程名> 未通过（得分：<分数>），但无法获取批改详情。请手动查看考试记录后决定是否重新考试。" `
   - 关闭标签页，返回课程列表页面，跳过阶段六。

##### 阶段六：重新考试（历史记录驱动作答）

1. 递增本会话考试计数（初始为 1，每次进入阶段六时 +1）。
2. 重新进入考试页面，等待加载完成。
3. 检查页面是否允许重新考试：
   - 如果页面提示"考试次数已用完"、"已达最大考试次数"、"不可重考"等类似信息，说明该考试平台限制了重考次数且已耗尽，在汇报中标注"考试平台限制无法重考，跳过该考试"，关闭标签页，返回课程列表页面，继续下一个课程。
4. 获取所有题目（同阶段一流程），进入阶段二的重考策略（利用历史批改记录驱动作答）。
5. 填写完毕后提交考试。
6. 等待结果，再次进入阶段四检查完成状态。

##### 考试流程总结

```
[阶段一] 获取全部题目
      ↓
[阶段二] 作答策略
      ├─ 无历史批改记录 → LLM直接推理作答
      └─ 有历史批改记录（不局限于本会话）
           ├─ 任意一次记录答对 → 直接采纳该正确答案
           ├─ 有correctAnswer → 直接填入
           ├─ 多次记录均错误 → 排除法（收集所有错误答案取并集→从剩余选择）
           └─ 新题 → LLM直接推理作答
      ↓
[阶段三] 填写答案并提交
      ↓
[阶段四] 检查完成状态 → 已完成 → 结束
      ↓ 未完成
      ├─ 本会话已考≥3次 → 跳过该考试，进入下一节课
      ├─ 考试平台限制无法重考 → 跳过该考试，进入下一节课
      └─ 可重考
           ↓
[阶段五] 采集历史批改记录 → 无法获取 → 告知用户，结束
      ↓ 获取成功
[阶段六] 重新考试
      ├─ 考试平台限制无法重考 → 跳过该考试，进入下一节课
      └─ 可重考 → 历史记录驱动作答 → 提交
           ↓ sessionAttemptCount++
           └──→ [阶段四] 检查完成状态
```

#### 视频类课程

1. 在课程列表页面点击该节课的链接，或打开其 URL。
2. 等待视频页面加载完成，执行视频状态检查脚本获取视频信息。
3. 检查视频状态是否正常：
   - 如果返回 `error:'no video element'`：页面上无视频元素，跳过该课程并在汇报中标注。
   - 如果 `paused=true`：点击播放按钮启动播放，尝试设置 1.5 倍速（倍速不超过 1.5x）。
   - 如果 `paused=false`：视频已在播放，尝试设置 1.5 倍速。
4. 再次执行视频状态检查脚本，确认 `paused=false`，记录 `duration`、`currentTime`、`playbackRate`。
5. 进入 5 分钟分片轮询循环：
   - 构造 nextStep 内容，包含：当前课程名、视频总时长、当前播放进度、播放倍速、课程列表中剩余课程信息。
   - 调用 `ae-timer duration=300 label="等待视频播放: <课程名> (<当前进度>/<总时长>s)" nextStep="<包含播放状态和后续指令的完整描述>"`。
   - ae-timer 返回后，执行视频状态检查脚本：
     - 如果 `ended=true` 或 `currentTime >= duration`：视频已播完，退出轮询。
     - 如果 `paused=true` 且非自然结束：视频被暂停或有弹窗，点击播放/关闭弹窗恢复播放，然后重新调用 ae-timer 继续 5 分钟等待。
     - 如果仍在播放：重新调用 ae-timer 继续 5 分钟等待，更新 nextStep 中的播放进度。
     - 如果返回 `error`：视频元素丢失，跳过该课程并标注。
6. 视频播完后，关闭视频标签页，返回课程列表页面。

##### 视频轮询 nextStep 模板

每次调用 ae-timer 时，nextStep 应包含以下信息（根据实际情况填写）：

```
视频播放等待结束。当前课程：<课程名>。请执行视频状态检查脚本，根据结果：
1. 如果视频已播完（ended=true 或 currentTime>=duration）：关闭当前视频标签页，返回课程列表页面，继续下一节课<下一节课名>。
2. 如果视频被暂停（paused=true）：点击播放按钮恢复播放，然后重新调用 ae-timer duration=300 继续等待。
3. 如果视频仍在播放：重新调用 ae-timer duration=300 继续等待。
```

#### 外链类课程

1. 在课程列表页面点击该节课的链接，或打开其 URL。
2. 等待外链页面加载完成，调用 `chrome-devtools_take_snapshot` 获取页面结构。
3. 判断外链内容是否为另一个课程列表页面：
   - 如果页面结构与课程列表页面类似（包含多节课、有课程类型标识），则递归执行本技能的"第二步：遍历课程列表"流程处理该页面上的所有课程。
   - 如果不是课程列表页面，调用 `ae-timer duration=3 label="等待外链页面" nextStep="外链等待结束，请关闭当前外链标签页，返回课程列表页面，继续处理下一节课"`。
4. 关闭外链标签页，返回原课程列表页面。

### 第三步：完成汇报

所有课程处理完毕后，输出完成摘要：

- 已完成课程数量和列表（按类型分组）。
- 考试类课程的详细信息：
  - 考试名称、考试成绩、是否通过。
  - 重考次数（如重考过）。
  - 每次考试的置信度分布（高/中/低各多少题）。
  - 未能获取错题的考试（如有）。
- 跳过或失败的课程及原因。
- 已关闭的临时标签页数量。

## 标签页管理规则

- 课程列表页面始终保持在一个固定标签页中，不关闭。
- 每节课在单独的新标签页中打开，处理完毕后立即关闭该标签页。
- 每次处理完一节课后，确认回到课程列表标签页再继续下一节课。
- 如果标签页数量超过 10 个，暂停并关闭所有非课程列表标签页后再继续。

## 视频播放注意事项

- 倍速最高 1.5 倍，不得超过。
- 如果视频播放器不支持倍速调节，以默认速度播放。
- 如果视频加载失败或无法播放，跳过该课程并在汇报中标注。
- 每 5 分钟检查一次播放状态，确保能及时处理暂停、弹窗等异常。

## 考试答题注意事项

- 考试作答不使用多代理并行分析或头脑风暴，由 LLM 直接逐题推理作答。
- 有历史批改记录时（不局限于本会话，包括从考试平台获取的所有历史记录）优先利用历史记录驱动作答：同一题只要在任意一次历史记录中答对，直接采纳该正确答案；有 correctAnswer 的错题直接填入；多次记录中均错误的题目采用排除法（收集所有历史错误答案取并集构建排除集合，从剩余选项中选择）；排除后仅剩一个选项时直接选择，无剩余选项时回退独立推理。
- 排除法的前提是获取所有历史考试记录，记录越完整排除集合越大、正确率越高；无法获取全部历史记录时必须标注排除法可能不完整。
- 考试提交后必须检查课程完成状态；未完成时尝试获取批改记录并重考。
- 本会话考试次数门禁：最多 3 次，达到 3 次仍未通过则跳过该考试进入下一个课程。此处的 3 次指本会话考试次数，不算历史考试次数。
- 考试平台本身可能有考试次数限制，如果页面提示无法重考（如"考试次数已用完"等），跳过该考试进入下一个课程。
- 无法获取批改详情时必须告知用户，不得跳过此步骤直接重考。
- 如果考试有答题时间限制，在时间限制内完成；如果时间不足，优先完成已读题目。
- 不反复修改非错题的已选答案。

## 安全边界

- 本技能仅处理用户明确指定的课程 URL，不自动发现或访问未授权的课程。
- 考试答题由 LLM 直接推理作答，不使用多代理并行分析或搜索验证；重考时利用历史批改记录中的正确答案和排除法提升正确率。
- 视频播放倍速不超过 1.5 倍，遵守课程平台规则。
- 遇到需要登录的页面时，提示用户手动登录后继续，不自动输入凭据。
- 遇到人机验证（验证码、滑块等）时，提示用户手动完成后继续。
- 不修改课程平台的账户设置或个人信息。
- 无法获取错题详情时必须如实告知用户，不得伪造或跳过。

## 验证方式

- 确认所有课程列表中的课程都已处理（完成或跳过并记录原因）。
- 确认所有临时标签页已关闭，仅保留课程列表标签页。
- 确认汇报中的课程数量与列表中识别到的数量一致。
