# V1 串联验证

## 角色

端到端串联验证专家。沿数据流追踪证据，验证跨模块全链路的数据流转正确性、不变量全局守卫和契约闭合性。

## 适用场景

- 上游步骤（G1-G3、A1-A2、L1-L3）产物已就绪，需要端到端验证全链路
- 需要确认契约在实际数据流中被正确遵守
- 需要验证不变量在全局范围内被守卫
- 需要计算端到端覆盖率并确认闭合

## 不适用场景

- 上游产物尚未就绪（应先完成对应上游步骤）
- 单模块单元测试（属于 L3 范畴）
- 契约设计或不变量定义（属于 A1/G1 范畴）

## 产物根目录

所有产物写入**产物根目录**下。默认根目录为 `docs/ae/galv/<项目名>/`。

`<项目名>` 由以下规则确定：
1. 若产物根目录下已存在 `galv-manifest.yaml`，读取其中的 `project_name` 字段作为项目名
2. 若不存在，提示用户先执行上游技能创建 manifest，或由用户手动提供项目名后由本技能创建
3. 后续所有技能必须读取 `galv-manifest.yaml` 获取项目名，禁止自行推断

整个根目录自包含、可移植：内部所有路径均为相对路径，目录可整体移动到任意位置。读取全部阶段产物后，任何 AI 工具可据此生成功能等价、结构等价的软件系统。

本阶段的产物位于根目录下 `v1/` 子目录。

## 产物独占

本技能独占拥有以下产物，只有本技能可以修改（路径相对于产物根目录）：

- `v1/e2e-trace/`（≤3 个 E2E 场景时可单文件 `v1/e2e-trace.md`）
- `v1/invariant-guard-matrix/`（≤5 条不变量时可单文件 `v1/invariant-guard-matrix.md`）
- `v1/e2e-coverage.md`

**禁止修改**上游技能产物和下游技能产物。

## 上游依赖（只读）

- 所有上游步骤的产物（G1-G3、A1-A2、L1-L3）

## 执行流程

### T1 扩展端到端场景

从 A2 场景扩展为完整 E2E 场景：

- 从用户操作起点→所有相关模块→最终状态断言
- 每步含：模块 / 动作 / 输入 / 输出 / 状态断言 / 不变量检查

### T2 构造端到端测试数据

为每个 E2E 场景构造：

- 起点模块初始状态
- 每步跨模块传递数据
- 每个模块内部状态变更
- 终点模块断言数据

测试数据必须覆盖正常路径和异常路径。

### T3 逐场景推演

沿 a1/data-flow/ 路径走完全链路，逐步检查：

1. 输入/输出是否符合契约
2. 状态同步是否正确
3. 不变量守卫是否通过
4. 延迟和超时是否在约束内

推演过程中记录每步的通过/失败状态和证据。任何步骤失败时，精确定位到具体模块和契约条目。

### T4 验证高风险场景

- 跨端冲突：并发操作导致的数据冲突
- 超时降级：超时场景下的降级行为
- 离线同步：离线状态恢复后的数据一致性

### T5 生成不变量守卫矩阵

为每条不变量记录：

| 字段 | 说明 |
|------|------|
| 不变量编号 | 引用 G1 定义 |
| 不变量描述 | 不变量的约束内容 |
| 强制执行模块 | 哪些模块在运行时强制执行 |
| E2E 检查场景 | 哪些 E2E 场景检查此不变量 |
| 执行方式 | 代码断言 / 数据库约束 / 中间件拦截等 |

### T6 计算端到端覆盖率

| 覆盖维度 | 通过标准 |
|----------|---------|
| 契约 E2E 覆盖 | 每条契约至少 1 个 E2E 场景 |
| 不变量 E2E 覆盖 | 每条不变量至少 1 个 E2E 场景守卫 |
| 冲突规则 E2E 覆盖 | 每个冲突解决规则至少 1 个 E2E 场景触发 |

## 单轨格式规则

所有产物文件采用 Markdown + YAML Frontmatter 单轨格式：

- Frontmatter 为机器可读的唯一真源，正文为人类阐释
- 正文不允许出现 Frontmatter 中不存在的实体名、字段名、规则名
- 正文只允许包含：Frontmatter 字段的业务含义解释、设计决策的理由、用户确认记录
- 如需补充信息，必须先在 Frontmatter 中添加对应条目，再在正文中解释
- 每条 Frontmatter 条目可标注 `origin` 字段：`derived`（从上游推导，可信度最高）、`inferred`（AI 推断补充，需人工确认）、`asserted`（人类断言，最可靠）

## 验收关卡

| 编号 | 检查项 | 通过标准 |
|------|--------|---------|
| V1-K1 | 推演全通过 | 所有 E2E 推演场景 pass |
| V1-K2 | 契约 E2E 覆盖 100% | 每条契约至少 1 个 E2E 场景 |
| V1-K3 | 不变量 E2E 覆盖 100% | 每条不变量至少 1 个 E2E 场景守卫 |
| V1-K4 | 冲突规则 E2E 覆盖 100% | 每个冲突解决规则至少 1 个 E2E 场景触发 |
| V1-K5 | 失败可定位 | 失败场景精确定位到具体模块和契约条目 |
| V1-K6 | 文件行数合规 | 所有产物文件不超过 500 行 |
| V1-K7 | 人工审核通过 | 用户确认 E2E 推演场景覆盖完整、不变量守卫矩阵正确、覆盖率达标 |

## 回退说明

| 失败类型 | 回退目标 |
|---------|---------|
| 单模块逻辑错误 | L2 |
| 契约不匹配 | A1 |
| 数据模型不支持 | G2 |
| 不变量错误 | G1 |

## 安全边界

- 禁止修改上游产物：G1-G3、A1-A2、L1-L3 的所有文件均为只读
- 推演失败时不掩盖：任何推演失败必须如实记录
- 覆盖率未达 100% 不得标记为通过
- V1-K7 须由用户确认后方可视为本步骤完成
