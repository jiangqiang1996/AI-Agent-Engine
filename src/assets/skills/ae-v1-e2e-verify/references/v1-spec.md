# V1 步骤摘要

## 目标

端到端走通跨模块全链路，验证数据流转正确、不变量全局守卫、契约全部闭合。

V1 不是"把所有模块跑一遍"，而是"沿数据流追踪证据"。

## 任务清单

| 任务 | 说明 |
|------|------|
| T1 扩展端到端场景 | 从 A2 场景扩展为完整 E2E 场景：用户操作起点→所有相关模块→最终状态断言 |
| T2 构造端到端测试数据 | 起点模块初始状态、每步跨模块传递数据、每个模块内部状态变更、终点模块断言 |
| T3 逐场景推演 | 沿 data-flow 路径走完全链路，检查输入/输出符合契约、状态同步正确、不变量守卫通过 |
| T4 验证高风险场景 | 跨端冲突、超时降级、离线同步 |
| T5 生成不变量守卫矩阵 | 每条不变量在哪些模块中被强制执行、在哪些 E2E 场景中被检查 |
| T6 计算端到端覆盖率 | 每条契约至少1个E2E场景、每个冲突规则至少1个E2E场景、每条不变量至少1个E2E场景守卫 |
| T7 产物审查 | 逐条对照验收关卡，调用 ae:review mode=autofix domain=document 审查 v1/ 目录 |

## 验收关卡

| 编号 | 检查项 | 通过标准 |
|------|--------|---------|
| V1-K1 | 推演全通过 | 所有 E2E 推演场景 pass |
| V1-K2 | 契约 E2E 覆盖 100% | 每条契约至少 1 个 E2E 场景 |
| V1-K3 | 不变量 E2E 覆盖 100% | 每条不变量至少 1 个 E2E 场景守卫 |
| V1-K4 | 冲突规则 E2E 覆盖 100% | 每个冲突解决规则至少 1 个 E2E 场景触发 |
| V1-K5 | 失败可定位 | 失败场景精确定位到具体模块和契约条目 |
| V1-K6 | 指纹一致 | upstream_fingerprints 与全部上游产物一致 |
| V1-K7 | 文件行数合规 | 所有产物文件不超过 500 行 |
| V1-K8 | 审查通过 | ae:review 审查 v1/ 目录无阻断发现 |

## 回退规则

- 单模块逻辑错误 → 回 L2
- 契约不匹配 → 回 A1
- 数据模型不支持 → 回 G4
- 不变量错误 → 回 G1

## 通用产物规格

- 单轨格式：YAML Frontmatter 为唯一真源，正文为人类阐释
- 文件行数硬约束：每个产物文件不超过 500 行
