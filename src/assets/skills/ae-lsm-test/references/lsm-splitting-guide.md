# LSM 测试用例产物拆分策略

测试用例产物的核心实体是 `TC-*` 测试用例，每条用例包含需求映射、测试步骤、预期结果、测试类型和优先级。拆分时优先保证同一功能域或同一测试类型的用例聚合在一起，便于定位和执行。

## 行数限制

单个产物文件不得超过 800 行（含 frontmatter）。超过时必须拆分为文件夹结构。

## 拆分维度

按功能域或测试类型分组 `TC-*` 条目，优先按功能域拆分：

- **按功能域**：同一功能模块的测试用例放在同一子文件（如 `auth-tests.md`）
- **按测试类型**：同一测试层级的用例放在同一子文件（如 `integration-tests.md`、`e2e-tests.md`）

当功能域内用例数量适中时优先按功能域拆分；当项目需要按测试层级组织执行时优先按测试类型拆分。

## 目录结构

```
ae/lsm/test/
└── <project-name>/
    ├── index.md               # 索引文件
    ├── auth-tests.md          # 功能域：认证模块的 TC-* 条目
    ├── order-tests.md         # 功能域：订单模块的 TC-* 条目
    └── ...
```

或按测试类型：

```
ae/lsm/test/
└── <project-name>/
    ├── index.md
    ├── unit-tests.md          # 单元测试用例
    ├── integration-tests.md   # 集成测试用例
    └── e2e-tests.md           # 端到端测试用例
```

## 索引文件

索引文件 `index.md` 是文件夹的入口，必须包含：

1. **完整 frontmatter**：与未拆分产物相同的元数据，附加 `splitFrom`（原单文件名）和 `totalFiles`（子文件数量）
2. **测试概述**：一段话描述整个测试的范围、覆盖策略和关键结论
3. **子文件索引表**：列出每个子文件的文件名、涵盖的 `TC-*` ID 范围和作用描述

```markdown
---
lsmKind: test
upstreamRefs: [...]
traceTable: { ... }
trimmingGuide: { ... }
splittingGuide: { ... }
splitFrom: <project-name>.md
totalFiles: <N>
---

# LSM Test: [项目名称]

## 测试概述

[一段话描述整个测试的范围、覆盖策略和关键结论]

## 子文件索引

| 文件名 | 范围 | 作用 |
|--------|------|------|
| auth-tests.md | TC-001 ~ TC-005 | 认证模块的完整测试用例 |
| order-tests.md | TC-06 ~ TC-12 | 订单模块的完整测试用例 |
```

## 子文件

每个子文件必须包含：

1. **轻量 frontmatter**：`lsmKind: test` 和 `parentIndex: ./index.md`
2. **该范围的完整测试用例**：需求映射、测试步骤、预期结果

```markdown
---
lsmKind: test
parentIndex: ./index.md
---

# 认证模块测试

## TC-001: 用户登录成功

[完整测试用例内容]
```

**禁止拆断单个 `TC-*` 条目**：每个测试用例的需求映射、测试步骤、预期结果必须完整存在于同一子文件中。

**测试数据与前置条件**：全局性的测试数据准备和前置条件放在索引文件；仅与特定子文件相关的测试数据放在该子文件中。

## 拆分触发

1. AI 生成产物时，先评估预估行数；若预计超过 800 行，直接按拆分结构生成
2. 生成过程中发现行数超限时，暂停并重构为拆分结构
3. 拆分时优先按功能域边界分组，保持每个子文件内用例的逻辑完整性
