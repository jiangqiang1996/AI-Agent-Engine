# 原型预览生成

将 ae:prd 产出的原型文档（`prototype/` 下的 md 文件）转换为多页面 HTML 静态文件，供用户直接在浏览器中打开查看效果，验证原型是否正确。

**核心定位：纯还原工具。** 本技能只将原型文档中写明的页面效果还原为 HTML 静态文件，不超出文档声明的语义边界。不考虑组件复用，不引入任何技术栈，不参考任何设计文档。重依赖用 div/span 占位代替，轻量级依赖可直接引入。在不违反原型文档明确声明的语义边界前提下对页面进行合理美化（间距、圆角、阴影、过渡等），使预览更接近真实产品视觉体验。

## 核心原则

1. **纯还原，禁止镀金（硬约束）** - 仅实现原型文档中明确写明的页面效果，不超出文档声明的语义边界（页面数量、路由、布局区域划分、交互跳转、表单字段和必填规则、主题色和次要颜色 HEX 值、响应式行为）。不多做任何超出文档语义边界的事情，不少做任何文档写明的内容。允许的页面美化见核心原则 9。
2. **禁止构建工具（硬约束）** - 产出纯 HTML + CSS + JS 静态文件，禁止使用 Vite、Webpack、Rollup、esbuild 等任何打包构建工具。产出的文件必须可直接在浏览器中通过 `file://` 协议打开，无需任何服务器或构建步骤。
3. **禁止引入技术栈与重依赖（硬约束）** - 禁止引入任何框架或重型第三方依赖（React、Vue、Tailwind CSS 等）。所有页面以原生 HTML + CSS + JS 为基础实现，轻量级依赖按原则 4 处理。即使原型文档或需求文档中存在技术栈声明（`09-tech-stack.md`），禁止读取和遵守。
4. **依赖替代策略（硬约束）** - 原型文档中涉及的外部依赖按以下策略处理：
   - **重依赖**（框架、UI 组件库、图表库、地图 SDK、富文本编辑器等需要构建工具或运行时框架支撑的依赖）→ 用 `<div>` / `<span>` 占位代替，占位元素须标注原依赖名称和预期效果（如 `<div data-placeholder="echarts 图表：柱状图">图表区域</div>`），保持页面布局结构完整。
   - **轻量级依赖**（纯 CSS 库、图标字体、小型 JS 工具等无需构建工具即可通过 `<link>` / `<script>` 直接引入的依赖）→ 可直接通过 CDN 或本地文件引入，但须确保 `file://` 协议下可用；引入时标注依赖名称、固定版本和用途；CDN 引入须使用固定版本 URL（禁止 latest），建议附带 `integrity` 属性（SRI 校验）防止供应链篡改。
   - **判断标准**：能在 `file://` 协议下通过单个 `<link>` 或 `<script>` 标签直接引入并正常工作的为轻量级依赖；否则为重依赖，必须用占位代替。
5. **禁止参考项目资产（硬约束）** - 生成时禁止参考当前项目中除原型文档以外的任何资产。不扫描项目组件目录、不读取项目源码、不引用项目已有组件或样式。不读取 ae:design 产出的任何文档。
6. **颜色定义硬约束** - 必须完全遵守原型文档中声明的主题色和次要颜色。原型文档中的颜色定义（HEX 值）是页面配色的唯一真源，禁止自行推断或替换颜色。
7. **响应式硬约束** - 必须完全遵守原型文档中声明的响应式布局需求。原型文档声明响应式时必须实现对应的 media query 断点适配；声明非响应式时禁止添加任何响应式样式。
8. **产出隔离（硬约束）** - 每次还原产出隔离到 `ae/prototype-preview/<子目录>/` 下，不同需求、不同版本的原型预览互不覆盖。禁止直接生成到 `ae/prototype-preview/` 根目录。
9. **页面美化（硬约束）** - 在不违反原型文档明确声明的前提下，对页面进行合理美化：
   - **允许的美化**：合理的间距、圆角、阴影、过渡动画、hover 效果、字体层级、视觉留白、按钮和表单控件的现代化样式、卡片和容器的视觉层次等通用视觉优化。
   - **边界**：不得改变原型文档声明的页面数量、路由、布局区域划分、交互跳转、表单字段和必填规则、主题色和次要颜色 HEX 值、响应式行为；不得新增原型文档未声明的页面或功能模块。
   - **目的**：使原型预览更接近真实产品的视觉体验，便于验证产品逻辑而非仅验证结构骨架。

## 输入来源

按优先级识别输入：

1. **原型文档路径** - 用户直接提供 `prototype/01-prototype.md` 或 `prototype/` 目录路径时，直接使用。
2. **prd 目录路径** - 用户提供 `ae/prds/<topic>-YYYY-MM-DD/` 路径时，自动识别 `prototype/` 子目录。
3. **未传参** - 自动搜索 `ae/prds/` 下最新日期目录中的 `prototype/` 子目录。未找到时询问用户提供路径。

**自动搜索规则：** 在 `ae/prds/` 下按目录名日期降序排列，取最新目录的 `prototype/` 子目录。

## 产出子目录命名规则

每次还原产出隔离到 `ae/prototype-preview/<子目录>/` 下，子目录命名规则：

```
ae/prototype-preview/<topic>-<date>/
```

- `topic`：从 prd 目录名提取（如 `ae/prds/user-auth-2026-07-20/` → `user-auth`）
- `date`：从 prd 目录名提取日期（如 `2026-07-20`）
- 如直接传入原型文档路径，从路径向上追溯 prd 目录名提取；无法追溯时使用 `prototype-<YYYY-MM-DD>`（当前日期）

**示例：**
```
ae/prototype-preview/
├── user-auth-2026-07-20/       # user-auth 需求 7月20日版本
├── user-auth-2026-07-25/       # user-auth 需求 7月25日版本（同需求不同版本）
├── resource-mgmt-2026-07-20/   # resource-mgmt 需求 7月20日版本（不同需求）
└── ...
```

## 执行流程

```
步骤 0：识别输入来源 + 版本冲突检测
  ├─ 0.1 解析参数，确定原型文档路径
  ├─ 0.2 自动搜索（未传参时）
  ├─ 0.3 计算产出子目录名
  └─ 0.4 版本冲突检测与处理

步骤 1：读取原型文档，构建页面清单
  ├─ 1.1 读取 prototype/01-prototype.md 索引文件
  └─ 1.2 读取 prototype/NN-pages-*.md 页面描述文件

步骤 2：生成 HTML 静态文件
  ├─ 2.1 生成共享 CSS 文件（颜色定义 → CSS 变量）
  ├─ 2.2 逐页面生成 HTML 文件
  └─ 2.3 生成 index.html 导航入口

步骤 3：验收确认（可选）
  ├─ --no-inspect → 跳过
  ├─ --yes → 执行验收，不询问
  └─ 未传参 → 询问用户

步骤 4：输出总结
```

### 步骤 0：识别输入来源 + 版本冲突检测

#### 0.1 解析参数

- 位置参数路径包含 `prototype/` → 直接作为原型文档目录
- 位置参数为 `ae/prds/` 下的路径 → 拼接 `prototype/` 子目录
- 无位置参数 → 自动搜索

#### 0.2 自动搜索

在 `ae/prds/` 下按目录名日期降序排列，取最新目录的 `prototype/` 子目录。

#### 0.3 计算产出子目录名

按"产出子目录命名规则"计算目标子目录名。

#### 0.4 版本冲突检测与处理

检测 `ae/prototype-preview/<子目录名>/` 是否已存在：

**子目录不存在（首次还原或不同需求/不同版本）：**
- 直接进入步骤 1，产出到新子目录

**子目录已存在（同一原型的预览页面已生成过）：**
- **强制询问用户**（无论是否传入 `--yes`，版本冲突询问不可跳过）：

```
检测到该原型的预览页面已存在：ae/prototype-preview/<子目录名>/

请选择处理方式：
1. 更新已存在的预览页面 — 覆盖现有 HTML 文件，保留原目录
2. 隔离生成新版本 — 生成到新子目录 <子目录名>-v2/（如已存在 -v2 则递增 -v3、-v4...）
```

- 用户选择"更新" → 产出到原目录，覆盖现有文件
- 用户选择"隔离生成新版本" → 计算新子目录名（`<子目录名>-v2`，如已存在则递增），产出到新目录

### 步骤 1：读取原型文档，构建页面清单

#### 1.1 读取索引文件

读取 `prototype/01-prototype.md`，提取：

- **页面清单**（页面 ID、名称、路由、功能域）
- **路由表**
- **导航结构**（布局模式、导航项、面包屑规则）
- **主题声明**（主题色 HEX、次要颜色 HEX、色调、视觉风格关键词）
- **响应式声明**（是否响应式、断点定义）
- **file-plan**

#### 1.2 读取页面描述文件

读取 `prototype/NN-pages-*.md`，提取每页的：

- **布局结构**（区域划分、区域排列、区域用途）
- **交互流程**（点击什么 → 跳转哪里 / 触发什么）
- **页面元素清单**（元素、类型、必填、验证规则、所属区域）
- **响应式布局**（各断点下的布局变化描述，或"不支持响应式，固定布局"）

#### 1.3 页面清单去重与汇总文档识别（硬约束）

深入分析原型文档，识别并排除汇总文档，确保页面清单只包含真实的独立页面：

**汇总文档识别规则：**
- **汇总文档特征**：一个 `NN-pages-*.md` 文件的内容是对多个其他页面原型文档的汇总、索引或概述，而非描述一个独立的、有自身路由和布局的页面。典型特征包括：无独立路由（路由为空或指向其他页面）、无独立布局结构（仅列出其他页面的摘要）、内容以引用/链接/表格形式聚合其他页面信息。
- **独立页面特征**：有独立路由、有完整的布局结构描述、有自身的页面元素清单和交互流程。
- **判断方法**：逐个读取 `NN-pages-*.md` 文件，对照索引文件 `01-prototype.md` 中的页面清单和路由表，验证该文件描述的页面是否有独立路由和独立布局。若文件内容仅为其他页面的汇总且无独立路由，判定为汇总文档，从页面清单中排除。
- **排除处理**：汇总文档不生成对应的 HTML 文件，不计入页面数量，不出现在 index.html 导航入口中。汇总文档中的信息（如跨页面流程概述）仅作为理解全局交互的参考，不作为独立页面还原。

**最终页面清单 = 索引文件页面清单 - 汇总文档。** 校验最终页面数量与路由表条目数一致，不一致时回退人工确认。

### 步骤 2：生成 HTML 静态文件

所有文件生成到 `ae/prototype-preview/<子目录名>/` 目录下。

#### 2.1 生成共享 CSS 文件

生成 `<子目录>/styles.css`，包含：

- **CSS 变量定义（从主题声明转换，硬约束）：**
  - 主题色 → `--color-primary: #HEX`
  - 次要颜色 → `--color-background: #HEX`、`--color-text: #HEX`、`--color-border: #HEX`、`--color-text-secondary: #HEX`（对应次要文本色，用于辅助文字、占位符）、`--color-accent: #HEX` 等
  - 原型文档声明的所有颜色必须全部转换为 CSS 变量，禁止遗漏，禁止自行添加未声明的颜色
  - 原型文档中标注为"无"的颜色声明跳过对应 CSS 变量生成，不计入遗漏
- **全局重置样式**（box-sizing、margin、padding 归零 — 仅最小必要范围）
- **响应式 media query（从响应式声明转换，硬约束）：**
  - 原型声明响应式 → 按声明的断点生成 media query 基础设定
  - 原型声明非响应式 → 禁止生成任何 media query
- **导航结构样式**（从导航结构声明转换）

**禁止镀金：** 只生成原型文档中明确声明的颜色和样式，不添加文档未声明的颜色、通用样式或 CSS reset 超出最小必要范围的内容。

#### 2.2 逐页面生成 HTML 文件

为每个页面生成 `<子目录>/<page-name>.html`，包含：

- `<head>` 中引入 `styles.css` 和页面专属 `<style>`（如有）
- `<body>` 中的 HTML 结构（从布局结构文字描述还原）
- 页面专属 CSS（内联在 `<style>` 标签中，使用 `styles.css` 中定义的 CSS 变量）
- 交互 JS（内联在 `<script>` 标签中，从交互流程用原生 JS 实现）

**HTML 结构还原规则：**
- 按布局结构文字描述生成等效 HTML 结构：
  - "顶部区域：Logo + 页面标题" → `<header><img><h1></header>`
  - "中部区域：表单" → `<main><form></main>`
  - "底部区域：按钮 + 链接" → `<footer><button><a></footer>`
- 页面元素清单中的元素类型 → 对应 HTML 标签：
  - email input → `<input type="email">`
  - password input → `<input type="password">`
  - submit button → `<button type="submit">`
  - link → `<a href="...">`
  - text → `<span>` / `<p>`
  - image → `<img>`

**颜色使用规则（硬约束）：**
- 所有颜色必须通过 CSS 变量引用（`var(--color-primary)` 等），禁止硬编码 HEX 值
- 使用颜色时必须对应原型文档中声明的颜色用途（主题色用于主按钮/强调，次要颜色用于背景/文本/边框等）
- 禁止使用原型文档未声明的颜色

**响应式实现规则（硬约束）：**
- 原型声明响应式 → 按声明的断点实现布局适配（如移动端单列、桌面端多列）
- 原型声明非响应式 → 固定布局，禁止添加任何 `@media` 规则
- 响应式行为仅实现原型文档中明确声明的断点和布局变化，禁止自行添加未声明的断点

**交互还原规则：**
- 文档中写明的交互流程（如"点击登录按钮 → 提交表单 → 成功跳转 /resources"）用原生 JS 实现
- 跳转用 `window.location.href` 实现
- 表单验证用原生 HTML5 验证属性（`required`、`type="email"` 等）+ 原生 JS
- **禁止使用危险 API**：禁止使用 `eval`、`new Function`、`document.write`、`innerHTML`（赋值）、`outerHTML`（赋值）、`insertAdjacentHTML`、`setTimeout`（字符串参数）、`setInterval`（字符串参数）；动态更新 DOM 使用 `textContent`、`createElement` + `appendChild` 等安全 API 替代 `innerHTML`；从原型文档提取的文本内容在写入 HTML 前必须进行 HTML 实体转义（`<` → `&lt;`、`>` → `&gt;`、`"` → `&quot;`、`'` → `&#39;`、`&` → `&amp;`）；交互 JS 仅实现文档明确声明的跳转和表单验证，不执行动态代码生成
- **禁止实现文档未写明的交互**，即使该交互"显然应该有"（纯视觉反馈类 hover/过渡不属于此条约束，归入页面美化范畴，见核心原则 9；此条约束针对跳转、提交、数据变更等行为交互）

**禁止镀金检查清单（生成每个文件后逐项检查）：**
- [ ] 是否添加了文档未声明的页面或元素？
- [ ] 是否遗漏了文档明确声明的页面、元素或交互行为？（不少做）
- [ ] 是否添加了文档未声明的交互行为？
- [ ] 是否使用了文档未声明的颜色？
- [ ] 是否添加了文档未声明的响应式断点或行为？
- [ ] 是否引入了重依赖（框架/组件库/图表库等）而未用 div/span 占位代替？
- [ ] 引入的轻量级依赖是否可在 file:// 协议下直接工作？
- [ ] 是否使用了任何构建工具语法（如 import、JSX、TS）？
- [ ] 是否使用了危险 API（eval、new Function、document.write、innerHTML 赋值、outerHTML 赋值、insertAdjacentHTML、setTimeout/setInterval 字符串参数）或未对文本内容进行 HTML 转义？
- [ ] 是否引用了项目已有组件、样式或源码？（禁止参考项目资产）
- [ ] 是否写入到正确的隔离子目录？（产出隔离）
- [ ] 页面美化是否超出了原型文档声明的边界？（不得改变页面数量、路由、布局区域划分、交互跳转、表单字段、颜色 HEX 值、响应式行为）
- 任一项为"是"则移除多余内容或补充遗漏内容，仅保留文档写明的部分（允许的美化除外）。

#### 2.3 生成 index.html 导航入口

生成 `<子目录>/index.html`，包含：

- 所有页面的链接列表（按路由表顺序）
- 每个链接指向对应的 HTML 文件
- 简洁的页面标题和描述（从页面清单提取）
- 使用 `styles.css` 中定义的颜色变量（遵守颜色硬约束）

**禁止镀金：** index.html 只提供导航链接，不添加额外的欢迎页内容、样式美化或交互效果（除非原型文档中明确写了首页/落地页的设计）。

### 步骤 3：验收确认

**参数与验收确认规则：**

| 参数 | 验收行为 |
|----------|----------|
| `--no-inspect` | 跳过验收，不询问 |
| `--yes` | 执行验收，不询问 |
| 无参数 | 使用 `question` 工具询问用户是否执行验收 |

> 版本冲突询问（步骤 0.4）不受 `--yes` 影响，始终强制询问。

**验收方式：** 执行验收时，通过 `ae:playwright` 技能打开 `<子目录>/index.html`（`file://` 协议），逐页面截图验证。截图保存到 `ae/screenshots/prototype-preview/` 目录。验收项按优先级分级：

**P0 验收项（确定性边界核心，必须通过）：**
- 页面数量是否与原型文档一致
- 每页路由是否与原型文档路由表一致（文件名与路由对应）
- 颜色是否与原型文档声明的主题色和次要颜色 HEX 值一致（通过 getComputedStyle 验证 CSS 变量值）
- 响应式行为是否与原型文档声明一致（声明响应式时验证断点适配，声明非响应式时验证无 @media 规则）

**P1 验收项（重要，应通过）：**
- 每页布局结构是否与原型文档描述一致
- 导航结构是否与原型文档声明一致（布局模式、导航项）
- 表单字段类型和必填规则是否与原型文档页面元素清单一致
- 交互行为是否与原型文档写明的一致（跳转目标、表单提交、验证规则等逐项核对）
- 重依赖占位是否标注了原依赖名称和预期效果
- 轻量级依赖引入是否在 file:// 协议下正常工作

**P2 验收项（次要，尽量通过）：**
- 无控制台错误

验收发现差异时，对照原型文档修正 HTML 文件（仅修正与文档不一致的部分，不优化文档未提及的内容），重新验证。最多 2 轮返工。2 轮返工后仍有 P0 差异时，在输出总结中标注未解决的 P0 项为残余风险。

## 浏览器操作

仅当执行验收阶段（步骤 3）时需要浏览器操作。浏览器操作一律通过 `ae:playwright` 技能完成（`ae:prototype-preview` 的验收需求为对比原型文档与 HTML 产出，涉及 P0 级页面数量/路由/颜色 HEX/响应式声明校验，与 `@e2e-test-runner` 通用验收模式能力不匹配，因此直接调用 `ae:playwright`）。无法完成验收时标注"验收跳过"，不阻断 HTML 文件生成。

## 安全边界

- **禁止引入重依赖** — 框架、UI 组件库、图表库等重依赖用 div/span 占位代替；轻量级依赖（纯 CSS/图标字体等）可直接引入但须确保 file:// 可用
- **禁止使用任何打包构建工具** — 产出文件必须可直接 `file://` 打开
- **禁止参考项目资产** — 不扫描、不读取、不引用项目中除原型文档以外的任何文件
- **禁止读取 ae:design 文档** — 本技能不消费设计文档，仅消费 ae:prd 原型文档
- **禁止镀金** — 仅实现原型文档中明确写明的内容，不多做不少做；允许在不违反文档声明的前提下进行页面美化（间距、圆角、阴影、过渡等通用视觉优化）
- **禁止使用未声明的颜色** — 所有颜色必须来自原型文档的主题声明
- **禁止添加未声明的响应式** — 响应式行为必须与原型文档声明一致
- **禁止修改源文档** — 不修改原型文档，只读取并还原
- **禁止修改项目源码** — 所有产出仅写入 `ae/prototype-preview/<子目录>/` 目录
- **禁止跳过版本冲突询问** — 同原型已存在预览时必须询问用户，`--yes` 不可跳过此询问
- **禁止使用危险 API** — 禁止 eval/new Function/document.write/innerHTML 赋值/outerHTML 赋值/insertAdjacentHTML/setTimeout(setInterval)字符串参数；动态 DOM 更新使用 textContent/createElement+appendChild；文本内容写入 HTML 前必须 HTML 实体转义

## 不适用场景

- 需要真实前端开发实现 → 使用 `ae:work` 调度 `@ui-architect` 和 `@logic-weaver`
- 需要可交付的生产代码 → 使用 `ae:work`
- 需要引入技术栈和组件库 → 使用 `ae:work` 调度 `@ui-architect` 和 `@logic-weaver`
- 需要参考项目已有组件资产 → 使用 `ae:work` 调度 `@ui-architect` 和 `@logic-weaver`
- 需要验证 ae:design 页面设计文档 → 使用 `ae:work`（设计文档含技术栈，不适用本技能）

## 验证方式

- 产出的 HTML 文件可直接在浏览器中通过 `file://` 协议打开
- 页面数量、路由、布局结构、交互行为与原型文档一致
- 颜色与原型文档声明的主题色和次要颜色完全一致
- 响应式行为与原型文档声明完全一致
- 不同需求、不同版本的预览页面隔离在各自子目录，互不覆盖
- 无重依赖、无构建工具、无框架引入；轻量级依赖须确保 file:// 可用
- 验收通过（如执行）
