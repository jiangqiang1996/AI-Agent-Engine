# G4 数据模型 步骤摘要

## 目标

从 G1 不变量、G2 业务场景和 G3 架构决策推导完整数据模型，产出可直接生成 DDL 的实体、字段、关系、约束和状态机。DDL 禁止 FOREIGN KEY，引用用逻辑软约束替代。

## 核心规则

- 每条不变量必须映射为至少一条数据约束
- 禁止 FOREIGN KEY，引用用 logical_ref + `-- ref:` 注释声明
- 字段双源发现：不变量推导（derived）∪ 业务场景推断（inferred）

## 任务清单

| 任务 | 说明 |
|------|------|
| T1 基于 G2 field-catalog 合并字段集确认实体 | 合并 derived 和 inferred 字段集，不变量补充约束性实体 |
| T2 定义逻辑关联 | 1:1/1:N/M:N，logical_ref（非数据库外键），`-- ref:` 注释 |
| T3 定义约束 | 字段级/关系级/跨实体，级联仅逻辑声明，不生成 ON DELETE CASCADE |
| T4 定义状态机 | 有状态实体的状态迁移图：初始状态、合法状态、迁移路径、守卫条件 |
| T5 映射不变量到约束 | 每条不变量映射为数据约束，trace 标注 invariant_id |
| T6 标注端/模块归属 | 字段标注哪些端可读、哪些端可编辑，引用 g2/roles.md |
| T7 生成验证 DDL | CREATE TABLE + CHECK + UNIQUE + NOT NULL，禁止 FOREIGN KEY |
| T8 标注性能暗示 | 高频查询→索引、低延迟→缓存、高并发→锁策略，引用 g1/nfr.md |
| T9 执行 DDL 验证 | 建表+合法数据验证+非法数据验证 |
| T10 产物审查 | ae:review mode=autofix domain=document g4/，最多3次 |

## 验收关卡

| 编号 | 检查项 | 通过标准 |
|------|--------|---------|
| G4-K1 | 不变量有约束 | 每条不变量有对应约束且 trace 字段标注不变量 id |
| G4-K2 | CRUD 覆盖完整 | 每个实体的创建/读取/更新/删除路径存在或明确标注不适用 |
| G4-K3 | 实体归属明确 | 每个实体和字段标注端/模块归属 |
| G4-K4 | 状态机完整 | 有状态实体有完整状态机，无死锁，无不可达状态 |
| G4-K5 | 无孤儿字段 | 每个字段至少被一个端/模块引用 |
| G4-K6 | DDL 验证通过 | 建表成功，约束生效 |
| G4-K7 | 无遗漏实体 | 不变量涉及的所有名词均被建模 |
| G4-K8 | 性能暗示已标注 | 每个高频/高并发/低延迟场景有 performance_hints |
| G4-K9 | 字段双源闭合 | derived 可溯源至不变量，inferred 可溯源至场景 |
| G4-K10 | DDL 无外键 | DDL 中无 FOREIGN KEY 声明，引用仅用 -- ref: 注释 |
| G4-K11 | 文件行数合规 | 所有产物文件不超过 500 行 |
| G4-K12 | 产物审查通过 | ae:review autofix 审查通过 |

## 回退规则

- 不变量遗漏 → 回 G1 修正
- 业务场景遗漏 → 回 G2 补充场景
- 架构决策影响数据模型 → 回 G3 修正架构
- 数据模型内部问题 → 仅重做 G4

## 通用产物规格

- 单轨格式：YAML Frontmatter 为唯一真源，正文为人类阐释
- 文件行数硬约束：每个产物文件不超过 500 行
