# Web Forge

统一前端能力入口，整合自由设计、设计还原、交互逻辑与浏览器验收。本技能分析用户意图后，按需交错调度四个子代理完成任务，最多执行 3 轮修复+回归。

## 子代理

| 子代理 | 模型 | 职责 | 触发条件 |
|--------|------|------|----------|
| `@ui-architect` | $vision | 无 Figma 约束的自由 UI 设计实现与一轮视觉验证 | 用户要求自由设计、初版页面、组件设计 |
| `@ui-matcher` | $vision | 以 Figma 设计稿、截图或文字设计规格为准的精确还原实现 | 用户提供 Figma URL、设计截图或具体文字设计规格（布局、尺寸、颜色等） |
| `@logic-weaver` | $deep | 前端交互逻辑实现与 API 集成 | 用户要求实现交互功能、对接后端 API、表单逻辑 |
| `@browser-inspector` | $vision | 端到端浏览器测试与回归验证 | 用户要求浏览器验收、E2E 测试、交互验证 |

## chrome-devtools MCP 门禁

在执行任何浏览器操作前，必须先使用 `ae:chrome-devtools` 技能完成浏览器 MCP 动态注册并确认连接就绪；`ae:chrome-devtools` 是浏览器 MCP 的唯一管理入口，不应直接调用 `ae-chrome-devtools-mcp` 工具。MCP 未就绪时不得执行浏览器操作。

MCP 已在配置中声明、用户声称已配置或本地进程检查成功，都不能替代通过 `ae:chrome-devtools` 技能完成的注册确认。只有当 MCP 注册失败、用户拒绝启动或当前环境无法启动时，才记录"无法验收"并停止浏览器流程，不得继续执行浏览器操作命令。

## 工作流

### 步骤 1：意图分析

分析用户输入，确定需要调度的子代理及执行顺序：

**参数标记：**

- `--design`：强制使用 `@ui-architect`
- `--match`：强制使用 `@ui-matcher`
- `--logic`：强制使用 `@logic-weaver`
- `--inspect`：强制使用 `@browser-inspector`

**自动推断规则：**

- 用户要求"设计页面"、"做个界面"、"初版"且未提供具体设计规格 → `@ui-architect`
- 用户提供 Figma URL/截图、要求"还原设计稿"、"对齐设计"，或提供具体文字设计规格（如"采用xx布局，菜单宽xx像素，xx颜色"） → `@ui-matcher`
- 用户要求"实现交互"、"对接 API"、"表单逻辑" → `@logic-weaver`
- 用户要求"测试"、"验收"、"E2E"、"浏览器验证" → `@browser-inspector`
- 用户提供现有 HTML 文件路径（如 `ae/documents/html/xxx.html`、`./index.html`） → 根据用户附加意图选择：若要求"修改交互/对接 API"则进入 `@logic-weaver`（模式 5），若要求"验收/测试"则进入 `@browser-inspector`（模式 6），若要求"重新设计/还原"则按设计规格有无进入 `@ui-architect` 或 `@ui-matcher`（模式 1/2）
- 用户描述的复合需求可能需要多个子代理按顺序执行

### 步骤 2：子代理交错调度

按意图分析结果调度子代理。执行分为三个阶段，每个阶段对应一个子代理职责域：

**约束透传声明：**

主代理在调度任何子代理时，必须透传以下约束，子代理不得绕过：

- chrome-devtools MCP 门禁：涉及浏览器操作的子代理（`@browser-inspector`、`@ui-architect` 视觉验证、`@ui-matcher` 对比验证）必须先通过 `ae:chrome-devtools` 完成注册
- 截图保存路径：所有截图必须保存到 `ae/screenshot/` 目录
- 登录检测：打开目标页面后须执行登录检测流程
- 用户提供的具体约束（如 CSS 硬约束、设计规格、输出路径等）必须原样传递给子代理

**三阶段执行模型：**

- **执行阶段 1（视觉实现）**：`@ui-architect` 或 `@ui-matcher`，两者互斥，根据意图分析结果只调度其中一个
- **执行阶段 2（交互逻辑）**：`@logic-weaver`，仅当任务涉及交互功能、API 对接或表单逻辑时执行；无交互需求时跳过此阶段
- **执行阶段 3（浏览器验收）**：`@browser-inspector`，强制执行，不得跳过

**阶段间回退规则：**

- 进入执行阶段 2 时，`@logic-weaver` 需对发现的问题分类处理：
  - **结构缺陷**（缺少必要的 DOM 元素、选择器不可用、布局无法承载交互） → 回到执行阶段 1 修复视觉实现，修复后重新执行阶段 2（非从断点继续）
  - **交互实现问题**（事件绑定失败、API 对接错误、状态管理 bug） → 在阶段 2 内直接修复，不回退
- 进入执行阶段 3 时，若 `@browser-inspector` 发现问题，根据问题类型回退到对应阶段：
  - 视觉问题 → 回到阶段 1 修复
  - 交互/功能问题 → 回到阶段 2 调用 `@logic-weaver`
- 所有阶段的回退修复共享一个全局计数器，总计最多 3 轮回退修复+回归；1 轮 = 一次回退修复 + 一次回归验证；计数器由主代理（ae:web-forge）在跨 Task 调度时维护，不因子代理调用而重置；达到上限后仍有问题时输出剩余问题清单

**回退时视觉子代理选择：**

- 回退到执行阶段 1 时，复用该任务中首次调度的视觉子代理（`@ui-architect` 或 `@ui-matcher`），确保视觉风格一致性
- 对于跳过执行阶段 1 的调度模式（模式 5、模式 6），若回退需要进入执行阶段 1，则触发阶段 1 补执行，按自动推断规则选择视觉子代理，模式升级为完整三阶段流程
- 对于跳过执行阶段 2 的调度模式（模式 6），若回退需要进入执行阶段 2，则触发阶段 2 补执行，调用 `@logic-weaver` 处理交互问题

**典型调度模式：**

所有调度模式必须以 `@browser-inspector` 验收作为强制收尾步骤，不得跳过验收直接交付。

1. **纯设计**：执行阶段 1 `@ui-architect` → 执行阶段 3 `@browser-inspector`（跳过执行阶段 2）
2. **设计还原**：执行阶段 1 `@ui-matcher` → 执行阶段 3 `@browser-inspector`（跳过执行阶段 2）
3. **设计+交互**：执行阶段 1 `@ui-architect` → 执行阶段 2 `@logic-weaver` → 执行阶段 3 `@browser-inspector`
4. **还原+交互**：执行阶段 1 `@ui-matcher` → 执行阶段 2 `@logic-weaver` → 执行阶段 3 `@browser-inspector`
5. **已有设计+交互**：执行阶段 2 `@logic-weaver` → 执行阶段 3 `@browser-inspector`（跳过执行阶段 1，页面已存在只需实现交互）
6. **已有设计+验收**：执行阶段 3 `@browser-inspector`（跳过执行阶段 1 和 2，页面已存在只需浏览器验收）

每个模式中任意阶段发现问题均可按阶段间回退规则回到对应阶段重新执行。

**验收降级：**

仅当 chrome-devtools MCP 注册失败、用户拒绝启动或当前环境无法启动浏览器时，记录"无法验收"并停止流程，不得跳过验收直接交付。

## 截图保存路径

所有截图必须保存到 opencode 启动目录下的 `ae/screenshot/` 目录中。

截图前须确保目录存在：

```bash
mkdir -p ae/screenshot
```

```powershell
New-Item -ItemType Directory -Path ae/screenshot -Force | Out-Null
```

## 登录检测

在浏览器操作中打开目标页面后、截图前，检测目标页面是否需要登录。详细流程参考 `references/login-detection.md`。

检测信号：
- URL 包含 `/login`、`/signin`、`/auth`、`/oauth`
- 存在 `input[type="password"]` 密码输入框
- 存在包含"登录"、"Login"、"Sign In"文本的按钮

如检测到登录页面，执行登录等待流程，每 5 秒检测一次，最长等待 300 秒。

## 边界

**硬性约束：主代理严禁直接执行实现任务。** 本技能主代理（ae:web-forge 自身）严禁直接编写代码、编写测试、修改样式、实现交互逻辑或执行浏览器操作。所有实现任务必须且只能通过调度子代理（@ui-architect、@ui-matcher、@logic-weaver、@browser-inspector）间接完成。主代理职责仅限于：意图分析、子代理调度、结果汇总和修复回归编排。违反此约束属于执行错误。

不负责：
- 后端业务逻辑实现
- 数据库设计或迁移
- 非浏览器类测试

## 不适用场景

- 纯后端任务：使用 `ae:work`
- 文档审查：使用 `ae:review`
- 不涉及浏览器的代码开发：使用 `ae:work`
