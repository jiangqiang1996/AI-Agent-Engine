# LSM 设计

## 角色

把需求规格转成全方面详细设计，固定 `U-*` 实现映射和后续阶段入口。

## 适用场景

- 用户明确要求 LSM 链路、`ae:lsm-design` 或详细设计
- 已有显式 spec，需要继续生成设计
- 用户通过目标描述直接启动设计，无需上游 spec 文件
- 需要把需求映射到实现单元、验证单元和后续输入

## 不适用场景

- 需求尚未明确且无目标描述，应先执行 `ae:lsm-spec`
- 仅需要编码实现且无需设计决策时，可直接使用 `ae:lsm-build`

## 输入处理

1. 用户传入目标描述时，基于描述直接推导设计范围；目标描述是最基本的输入形式，无需任何上游文件
2. 用户显式传入 spec 路径时，以显式路径为准
3. 无显式输入时，根据当前会话讨论的主题，在工作区 `ae/lsm/spec/` 下搜索最符合的 spec 产物
4. 推测不到对应的 spec 产物时，要求用户传入目标描述或 spec 路径
5. 不自动选择历史目录中的产物，不默认扫描历史目录

## 执行流程

1. 解析输入：目标描述 / spec 路径 / 会话推测
2. 若输入为目标描述（无上游 spec）：根据描述推导设计范围、关键约束和实现单元，与用户确认后继续；此时 `R-*` 需求 ID 由本技能内联生成
3. 若输入为 spec 路径：读取 spec 和需求追溯表
4. 生成设计决策、接口边界、数据模型和实现单元
5. 固化 `U-*` 实现映射和风险说明，每个 `U-*` 映射到对应的 `R-*` 需求
6. 生成设计文档；文档过大时按模块或功能域拆分为多个子设计文件，主文件建立索引
7. 若存在任意 `U-*` 标记为"涉及 UI"：
   - 生成独立的 UI 设计子文件（`ui-design.md`），使用 `references/ui-design-template.md` 模板
   - UI 设计子文件承载项目级设计体系（设计令牌、组件规范、信息架构）和页面映射（`P-*`）
   - 每个"涉及 UI"的 `U-*` 在"UI 设计引用"字段中填写对应的 `P-*` 页面映射 ID
   - 主设计文件的"子文件索引"中列出 UI 设计子文件
8. 根据项目实际情况动态裁剪模板可选字段，裁剪标记使用 `<!-- trimmed: 原因 -->`
9. 调用 `ae:review domain=document scenes=design` 对 design 产物进行审查
10. 审查通过后，根据需求类型推荐下一步技能

## 产物要求

- 产物路径：`ae/lsm/design/`
- 主设计文件使用 `references/design-template.md` 作为结构参考，裁剪指引见 `references/lsm-trimming-guide.md`
- 元数据（上游路径、输入 ID、输出 ID、追溯表、验证证据、未验证项）全部由 frontmatter 承载，正文不含"元信息"章节
- 每个实现单元包含 `U-*` ID、需求映射、设计决策、接口边界及可选字段；可选字段按模板 trimmingGuide 裁剪
- 设计文档过大时拆分为多个子设计文件，主文件建立索引指向子文件
- 存在"涉及 UI"的实现单元时，必须生成 UI 设计子文件：
  - 子文件路径：`ae/lsm/design/ui-design.md`
  - 使用 `references/ui-design-template.md` 模板
  - 必须包含：设计令牌、信息架构与导航、页面映射（`P-*`）
  - 页面映射中的 `P-*` 与主文件的 `U-*` 通过"UI 设计引用"字段双向关联
  - 组件规范、交互状态、响应式、可访问性、动效、国际化按 trimmingGuide 条件裁剪
- **800 行硬限制**：单个产物文件不得超过 800 行（含 frontmatter）；超过时必须拆分为文件夹结构，文件夹自包含
- 拆分后文件夹包含索引文件 `index.md` 和子文件；索引文件承载完整 frontmatter 元数据和子文件索引表（文件名、范围、作用），可直接理解每个子文件
- UI 设计子文件超 800 行时按页面或功能域进一步拆分为 `ui-<scope>.md` 子文件
- 拆分规范见 `references/lsm-splitting-guide.md`

## 安全边界

- 不默认扫描历史目录找 spec
- 返工时仅修改本技能产物（design），不修改上游 spec 和下游产物
- 不新增远程写操作流程

## 完成标准

- 产物包含 `U-*` 实现映射
- 每个 `U-*` 映射到对应的 `R-*` 需求
- 存在"涉及 UI"的 `U-*` 时，UI 设计子文件已生成且包含 `P-*` 页面映射和设计令牌
- design 已通过 `ae:review` 审查，审查结论为 passed 或有明确的未阻断发现
- 下一步推荐：
  - 若需求涉及 UI → `ae:lsm-mockup`（视觉还原验证）
  - 若无 UI 需求 → `ae:lsm-test` 或 `ae:lsm-build`
  - 或重新执行 `ae:lsm-design` 返工
