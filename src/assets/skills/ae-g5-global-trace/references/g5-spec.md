# G5 全局数据推演 步骤摘要

## 目标

基于 G1 不变量、G2 业务场景、G3 架构决策和 G4 数据模型，用测试数据代入端到端场景，验证不变量在全局范围内成立。

## 核心规则

- 每个推演场景必须引用 G2 业务场景 ID
- 引用一致性验证为应用层校验（无 FOREIGN KEY）
- DDL 引用路径为 g4/ddl-verify.sql

## 任务清单

| 任务 | 说明 |
|------|------|
| T1 基于 G2 业务场景设计推演场景 | 基于 g2/business-scenarios/ 设计端到端场景，引用业务场景 ID |
| T2 构造测试数据 | given/when/then 三段式，正常值+边界值+异常值 |
| T3 逐场景推演 | 代入数据检查状态迁移+不变量+引用一致性 |
| T4 计算覆盖率 | 不变量覆盖率+状态迁移覆盖率，未覆盖清单 |
| T5 产物审查 | ae:review mode=autofix domain=document g5/，最多3次 |

## 验收关卡

| 编号 | 检查项 | 通过标准 |
|------|--------|---------|
| G5-K1 | 推演全通过 | 所有场景 pass |
| G5-K2 | 不变量覆盖 100% | 每条不变量至少 1 个场景覆盖 |
| G5-K3 | 状态迁移覆盖 100% | 每个迁移至少 1 个场景触发 |
| G5-K4 | 失败可定位 | 失败场景可定位到具体不变量或迁移 |
| G5-K5 | 场景来源可解析 | 每个推演场景引用 G2 业务场景 ID |
| G5-K6 | 文件行数合规 | ≤500 行 |
| G5-K7 | 产物审查通过 | ae:review autofix 通过 |
| G5-K8 | 人工审核通过 | 用户确认 |

## 回退规则

- 不变量问题 → 回 G1
- 业务场景遗漏 → 回 G2
- 架构问题 → 回 G3
- 数据模型问题 → 回 G4
- 推演逻辑问题 → 仅重做 G5

## 通用产物规格

- 单轨格式：YAML Frontmatter 为唯一真源，正文为人类阐释
- 文件行数硬约束：每个产物文件不超过 500 行
