# 保存会话执行流程

将当前会话中已经形成的执行流程提炼为可复用技能。默认保存为当前工作空间的项目级技能；当且仅当当前工作空间被确认是 `ai-agent-engine` 插件源码仓库时，按 AE 内置技能方式注册。

## 核心约束

1. 普通项目模式只允许写入 `.opencode/skills/<skill-name>/SKILL.md`，禁止写入全局技能目录。
2. 只有确认当前工作空间是 `ai-agent-engine` 插件源码仓库时，才允许修改 `src/assets/skills/`、`src/schemas/ae-asset-schema.ts` 和 `src/services/ae-catalog.ts`。
3. 普通项目技能必须符合 opencode 官方技能规范：目录名、frontmatter `name` 均为小写字母、数字和连字符组成的同一名称。
4. AE 内置技能使用本插件源码约定：目录名为 `ae-<name>`，frontmatter `name` 为 `ae:<name>`，命令名为 `ae-<name>`。
5. 写入任何文件前必须展示完整草案、目标路径、保存模式、同步文件和配套产物，并获得用户明确确认。
6. 默认只写 `SKILL.md`；只有流程确实需要稳定结构化接口时才新增工具，只有服务单个技能的重复本地处理才新增技能子目录脚本。

## 输入

可选参数：目标技能名或流程关注点。

如果用户未提供目标技能名，先根据会话流程生成一个简短的 kebab-case 技能名。

## 名称归一化

先把用户输入归一化为核心名 `<name>`，再按保存模式派生目录、frontmatter 和命令名。

| 用户输入 | 核心名规则 |
|---|---|
| `/ae-foo` | `foo` |
| `ae:foo` | `foo` |
| `ae-foo` | `foo` |
| `foo` | `foo` |
| 中文句子、动词短语、包含空格的描述 | 视为流程关注点，生成简短 kebab-case 核心名 |

派生规则：

- 普通项目模式：目录名和 frontmatter `name` 都使用 `<name>`。
- AE 内置技能模式：目录名为 `ae-<name>`，frontmatter `name` 为 `ae:<name>`，命令名为 `ae-<name>`。
- 不得生成 `ae-ae-*`、`ae:ae-*` 或目录名与 frontmatter 混用的结果。

## 快速路由

1. 先判定保存模式。
2. 普通项目模式写 `.opencode/skills/`，不修改插件源码注册文件。
3. AE 内置技能模式写 `src/assets/skills/`，并更新 schema、catalog 和帮助可见性链路。
4. 不确定保存模式时必须暂停并询问用户，不能继续设计草案。
5. 再判定配套产物：默认无；需要稳定结构化接口才新增工具；只服务技能内部才新增脚本。

## 保存模式判定

识别必须简单有效，优先使用少量高置信度信号，不做大范围扫描，不用模糊关键词猜测。

### 识别步骤

1. 确定当前工作空间根目录：优先使用运行环境提供的 workspace root；无法获取时使用当前 Git 仓库根目录；如果不在 Git 仓库内，则使用当前工作目录。
2. 读取根目录 `package.json`，检查 `name` 是否为 `ai-agent-engine`。
3. 检查两个最小源码注册锚点是否同时存在：`src/schemas/ae-asset-schema.ts` 和 `src/services/ae-catalog.ts`。
4. 如果仍不确定，再检查辅助锚点：`src/tools/index.ts`、`src/assets/skills/`、`opencode.json`、`src/assets/skills/ae-save-session-flow/SKILL.md`。

### 判定规则

- 直接判定为 AE 内置技能模式：`package.json` 的 `name` 为 `ai-agent-engine`，且两个最小源码注册锚点都存在。
- 直接判定为普通项目模式：`package.json` 不存在，或 `package.json` 的 `name` 明确不是 `ai-agent-engine`，且两个最小源码注册锚点都不存在。
- 必须询问用户确认：`package.json` 和源码注册锚点信号冲突，或当前工作空间看起来是更大仓库的子目录且无法确认根目录。

进入草案设计前，必须先给出判定摘要；如果判定结果为“需要用户确认”，必须暂停并提问：

```markdown
保存模式判定

- workspace root: <路径>
- package.json name: <不存在|值>
- src/schemas/ae-asset-schema.ts: <存在|不存在>
- src/services/ae-catalog.ts: <存在|不存在>
- 判定结果: <普通项目模式|AE 内置技能模式|需要用户确认>
- 理由: <一句话>
```

## 执行流程

### 第一步：提取会话流程

回顾当前会话，提取可复用的执行流程，而不是逐字记录聊天内容。

重点识别：

- 用户的原始目标和关键约束
- 助手采用的阶段划分
- 读取、搜索、编辑、验证、审查、门禁等关键动作顺序
- 用户确认点或必须暂停提问的节点
- 不能自动执行的操作边界
- 最终交付格式和验收证据
- 本流程未来复用时需要参数化的内容

必须排除：

- 一次性的文件路径，除非它们是流程本身要求的固定位置
- 临时调试输出
- 与流程无关的工具噪声
- 用户未确认的推测性规则

### 第二步：设计目标技能

草案必须包含：

- `name` 和 `description`
- 标题、适用场景、输入说明
- 分阶段执行流程
- 用户确认点
- 写入或修改文件时的边界
- 如需配套能力，明确工具或脚本的用途、输入、输出、调用时机和失败处理
- 完成后的汇报格式

如果流程会创建、修改或删除文件，必须明确要求在写入前展示草案并等待用户确认。

### 第三步：展示草案并请求确认

在写入任何文件前，向用户展示：

````markdown
计划创建技能：<目标路径>
保存模式：<普通项目模式|AE 内置技能模式>

```markdown
<完整 SKILL.md 草案>
```

计划同步的注册或文档文件：
- <文件 1>
- <文件 2>

计划创建的配套工具或脚本：
- <无|工具路径|脚本路径>

请选择：
1. 确认保存
2. 修改后保存：<修改意见>
3. 取消
````

明确确认包括：用户输入 `1`、`确认保存`、`保存`、`可以保存`、`按这个保存`、`没问题，保存`。不算明确确认：`看起来不错`、`继续`、`你觉得呢`、只提出修改意见但未明确说保存。

如果用户选择“修改后保存”，必须先根据修改意见生成修订版草案并再次展示；只有用户确认修订版后，才可写入。

### 第四步：处理冲突

如果目标技能、工具或脚本已存在，必须展示将被覆盖的目标路径和新草案，并询问用户选择覆盖、改名、合并或取消。选择合并时先读取旧文件，展示合并草案和冲突点，再次确认后写入。

### 第五步：写入技能

#### 普通项目模式

确认后执行：

1. 创建或更新 `.opencode/skills/<skill-name>/SKILL.md`。
2. 如需要脚本，在该技能子目录下创建脚本，并在 `SKILL.md` 中使用相对路径引用。
3. 如需要工具，写入 `.opencode/tools/<tool-name>.ts`，并在技能文档中写明工具名称、参数和调用时机。
4. 不得修改 `opencode.json`，除非用户明确要求。
5. 写入后读取文件，确认 frontmatter 和目录名一致；如创建工具或脚本，同时确认工具文件结构、脚本相对路径和技能文档引用一致。
6. 如无法自动验证工具加载或脚本运行，完成汇报中标记为“结构检查通过，运行时生效仍需重载或手动调用验证”。

#### AE 内置技能模式

确认后按本仓库公开技能定义方式同步注册：

1. 创建或更新 `src/assets/skills/ae-<name>/SKILL.md`，frontmatter 使用 `name: ae:<name>`。
2. 更新 `src/schemas/ae-asset-schema.ts`：在 `SKILL` 常量和 `AeSkillNameSchema` 中添加新技能常量；命令名通过 `COMMAND` 自动派生。
3. 更新 `src/services/ae-catalog.ts`：按现有技能顺序加入条目，使用 `SKILL.<KEY>`、`COMMAND.<KEY>` 和 `skillDir(SKILL.<KEY>)`。
4. 确保 catalog `description` 与 SKILL.md frontmatter 语义一致，`argumentHint` 与 `argument-hint` 字面一致。
5. 只有当统一 catalog 模板无法表达命令行为时，才新增 `src/assets/commands/ae-<name>.md`。
6. 新增公开技能必须确保 `/ae-help` 可发现；不要在 README 或用户手册中手写完整重复清单。
7. 如新增工具，按本仓库工具创建方式实现，并补充工具、服务或 schema 测试。
8. 运行验证命令，至少包含 `npm run typecheck`；若改动 TypeScript 注册、命令模板、工具、服务、schema 或文档生成逻辑，应优先运行 `npm run test` 和 `npm run build`。
9. 写入后读取关键文件，确认技能名、目录名、catalog、命令名、工具名、脚本路径和文档说明一致。

不得只把技能写入 `.opencode/skills/` 后宣称完成；在 AE 内置技能模式下，`src/assets/skills/` 是受版本控制的公开技能真源。

### 第六步：完成汇报

保存成功后，按以下格式汇报：

```markdown
已保存技能：`<目标 SKILL.md 路径>`

保存模式：<普通项目模式|AE 内置技能模式>
技能名：`<skill-name>`
用途：<description>
同步文件：<如适用，列出 schema/catalog/commands/README/usage-guide>
配套产物：<无|工具|脚本及路径>
验证：<列出已运行命令，并说明 frontmatter、目录名、命令名和文档一致性检查结果>
```

如果用户取消，明确说明未写入任何文件。

## 质量标准

- 技能描述必须面向未来复用，而不是只描述本次会话。
- 流程步骤必须可执行、可验证。
- 用户确认点必须清晰，不得把确认隐含在流程中。
- 普通项目模式生成的技能不得依赖本插件源码仓库的动态注册能力。
- AE 内置技能模式必须纳入本仓库的正式注册链路，确保命令、帮助和文档同步可发现。
- 配套工具必须有清晰的 LLM 可调用接口；配套脚本必须保持在技能子目录内，避免污染项目级公共工具。
