# OpenCode 代理规范摘要

## 路径

- 项目级代理：`.opencode/agents/<name>.md`。
- 全局代理：`~/.config/opencode/agents/<name>.md`。
- Markdown 文件名就是代理名，例如 `code-reviewer.md` 对应 `code-reviewer`。
- AE 插件源码中的 `src/assets/agents/` 只用于维护内置代理，不是普通用户代理路径。

## 创建与更新目标解析

- 创建新项目级代理时，如果项目级目标已存在，停止并询问改为更新、换名或取消。
- 创建新项目级代理时，如果项目级目标不存在但全局同名代理存在，说明项目级代理会遮蔽全局代理，询问创建项目级影子代理、改为更新全局代理、换名或取消。
- 更新项目级代理时，如果项目级目标不存在但全局同名代理存在，说明项目级不存在，询问是否改为全局更新或改为创建项目级代理。
- 更新全局代理时，写入前必须说明全局影响范围并取得确认。
- 更新但未指定 scope 时，同时检查项目级和全局级同名候选；两个都存在时列出路径并让用户选择，选择全局时再次确认影响范围。
- 更新目标不存在时，不自动转为创建；询问修正名称、切换 scope 或改为创建。

## 更新草案格式

更新既有代理前，先读取旧文件并展示草案。草案至少包含：

- 目标路径和 scope。
- frontmatter 变化表，列出旧值、新值和变化原因。
- 正文增删摘要。
- 将删除或重写的旧段落。
- 敏感字段或正文指令变化。
- 同级命令检查结果。
- 写入前确认问题。

写入前保留旧内容作为本轮会话内恢复依据。校验失败时报告失败原因；如果修复涉及语义、权限或命令绑定变化，必须再次确认后再写入。

## 必填字段

- `description`：代理用途和触发场景的简短描述。
- `mode`：代理模式，建议显式写入，避免默认 `all` 带来过宽触发范围。

## 常用可选字段

- `model`：覆盖代理使用的模型。
- `temperature`：控制随机性，分析类代理通常使用较低值。
- `top_p`：控制响应多样性，可作为温度替代。
- `steps`：限制最大代理迭代次数。
- `disable`：禁用该代理。
- `prompt`：引用或指定自定义系统提示词；Markdown 代理通常直接用正文作为提示词，只有确需外部提示词文件时才写入。
- `tools`：启用或禁用工具。
- `permission`：控制 `edit`、`bash`、`webfetch` 等权限。
- `hidden`：只适用于 `mode: subagent`，用于从自动补全菜单隐藏代理。
- `color`：配置 UI 显示颜色，可使用十六进制颜色或主题色。
- 其他模型或提供商选项：OpenCode 会直接传递给模型提供商；只有用户明确要求并能说明用途时才写入。

这些字段都是可选支持项，不要求创建或更新代理时同时配置。默认只写入完成目标所需的最小 frontmatter。

## 模式选择

- `subagent`：适合按需委派的专业代理，是本技能默认值。
- `primary`：适合用户直接切换并持续对话的主代理。
- `all`：同时作为主代理和子代理可用，只有明确需要两种入口时才使用。

## 命令绑定

- 项目级命令：`.opencode/commands/<name>.md`。
- 全局命令：`~/.config/opencode/commands/<name>.md`。
- 命令 frontmatter 使用 `agent: <name>` 绑定代理。
- 若命令应强制作为子任务运行，可以设置 `subtask: true`。
- 若命令需要覆盖模型，可以设置 `model`。
- 命令正文保留 `$ARGUMENTS`，用于透传用户参数。
- 更新代理时默认只检查同级同名命令，不跨 scope 搜索或修改命令。
- 项目级代理只检查项目级命令目录，全局级代理只检查全局命令目录。
- 当代理职责、名称或输入约定变化时，在同一 scope 的命令目录中搜索 `agent: <name>` 的非同名绑定并报告风险。
- 命令存在时检查 `agent: <name>`、`$ARGUMENTS` 和描述是否仍匹配代理职责。
- 命令不存在时只报告“未发现同级命令”，不默认创建。
- 命令绑定错误或描述过期时默认报告风险；只有用户明确要求同步时，才展示命令草案并确认写入。

## 字段边界

- 不生成 `maxSteps`，该字段已弃用，应使用 `steps`。
- `hidden` 仅用于 `mode: subagent`。
- 不指定 `mode` 时 OpenCode 默认可能为 `all`，因此本技能生成文件时必须显式写入 `mode`。
