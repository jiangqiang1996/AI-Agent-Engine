# ae:video — 视频内容识别

将本地视频转换为 Markdown 描述。通过内置 `ae-video` 工具调用 `modelScenarios.video` 配置的模型实现，无需安装额外依赖。

## 适用场景

- 用户需要理解视频内容（将视频转为文字描述供 LLM 阅读）
- 用户明确要求将视频内容持久化为 Markdown 文件
- 当前模型不支持直接读取视频文件时，用本技能替代直接读取
- 需要定向识别视频特定内容时，通过 prompt 参数指定识别重点
- 教程视频、会议录屏、监控片段、短视频等场景的内容分析和字幕生成

## 不适用场景

- 模型支持读取视频且只需查看/理解视频内容时，应直接使用 Read 工具读取，禁止调用本技能
- 不支持图片、音频等非视频格式
- 不支持远程 URL，仅处理当前工作区内本地文件

## 关键约束

- **模型不支持视频输入时禁止使用 Read 工具读取视频**：Read 工具读取 MP4/WebM 等视频文件时，如果当前模型不支持视频输入，会报错。此时必须通过本技能转换，不得尝试直接 Read 视频文件。
- **自动调用，不询问用户**：当检测到模型不支持视频输入、或 Read 读取视频报错时，必须立即自动调用本技能，不得向用户提问是否调用、不得列出可选方案让用户选择、不得停下来等待用户确认。直接调用，拿到结果后继续完成任务。

## 模型配置

识别视频使用的模型通过 `ae.jsonc` 的 `modelScenarios.video` 配置：

```jsonc
{
  "modelScenarios": {
    "video": "google/gemini-2.0-flash"
  }
}
```

未配置时，由 opencode 自行分配当前默认模型。建议配置支持视频输入的多模态模型（如 `google/gemini-2.0-flash`、`google/gemini-2.5-pro` 等）。

## 核心工作流

1. 接收用户提供的视频文件路径和识别提示词（prompt 参数）
2. 检测视频格式（MP4/WebM/AVI/MOV/MKV/FLV）
3. 读取视频内容，调用 `modelScenarios.video` 配置的模型识别
4. 将识别结果作为 Markdown 直接返回（不附加元数据）
5. 根据 outputMode 参数决定输出方式：
   - `file`（默认）：写入 `ae/markdown/` 目录（或用户指定的 outputPath）
   - `inline`：直接返回 Markdown 内容，不写文件

## 调用纪律

- 单次调用只处理一个文件；需要批量处理时逐一调用或建议用户使用脚本
- outputMode=file 时转换结果自动写入 `ae/markdown/` 子目录，文件名规则：`video-to-markdown-<时间戳>-<随机串>.md`
- prompt 参数指定时，覆盖默认识别提示词，用于定向识别
- 不需要用户确认即可执行（只读操作，不修改原视频）
- **file 参数必须是真实、完整、物理存在的路径**：禁止仅传文件名。路径来源不确定时，先用 `glob` 或 `bash` 的 `Test-Path`/`ls` 确认文件物理存在再调用。被 `.gitignore` 忽略的文件只要物理存在就应正常处理，不得以 Git 状态判断存在性

## prompt 参数使用指南

prompt 参数是本技能的核心能力，用于控制识别重点和输出质量。不同场景应使用不同的 prompt：

### 通用视频识别

未提供 prompt 时使用默认提示词，适合通用场景的视频内容描述（场景时间线、对话旁白、字幕文字、动作事件等）。

### 字幕生成场景

**完整字幕转写：**

```
prompt=为这段视频生成完整字幕。按时间戳分段输出，格式为"MM:SS - MM:SS: 字幕内容"。保留所有对话和旁白，逐字转写，不总结。标注说话人（如可识别）。
```

### 定向识别场景

**教程视频步骤提取：**

```
prompt=这是一段操作教程视频。请按步骤提取操作流程：每个步骤标注时间点、操作动作、关键界面元素。以编号列表输出，每步一句话概括动作。
```

**监控片段事件分析：**

```
prompt=这是一段监控视频。请按时间线记录所有异常事件：标注发生时间、事件类型（人员/车辆/物体）、运动方向、持续时长。无异常时段简要标注"无异常"。
```

**会议录屏内容结构化：**

```
prompt=这是一段会议录屏。请按议程结构输出：每个议题标注开始时间、讨论要点、决议结论。屏幕共享内容单独标注"屏幕共享: [内容描述]"。
```

### prompt 编写原则

1. **明确识别目标**：清楚说明需要从视频中获取什么信息（字幕 vs 事件 vs 步骤）
2. **时间线意识**：视频是时序媒体，prompt 中应说明是否需要时间戳标注
3. **结构化要求**：使用编号列表或格式约定指定输出结构
4. **保留原文**：要求"逐字"保留对话和旁白内容，不总结、不改写
5. **格式约束**：指定输出格式（时间线、列表、表格等）
6. **上下文说明**：说明视频来源（教程/会议/监控等），帮助模型理解识别重点

## 输出

返回 Markdown 格式的视频描述，包含：
- outputPath：写入的 Markdown 文件路径（outputMode=file 时存在）
- content：视频内容的 Markdown 描述

## 边界

- 仅处理当前工作区内本地视频文件（MP4/WebM/AVI/MOV/MKV/FLV）
- 不处理远程 URL
- 不处理图片、音频等非视频格式
- 视频文件不存在时返回友好提示
- 视频过大时返回提示并建议裁剪或压缩
