# L2 步骤摘要

## 目标

各模块在 A1 契约约束下，并行完成内部逻辑设计，产出可直接指导编码的设计文档。

## 执行方式

各模块并行，互不阻塞。每个模块只读取自己参与的契约，不依赖其他模块的内部设计。

## 任务清单（每模块独立执行）

| 任务 | 说明 |
|------|------|
| T1 确认职责范围 | 读取 contracts/index.md 中 source 或 target 为本模块的契约条目，确认职责边界 |
| T2 设计内部逻辑 | API路由/消息处理/定时任务/业务计算/数据访问，含 preconditions 和 postconditions |
| T3 设计数据库表结构 | 基于 data-model 中归属本模块的实体，生成完整 DDL + 索引 + 分区策略 + 性能暗示 |
| T4 设计接口实现 | 参数校验规则、错误码和错误响应格式、重试策略和降级方案 |
| T5 设计状态管理 | 基于 state-machines 实现状态迁移守卫逻辑 |
| T6 填写契约合规声明 | 逐条声明本模块在契约中的角色和已满足的 obligations |
| T7 编写内部推演用例 | 每条逻辑至少1个正常路径，每条前置条件至少1个违反用例，每个不变量至少1个守卫用例 |

## 验收关卡（每模块独立执行）

| 编号 | 检查项 | 通过标准 |
|------|--------|---------|
| L2-K1 | 无跨模块硬编码 | 外部引用指向 A1 契约，不硬编码其他模块内部 |
| L2-K2 | 契约合规完整 | 本模块参与的所有契约 obligations 均已满足 |
| L2-K3 | DDL 可执行 | ddl.sql 与 data-model 中本模块实体一致 |
| L2-K4 | 状态机一致 | 与 state-machines 一致 |
| L2-K5 | 界面对应 | 如有界面，与 ui-spec 中本模块视图一一对应 |
| L2-K6 | 不变量有实现 | 本模块范围的不变量全部有实现条目 |
| L2-K7 | 指纹一致 | upstream_fingerprints 与全局+关联阶段产物一致 |
| L2-K8 | 文件行数合规 | 所有产物文件不超过 500 行 |

## 回退规则

- 契约理解偏差 → 回 A1 澄清契约
- 模块内部设计错误 → 仅重做本模块受影响子文件

## 通用产物规格

- 单轨格式：YAML Frontmatter 为唯一真源，正文为人类阐释
- 文件行数硬约束：每个产物文件不超过 500 行
