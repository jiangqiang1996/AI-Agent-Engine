# 迭代任务循环

目标驱动的自包含迭代执行器。内联实施 + ae:review 审查闭环，不委派子代理实施，不产出需求/设计文档。

**适用场景：** 探索性调试、环境搭建、遗留代码修复
**不适用场景：** 有明确计划 → `ae:work`；需求不明确 → `ae:prd`；代码审查 → `ae:review`

## 核心原则

1. **交互全部前置** — Phase 0 解决所有用户问题，此后直至 Phase 3 禁止 `question` 工具或任何形式提问
2. **成功条件锁死** — Phase 0 确认的成功条件列表不可在循环中修改；条件有误属于瓶颈退出
3. **原始目标为真** — 用户原始目标文本作为实施依据
4. **内联实施** — 所有变更由本会话直接执行（编辑文件、运行命令），禁止委派子代理实施
5. **ae:review 审查闭环** — 每轮变更后调用 ae:review mode=autofix，审查发现驱动修复
6. **双重退出校验** — ae:review 无阻断发现 AND 成功条件全部达成，两者独立校验不互蕴含
7. **遇到歧义自行决策** — 循环体中不确定情况自行选择最优解，不得暂停或退出

## 输入

<goal> #$ARGUMENTS </goal>

如果 `<goal>` 为空，询问用户："你想完成什么目标？"

**ae:work 排除规则：** 输入解析时无视 `ae:work` 或 `/ae-work` 前缀，不作为执行技能注入；全流程禁止调用 ae:work 技能。

## 工作流

### Phase 0：准备（允许交互）

#### 0.1 解析用户目标 — 解读 `<goal>`，识别核心意图与约束
#### 0.2 扫描项目状态 — 扫描相关文件/代码/配置，返回：是否有相关实现（是/否）+ 实现概况，供 Phase 1 条件性跳过判定
#### 0.3 预分析提问 — 分析目标歧义，将问题分为不可默认项（需用户确认）和可默认项（采用建议默认值）。无歧义时可为空
#### 0.4 收集用户回答 — 使用 `question` 工具逐条确认不可默认项
#### 0.5 推导成功条件 — 推导 3-8 条可客观验证的成功条件，格式 `SC-N: 描述`
#### 0.6 展示确认清单 + 用户确认 — 展示目标解读、项目状态、交互答案、成功条件列表；用户确认后锁死

> **Phase 0 结束。⛔ 此后直至 Phase 3，禁止任何用户交互。**

### Phase 1：条件性首次实施

根据 0.2 扫描结果：**无相关实现** → 内联实施首次变更（直接编辑文件、运行命令）；**已有相关实现** → 跳过 Phase 1。完成后无条件进入 Phase 2。

### Phase 2：内联实施 + ae:review 循环（禁止交互）

**参数：** 上限 30 轮，瓶颈阈值连续 3 轮无新增达成的成功条件。一轮 = 一次完整的"内联变更 → ae:review mode=autofix"调用。

#### Step 1：内联变更

变更触发来源为双重路径：
- (a) 上轮 ae:review 有未通过项 → 根据审查发现内联修复
- (b) 审查通过但成功条件未全部达成 → 针对未达成条件内联实施
- 首轮触发：Phase 1 跳过时以成功条件未达成为触发源；Phase 1 已执行变更时可直接进入 Step 2 审查

变更策略由 LLM 自主决策。禁止提问，禁止调用 ae:work。

#### Step 2：ae:review mode=autofix

- **软件任务**（涉及代码文件变更）：`ae:review mode=autofix goals=<成功条件列表>`（默认 domain=code）
- **非软件任务**（无代码变更）：`ae:review mode=autofix domain=document goals=<成功条件列表>`
- **混合任务**：按软件任务处理，审查范围描述同时包含代码和文档质量方向
- 成功条件列表通过 `goals=` 参数传入 ae:review，激活 goal-alignment-reviewer 逐条校验变更是否达成各项目标

**失败处理：** ae:review 整体失败（技能不可用等）时管道中止，报告已完成步骤、失败步骤和原因；部分专精代理失败时以已有审查发现继续，在最终报告标注未完成审查维度。

#### Step 3：退出判定

每轮结束后更新追踪状态：对照成功条件列表逐条校验当前项目状态，有新增达成则瓶颈计数归零，无新增则 +1。

**独立校验两项：** ① ae:review 无阻断发现 ② 成功条件全部达成（逐条检查，非由审查结论蕴含）。两项同时满足 → Phase 3（全部通过 ✅）。

不满足时按优先级：
| 优先级 | 条件 | 动作 |
|--------|------|------|
| 1 | 瓶颈计数 ≥ 3（连续 3 轮无新增达成的成功条件） | Phase 3（瓶颈退出 ⚠️） |
| 2 | 轮次 ≥ 30 | Phase 3（上限退出 ⚠️） |
| 3 | 其他 | → 回到 Step 1 |

#### → 回到 Step 1

### Phase 3：退出处理（允许交互）

**全部通过 ✅** — 输出 DONE，逐条列出每条成功条件的通过证据（文件路径、代码片段或测试结果）。

**瓶颈退出 ⚠️** — 展示诊断摘要（总轮次、通过/未通过条件、可能原因），`question` 提供选项：继续尝试 / 结束任务 / 切换方案。

**上限退出 ⚠️** — 展示进度摘要（总轮次 30、通过/未通过条件、最近 3 轮变化趋势），`question` 提供选项：继续尝试 / 结束任务 / 切换方案。
