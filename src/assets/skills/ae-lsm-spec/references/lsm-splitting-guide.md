# LSM 需求规格产物拆分策略

需求规格产物的核心实体是 `R-*` 需求条目，每条包含描述、验收标准、优先级、约束与假设和下游映射。拆分时按功能域或模块分组，保证同一功能域的需求完整性。

## 行数限制

单个产物文件不得超过 800 行（含 frontmatter）。超过时必须拆分为文件夹结构。

## 拆分维度

按功能域或模块分组 `R-*` 条目。同一功能域的需求条目放在同一子文件中，不跨域拆分同一逻辑单元。

## 目录结构

```
ae/lsm/spec/
└── <project-name>/
    ├── index.md               # 索引文件
    ├── user-management.md     # 功能域：用户管理的 R-* 条目
    ├── order-service.md       # 功能域：订单服务的 R-* 条目
    └── ...
```

## 索引文件

索引文件 `index.md` 是文件夹的入口，必须包含：

1. **完整 frontmatter**：与未拆分产物相同的元数据，附加 `splitFrom`（原单文件名）和 `totalFiles`（子文件数量）
2. **需求概述**：一段话描述整个需求的目标、范围和关键约束
3. **子文件索引表**：列出每个子文件的文件名、涵盖的 `R-*` ID 范围和作用描述

```markdown
---
lsmKind: spec
upstreamRefs: [...]
traceTable: { ... }
trimmingGuide: { ... }
splittingGuide: { ... }
splitFrom: <project-name>.md
totalFiles: <N>
---

# LSM Spec: [项目名称]

## 需求概述

[一段话描述整个需求的目标、范围和关键约束]

## 子文件索引

| 文件名 | 范围 | 作用 |
|--------|------|------|
| user-management.md | R-001 ~ R-003 | 用户管理功能域的完整需求条目 |
| order-service.md | R-04 ~ R-07 | 订单服务功能域的完整需求条目 |
```

## 子文件

每个子文件必须包含：

1. **轻量 frontmatter**：`lsmKind: spec` 和 `parentIndex: ./index.md`
2. **该功能域的完整需求条目**：描述、验收标准、优先级、约束与假设、下游映射

```markdown
---
lsmKind: spec
parentIndex: ./index.md
---

# 用户管理

## R-001: 用户注册

[完整需求条目内容]
```

**禁止拆断单个 `R-*` 条目**：每个需求条目的描述、验收标准、优先级、约束与假设必须完整存在于同一子文件中。

**跨域约束**：术语表、上游依赖、安全约束、技术栈约束、非目标等跨域章节放在索引文件中，所有子文件共享。

## 拆分触发

1. AI 生成产物时，先评估预估行数；若预计超过 800 行，直接按拆分结构生成
2. 生成过程中发现行数超限时，暂停并重构为拆分结构
3. 拆分时优先按功能域边界分组，保持每个子文件内需求条目的逻辑完整性
