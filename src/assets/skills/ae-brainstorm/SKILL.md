# 头脑风暴

`ae:brainstorm` 使用多个子代理从不同视角对同一主题进行多轮讨论，然后汇总讨论结果。

此技能只做一件事：**多角度发散讨论 → 汇总**。不产出持久文档，不做需求澄清，不做路由决策。当讨论结果需要沉淀为正式需求文档时，由调用方转交 `ae:prd`。

## 核心原则

1. **多视角** — 每轮讨论至少从 3 个不同视角出发，确保观点多样性。
2. **多轮迭代** — 后续轮次的子代理能看到前序轮次的输出，在其基础上补充、质疑或提出新角度。
3. **汇总而非收敛** — 汇总阶段如实呈现各视角的观点、分歧和共识，不替用户做取舍。
4. **不产出持久产物** — 讨论结果以会话内摘要呈现，除非用户明确要求，不写文件。

## 讨论视角

每轮讨论从以下视角中选取至少 3 个，根据主题性质组合：

| 视角 | 关注点 |
|------|--------|
| **乐观派** | 最好的可能结果、最大价值、机会窗口 |
| **批评者** | 风险、失败模式、隐藏假设、最坏情况 |
| **实用主义者** | 可行性、成本、时间约束、现有基础 |
| **创新者** | 非常规角度、类比、约束移除、横向想法 |
| **系统思维** | 长期影响、二阶效应、与其他系统的交互、持久能力 |

## 执行流程

### 阶段 1：准备

1. 确认讨论主题。如果主题过于宽泛，与用户对齐讨论边界。
2. 根据主题性质选择本轮讨论视角（至少 3 个）。

### 阶段 2：多轮讨论

默认进行 2-3 轮讨论。用户可在任意轮次后要求继续或停止。

**每轮讨论：**

1. 为每个选定视角派发一个子代理（使用 Task 工具，subagent_type 选择 `general`）。
2. 每个子代理的 prompt 包含：
   - 讨论主题
   - 该视角的关注点和角色设定
   - 前序轮次所有视角的输出摘要（首轮无此项）
   - 指令：从该视角出发，对主题进行发散讨论；如有前序轮次，在其基础上补充、质疑或提出新角度
3. 收集所有子代理的输出。

**并行调度硬约束**：你必须在同一轮回复中一次性发出所有视角的 Task 工具调用，禁止等上一个 Task 返回后再发出下一个。如果平台不支持在一条消息中发出多个工具调用，则退化为逐个发出，但不得因此跳过任何一个视角。发出调用前必须完整列出本轮计划调度的所有视角和对应代理，然后逐一确认每个都已发出调用，不允许只调了一部分就停下来。

**调度完整性自检**：在生成包含所有 Task 调用的回复时，逐个确认：本轮选定的每个视角是否都已包含在本次回复的 Task 调用中？如果有遗漏，立即补充发出。降级逐个发出模式下，自检在每条回复发出前确认尚未调度的视角是否已全部排入后续队列。

**轮次间：** 将本轮所有视角的输出整理为摘要，作为下一轮的输入。

### 阶段 3：汇总

1. 综合所有轮次、所有视角的讨论结果。
2. 识别：
   - **共识** — 多个视角一致认同的观点
   - **分歧** — 视角间持不同立场的议题
   - **盲区** — 所有视角都未充分讨论的方面
3. 呈现汇总结果，包含：各视角关键观点、共识列表、分歧及各方立场、盲区提示。
4. 给出简短摘要：讨论了什么、主要发现、仍不确定的内容。

除非用户明确要求，否则不写文件。
