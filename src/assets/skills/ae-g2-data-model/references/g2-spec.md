# G2 步骤摘要

## 目标

从不变量推导出完整的实体、字段、关系、约束和状态机，产出可直接生成 DDL 的数据模型。

## 任务清单

| 任务 | 说明 |
|------|------|
| T1 提取实体 | 从不变量中提取业务概念，检查隐含实体（如"库存不可为负"→必须有 Inventory 实体） |
| T2 定义字段 | 字段名、类型、必填/选填、默认值、枚举值、约束、端/模块归属 |
| T3 定义关系 | 1:1/1:N/N:M，级联删除/更新规则，业务含义 |
| T4 定义状态机 | 有状态实体的状态迁移图：初始状态、合法状态、迁移路径、触发条件、守卫条件、不可达状态标注 |
| T5 映射不变量到约束 | 每条不变量映射为数据模型中的具体约束，用 trace 字段标注 invariant_id |
| T6 标注端/模块归属 | 每个字段标注哪些端可读、哪些端可编辑 |
| T7 生成验证 DDL | CREATE TABLE + CHECK + 外键 + 唯一索引 |
| T8 标注性能暗示 | 高频查询→索引、低延迟→缓存、高并发→锁策略、批量导入→数据量级 |

## 验收关卡

| 编号 | 检查项 | 通过标准 |
|------|--------|---------|
| G2-K1 | 不变量映射完整 | 每条 G1 不变量在 data-model 中有对应约束强制执行 |
| G2-K2 | CRUD 覆盖完整 | 每个实体的创建/读取/更新/删除路径存在或明确标注不适用 |
| G2-K3 | 状态机无死锁 | 从初始状态可到达所有合法状态，无不可达状态 |
| G2-K4 | DDL 可执行 | ddl-verify.sql 在目标数据库中执行成功 |
| G2-K5 | 无孤儿字段 | 每个字段至少被一个端/模块引用 |
| G2-K6 | 指纹一致 | upstream_fingerprints 与 G1 产物 content_hash 一致 |
| G2-K7 | 文件行数合规 | 所有产物文件不超过 500 行 |

## 回退规则

- 实体遗漏或定义错误 → 回 G1 补充不变量/实体，再重做 G2
- 字段/关系/约束错误 → 仅重做 G2 受影响子文件

## 通用产物规格

- 单轨格式：YAML Frontmatter 为唯一真源，正文为人类阐释
- 正文不允许出现 Frontmatter 中不存在的实体名、字段名、规则名
- 文件行数硬约束：每个产物文件不超过 500 行
