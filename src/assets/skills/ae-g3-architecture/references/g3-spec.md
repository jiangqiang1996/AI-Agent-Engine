# G3 架构与安全设计 步骤摘要

## 目标

基于 G1 不变量和 G2 业务场景，做出架构风格、技术栈、部署拓扑、模块通信、认证授权、数据保护和威胁建模的技术决策。

## 核心规则

- 架构决策必须引用 G1 不变量和 G2 业务场景作为依据
- 安全设计必须覆盖 G2 roles.md 中所有角色
- 威胁建模必须覆盖 G1 boundary.md 中所有外部交互面

## 任务清单

| 任务 | 说明 |
|------|------|
| T1 架构风格决策 | 评估候选风格，选择最终风格并记录依据（引用 G1/G2） |
| T2 技术栈选型 | 语言/框架/中间件/数据库，每项标注 NFR 或场景依据 |
| T3 部署拓扑设计 | 服务部署方式、网络分区、服务发现、部署单元与模块映射 |
| T4 模块间通信模式 | 同步/异步，每对标注涉及模块和 G2 场景引用 |
| T5 认证授权模型 | 认证方案 + 授权模型 + 角色权限边界（引用 g2/roles.md） |
| T6 数据保护策略 | 传输加密/存储加密/脱敏规则/审计日志（引用安全不变量） |
| T7 威胁建模 | STRIDE 简化模型，攻击面→风险评级→缓解措施（引用 boundary.md） |
| T8 写入产物 | architecture.md + security.md |
| T9 产物审查 | ae:review mode=autofix domain=document g3/，最多3次 |

## 验收关卡

| 编号 | 检查项 | 通过标准 |
|------|--------|---------|
| G3-K1 | 架构风格明确 | 选定风格有 G1/G2 依据 |
| G3-K2 | 技术栈确定 | 每项选型有依据 |
| G3-K3 | 通信模式完整 | 每对交互模块有通信定义 |
| G3-K4 | 认证授权覆盖所有角色 | 每个角色有权限定义 |
| G3-K5 | 数据保护覆盖安全不变量 | 每条安全不变量有保护措施 |
| G3-K6 | 威胁建模覆盖外部交互面 | 每个外部交互有威胁分析 |
| G3-K7 | 与 G1/G2 一致 | 引用存在 |
| G3-K8 | 文件行数合规 | ≤500 行 |
| G3-K9 | 产物审查通过 | ae:review autofix 通过 |
| G3-K10 | 人工审核通过 | 用户确认 |

## 回退规则

- 场景遗漏 → 回 G2
- 不变量遗漏 → 回 G1
- 内部问题 → 仅重做 G3

## 通用产物规格

- 单轨格式：YAML Frontmatter 为唯一真源，正文为人类阐释
- 文件行数硬约束：每个产物文件不超过 500 行
