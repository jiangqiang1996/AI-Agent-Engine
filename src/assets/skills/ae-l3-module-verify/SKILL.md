# L3 子模块验证

## 角色

L3 验证执行者，对指定模块执行数据推演、DDL 验证、UI 还原验证和覆盖率计算，确保模块内部设计可落地、可还原、可追溯。

## 适用场景

- L2 模块设计已完成，紧邻前序技能为 L2（子模块独立设计），需要验证推演正确性
- DDL 需要实际建表验证约束和索引
- 界面模块需要验证还原度
- 需要输出覆盖率报告和未覆盖清单

## 不适用场景

- 前序技能产物（G1/G2/G3/G4/G5/A1/A2/L1/L2）未就绪时不得执行本技能
- 未完成 L2 设计的模块（应先执行 L2 技能）
- 跨模块集成验证（属于 V1 范畴）
- 需要修改上游产物的场景（本技能只读上游）

## 输入自动发现

本技能需要用户指定 `module` 参数（目标模块名），其余输入自动发现：

1. **产物根目录发现**：在工作区 `docs/ae/galv/` 下搜索 `galv-manifest.yaml`，取其 `project_name` 字段定位根目录 `docs/ae/galv/<项目名>/`（若搜索到多个 manifest，提示用户选择目标项目）
2. 若未找到 manifest，提示用户先执行 G1 创建 manifest
3. **上游产物发现**：从产物根目录按上游依赖表自动读取已存在的上游产物文件；缺失时记录警告，不阻断执行
4. **模块名来源**：用户通过 `module=<模块名>` 参数指定；若未指定，从 G4 数据模型或 L2 已有设计中提取模块列表供用户选择（优先 L2 已有设计，因本技能验证的是 L2 产物）
5. 用户也可显式传入项目名覆盖自动发现结果

## 输入

必须通过参数 `module=<模块名>` 指定目标模块。缺少该参数时，从上游产物中提取模块列表供用户选择。

## 产物根目录

所有产物写入**产物根目录**下。默认根目录为 `docs/ae/galv/<项目名>/`。

`<项目名>` 由以下规则确定：
1. 若产物根目录下已存在 `galv-manifest.yaml`，读取其中的 `project_name` 字段作为项目名
2. 若不存在，在工作区 `docs/ae/galv/` 下搜索已有的 `galv-manifest.yaml` 自动定位
3. 若仍未找到，提示用户先执行 G1 技能创建 manifest

整个根目录自包含、可移植：内部所有路径均为相对路径，目录可整体移动到任意位置。读取全部阶段产物后，任何 AI 工具可据此生成功能等价、结构等价的软件系统。

本阶段的产物位于根目录下 `l3/` 子目录。

## 产物独占

**独占产物**：只有本技能可以创建或修改（路径相对于产物根目录）：

| 产物 | 说明 |
|------|------|
| `l3/{module}/trace/` 或 `l3/{module}/trace.md` | 推演追踪记录 |
| `l3/{module}/trace-coverage.md` | 覆盖率报告 |
| `l3/{module}/ddl-verify.log` | DDL 验证日志 |

**共享产物**：`galv-manifest.yaml`（首次创建时由当前执行的技能负责，后续技能可读取和追加信息）

**禁止修改**上游技能产物（G1/G2/G3/G4/G5/A1/A2/L1/L2），对上游产物只读。同时禁止修改下游技能产物（V1/V2）。

## 上游依赖（只读）

- G1/G2/G3/G4/G5/A1/A2 的所有产物
- L1 产物：`l1/ui-spec/`、`l1/restore-score.md`
- L2 产物（同模块）：`l2/{module}/design/`、`l2/{module}/ddl.sql`

## 执行流程

### 1. 读取上游产物

读取本模块的 `l2/{module}/design/` 下所有设计文档，提取推演用例、不变量定义、状态机。读取 `l2/{module}/ddl.sql`。如有界面，读取 `l1/ui-spec/` 下对应视图规格。

### 2. T1 执行内部数据推演

- 从 `l2/{module}/design/` 中提取所有推演用例
- 对每个用例代入具体数据，逐步走通模块内业务逻辑
- 逐场景检查：then 断言是否成立、不变量守卫是否触发、状态迁移是否符合状态机定义
- 记录每个场景的推演结果：pass / fail 及原因

### 3. T2 执行 DDL 验证

- 执行 CREATE TABLE 语句，确认成功
- 插入推演数据
- 验证 CHECK 约束：尝试插入违反约束的数据，确认被拒绝
- 验证逻辑引用一致性：检查引用字段值在目标实体中是否存在（应用层校验）
- 验证索引：确认索引已创建且查询可命中
- 记录每步结果到 `l3/{module}/ddl-verify.log`

### 4. T3 执行 UI 还原验证（如有界面）

- 仅当本模块包含界面视图时执行
- 对照 `l1/ui-spec/` 规格逐项检查视图实现
- 计算还原度 R = 符合项数 / 总检查项数
- 如无界面，记录"本模块无界面视图，跳过 T3"

### 5. T4 计算覆盖率

- 每条内部逻辑至少 1 个推演场景覆盖
- 每条不变量至少 1 个场景守卫覆盖
- 输出未覆盖清单

### 6. T5 产物审查

对当前阶段全部产物执行自检：

1. 逐条对照验收关卡 L3-K1~L3-K7
2. 确认每个产物文件不超过 500 行
3. 确认所有 Frontmatter 引用可解析到上游产物
4. 不通过项立即修复后重新检查
5. 调用 `ae:review mode=autofix domain=document` 审查 `l3/{module}/` 目录

## 产物格式

### trace 记录格式

目录形式时，`index.md` Frontmatter 必须包含 `type: directory_index` 和 `slices` 字段。

```markdown
### SCENARIO: <场景名>

- given: <前置条件与输入数据>
- when: <触发操作>
- then:
  - [PASS] <断言描述>
  - [FAIL] <断言描述> — 原因: <失败原因>
- invariant-guard:
  - [PASS] <不变量描述>
- state-transition: <起始状态> → <目标状态> [PASS/FAIL]
```

### trace-coverage 格式

```markdown
# 覆盖率报告 — {module}

## 逻辑覆盖

| 逻辑编号 | 逻辑描述 | 覆盖场景数 | 状态 |
|----------|----------|-----------|------|

## 不变量覆盖

| 不变量编号 | 不变量描述 | 守卫场景数 | 状态 |
|-----------|-----------|-----------|------|

## 未覆盖清单

## 汇总

- 逻辑覆盖率: X/Y (Z%)
- 不变量覆盖率: X/Y (Z%)
```

### ddl-verify.log 格式

```
[DDL-VERIFY] {module}
========================================
[CREATE-TABLE] <表名> ... [OK/FAIL]
[INSERT-DATA] <表名> ... [OK/FAIL]
[CHECK-CONSTRAINT] <约束名> ... [OK/FAIL]
[REF-CONSISTENCY] <约束名> ... [OK/FAIL]
[INDEX] <索引名> ... [OK/FAIL]
========================================
```

## 单轨格式规则

所有产物文件采用 Markdown + YAML Frontmatter 单轨格式：

- Frontmatter 为机器可读的唯一真源，正文为人类阐释
- 正文不允许出现 Frontmatter 中不存在的实体名、字段名、规则名
- 正文只允许包含：Frontmatter 字段的业务含义解释、设计决策的理由、用户确认记录
- 如需补充信息，必须先在 Frontmatter 中添加对应条目，再在正文中解释
- 每条 Frontmatter 条目可标注 `origin` 字段：`derived`（从上游推导，可信度最高）、`inferred`（AI 推断补充，需人工确认）、`asserted`（人类断言，最可靠）

## 验收关卡

| 编号 | 检查项 | 通过标准 |
|------|--------|---------|
| L3-K1 | 推演全通过 | 所有内部推演场景 pass |
| L3-K2 | 不变量覆盖 100% | 本模块范围的不变量每条至少 1 个场景覆盖 |
| L3-K3 | DDL 验证通过 | 建表成功，约束生效 |
| L3-K4 | 还原度达标 | 如有界面，R ≥ 0.9 |
| L3-K5 | 文件行数合规 | 所有产物文件不超过 500 行 |
| L3-K6 | 人工审核通过 | 用户确认推演结果正确、DDL 验证真实、覆盖率达标 |
| L3-K7 | 审查通过 | ae:review 审查 l3/{module}/ 目录无阻断发现 |

## 回退说明

| 失败类型 | 回退目标 | 修改产物 |
|----------|---------|---------|
| 推演失败 | L2 | `l2/{module}/design/` |
| DDL 失败 | L2 | `l2/{module}/ddl.sql` |
| 还原度不足 | L1 | `l1/ui-spec/` |

## 安全边界

- 独占产物只有本技能可修改
- 上游产物只读，本技能不得修改
- 本技能禁止读取或引用执行顺序在本技能之后的任何技能产物（V1/V2），以保证回退时后续产物不可见
- 每次调用只处理 `module=` 指定的一个模块
- 发现问题时回退上游技能，不直接修改上游产物
- L3-K6 须由用户确认后方可视为本步骤完成
