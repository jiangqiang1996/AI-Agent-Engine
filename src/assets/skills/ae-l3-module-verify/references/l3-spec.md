# L3 步骤摘要

## 目标

验证每个模块内部设计的数据推演通过、DDL 可落地、文档可还原性达标。

## 执行方式

各模块并行验证。

## 任务清单（每模块独立执行）

| 任务 | 说明 |
|------|------|
| T1 执行内部数据推演 | 用 L2 推演用例代入具体数据，检查 then 断言、不变量守卫、状态迁移 |
| T2 执行 DDL 验证 | 建表、插入推演数据、验证 CHECK/外键/索引 |
| T3 执行 UI 还原验证 | 如有界面，对本模块视图执行可还原性验证 |
| T4 计算覆盖率 | 每条内部逻辑至少1个场景覆盖，每条不变量至少1个场景守卫，输出未覆盖清单 |

## 验收关卡（每模块独立执行）

| 编号 | 检查项 | 通过标准 |
|------|--------|---------|
| L3-K1 | 推演全通过 | 所有内部推演场景 pass |
| L3-K2 | 不变量覆盖 100% | 本模块范围的不变量每条至少 1 个场景覆盖 |
| L3-K3 | DDL 验证通过 | 建表成功，约束生效 |
| L3-K4 | 还原度达标 | 如有界面，R ≥ 0.9 |
| L3-K5 | 指纹一致 | upstream_fingerprints 与 L2 产物一致 |
| L3-K6 | 文件行数合规 | 所有产物文件不超过 500 行 |

## 回退规则

- 推演失败 → 回 L2 修改 design/ 受影响子文件
- DDL 失败 → 回 L2 修改 ddl.sql
- 还原度不足 → 回 L1 修改 ui-spec/ 受影响子文件

## 通用产物规格

- 单轨格式：YAML Frontmatter 为唯一真源，正文为人类阐释
- 文件行数硬约束：每个产物文件不超过 500 行
