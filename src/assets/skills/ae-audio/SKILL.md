# ae:audio — 音频内容识别

将本地音频转换为 Markdown 描述。通过内置 `ae-audio` 工具调用 `modelScenarios.audio` 配置的模型实现，无需安装额外依赖。

## 适用场景

- 用户需要理解音频内容（将音频转为文字描述供 LLM 阅读）
- 用户明确要求将音频内容持久化为 Markdown 文件
- 当前模型不支持直接读取音频文件时，用本技能替代直接读取
- 需要定向识别音频特定内容时，通过 prompt 参数指定识别重点
- 会议录音、播客、采访、语音消息等场景的语音转写和内容分析

## 不适用场景

- 模型支持读取音频且只需查看/理解音频内容时，应直接使用 Read 工具读取，禁止调用本技能
- 不支持图片、视频等非音频格式
- 不支持远程 URL，仅处理当前工作区内本地文件

## 关键约束

- **模型不支持音频输入时禁止使用 Read 工具读取音频**：Read 工具读取 MP3/WAV 等音频文件时，如果当前模型不支持音频输入，会报错。此时必须通过本技能转换，不得尝试直接 Read 音频文件。
- **自动调用，不询问用户**：当检测到模型不支持音频输入、或 Read 读取音频报错时，必须立即自动调用本技能，不得向用户提问是否调用、不得列出可选方案让用户选择、不得停下来等待用户确认。直接调用，拿到结果后继续完成任务。

## 模型配置

识别音频使用的模型通过 `ae.jsonc` 的 `modelScenarios.audio` 配置：

```jsonc
{
  "modelScenarios": {
    "audio": "openai/gpt-4o-audio-preview"
  }
}
```

未配置时，由 opencode 自行分配当前默认模型。建议配置支持音频输入的多模态模型（如 `openai/gpt-4o-audio-preview`、`google/gemini-2.0-flash` 等）。

## 核心工作流

1. 接收用户提供的音频文件路径和识别提示词（prompt 参数）
2. 检测音频格式（MP3/WAV/OGG/FLAC/M4A/AAC）
3. 读取音频内容，调用 `modelScenarios.audio` 配置的模型识别
4. 将识别结果作为 Markdown 直接返回（不附加元数据）
5. 根据 outputMode 参数决定输出方式：
   - `file`（默认）：写入 `ae/markdown/` 目录（或用户指定的 outputPath）
   - `inline`：直接返回 Markdown 内容，不写文件

## 调用纪律

- 单次调用只处理一个文件；需要批量处理时逐一调用或建议用户使用脚本
- outputMode=file 时转换结果自动写入 `ae/markdown/` 子目录，文件名规则：`audio-to-markdown-<时间戳>-<随机串>.md`
- prompt 参数指定时，覆盖默认识别提示词，用于定向识别
- 不需要用户确认即可执行（只读操作，不修改原音频）
- **file 参数必须是真实、完整、物理存在的路径**：禁止仅传文件名。路径来源不确定时，先用 `glob` 或 `bash` 的 `Test-Path`/`ls` 确认文件物理存在再调用。被 `.gitignore` 忽略的文件只要物理存在就应正常处理，不得以 Git 状态判断存在性

## prompt 参数使用指南

prompt 参数是本技能的核心能力，用于控制识别重点和输出质量。不同场景应使用不同的 prompt：

### 通用音频识别

未提供 prompt 时使用默认提示词，适合通用场景的音频内容描述（语音转写、背景声音、音乐片段、情绪语气等）。

### 语音转写场景

**会议录音逐字转写：**

```
prompt=这是一段会议录音。请逐字转写所有对话，按发言人分组（如"说话人A:"），保留语气词和停顿，不总结不改写。标注每个发言的近似时间点。
```

**采访内容结构化：**

```
prompt=这是一段采访录音。请按问答结构转写：标注"Q:"（采访者）和"A:"（受访者），逐字保留回答内容，提取关键观点用引用块标记。
```

### 定向识别场景

**提取关键信息：**

```
prompt=识别这段音频中的所有提及的人名、地名、组织名、日期和数字，以 Markdown 列表输出，按类别分组。
```

**情绪和语气分析：**

```
prompt=分析这段音频中说话人的情绪变化时间线：按时间段标注情绪状态（如"0:00-0:15 平静"、"0:15-0:30 激动"），描述语气特征和语速变化。
```

### prompt 编写原则

1. **明确识别目标**：清楚说明需要从音频中获取什么信息（转写 vs 分析 vs 提取）
2. **结构化要求**：使用编号列表或格式约定指定输出结构
3. **保留原文**：要求"逐字"保留语音内容，不总结、不改写
4. **格式约束**：指定输出格式（Markdown 表格、列表、时间线等）
5. **上下文说明**：说明音频来源（会议/采访/播客等），帮助模型理解识别重点

## 输出

返回 Markdown 格式的音频描述，包含：
- outputPath：写入的 Markdown 文件路径（outputMode=file 时存在）
- content：音频内容的 Markdown 描述

## 边界

- 仅处理当前工作区内本地音频文件（MP3/WAV/OGG/FLAC/M4A/AAC）
- 不处理远程 URL
- 不处理图片、视频等非音频格式
- 音频文件不存在时返回友好提示
- 音频过大时返回提示并建议裁剪或压缩
