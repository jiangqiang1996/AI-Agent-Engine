# OpenCode 命令规范速查

OpenCode 命令是 Markdown 文件。项目级命令只影响当前项目，全局级命令影响当前用户的所有 OpenCode 项目。

## 路径

- 项目级：`.opencode/commands/<name>.md`。
- 全局级：`~/.config/opencode/commands/<name>.md`。
- 使用技能创建器同时创建命令和技能时，命令与技能必须同级创建。
- 使用技能创建器只创建命令时，命令正文必须自包含完整流程，不得要求加载未创建的同名技能。

## 基本模板

包装同名技能的命令：

```markdown
---
description: 使用 api-tester 技能处理请求
---

请使用 `skill` 工具加载 `api-tester` 技能，并严格按照该技能处理以下请求：

$ARGUMENTS
```

独立命令：

```markdown
---
description: 执行 API 联调流程
---

请直接按照以下流程处理用户请求，不要尝试加载同名技能：

1. 理解接口目标、环境和认证约束。
2. 读取必要上下文。
3. 设计并执行联调步骤。
4. 汇报请求摘要、验证结果和剩余风险。

用户请求：

$ARGUMENTS
```

## 参数占位

- `$ARGUMENTS` 表示用户在命令后输入的完整参数文本。
- 命令正文应明确说明如何使用这些参数，而不是只重复占位符。
- 如果需要固定位置参数，应在命令正文中写清顺序和含义。

## 同级约定

- 项目级技能对应项目级命令，适合只服务当前仓库的工作流。
- 全局级技能对应全局级命令，适合跨项目复用的个人工作流。
- 全局命令可能覆盖或影响多个项目中的同名命令发现，创建前应提醒用户影响范围。

## 校验重点

- 命令文件存在于与技能同级的命令目录。
- frontmatter 包含 `description`。
- 可选 frontmatter 包括 `agent`、`subtask`、`model`；只有需要绑定指定代理、强制子任务运行或覆盖模型时才写入。
- 命令正文是 `template`；Markdown 命令文件通常不需要在 frontmatter 中写 `template`。
- 包装技能的命令正文明确要求加载同名技能；独立命令正文直接包含完整执行流程。
- 正文保留 `$ARGUMENTS`，避免丢失用户请求。

## 更新技能时的命令同步

- 只有既有同级命令存在，或用户明确要求命令入口时，才同步命令文件。
- 既有同级命令存在时，必须先读取命令内容，再判断描述、正文和 `$ARGUMENTS` 是否需要同步。
- 更新命令描述时，保持它指向同名技能，不要改成加载其他技能。
- 命令正文必须继续保留 `$ARGUMENTS`，避免更新后丢失用户在命令后的输入。
- 如果技能更新不影响触发方式或命令说明，说明本次未修改命令即可，不要默认新增命令。
