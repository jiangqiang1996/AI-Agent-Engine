# OpenCode 技能规范速查

OpenCode 技能是带有 `SKILL.md` 的目录。OpenCode 会从配置的技能目录发现这些技能，并在会话中通过 `skill` 工具加载。

## 路径

- 项目级：`.opencode/skills/<name>/SKILL.md`。
- 全局级：`~/.config/opencode/skills/<name>/SKILL.md`。
- 默认使用项目级，只有用户明确要求全局级时才写入全局目录。

## 名称

- 推荐格式：`^[a-z0-9]+(-[a-z0-9]+)*$`。
- 长度建议为 1 到 64 个字符。
- 不使用路径分隔符、点号、空格、大写、中文或下划线。
- `SKILL.md` frontmatter 中的 `name` 应与目录名一致。

## Frontmatter

最小结构：

```markdown
---
name: api-tester
description: 辅助设计和执行 API 联调
---
```

要求：

- `name` 必填，使用技能名。
- `description` 必填，长度保持在 1 到 1024 字符之间。
- 描述应说明技能何时被使用，避免泛泛而谈。
- 可选字段包括 `license`、`compatibility`、`metadata`；仅在用户明确需要许可证、兼容性声明或字符串元数据时写入。
- `metadata` 是字符串到字符串的映射；不要为了“完整”而生成空元数据或无依据字段。
- OpenCode 当前只识别上述字段，未知字段会被忽略；更新既有技能时可保留已存在且有用的未知字段，但新建时不主动添加未知字段。

## 内容建议

- 说明技能的角色和目标。
- 说明适用场景和不适用场景。
- 给出执行流程和验证方式。
- 如果技能会写入文件或执行命令，写清确认和安全边界。
- 只引用用户项目中真实需要的路径，不把插件源码仓库结构当作普通项目前提。

## 更新既有技能检查清单

- 先读取现有 `SKILL.md`，不要在未理解旧内容时直接覆盖。
- 保持 frontmatter `name` 与目录名一致；除非用户明确要求重命名，否则不要改名。
- 保留或改进仍有效的 `description`、适用场景、执行边界和验证方式。
- 标出用户要求的变更点、需要删除或重写的内容，以及可能影响现有使用方式的冲突。
- 写入前向用户展示更新摘要或草案，得到明确确认后再编辑。
- 更新后运行结构校验，并向用户报告技能路径和验证结果。

## 排查

- 技能不可发现时，检查路径是否位于项目级或全局级技能目录。
- 加载失败时，检查 `SKILL.md` 是否存在且 frontmatter 以 `---` 成对包裹。
- 名称不匹配时，统一目录名和 frontmatter `name`。
- 描述为空或过长时，补充精确描述或拆分冗长说明到正文。
