# AI 结构化计划模板

本模板必须与 `ae:plan` 的 `type: plan` 计划模板结构保持一致。它是给 AI 执行使用的计划结构，不是汇报材料；不得补充输入人读文档没有的干系人、读者对象、业务价值、背景介绍或汇报型影响说明。

```markdown
---
type: plan
status: drafted
date: YYYY-MM-DD
title: <kebab-case-title>
origin: <输入人读详细设计文档路径，若无上游则删除此行>
originFingerprint: <输入文档指纹，若无上游则删除此行>
depth: <standard|deep>  # 轻量计划删除此行
---

# <标题>

## AI 解析契约
- canonicalKind: plan
- humanEquivalent: true
- stableIdsRequired: true
- implementationUnitsRequired: true
- noImplicitScope: true

## 来源与目标
[来源、目标、非目标和外部行为保持要求。可记录上游路径，但不得用上游路径替代具体内容]

## 范围

### 包含
- <范围内事项>

### 不包含
- <范围外事项>

### 约束 [可选]
- <业务、技术、时间或资源约束>

## 需求追溯
| 需求 ID | 计划响应 |
|---------|----------|
| R1 | U1 |

## 高层技术设计
[架构、数据流、状态流或关键设计说明。Mermaid 图可原样包含]

### 关键决策
- D1. <决策> → 理由: <理由>

## 专项设计 [可选]

[表、字段、索引、迁移策略、回填和回滚信号]

### 数据模型 [可选]

### 性能设计 [可选]

## 影响面 [可选]
- <会改变实现、验证、迁移、发布或回滚决策的受影响模块、接口、数据、工具或文档；不写干系人、读者对象或泛化影响介绍>

- [ ] 行为保持要求: <重构计划必填；普通计划按需填写>
- [ ] 依赖: <依赖单元或前置条件>
- [ ] 文件:
  - <文件路径>

  - <实现方案>

  - <模式或既有实现参考>

- [ ] 回滚信号 [可选]: <信号>

## 等价性检查
- implementationUnitsCount: <U* 数量>
- tracedRequirementsCount: <被追溯的 R* 数量>
- decisionsCount: <D* 数量>
- risksCount: <风险数量>
```

## 兼容要求

- `ae:doc-structure` 生成的 `type: plan` 文档必须可被 `ae:plan`、`ae:work`、`ae:refactor` 直接使用。
- 不得生成只适合阅读、但缺少实现单元或验证字段的计划。
- 从人读设计文档转换时，`origin` 必须记录输入文档路径，`originFingerprint` 按输入文档 frontmatter 生成；不得用来源路径替代正文内容。
- 不得为了匹配常见详细设计结构而新增干系人、读者对象、业务价值、背景介绍、影响叙述或最佳实践章节；只有输入人读文档未记录上游结构化文件，且这些内容已有并可等价映射到范围、约束、影响面或风险时才保留。
- 如果输入人读文档记录了上游结构化文件，输出必须与上游结构化文件双向等价：不得遗漏上游实现单元、验证、风险或待定问题，也不得接收输入文档新增的上游没有的实质语义。
