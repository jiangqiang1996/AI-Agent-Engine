# 登录检测与等待机制

本文档定义统一的登录检测流程，供所有浏览器截图能力复用。

## 检测机制

采用 **URL 检测 + 元素检测 + 超时截图** 的组合方案：

```
┌─────────────────────────────────────────────────────┐
│  检测到需要登录                                        │
├─────────────────────────────────────────────────────┤
│  1. 记录当前 URL 和页面状态                            │
│  2. 输出反馈提示："请完成登录，系统将自动检测"           │
│  3. 启动轮询检测（每 5s 一次，最长 5 分钟）              │
│     ├─ 检查 URL 是否变化                              │
│     ├─ 检查登录元素是否消失                            │
│     ├─ 检查用户元素是否出现                            │
│     └─ 每 10s 输出等待进度                             │
│  4. 任一条件满足 → 输出成功提示 + 继续执行               │
│  5. 超时 → 截图 + 询问用户选择                         │
└─────────────────────────────────────────────────────┘
```

## 检测条件优先级

| 优先级 | 检测方式 | 命令 | 适用场景 |
|--------|---------|------|---------|
| 1 | URL 变化 | `snapshot -i --json` 解析 URL | 传统登录跳转 |
| 2 | 登录元素消失 | 检测 `@login-form` 不存在 | 表单提交场景 |
| 3 | 用户元素出现 | 检测 `@user-avatar` 或 `@logout-button` | 通用检测 |
| 4 | 截图人工判断 | 展示截图 + `question` 工具 | 兜底方案 |

## 配置参数

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `max_wait` | 300s | 最大等待时间 |
| `interval` | 5s | 检测间隔 |
| `progress_interval` | 10s | 进度提示间隔 |
| `check_url` | true | 是否检测 URL 变化 |
| `check_elements` | true | 是否检测元素变化 |

## 登录表单识别

### 自动识别条件

通过 `agent-browser snapshot -i --json` 获取页面元素，检测以下信号：

| 信号类型 | 检测方式 | 权重 |
|---------|---------|------|
| URL 路径 | URL 包含 `/login`、`/signin`、`/auth`、`/oauth` | 高 |
| 密码输入框 | 存在 `input[type="password"]` | 高 |
| 登录按钮 | 按钮文本包含"登录"、"Login"、"Sign In" | 中 |
| 表单标签 | 表单包含 `@login-form`、`@signin-form` | 中 |
| 页面标题 | 标题包含"登录"、"Sign In"、"Log In" | 低 |

### 识别流程

1. 打开目标 URL 后运行 `agent-browser snapshot -i --json`。
2. 从快照中读取当前 URL、页面标题和可交互元素列表。
3. 如 URL 命中登录路径或页面包含密码输入框，判定为需要登录。
4. 如仅命中登录按钮或标题关键词，结合截图或上下文判断，避免把普通导航按钮误判为登录页。
5. 如果 JSON 快照不可用，降级为普通快照 + 截图 + 用户确认。

## 完整检测流程

### 步骤 1：检测登录需求

打开目标 URL 后运行 `agent-browser snapshot -i --json` 获取页面状态，并分析是否包含登录路径、密码输入框或登录按钮等信号。

### 步骤 2：记录初始状态

记录以下信息，供后续轮询判断：

- 初始 URL
- 登录相关元素引用列表（密码输入框、登录按钮、登录表单）
- 开始等待时间

登录相关元素必须作为列表逐个比对，不能把多个元素引用拼接成一个字符串后做单值比较。

### 步骤 3：输出反馈提示

使用聊天输出或 `question` 工具提示用户：

```
🔐 检测到登录页面

当前 URL: $INITIAL_URL

请在浏览器窗口中完成登录操作。
系统将自动检测登录状态...

等待中...（最长等待 300s）
```

### 步骤 4：轮询检测

每 5 秒重复执行一次页面状态采集，最长等待 300 秒。每 10 秒向用户输出一次等待进度。

每轮按以下顺序判断：

1. **URL 变化**：当前 URL 与初始 URL 不同，且不再包含登录路径。
2. **用户元素出现**：快照中出现用户头像、用户菜单、登出按钮等已登录态元素。
3. **登录元素消失**：初始记录的登录相关元素列表全部消失。只消失其中一个元素时不要直接判定成功。
4. **兜底确认**：检测信号不确定时，截图当前状态并询问用户是否已经完成登录。

如果到达 300 秒仍未满足成功条件，执行超时处理。

### 步骤 5：超时处理

先保存当前页面截图，再使用 `question` 工具询问用户：

```bash
agent-browser screenshot login-timeout.png
```

```typescript
question({
  questions: [{
    question: "登录等待超时（已等待 300s）。当前页面截图已保存: login-timeout.png。请选择：",
    header: "超时处理",
    options: [
      { label: "已完成登录", description: "继续执行后续步骤" },
      { label: "仍在登录中", description: "延长等待时间（+120s）" },
      { label: "登录失败", description: "跳过此步骤" },
    ],
  }]
})
```

## 集成示例

### 在技能中集成

```markdown
### 前置检查：登录状态检测

在打开目标页面后、截图前，检测是否需要登录：

1. `agent-browser open [URL]`
2. `agent-browser snapshot -i --json` 获取页面状态
3. 分析是否包含登录信号（见 login-detection.md）
4. 如检测到登录，执行登录等待流程
5. 登录成功后继续执行

详细流程参考本文档。
```

### 在代理中集成

```markdown
## 步骤 0：前置检查

**登录状态检测：**

1. 使用 `agent-browser snapshot -i --json` 获取当前页面状态
2. 检测 URL 是否包含登录路径，或页面是否包含密码输入框
3. 如检测到登录页面：
   - 输出反馈提示："🔐 检测到登录页面，请完成登录..."
   - 启动轮询检测（每 5s 检查一次）
   - 检测到登录成功后继续
   - 超时后截图并询问用户

详细流程参考 `ae:test-browser` 的登录检测与等待机制。
```

## 注意事项

1. **有头模式优先**：登录检测建议使用 `--headed` 模式，让用户能看到浏览器窗口
2. **超时配置**：根据项目实际情况调整 `max_wait`，复杂登录流程可能需要更长时间
3. **元素选择器**：`@user-avatar`、`@logout-button` 等选择器可能需要根据实际项目调整
4. **降级策略**：如果 `--json` 输出不可用，降级到固定时间等待 + 用户确认
