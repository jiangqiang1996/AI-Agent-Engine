# A1 步骤摘要

## 目标

定义模块间谁给谁传什么数据、传错了怎么办，锁定子模块并行设计的硬约束。

A 阶段完成后，各子模块才能独立展开。

## 任务清单

| 任务 | 说明 |
|------|------|
| T1 分配实体/字段归属 | 每个字段必须有且仅有一个权威归属方（真源），其他为只读副本方；交叉引用 g2/business-scenarios/ 确保场景覆盖 |
| T2 提取跨模块数据流 | 从 G5 推演场景中提取跨模块场景，梳理数据从哪产生、经哪些模块中转、到达哪 |
| T3 定义模块间契约 | 四类契约：data_ownership（数据归属）、event_flow（事件流）、state_sync（状态同步）、api_call（接口调用），每条含 payload、方向、一致性级别、冲突策略、超时、降级方案、security_context（引用 g3/security.md） |
| T4 定义共享状态与冲突解决策略 | 权威归属方、同步方向、一致性级别、冲突解决规则（last-write-wins/server-wins/合并建议/人工裁定） |
| T5 关联不变量守卫 | 每条契约至少关联1个不变量守卫 |
| T6 编写契约模拟用例 | 每条契约至少1个模拟用例，验证描述无歧义 |
| T7 定义外部系统集成契约 | 识别与外部服务的集成点，定义协议、认证、数据格式、超时、降级、重试策略 |
| T8 产物审查 | 逐条对照验收关卡，确认文件行数合规，调用 ae:review mode=autofix domain=document 审查 a1/ 目录 |

## 验收关卡

| 编号 | 检查项 | 通过标准 |
|------|--------|---------|
| A1-K1 | 契约引用可解析 | payload 引用可解析到 g4/data-model/ 中的实体/字段 |
| A1-K2 | 共享状态有归属 | 每个共享状态有唯一权威归属方和冲突解决规则 |
| A1-K3 | 无孤儿数据 | 每个实体每个字段至少出现在一个模块的职责范围内 |
| A1-K4 | 契约可模拟 | 每条契约至少1个模拟用例，给定输入可推算确定输出 |
| A1-K5 | 契约有守卫 | 每条契约至少关联1个不变量守卫 |
| A1-K6 | 指纹一致 | upstream_fingerprints 与 G1-G5 产物一致 |
| A1-K7 | 文件行数合规 | 所有产物文件不超过 500 行 |
| A1-K8 | 人工审核通过 | 用户确认契约定义合理、数据流完整、冲突解决策略可行 |
| A1-K9 | 安全上下文闭合 | 每条契约的 security_context 引用可解析到 g3/security.md |
| A1-K10 | 外部集成有契约 | 每个外部系统集成点有对应契约，含认证、超时、降级策略 |
| A1-K11 | 审查通过 | ae:review 审查 a1/ 目录无阻断发现 |

## 回退规则

- 实体/字段归属错误 → 回 G4 修改受影响子文件
- 模块拆分不合理 → 回 G1 修改 boundary.md
- 业务场景不支持 → 回 G2 修改 business-scenarios/
- 架构/安全约束冲突 → 回 G3 修改 architecture.md 或 security.md
- 推演覆盖不足 → 回 G5 修改 data-trace/
- 契约逻辑/同步策略错误 → 仅重做 A1 受影响子文件

## 通用产物规格

- 单轨格式：YAML Frontmatter 为唯一真源，正文为人类阐释
- 文件行数硬约束：每个产物文件不超过 500 行
