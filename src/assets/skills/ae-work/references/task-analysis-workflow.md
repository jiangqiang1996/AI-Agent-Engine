# 任务分析工作流

本文件定义 `ae:work` 阶段 1 的任务分析、待办构建和执行策略选择。

## 分析入口

设计文档和 worktree 交接输入默认调用 `ae-task-analyzer` 工具。裸提示词默认使用输入分流阶段的轻量任务分解结果，仅在文件范围无法判断、任务边界明显跨模块、需要并行安全矩阵，或轻量分解不足以生成待办时调用工具。

工具不可用、返回错误，或任务已判定为简单内联时，允许手动分析并记录降级原因。

调用规则：

- worktree 交接输入：design_path 指向的设计文件在 B worktree 中真实存在时使用 `mode:design`；design_path 不存在时停止执行，提示用户确认路径正确性或回到 A 会话重新迁移，禁止手动构建待办绕行或扫描 `ae/designs/` 目录寻找替代设计。
- 设计文档输入：使用 `mode:design`，传入设计路径。
- 裸提示词输入：优先使用轻量任务分解；需要升级时才使用 `mode:scan`，传入任务描述。

工具输出结构化任务列表 `units`、文件冲突矩阵 `conflict_matrix` 和并行组 `parallel_groups`。如果工具返回警告（如无法识别文件）或 `units` 为空，降级为手动任务拆分；不得因为任务分析工具未识别设计格式而停止继续执行。

## 待办构建

从设计推导任务，包含依赖关系、文件范围、共享产物、验证要求和优先级排序；`ae-task-analyzer.units` 可直接作为 `todo_units`。

从裸提示词进入时，若定位后发现明显可拆分且文件范围互不重叠的子任务，也必须构建任务列表。

若简单任务跳过完整任务列表，必须生成一个最小单任务 `todo_units`，作为阶段 2 的统一输入。

每个单元的 Verification 必须作为完成信号。

## 执行策略

| 策略 | 适用场景 |
|------|----------|
| 内联 | 1-2 个小任务，或并行组内没有可并发的多个任务 |
| 域代理串行 | 3+ 有依赖的任务，或所有安全组都只有 1 个任务，无法获得并行收益 |
| 域代理并行 | 任一 `is_parallel_safe=true` 的并行组包含 2 个及以上任务；同组任务可由开发域代理并行调度，不同组按 `execution_order` 串行推进 |

并行安全检查由 `ae-task-analyzer` 工具自动完成。若工具未被调用，必须手动构建“文件到任务单元”映射：若文件范围、状态、迁移、配置、公共契约、测试夹具或共享中间产物存在冲突，或任一任务依赖另一任务的未完成输出，则降级为串行。

并行安全检查结果作为 `DomainCallRequest.domainContext` 传入开发域代理。开发域代理内部负责专精代理调度；主代理不得再按旧模板自行二次派发。

## 输出契约

本阶段必须输出：

```json
{
  "todo_units": ["任务单元"],
  "conflict_matrix": ["文件冲突矩阵或手动检查结果"],
  "parallel_groups": ["并行组"],
  "execution_strategy": "inline|domain_serial|domain_parallel",
  "validation_command_candidates": ["候选验证命令"],
  "analysis_degradation_reason": "无降级时为 null"
}
```
