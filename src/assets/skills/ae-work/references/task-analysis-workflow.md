# 任务分析工作流

本文件定义 `ae:work` 阶段 1 的任务分析、待办构建和执行策略选择。

## 分析入口

主代理直接从输入中提取任务单元、文件范围和验证命令。

分析规则：

- worktree 交接输入：design_path 指向的设计文件在 B worktree 中真实存在时读取设计文档，从中提取实现单元；design_path 不存在时停止执行，提示用户确认路径正确性或回到 A 会话重新迁移，禁止手动构建待办绕行或扫描 `ae/designs/` 目录寻找替代设计。
- 设计文档输入：读取设计文档，从中提取实现单元、文件范围和验证命令。
- 裸提示词输入：使用输入分流阶段的轻量任务分解结果定位文件范围和任务边界。

从设计文档提取实现单元时，解析 `- [ ] **单元 N：**` 格式，提取每个单元的文件列表和验证命令。如果设计文档格式无法识别或提取结果为空，降级为手动任务拆分；不得因为无法识别设计格式而停止继续执行。

## 待办构建

从设计推导任务，包含依赖关系、文件范围、共享产物、验证要求和优先级排序；从设计文档提取的实现单元直接作为 `todo_units`。

从裸提示词进入时，若定位后发现明显可拆分且文件范围互不重叠的子任务，也必须构建任务列表。

若简单任务跳过完整任务列表，必须生成一个最小单任务 `todo_units`，作为阶段 2 的统一输入。

每个单元的 Verification 必须作为完成信号。

## 执行策略

| 策略 | 适用场景 |
|------|----------|
| 内联 | 1-2 个小任务，或并行组内没有可并发的多个任务 |
| 专精串行 | 3+ 有依赖的任务，或所有安全组都只有 1 个任务，无法获得并行收益 |
| 专精并行 | 任一 `is_parallel_safe=true` 的并行组包含 2 个及以上任务；同组任务可由编排层并行调度专精代理，不同组按组顺序（G1, G2, G3...）串行推进 |

主代理手动构建"文件到任务单元"映射来判断并行安全：若文件范围、状态、迁移、配置、公共契约、测试夹具或共享中间产物存在冲突，或任一任务依赖另一任务的未完成输出，则降级为串行。

并行安全检查结果作为调度上下文传入专精代理。编排层直接调度专精代理；主代理不得绕过 `scripts/specialist-select.mjs` 自行二次派发。

## 输出契约

本阶段必须输出：

```json
{
  "todo_units": ["任务单元"],
  "conflict_matrix": ["文件冲突矩阵或手动检查结果"],
  "parallel_groups": ["并行组"],
  "execution_strategy": "inline|specialist_serial|specialist_parallel",
  "validation_command_candidates": ["候选验证命令"],
  "analysis_degradation_reason": "无降级时为 null"
}
```
