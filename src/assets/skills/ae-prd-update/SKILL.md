# AI 辅助需求变更

`ae:prd-update` 根据用户的自然语言变更意图，修改已有需求文件，或创建新的独立需求目录。

此技能不实现代码。它修改需求文件。

**重要：修改文件时所有文件引用必须使用仓库相对路径，绝不能使用绝对路径。**

## 核心原则

1. **意图先行** - 先理解变更意图，定位目标条目，再生成修改方案。
2. **方案确认** - 修改前必须向用户展示方案（原始内容 → 修改后内容 → 影响范围），确认后才执行。
3. **精确 edit** - 需求条目是离散原子项，用 edit 工具精确修改目标条目，不触碰未变更条目。
4. **自包含约束** - 需求文档目录完全自包含，禁止引用外部工作空间文件。
5. **无变更追踪** - 直接修改文件内容。版本演化 = 创建新的独立需求目录。
6. **不追问实现方式** - 需求变更只修改产品行为和范围边界，不涉及技术选型。

## 交互规则

1. **一次只问一个问题** - 意图模糊时调用 `ae:grill` 追问，上限 3 轮。
2. **方案展示** - 用表格展示原始内容、修改后内容和影响范围。
3. **使用平台的提问工具** - 优先使用 opencode 的 `question` 工具。

## 功能描述

<feature_description> #$ARGUMENTS </feature_description>

**如果上面的功能描述为空，询问用户：** "您想变更什么需求？请描述变更意图，如'把 R1 的密码要求改成至少12位含特殊字符'。"

在获得用户的变更意图之前不要继续。

## 变更类型

| 变更类型 | 行为 | 影响范围 |
|---------|------|---------|
| 修改需求描述 | 直接修改目标条目 | 模块内 |
| 新增需求条目 | 添加新条目，分配新 ID | 模块内 |
| 删除需求条目 | 物理删除目标条目 | 模块内 |
| 修改验收条件 | 直接修改目标 SC | 模块内 |
| 修改原型/页面 | 直接修改对应页面文件 | 模块内 |
| 修改模块边界 | 迁移需求条目到新模块 | 全局 + 多模块 |
| 修改全局决策 | 直接修改 decisions.md | 全局 + 所有受影响模块 |

## 执行流程

### 阶段 0：恢复和路由

识别要变更的需求文档：
- 从当前会话上下文中用户明确提到的需求文件名或路径
- 当前会话中已产出的需求文档

读取 prd `overview.md` 获取模块清单和范围边界。

### 阶段 1：意图理解

1. 读 prd `overview.md`（问题框架 + 范围边界 + 模块清单）
2. 解析用户变更意图，定位目标需求条目/模块
3. 如意图模糊 → 调用 `ae:grill` 追问澄清（上限 3 轮）
4. 输出结构化变更意图：`{targetId, changeType, description, affectedModule}`

### 阶段 2：上下文加载

1. 读 `overview.md` + 相关全局文件（decisions.md / non-functional.md / tech-stack.md / design-vision.md，如存在）
2. 读 `modules/<NN>-<m>/requirements.md`（+ `modules/<NN>-<m>/pages/` 如涉及 UI）
3. 理解目标需求的完整上下文（依赖链、验收条件、原型引用）

### 阶段 3：方案生成（先提案不直接改）

1. 生成修改方案表格：

   | 项目 | 原始内容 | 修改后内容 |
   |------|---------|-----------|
   | R1 描述 | "密码需至少8位..." | "密码需至少12位含特殊字符..." |
   | PAGE-001 字段清单 | password(必填, 至少8位...) | password(必填, 至少12位含特殊字符...) |

2. 生成影响范围表格：

   | 受影响文件 | 受影响 ID | 变更类型 |
   |-----------|---------|---------|
   | prd modules/01-auth/requirements.md | R1 | modify |
   | prd modules/01-auth/pages/01-register.md | PAGE-001 | modify |

3. 展示方案 → 用户确认
   - 确认 → 进入阶段 4
   - 拒绝 → 询问是否调整方案 → 回到阶段 3
   - 取消 → 结束

### 阶段 4：执行修改

1. Read 目标文件完整内容
2. 用 edit 工具精确修改目标条目：
   - 修改需求描述（如 R1 描述）
   - 修改关联原型（如涉及 UI，编辑对应 `pages/<NN>-<page-name>.md`）
   - 修改验收条件（如有）
3. 如修改模块边界，迁移需求条目到新模块目录

### 阶段 5：结果输出

1. 输出变更摘要
2. 提示用户可运行 `/ae-design` 重新生成设计，或运行 `/ae-work` 实施变更

## 安全边界

- 修改前必须 Read 完整文件，用 edit 精确匹配，禁止盲目 write 覆盖
- 修改方案必须经用户确认后才执行
- 批量变更逐个生成方案，统一确认后批量执行
- 不修改 design 文件

## 交接

变更完成后呈现下一步选项：
- 运行 `/ae-design` 重新生成设计
- 运行 `/ae-work` 实施变更
- 继续变更其他需求
