# 从会话创建或更新技能

从当前会话提取可复用流程或资产纠偏经验，整理为创建或更新 OpenCode 原生技能的需求，并在用户明确确认后转交 `ae:skill-creator`。除非用户明确要求"全局""全局级"或传入 `--global`，默认处理项目级技能。

## 参数说明

| 参数 | 必填 | 说明 |
|------|------|------|
| 目标技能名/流程关注点/资产名/纠偏摘要 | 否 | 描述要创建或更新的技能目标 |
| `--global` | 否 | 创建全局级技能，影响当前用户所有项目 |
| `--no-command` | 否 | 只创建技能，不创建同级命令 |

参数解析规则：`--global`、`--no-command` 为标志参数，直接识别；其余输入作为技能目标描述。

## 职责边界

- 本技能只负责总结当前会话、诊断资产偏差、整理转交需求和调用 `ae:skill-creator`。
- 本技能不得直接写入技能、命令、代理、规则、工具、hook、service、schema 或注册文件。
- 技能文件、命令文件、目录结构、冲突处理、更新合并和结构校验统一由 `ae:skill-creator` 负责。
- 全局级会影响当前用户的所有 OpenCode 项目，只有用户显式要求时才可转交全局级。
- 用户传入 `--no-command` 时，创建场景要求不创建命令；更新场景不新增命令，已有命令默认不触碰，除非用户明确要求同步或 `ae:skill-creator` 再次确认。

## 输入分流

支持可选参数：目标技能名、流程关注点、资产名、纠偏摘要、`--global`、`--no-command`。

- 普通会话沉淀：用户想把当前执行流程、协作方式、验证套路或交付格式固化为技能。
- 资产纠偏沉淀：用户指出某个技能、命令、代理、规则或代码实现偏航，希望形成以后可复用的纠偏流程。
- 创建意图：用户要求创建新技能，或当前候选名称没有同名技能。
- 更新意图：用户明确要求更新，指定已有技能名，或发现同名技能已经存在。

如果输入缺少必要信息，先补问，不要猜测。用户只说“继续”“看起来不错”“你觉得呢”不算创建或更新确认。

## 普通会话沉淀

提取可复用流程，而不是逐字记录聊天内容。重点识别：

- 用户目标、关键约束和成功标准。
- 阶段划分、关键动作顺序和验证方式。
- 必须暂停询问的确认点。
- 文件写入、Git、网络、浏览器、外部命令等操作边界。
- 未来复用时需要参数化的输入。
- 完成汇报格式和验收证据。

排除一次性路径、临时调试输出、工具噪声和用户未确认的推测性规则。

## 资产纠偏沉淀

先定位候选资产，再决定是否适合沉淀为技能。

需要提取四项信息：

- 入口：用户触发的命令、技能、代理或文件路径。
- 实际行为：刚才偏航做了什么。
- 期望行为：用户希望以后怎么做。
- 证据：会话调用链、工具调用、文件内容、错误输出或用户明确说明。

归一化候选资产时遵循：

- `/ae-foo`、`ae-foo` 和 `foo` 可归一化为候选技能 `ae:foo` 或命令 `ae-foo`。
- `@agent-name` 归一化为代理名 `agent-name`。
- 文件路径优先作为项目级资产候选，不反推出全局资产写入目标。
- 命令入口可能只是包装，必须区分入口资产与实际执行资产。

候选不唯一、调用链证据不足，或不确定应纠偏入口资产还是下游执行资产时，必须暂停询问用户。如果偏差不是资产问题，只输出诊断，不调用 `ae:skill-creator`。

## 转交需求

整理给 `ae:skill-creator` 的需求必须包含：

- 建议技能名和一句话用途。
- 这是创建新技能还是更新已有技能。
- 作用域：默认项目级；显式 `--global` 时为全局级，并说明影响范围。
- 是否创建或同步同名命令；默认创建，`--no-command` 时不创建或不新增。
- 适用场景和不适用场景。
- 输入参数或用户需要提供的信息。
- 分阶段执行流程、确认点、操作边界、验证方式和完成汇报格式。
- 更新已有技能时，列出现有技能名、当前会话新增内容、应保留内容、潜在冲突、命令同步建议和写入前确认要求。
- 资产纠偏场景还要包含候选资产、入口/执行资产区分、偏差表现、期望行为、证据置信度和多候选确认规则。

## 确认模板

调用 `ae:skill-creator` 前，展示转交摘要并取得明确确认：

```markdown
准备转交给 `ae:skill-creator`：

- 操作：创建新技能|更新已有技能
- 建议技能名：`<name>`
- 作用域：项目级|全局级
- 命令处理：创建同名命令|不创建命令|不新增命令|同步既有命令待确认
- 来源类型：普通会话流程|资产纠偏流程
- 关注点：<一句话摘要>

转交需求：
<面向 ae:skill-creator 的完整需求说明>

请选择：
1. 确认创建/确认更新
2. 修改后创建/修改后更新：<修改意见>
3. 只输出流程摘要
4. 只输出诊断，不创建/不更新
5. 取消
```

明确确认包括：用户输入 `1`、`确认创建`、`确认更新`、`创建`、`更新`、`可以创建`、`可以更新`、`按这个创建`、`按这个更新`。如果用户选择修改后创建或更新，必须先更新转交需求并再次确认。

## 调用 ae:skill-creator

用户确认后，使用 `ae:skill-creator` 处理实际创建或更新，并把确认过的完整需求作为输入传递。

- 默认不附加 `--global`。
- 用户明确要求全局级时，在输入中包含 `--global` 并说明影响所有 OpenCode 项目。
- 用户传入或确认不创建命令时，在输入中包含 `--no-command`。
- 如果 `ae:skill-creator` 要求进一步确认、处理冲突或修订草案，按其流程继续。

如果用户只要摘要、只要诊断或取消，明确说明未调用 `ae:skill-creator`，也未写入任何文件。

## 完成汇报

`ae:skill-creator` 完成后，汇总：

- 处理的是创建还是更新。
- 作用域是项目级还是全局级。
- 命令状态：已创建、已同步、未创建、未触及。
- 流程来源：普通会话沉淀或资产纠偏沉淀。
- 创建或更新结果：引用 `ae:skill-creator` 返回的文件路径和校验结果。
- 剩余风险：无法自动验证的动态来源或人工验收项。
