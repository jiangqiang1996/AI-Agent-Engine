# 安全设计维度契约模板

**触发条件：** prd 标注涉及安全边界/认证授权/敏感数据，或风险维度命中"用户数据输入"（条件必产出）
**产出文件：** `security/security.md`（默认单文件，≤ 300 行；超 300 行自动拆分为 `security/01-security.md` 索引 + `security/NN-<domain>.md` 分组实体，domain 如 auth/threat-model/data-protection）
**产出方：** `@security-designer` 子代理
**可还原性目标：** 任意 AI 据此实现不引入安全漏洞的代码

## 产出方式

**默认单文件产出（1 次调用）。** security 维度内容通常紧凑，默认产出单文件 `security/security.md`。

**自动拆分机制：** 当 security 内容预计超 300 行时（大型系统威胁模型/数据分级/授权矩阵随业务规模膨胀），索引层子代理在 file-plan 中预先声明拆分方案，阶段 2 直接按子主题分组产出多个文件（生成时拆分，非先生成大文件再拆分）：
- 索引文件 `security/01-security.md`：威胁模型概览 + 信任边界 + 负向设计空间 + file-plan
- 分组实体文件 `security/NN-<domain>.md`：按子主题分组（如 `02-auth.md` 认证授权流程、`03-data-protection.md` 数据分级与密钥管理、`04-threat-model.md` 详细威胁模型与输入验证 + 审计日志）

拆分判定：索引层子代理评估内容规模，预计超 300 行时在 file-plan 中声明拆分；已产出文件即时校验，超 300 行打回重新按子主题分组生成，最多重试 2 次。

## 契约元素（MVCE）

security 维度的最小可验证契约元素集，标注 `[核心]` 或 `[可选]`：

- `[核心]` **威胁模型表**：STRIDE 分析
- `[核心]` **信任边界**：信任域、信任对象、信任假设、被攻破影响、故障模式、降级策略
- `[核心]` **认证授权流程**：认证流程图、授权决策点、Token 生命周期
- `[核心]` **数据分级表**：数据级别、示例、存储保护、传输保护、访问控制
- `[核心]` **密钥管理**：存储方式、轮换策略、访问控制、环境隔离、泄露检测、日志脱敏
- `[核心]` **第三方依赖安全审查**：依赖名、版本、已知漏洞状态、许可证合规、lockfile 锁定
- `[核心]` **输入验证策略**：验证位置、验证规则、输出编码
- `[核心]` **审计日志要求**：记录事件、日志内容、不可篡改、敏感数据脱敏
- `[核心]` **负向设计空间**：禁止的安全模式（含密钥日志泄露禁令和高危 CVE 依赖禁令）
- `[可选]` **合规约束**：适用法规、合规要求

轻量级任务可省略 `[可选]` 元素。

## 契约内容

```markdown
## 安全设计

### 威胁模型
（STRIDE 分析：Spoofing, Tampering, Repudiation, Information Disclosure, Denial of Service, Elevation of Privilege）

| 威胁类型 | 攻击场景 | 缓解措施 |
|---------|---------|---------|
| Spoofing | 伪造身份 | OAuth 2.0 + MFA |
| Tampering | 篡改数据 | HMAC 签名 + 审计日志 |

### 信任边界

| 信任域 | 信任对象 | 信任假设 | 被攻破影响 | 故障模式 | 降级策略 |
|--------|---------|---------|-----------|---------|---------|
| 外部用户 | 浏览器端用户 | 用户身份经认证后可信 | 伪造身份访问 | 认证服务不可用 | 拒绝访问，不降级 |
| 第三方 API | 外部服务提供者 | 返回数据格式正确 | 注入恶意数据 | 服务返回异常 | 降级为缓存数据或报错 |
| 内部服务 | 微服务间调用 | 内网可信 | 横向移动 | 服务不可用 | 熔断降级 |

### 认证授权流程
（认证流程图、授权决策点、Token 生命周期）

### 数据分级与保护

| 数据级别 | 示例 | 存储保护 | 传输保护 | 访问控制 |
|---------|------|---------|---------|---------|
| 公开 | 公告 | 无 | HTTPS | 无 |
| 内部 | 用户名 | 加密 | HTTPS | 认证 |
| 机密 | 密码 | bcrypt | HTTPS | 认证+授权 |
| 绝密 | 密钥 | KMS | mTLS | 最小权限 |

### 密钥管理
- 存储方式：[环境变量 / KMS / Vault]
- 轮换策略：[周期]
- 访问控制：[最小权限原则]
- 环境隔离：[dev/staging/prod 密钥分离，禁止跨环境复用]
- 泄露检测：[pre-commit hook + CI secret scanning]
- 日志脱敏：[密钥、Token 在日志和错误响应中必须脱敏]

### 第三方依赖安全审查

| 依赖名 | 版本 | 已知漏洞状态 | 许可证合规 | lockfile 锁定 |
|--------|------|------------|-----------|--------------|
| [依赖名] | [版本] | [无已知CVE / 有高危CVE待修复] | [MIT/Apache-2.0/合规] | [是/否] |

### 输入验证策略
- 验证位置：[边界层 / 服务层]
- 验证规则：[白名单优先 / 长度限制 / 格式校验]
- 输出编码：[上下文相关编码]

### 审计日志要求
- 记录事件：[认证/授权/数据变更/管理操作]
- 日志内容：[who, what, when, where, result]
- 不可篡改：[追加写入 / 签名]
- 敏感数据脱敏：[审计日志中不得记录密码、Token、密钥明文]

### 合规约束
- 适用法规：[GDPR / HIPAA / 等保 / PCI-DSS]
- 合规要求：[具体要求列表]
```

## 负向设计空间

security 维度的禁止模式：

- **禁止明文传输敏感数据**：必须使用 HTTPS/TLS，不得降级为 HTTP
- **禁止客户端存储密钥**：密钥必须存储在服务端（环境变量/KMS/Vault），不得硬编码或存入前端
- **禁止 SQL 字符串拼接**：必须使用参数化查询，防止注入
- **禁止无校验的用户输入**：所有用户输入必须在边界层和服务层双重校验
- **禁止过度宽松的 CORS**：CORS 策略必须限定具体来源，不得使用 `*`
- **禁止无审计的敏感操作**：认证、授权、数据变更必须记录审计日志
- **禁止将密钥或 Token 写入日志、错误响应或审计日志明文内容**：必须脱敏处理
- **禁止引入有未修复高危 CVE 的第三方依赖**：引入前必须检查 CVE 状态，高危 CVE 未修复禁止引入
