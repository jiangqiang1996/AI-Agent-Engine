# 测试用例设计维度文件模板

**触发条件：** 模块涉及测试（dimension-triggers.md §模块维度触发）
**产出位置：** `modules/<NN>-<m>/test-cases.md`
**产出方：** `@test-cases-designer` 子代理
**可还原性目标：** 任意 AI 据此直接编写完善的自动化测试脚本（API 测试 + 浏览器端到端测试），且覆盖度可验证

frontmatter 为 `type: design-test-cases`。

## 测试设计方法（强制使用）

每个契约元素必须按以下方法系统化枚举场景，不得凭直觉挑选少量场景应付。先按方法列出覆盖清单，再从覆盖清单生成用例细节。

### 1. 等价类划分（Equivalence Partitioning）

- 每个输入参数划分有效等价类 + 无效等价类，每个等价类至少 1 个代表用例
- 有效等价类：符合约束的典型值、边界内代表值
- 无效等价类：类型错误、约束越界、空值、格式不匹配
- 示例：`limit` 参数 → 有效 `{1..100}` / 无效 `{≤0, >100, 非数字, null, 空字符串}`

### 2. 边界值分析（BVA，6 点法）

- 每个有界参数取 6 个边界点：`min-1, min, min+1, max-1, max, max+1`
- 适用范围：数值范围、字符串长度、集合大小、分页参数、文件大小
- 无界参数取典型值 + 极端值（空、超长、单元素）

### 3. 决策表测试（Decision Table）

- 多条件组合的业务规则必须产出决策表
- 每个条件组合（`2^N` 行，可按等价化简）至少 1 个用例
- 示例：权限决策 = `角色 × 资源状态 × 操作类型` → 决策表每行 1 用例
- 决策表记录在覆盖矩阵中，用例追溯到决策表行号

### 4. 状态转换测试（State Transition）

- 不仅测路径，还测每个转换边（`N×N` 矩阵，N 为状态数）
- 合法转换边：每条至少 1 用例
- 关键非法转换边：不应到达的状态至少 1 用例（如 `error → success` 不应自动恢复）
- 包含自环、终态、不可达态的覆盖标注
- 示例：`ST-form` 有 `idle/loading/success/error` 4 态 → 16 个转换边，合法边逐条覆盖

### 5. 成对组合测试（Pairwise）

- ≥3 个独立参数的端点用成对组合覆盖（正交表或工具生成）
- 减少组合爆炸同时保证每对参数组合至少被覆盖 1 次
- 示例：`POST /resources` 有 `type(3值) × status(4值) × visibility(2值)` → 成对组合 ~12 组而非全组合 24 组

### 6. 错误猜测（Error Guessing）

- 基于领域知识补充易错场景：
  - 空值 / null / undefined / 空字符串 / 空数组
  - 超长字符串（> 10000 字符）、特殊字符（Unicode、emoji、SQL/HTML 注入字符）
  - 并发请求（同一资源同时操作）、超时、网络中断、重试、幂等破坏
  - 时区/时间边界（跨天、跨月、DST 切换）、数值精度（浮点比较）
  - 大数据量（分页边界、批量上限）、文件上传（类型伪造、大小超限）

## 覆盖硬约束（量化）

1. **每端点 ≥ 7 场景** — 1 正常 + ≥2 等价类有效代表 + 2 边界值 + ≥1 错误码触发 + 1 幂等验证（如适用）。无幂等时需 ≥2 错误码触发，确保总数 ≥ 7
2. **每参数 ≥ 4 场景** — 1 有效代表 + 2 边界值（min/max 附近）+ 1 无效类型
3. **每交互行为 ≥ 3 场景** — 1 正常 + 1 边界（空输入/极限值）+ 1 异常（网络失败/权限不足/校验失败）
4. **每状态机转换边 ≥ 1 用例** — `N×N` 矩阵中所有合法边逐条覆盖 + 关键非法边至少 1 用例
5. **每业务规则 ≥ 决策表行数用例** — 决策表化简后每行 1 用例。业务规则使用稳定 ID `BR-XXX`，决策表行号格式 `DT-BR-XXX-N`
6. **每错误码 ≥ 1 触发用例** — 模块 api.md 定义的每个错误码必须被至少 1 个用例触发
7. **每数据库约束 ≥ 1 违反用例** — 唯一约束、外键约束、CHECK 约束、NOT NULL 各 1 个违反用例
8. **每权限角色 ≥ 1 授权用例** — 有权通过 + 无权拒绝各 1 个用例
9. **覆盖密度目标** — P0 路径 100% / P1 路径 ≥ 90% / 端点覆盖率 100% / 参数边界覆盖率 ≥ 95%
10. **禁止重复用例** — 满足以下任一即判定为重复，必须删除或合并：
    - 相同输入 + 相同预期断言
    - 相同契约元素 + 相同场景描述
    - 断言集完全包含于另一用例的断言集
    - 仅测试数据不同但断言意图和断言点完全一致（换皮重复）
    判定方式：覆盖密度统计中"实际用例数"必须剔除重复项后统计
11. **禁止无意义测试** — 每个用例必须同时满足以下全部条件：
    - 断言具体字段值/状态/行为，禁止"返回成功""工作正常"等弱断言
    - 验证有业务语义的行为，禁止"测试能跑通"式的空壳用例
    - 用例场景必须对应至少 1 个契约元素或需求条目，禁止无追溯的孤立用例
    - 步骤和预期必须有可观测差异，禁止仅复制模板未实质化
12. **浏览器可测** — 所有前端交互用例必须可被浏览器自动化工具（Playwright/Selenium）执行：步骤可编程操作、预期可编程断言
13. **API 可测** — 所有后端用例必须可被 API 测试框架直接执行：请求可构造、响应可断言
14. **每条需求 R ≥ 3 场景** — 1 正常 + 1 边界 + 1 异常。覆盖矩阵中每个需求条目至少对应 3 个不同场景的测试用例，缺失任一类型视为覆盖不足
15. **每条成功标准 SC ≥ 1 验收用例** — 验收映射表中每个 prd 成功标准必须至少有 1 条 TC 追溯记录，优先使用 P0 用例覆盖

```markdown
### 负向设计空间

- **禁止无追溯的 P0/P1 用例**：每条 P0/P1 用例必须至少追溯到 1 个契约元素
- **禁止弱断言**：断言不得只写"成功"或"返回正确"，必须指明具体字段和值
- **禁止与实现耦合的脆弱测试**：测试不得依赖具体实现细节（内部方法名、私有属性）
- **禁止无边界场景**：必须有边界值测试，不得只测正常路径
- **禁止无错误路径**：必须有异常场景测试
- **禁止无意义测试**：每个用例必须验证有业务意义的行为，禁止"测试能跑通"式的空壳用例；用例场景必须对应至少 1 个契约元素或需求条目，步骤和预期必须有可观测差异
- **禁止重复用例**：相同输入+相同预期、相同契约元素+相同场景、断言集包含、仅测试数据不同的换皮重复，均判定为重复，必须删除或合并
- **禁止不可自动化的用例**：所有用例的步骤必须可编程操作，预期必须可编程断言
- **禁止遗漏接口用例**：模块 api.md 的每个端点必须至少有 1 正常 + 1 异常用例
- **禁止遗漏交互用例**：模块 ui-ux.md 的每个交互行为必须至少有 1 用例
- **禁止遗漏状态机路径**：每个状态机的每条转换路径必须至少有 1 用例
```

## 契约元素（MVCE）

- `[核心]` **覆盖矩阵表**：需求 × 场景 × 边界 × 测试设计方法 × 测试层级 × 契约元素的交叉覆盖表
- `[核心]` **覆盖密度统计表**：每个端点/状态机/错误码/数据库约束的应有场景数 vs 实际用例数 vs 覆盖率 vs 缺口
- `[核心]` **接口覆盖完整性表**：每个端点 → 正常/异常/边界/等价类/决策表用例 → 覆盖状态
- `[核心]` **交互覆盖完整性表**：每个交互行为 → 用例 → 覆盖状态
- `[核心]` **状态机覆盖完整性表**：每个状态机转换边 → 用例 → 覆盖状态
- `[核心]` **P0-P3 用例表**：每条含稳定 ID `TC-XXX`、场景、前置、步骤、预期、断言、契约追溯、测试设计方法来源
- `[核心]` **维度覆盖追溯表**：用例 ID → 契约元素 ID → 断言要点
- `[核心]` **验收映射表**：prd 成功标准 → 对应用例 → 验证方式
- `[可选]` **测试数据策略**：生成方式、隔离方式、敏感数据脱敏
- `[核心]` **行为契约规格**：每个用例的输入 → 状态转换 → 断言 → 边界条件精确规格，步骤可编程操作、预期可编程断言

`[核心]` 元素不得省略。
