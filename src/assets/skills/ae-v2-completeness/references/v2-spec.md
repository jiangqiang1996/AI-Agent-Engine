# V2 步骤摘要

## 目标

逐条不变量追踪从声明到实现的证据链，识别断裂、遗漏和未覆盖项，确保每条不变量有完整闭环。

## 任务清单

| 任务 | 说明 |
|------|------|
| T1 构建完整性矩阵 | 逐条不变量追踪 G1→G2→G3→G4→A1→L2→V1 链路 |
| T2 检查链路完整性 | 任何一环缺失=断裂链路，标记断裂位置 |
| T3 识别未覆盖实体/字段 | 对比 g4/data-model/ 与 L2 实现 |
| T4 识别未实现契约 | 对比 a1/contracts/ 与 L2 合规声明，检查 g3/security.md 安全策略实现 |
| T5 汇总完整性问题 | P0 不变量链路断裂、P1 实体/字段未覆盖、P2 契约未满足 |
| T6 产物审查 | 逐条对照验收关卡，调用 ae:review mode=autofix domain=document 审查 v2/ 目录 |

## 验收关卡

| 编号 | 检查项 | 通过标准 |
|------|--------|---------|
| V2-K1 | 不变量链路完整 | 每条不变量 G2→G3→G4→A1→L2→V1 每步都有对应条目 |
| V2-K2 | 实体/字段有实现 | 每个实体和字段在 L2 中有实现条目 |
| V2-K3 | 契约已满足 | 每条契约在 L2 合规声明中已满足 |
| V2-K4 | 无断裂链路 | 不存在只有 G1 声明但无实现证据的不变量 |
| V2-K5 | 矩阵可自动校验 | Frontmatter 引用均可解析到实际产物条目 |
| V2-K6 | 文件行数合规 | 所有产物文件不超过 500 行 |
| V2-K7 | 人工审核通过 | 用户逐条确认不变量链路无断裂、实体/字段无遗漏、契约全部满足 |
| V2-K8 | 审查通过 | ae:review 审查 v2/ 目录无阻断发现 |

## 回退规则

断裂处在哪里就回哪里补全：

- 断裂@G2 → 回 G2 补全业务场景覆盖
- 断裂@G3 → 回 G3 补全架构安全映射
- 断裂@G4 → 回 G4 补全约束映射
- 断裂@A1 → 回 A1 补全契约守卫
- 断裂@L2 → 回 L2 补全实现条目
- 断裂@V1 → 回 V1 补全验证条目

补全后从断裂点开始重新执行后续所有步骤，再回到 V2 重新检查。

## 通用产物规格

- 单轨格式：YAML Frontmatter 为唯一真源，正文为人类阐释
- 文件行数硬约束：每个产物文件不超过 500 行
