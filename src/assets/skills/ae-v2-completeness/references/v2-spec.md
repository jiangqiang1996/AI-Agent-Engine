# V2 步骤摘要

## 目标

确认每条不变量从 G1 声明到最终实现有完整的证据链，无断裂、无遗漏。

V2 是最后一道闸门——即使 V1 通过，如果某条不变量在中间步骤缺少对应条目，V2 必须拦截。

## 任务清单

| 任务 | 说明 |
|------|------|
| T1 构建完整性矩阵 | 逐条不变量追踪：G1 声明 → G2 约束映射 → A1 契约守卫 → L2 实现 → V1 E2E 验证 |
| T2 检查链路完整性 | 每环必须有对应条目，任何一环缺失 = 断裂链路 |
| T3 识别未覆盖实体/字段 | data-model 中有定义但 L2 设计中无实现的实体或字段 |
| T4 识别未实现契约 | A1 定义了但 L2 契约合规声明中未满足的条目 |
| T5 汇总完整性问题 | P0：不变量链路断裂；P1：实体/字段未覆盖；P2：契约未满足 |

## 验收关卡

| 编号 | 检查项 | 通过标准 |
|------|--------|---------|
| V2-K1 | 不变量链路完整 | 每条不变量 G2→A1→L2→V1 每步都有对应条目 |
| V2-K2 | 实体/字段有实现 | 每个实体和字段在 L2 中有实现条目 |
| V2-K3 | 契约已满足 | 每条契约在 L2 合规声明中已满足 |
| V2-K4 | 无断裂链路 | 不存在只有 G1 声明但无实现证据的不变量 |
| V2-K5 | 矩阵可自动校验 | Frontmatter 引用均可解析到实际产物条目 |
| V2-K6 | 文件行数合规 | 所有产物文件不超过 500 行 |

## 回退规则

断裂处在哪里就回哪里补全：

1. 断裂@G2 → 回 G2 补全约束映射，重跑 G2→V2
2. 断裂@A1 → 回 A1 补全契约守卫，重跑 A1→V2
3. 断裂@L2 → 回 L2 补全实现条目，重跑 L2→V2
4. 断裂@V1 → 回 V1 补全验证条目，重跑 V1→V2

补全后从断裂点开始重新执行后续所有步骤，再回到 V2 重新检查。

## 通用产物规格

- 单轨格式：YAML Frontmatter 为唯一真源，正文为人类阐释
- 文件行数硬约束：每个产物文件不超过 500 行
