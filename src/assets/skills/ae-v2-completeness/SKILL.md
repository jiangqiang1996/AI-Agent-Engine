# V2 完整性回溯

## 角色

流程最后一道闸门。即使 V1 通过，只要某条不变量在中间步骤缺少对应条目，V2 必须拦截。

## 适用场景

- V1 验证已完成后，确认不变量从声明到实现有完整证据链
- 需要检查实体/字段是否全部被实现覆盖
- 需要检查契约是否全部在实现中满足

## 不适用场景

- 前序技能产物未就绪时不得执行（特别是紧邻前序 V1 产物未就绪时，不得启动本技能）
- 仅需单步骤检查而非完整链路回溯

## 输入自动发现

本技能无需用户手动指定输入路径。执行时按以下规则自动发现产物根目录和上游产物：

1. **产物根目录发现**：在工作区 `docs/ae/galv/` 下搜索 `galv-manifest.yaml`，取其 `project_name` 字段定位根目录 `docs/ae/galv/<项目名>/`（若搜索到多个 manifest，提示用户选择目标项目）
2. 若未找到 manifest，提示用户先执行 G1 创建 manifest
3. **上游产物发现**：从产物根目录按上游依赖表自动读取已存在的上游产物文件；缺失时记录警告，不阻断执行
4. 用户也可显式传入项目名覆盖自动发现结果

## 产物根目录

所有产物写入**产物根目录**下。默认根目录为 `docs/ae/galv/<项目名>/`。

`<项目名>` 由以下规则确定：
1. 若产物根目录下已存在 `galv-manifest.yaml`，读取其中的 `project_name` 字段作为项目名
2. 若不存在，在工作区 `docs/ae/galv/` 下搜索已有的 `galv-manifest.yaml` 自动定位
3. 若仍未找到，提示用户先执行 G1 技能创建 manifest

整个根目录自包含、可移植：内部所有路径均为相对路径，目录可整体移动到任意位置。读取全部阶段产物后，任何 AI 工具可据此生成功能等价、结构等价的软件系统。

本阶段的产物位于根目录下 `v2/` 子目录。

## 产物独占

**独占产物**（只有本技能可以创建或修改，路径相对于产物根目录）：

- `v2/completeness/`（≤3 条不变量时可单文件 `v2/completeness-matrix.md`）
- `v2/completeness-gaps.md`

**共享产物**：

- `galv-manifest.yaml`（首次创建时由当前执行的技能负责，后续技能可读取和追加信息）

**禁止修改**上游技能产物（G1-G5、A1-A2、L1-L3、V1）。

## 上游依赖（只读）

紧邻前序技能：**V1**（ae:v1-e2e-verify），其产物 `v1/` 就绪后方可启动本技能。

| 步骤 | 产物 | 用途 |
|------|------|------|
| G1 | `g1/invariants/` | 不变量声明，追踪链路起点 |
| G2 | `g2/business-scenarios/`、`g2/field-catalog.md`、`g2/roles.md` | 业务场景覆盖，检查不变量→场景对应 |
| G3 | `g3/architecture.md`、`g3/security.md` | 架构/安全约束映射，检查不变量→架构安全对应 |
| G4 | `g4/data-model/` | 约束映射+实体/字段定义，检查不变量→约束对应，识别未覆盖实体和字段 |
| A1 | `a1/contracts/` | 契约守卫，检查不变量→契约对应 |
| L2 | `l2/{module}/design/` | 实现设计，检查约束/契约→实现对应 |
| V1 | `v1/e2e-trace/` | E2E 验证，检查实现→验证对应 |

对上游产物只读，禁止修改。

## 执行流程

### T1 构建完整性矩阵

逐条不变量，按以下链路追踪对应条目：

```
G1 声明 → G2 场景覆盖 → G3 架构安全 → G4 约束映射 → A1 契约守卫 → L2 实现 → V1 E2E 验证
```

矩阵每行格式：

```markdown
| 不变量ID | G1声明 | G2场景 | G3架构安全 | G4约束 | A1契约 | L2实现 | V1验证 | 链路状态 |
|----------|--------|--------|-----------|--------|--------|--------|--------|----------|
| INV-001  | ✓ §1.1 | ✓ SC-01| ✓ ARC-01  | ✓ C-01 | ✓ K-01 | ✓ §3.2 | ✓ TC-01| 完整     |
| INV-002  | ✓ §1.1 | ✓ SC-02| ✗         | ✓ C-02 | ✗      | ✗      | ✗      | 断裂@G3  |
```

### T2 检查链路完整性

对矩阵中每条不变量，检查链路每环是否有对应条目。任何一环缺失 = 断裂链路，标记断裂位置。

### T3 识别未覆盖实体/字段

对比 `g4/data-model/` 与 L2 实现：遍历 `g4/data-model/` 中每个实体和字段，检查 `l2/{module}/design/` 中是否有对应实现条目。

### T4 识别未实现契约

对比 a1/contracts/ 契约定义与 L2 契约合规声明：遍历 a1/contracts/ 中每条契约，检查 L2 合规声明中是否标记为"已满足"。同时检查 `g3/security.md` 中的安全策略是否在 L2 中有实现条目。

### T5 汇总完整性问题

按严重级别汇总到 `v2/completeness-gaps.md`：

- **P0**：不变量链路断裂
- **P1**：实体/字段未覆盖
- **P2**：契约未满足

### T6 产物审查

对当前阶段全部产物执行自检：

1. 逐条对照验收关卡 V2-K1~V2-K8
2. 确认每个产物文件不超过 500 行
3. 确认所有 Frontmatter 引用可解析到上游产物
4. 不通过项立即修复后重新检查
5. 调用 `ae:review mode=autofix domain=document` 审查 `v2/` 目录

## 产物格式

### v2/completeness-matrix.md（单文件模式）

```yaml
step: V2
type: completeness-matrix
invariant-count: <N>
status: passed | failed
upstream:
  G1: g1/invariants/
  G2: g2/business-scenarios/
  G3: g3/architecture.md
  G4: g4/data-model/
  A1: a1/contracts/
  L2: l2/{module}/design/
  V1: v1/e2e-trace/
```

### v2/completeness/ 目录模式

```
v2/completeness/
├── index.md          # 汇总索引
├── INV-001.md        # 单条不变量链路详情
└── ...
```

目录形式时，`index.md` Frontmatter 必须包含 `type: directory_index` 和 `slices` 字段。

### v2/completeness-gaps.md

```yaml
step: V2
type: completeness-gaps
p0-count: <N>
p1-count: <N>
p2-count: <N>
status: passed | failed
```

正文按 P0/P1/P2 分级列出具体问题。

## 单轨格式规则

所有产物文件采用 Markdown + YAML Frontmatter 单轨格式：

- Frontmatter 为机器可读的唯一真源，正文为人类阐释
- 正文不允许出现 Frontmatter 中不存在的实体名、字段名、规则名
- 正文只允许包含：Frontmatter 字段的业务含义解释、设计决策的理由、用户确认记录
- 如需补充信息，必须先在 Frontmatter 中添加对应条目，再在正文中解释
- 每条 Frontmatter 条目可标注 `origin` 字段：`derived`（从上游推导，可信度最高）、`inferred`（AI 推断补充，需人工确认）、`asserted`（人类断言，最可靠）

## 验收关卡

| 编号 | 检查项 | 通过标准 |
|------|--------|---------|
| V2-K1 | 不变量链路完整 | 每条不变量 G2→G3→G4→A1→L2→V1 每步都有对应条目 |
| V2-K2 | 实体/字段有实现 | 每个实体和字段在 L2 中有实现条目 |
| V2-K3 | 契约已满足 | 每条契约在 L2 合规声明中已满足 |
| V2-K4 | 无断裂链路 | 不存在只有 G1 声明但无实现证据的不变量 |
| V2-K5 | 矩阵可自动校验 | Frontmatter 引用均可解析到实际产物条目 |
| V2-K6 | 文件行数合规 | 所有产物文件不超过 500 行 |
| V2-K7 | 人工审核通过 | 用户逐条确认不变量链路无断裂、实体/字段无遗漏、契约全部满足 |
| V2-K8 | 审查通过 | ae:review 审查 v2/ 目录无阻断发现 |

## 回退说明

断裂处在哪里就回哪里补全：

1. 断裂@G2 → 回 G2 补全业务场景覆盖，重跑 G2→V2
2. 断裂@G3 → 回 G3 补全架构安全映射，重跑 G3→V2
3. 断裂@G4 → 回 G4 补全约束映射，重跑 G4→V2
4. 断裂@A1 → 回 A1 补全契约守卫，重跑 A1→V2
5. 断裂@L2 → 回 L2 补全实现条目，重跑 L2→V2
6. 断裂@V1 → 回 V1 补全验证条目，重跑 V1→V2

补全后从断裂点开始重新执行后续所有步骤，再回到 V2 重新检查。

## 安全边界

- 禁止修改任何上游产物；发现缺失时记录到 gaps，由上游技能补全
- 禁止跳过断裂链路标记为"通过"
- 矩阵引用必须可解析，禁止伪造引用
- 产物文件行数不得超过 500 行
- V2-K7 须由用户确认后方可视为本步骤完成
