# 保存 Rules

rules 分支由 `ae:save-experience` 统一执行：识别候选规范、读取已有 `.opencode/rules/` 去重、执行历史交叉验证、展示冲突提醒、获得用户确认后写入。

## 候选识别

只保存未来必须长期遵守的规则。案例、复盘、已验证方案和研究结论应优先保存在 solution 中，不要强行规则化。

候选规范必须满足：可跨未来任务复用、能用明确行为判断是否违反、不是一次性修复步骤、不是尚未验证的偏好。无法同时满足时，改写为 solution 经验或放弃写入 rules。

## 读取与去重

1. 读取当前项目 `.opencode/rules/**/*.md`，目录缺失时说明“无已有 rules 可去重”。
2. 检查全局或历史规则引用时只做交叉验证，不把其他项目规则直接复制到当前项目。
3. 将候选规范与已有规则逐条比较，标记为新增、重复、覆盖、冲突或需要合并。
4. 重复规则不写入；覆盖或合并规则必须展示原规则路径、候选差异和推荐处理方式。

## 历史交叉验证

从本次会话证据、相关 design/review/gate 产物和 `ae/solutions/` 中提取支持该规则的摘要。没有可引用证据时，不得把规则写成强制要求，只能保存为待验证 solution 或放弃写入。

## 冲突处理

发现候选规则与已有 rules、项目规范或用户明确偏好冲突时，必须停止自动写入并向用户展示：冲突规则路径、冲突点、可选处理方案和推荐方案。用户未选择前不得写入。

## 语境判断

- 普通下游项目：只保存适用于当前项目长期开发的规则。
- AE 插件源码维护：可以保存源码维护规则，但必须标明语境。
- AE 源码维护专用 rules 不得写入普通下游项目自动注入的 `.opencode/rules/`。

## 写入前确认

写入前必须展示：目标路径、规则标题、适用语境、已有规则去重结果、冲突检查、证据摘要和脱敏结果。用户未确认时不得写入文件。

## 脱敏门禁

rules 写入前必须执行与 solution 等价的敏感信息门禁。禁止保存 token、私钥、密码、完整环境变量、含密 URL、原始敏感日志、PII、客户/租户标识、内部 URL、私有工单或 PR 链接、绝对本机路径、内部凭证路径、专有数据样例和安全事件原始细节。

如果脱敏结果不通过，先改写为规则级摘要；仍无法脱敏时停止写入。未通过脱敏或用户未确认脱敏结果时，不得写入 `.opencode/rules/`。
