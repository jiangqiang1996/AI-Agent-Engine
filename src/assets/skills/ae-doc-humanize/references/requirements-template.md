# 自包含需求文档模板

用于把 `type: brainstorm` 的 AI 结构化需求产物转换为人读需求文档。

输出文档必须完整承载需求语义。允许记录上游文件路径用于溯源，但不得要求读者打开上游文件才能理解需求。

本模板是 `type: brainstorm` 的人读等价视图，不是独立 PRD 创作模板。输出中的每个章节、字段、示例和说明都必须能从 `ae:brainstorm` 产物的明确内容直接映射或直接推出；源产物没有对应语义时删除该元素，不用通用产品文档元素补齐。给 AI 的需求文档不需要干系人、读者对象、用户画像、业务价值、市场论证或背景介绍；人读版本也不得补充这些内容，除非它们已经在源产物中作为需求范围、约束或验收条件存在。

```markdown
---
type: requirements
date: YYYY-MM-DD
title: <kebab-case-title>
upstream: <上游文件路径>
---

本文档是 `<主题>` 的人读需求等价版本。上游文件：`<上游文件路径>`。本文档为自包含版本，不依赖打开上游文件即可阅读和评审。
```

## 转换要求

- 保留所有需求 ID（如 `R1`、`R2`）和非功能需求 ID（如 `NFR1`、`NFR2`）。
- 保留可恢复 `type: brainstorm` 正文结构所需的信息：问题框架、用户与场景、需求分组、成功标准、范围边界、关键决策、依赖/假设、待定问题和等价性计数。
- 人读需求文档不得包含“下一步”章节或后续流程指令；即使源结构化文档包含“下一步”，也由 `ae:doc-structure` 在反向结构化时按目标模板补回，不作为人读等价正文的一部分。
- 必须记录上游文件路径，但不得用上游路径替代正文内容。
- 如果源文档有 R* 绑定的验收条件，必须保留在对应需求下，不得移动到“验收标准”章节；“验收标准”只承载源文档“成功标准”中的全局成功判断。
- 可选章节只在源文档有对应语义时出现。
- 不得新增源产物中没有的干系人、读者对象、背景介绍、用户画像、业务价值、市场论证、影响叙述、非功能要求、约束、决策、依赖、术语或参考信息。
- 允许的“直接推出”只包括格式展开、同义改写、把 `R* → 验收:` 拆成需求描述和验收条件、把稳定 ID 计数写入等价性检查；不得基于常识或最佳实践补充内容。
- 开放问题必须保留源文档中的影响需求 ID 和问题类型标记，例如 `[影响 R1][用户决策]`、`[影响 R2][技术]`，不得只保留自然语言问题。
