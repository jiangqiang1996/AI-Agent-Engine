# 计划交接

本文件包含计划写入后的说明。在计划文件已写入且信心检查完成之后加载。

## 5.3.8 技能内 review 闭环

针对计划文件运行技能内 review 闭环。此环节补强现有文档审查逻辑，明确审查者、auto 修复范围和收敛协议。

**审查调用：** 调用 `ae:review mode=headless domain=document <plan-path>`，审查者为 `step-granularity-reviewer`。`mode=headless` 表示 ae:review 被技能内部调用时不输出"下一步推荐技能"引导，仅返回审查结果（status/findings/summary）给本技能，由 ae:plan 自身负责下一步引导。

**auto 修复范围：** 步骤粒度过粗、验证命令缺失、并行分组遗漏、依赖顺序错误。ae:review 返回的 auto 可修复发现由本技能自动应用修复，修复后重新运行审查。

**收敛协议（上限 2 轮）：**
- 第 1 轮：初次审查 → auto 修复 → 重新审查
- 收敛判定：重新审查后无新增 P0/P1 发现即为收敛
- 未收敛处理：2 轮后仍有 P0/P1 阻断，回退 design（返回上游 ae:design 修正设计契约），不进入 5.4

**管道模式：** 以 `mode=headless` 运行。无头模式静默应用自动修复并返回结构化发现。

信心检查和文档审查捕获不同类别的问题：
- 信心检查加强理由、排序、风险处理
- 文档审查检查步骤粒度、一致性、可行性、范围对齐

## 5.3.9 最终检查和清理

确认计划更具体、边界保持完整，并且源决策已被保留。如果使用了制品暂存模式，清理临时目录。

## 5.4 生成后选项

**管道模式：** 跳过交互菜单，立即将控制权返回给调用者。

技能内 review 闭环收敛后，呈现下一步选项。执行计划已就绪。接下来使用 ae:work 执行实施。

**问题：** "计划已就绪。接下来你想做什么？"

**选项：**
1. **启动 `/ae-work <plan-path>`**（推荐，由用户确认后另行发起）
2. **暂时完成**

**上下文中提供额外的文档审查：** 如上下文显示仍有未解决的 P0/P1 发现，提议再运行一轮文档审查。

如果用户选择启动执行，只输出可运行的 `/ae-work <plan-path>` 建议和计划路径；不得在当前 `ae:plan` 流程中自动调用 `ae:work`。只呈现下一步选项，不自动执行任何后续技能。如用户需要外部跟踪，输出计划路径和摘要即可。

**阻断时引导：** 若技能内 review 闭环未收敛（2 轮后仍有 P0/P1），回退上游 ae:design 修正设计契约；若用户直接调用 ae:plan 且无上游 design，回退用户澄清。
