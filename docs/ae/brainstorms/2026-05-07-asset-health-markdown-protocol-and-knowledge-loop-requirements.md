# 资产健康巡检、技能 Markdown 协议测试与经验库闭环

## 问题框架

AE 的核心价值依赖 `src/assets/` 中的技能、命令、代理、规则和配置说明与 TypeScript 注册逻辑保持一致。当前仓库已经存在 catalog、help、gate、setup gate、运行时资产定位和若干一致性测试，但仍容易出现三类问题：资产描述与注册信息漂移，Markdown 规则中的硬约束难以机器验证，以及历史审查、失败、方案沉淀无法被后续流程稳定复用。

这项改进面向 AE 插件维护者和后续使用 AE 工作流的代理。目标不是一次性扩展更多能力，而是让现有能力更可发现、更可验证、更可恢复，并把重复出现的问题转化为可检索的组织经验。

## 需求

**P0: 资产健康巡检**
- R1. 系统应能发现可分发资产与注册/目录清单之间的漂移 → 验收: 当技能、命令、代理、工具或公开帮助清单存在缺失、重复、命名不一致或路径失效时，验证流程能给出明确失败信息和对应资产名称。
- R2. 系统应能检查关键资产描述的一致性，但首版只覆盖确定性协议 → 验收: 对 frontmatter、catalog、命令模板、help 输出或工具描述中必须字面一致或必须包含的字段/短语进行检查；超出确定性规则的自然语言语义冲突保留给人工审查或后续增强。
- R3. 系统应区分运行时资产真源与开发/调试产物 → 验收: 巡检结论不得把 `.opencode/`、`dist/`、`docs/ae/` 或本仓库开发规则误当作面向插件用户的资产真源；涉及运行时能力时以 `src/` 下可分发资产为准。

**P0: 技能 Markdown 协议测试**
- R4. 系统应将 Markdown 中最高风险的硬约束转化为可验证协议 → 验收: 首批协议覆盖 setup 前置、Git 写操作授权、破坏性本地操作授权、远程写操作边界和高风险操作说明；运行时独立性等更广协议可作为后续扩展。
- R5. 系统应优先覆盖会导致用户流程越权或跳步的协议 → 验收: 如果公开技能、命令、代理或规则引导用户执行 `agent-browser`、Git 写操作、远程写操作、破坏性本地操作或跳过审查/验证，协议测试能检查是否存在对应前置条件和降级说明；任何 `agent-browser` 可执行命令或可复制命令出现前，必须要求当前会话已完成 `ae:setup`，且不得以安装状态、命令存在检查或用户声明替代。
- R6. Git 写操作和破坏性本地操作协议必须检查授权粒度 → 验收: 相关资产必须要求授权绑定目标仓库、目标分支、工作区、完整命令参数、风险说明和明确授权来源；授权不得外推为 push、PR、force push、skip hooks、amend 或 Git 配置修改；未授权时必须停止而不是给出可复制危险命令。
- R7. 协议测试应给出面向维护者的修复线索 → 验收: 失败信息包含资产路径、违反的协议主题和期望的用户可见语义，而不是只给出模糊快照差异。

**P1: 经验沉淀统一入口**
- R8. 系统应将现有 `ae:save-rules` 升级为统一经验沉淀入口 `ae:save-experience` → 验收: 用户触发经验沉淀时只需使用一个推荐入口；该入口能识别当前会话中的方案型经验和规则型经验，并明确说明每类内容将保存到何处。
- R9. `ae:save-experience` 应按“先保存解决方案，再提炼规范”的流程编排 → 验收: 审查发现、失败门禁、资产漂移修复、竞品研究和已验证方案先被保存为结构化 solution 条目；随后仅将真正应长期遵守的规则提炼并保存到 `.opencode/rules/`。
- R10. 方案型经验保存流程应抽成可被主技能引用的独立说明 → 验收: solution 保存逻辑包含候选识别、去重、文件命名、结构化字段、适用语境、证据摘要、后续引用方式、脱敏检查和写入前确认；确认内容必须包含目标路径、标题、语境标签、证据摘要和脱敏结果，未确认时不得写入文件。
- R11. 规范型经验保存流程应抽成可被主技能引用的独立说明，并迁移到 `ae:save-experience` 内部 rules 分支 → 验收: rules 保存逻辑保留候选规范识别、已有规则去重、历史交叉验证、冲突提醒、用户确认和 `.opencode/rules/` 写入策略；主技能在 solution 保存后调用该流程提炼规范。
- R12. 经验写入必须包含敏感信息边界 → 验收: 写入 solution 或 rules 前必须避免保存凭证、私钥、token、完整环境变量、含密 URL、原始敏感日志和不必要的个人信息；证据优先保存摘要、相对路径和可复现线索，而不是原始敏感输出。
- R13. 经验沉淀应避免污染普通下游项目假设 → 验收: solution 条目和 rules 条目都必须标明适用语境；仅适用于 AE 插件源码维护的经验不得被描述为所有用户项目的通用要求；写入 rules 前必须判断目标项目语境，AE 源码维护专用规则不得写入普通下游项目自动注入的 `.opencode/rules/`。
- R14. `ae:save-rules` 的历史入口应彻底移除 → 验收: 可分发资产、schema、catalog、命令注册、help、模型路由和测试中不再暴露 `ae:save-rules`；rules 保存只能通过 `ae:save-experience` 内部 rules 分支进入。
- R15. AE 工作流发现已有经验应先采用低成本提示方式 → 验收: 首版只要求在相关技能或流程中提示维护者检查经验库或引用明确条目；自动相似度检索、自动注入和跨阶段主动推荐不属于首版必须能力。

**使用体验与边界**
- R16. 巡检和协议测试应默认服务维护者的交付前验证 → 验收: 维护者能在修改资产、命令、规则、工具描述或公开流程后运行验证，并获得是否可交付的结论。
- R17. 失败结果应可被后续计划和修复任务引用 → 验收: 每个失败项具备稳定主题或标识，后续 `ae:plan` 或 `ae:work` 可以引用它来安排修复，不需要重新解释问题。
- R18. 该能力不应要求引入完整通用编排语言或重型治理平台 → 验收: 需求满足时不依赖新增跨平台安装体系、通用 command DSL、外部数据库或远程协作写操作。

## 成功标准

- 修改 AE 资产或公开流程后，维护者能更早发现资产漂移、规则遗漏和越权引导。
- Markdown 协议失败能指向具体资产和具体约束，减少靠人工审查记忆发现问题。
- 重复出现的审查结论、竞品启发和修复方案能通过 `ae:save-experience` 先沉淀为 solution，再按需提炼为 rules，后续工作流可按明确引用复用。
- 后续规划不需要重新决定这项能力要解决什么问题、优先覆盖哪些风险或排除哪些方向。

## 范围边界

- 不把跨 `opencode` / `codex` / `claude code` 的安装适配作为目标。
- 不直接照搬重型 OpenCode 全家桶，不新增 tmux 面板、后台任务系统或模型 fallback 体系。
- 不优先新增大量技能、代理或命令；本需求优先治理现有资产质量，并倾向把经验沉淀收敛到一个推荐入口。
- 不把经验库做成自动知识检索系统或远程协作系统；若需要外部 Issue、PR 或 Release，由用户在外部系统自行处理。
- 不把所有经验都强行规则化；只有未来必须长期遵守的约束才应写入 `.opencode/rules/`，案例、复盘和已验证方案应保留在 solution 条目中。
- 不要求 `ae:save-experience` 阻塞 P0 资产健康巡检和 Markdown 协议测试交付；最终交付形态只保留 `ae:save-experience` 一个经验沉淀入口。
- 不要求所有下游用户项目具备本仓库的源码结构；涉及 AE 源码维护的规则必须明确标注语境。

## 关键决策

- 优先做“资产健康巡检 + Markdown 协议测试”，经验库只做最小沉淀闭环: 前两者直接服务交付前验证，经验库作为减少重复研究的低成本补充，不阻塞首版验证能力。
- 先服务 AE 插件维护者，再考虑面向普通用户暴露诊断入口: 当前价值最大的是提升本仓库资产交付质量，避免过早扩展为通用治理平台。
- 经验沉淀入口采用 `ae:save-experience`: 它作为推荐入口统一编排经验保存，先保存 solution，再提炼 rules，避免用户在多个保存技能之间做工具选择。
- solution 与 rules 使用拆分的引用流程: 方案型经验和规范型经验的详细保存逻辑分别放入可被主技能引用的子流程，主技能保持编排职责，便于后续扩展新的沉淀类型。
- 经验库必须带语境标签: 本仓库同时包含插件源码维护能力和面向下游项目的运行时能力，语境不清会导致错误规则外溢。
- 移除 `ae:save-rules` 入口: 最新决策是只保留 `ae:save-experience` 作为统一沉淀入口，rules 分支内嵌在该技能中。
- 渐进交付优先于入口一次性重构: `ae:save-experience` 是目标形态，规划时应避免让统一入口、子流程拆分或命名迁移延误 P0 验证能力。

## 依赖 / 假设

- 当前仓库的可分发资产真源在 `src/assets/`，工具注册和服务逻辑在 `src/tools/`、`src/services/`，这是已通过仓库规则和源码扫描确认的前提。
- 已有测试覆盖部分 catalog、help、setup gate 和配置行为；本需求假设后续规划会优先复用这些现有验证入口，而不是另起一套孤立体系。
- `docs/ae/solutions/` 当前不存在；经验库闭环可以新建稳定位置，也可以在规划阶段选择其他等价位置，但首版不要求自动相似度检索。
- 原 `ae:save-rules` 的规则型经验保存流程应迁移到 `ae:save-experience` 的 rules 子流程，而不是保留旧技能入口。
