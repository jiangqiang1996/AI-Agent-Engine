# 资产可达性图谱需求

## 问题框架

AE 插件已经拥有多类资产：技能、命令、代理、工具、catalog、review selector 和仓库内声明的公开入口。当前维护难点不是单个文件是否存在，而是这些资产是否能从公开入口真实触达，以及不同资产之间的结构化关系是否闭合。

维护者需要一份仓库内可查看的可视化文档，用来快速理解 AE 工作流拓扑，并发现明显的孤儿资产、断链引用、重复入口或高耦合节点。首版聚焦结构化引用，避免自然语言提示词正文扫描带来的误报。

## 需求

**图谱产物**
- R1. 系统应生成或维护一份仓库文档形式的资产可达性图谱，面向维护者阅读。→ 验收: 仓库中存在一份 Markdown 文档，包含可直接渲染的 Mermaid 图或等价的文本图谱。
- R2. 图谱应覆盖结构化资产类型：公开入口、技能、命令、代理、工具、catalog 条目和 review selector 相关审查代理。→ 验收: 文档中能区分这些资产类型，并能看到它们之间的主要结构化关系。
- R3. 图谱应从结构化来源建立边关系，而不是从自然语言提示词正文中猜测关系。→ 验收: 首版范围说明中明确列出允许的数据源和排除的数据源。

**入口与数据源**
- R4. 首版应明确定义可达性根节点。→ 验收: 文档说明首版至少把默认用户入口、公开命令、可直接加载技能和插件暴露工具作为入口类型，并说明哪些入口类型仅作为源码声明分析，不调用运行时行为。
- R5. 首版应区分结构化元数据和自然语言正文。→ 验收: 文档允许使用 `SKILL.md` frontmatter、文件路径、代码常量、catalog、命令注册和 review catalog/selector 等结构化来源；明确不把 `SKILL.md` 正文、agent prompt 正文或 README 自由文本引用作为强关系。

**可达性诊断**
- R6. 图谱文档应分别标记“存在但不可达”“引用但不存在”“重复入口或别名”三类风险。→ 验收: 文档包含风险说明区，并为每类风险分别给出状态条目。
- R7. 风险状态不应只有“已发现/未发现”二元结果。→ 验收: 每类风险状态至少支持“已发现”“未发现且覆盖完整”“未发现但覆盖不完整”“未覆盖”，并列出已检查的数据源。
- R8. 图谱应能帮助维护者判断某个代理是否被结构化工作流触达，尤其是 review 相关代理。→ 验收: review selector 或 review catalog 中的代理在图谱中有单独分组或路径说明。
- R9. 当图谱无法证明某条关系时，应将其标为未知或未覆盖，而不是推断为不存在。→ 验收: 文档包含“覆盖边界”说明，区分未覆盖与确认不可达。

**使用体验**
- R10. 首版输出应优先服务仓库维护者，不要求接入 `/ae-help`、TUI 或运行时诊断入口。→ 验收: 范围边界中明确运行时展示不属于首版；但仓库中的帮助入口声明可作为结构化资产参与分析。
- R11. 图谱应足够轻量，适合作为后续计划阶段的输入。→ 验收: 如果 Mermaid 图过大，文档可拆分为入口、技能/命令、review 代理、工具等子图。
- R12. 图谱文档应包含后续演进建议。→ 验收: 文档指出哪些检查可在后续演进为测试门禁或自诊断能力。
- R13. 图谱应声明鲜度和维护触发条件。→ 验收: 文档说明生成或更新时间、所用数据源，以及新增/删除技能、命令、代理、工具、catalog 或 selector 规则时需要更新图谱。

## 成功标准

- 维护者能在一个文档中看清 AE 资产之间的主要结构化路径。
- 文档能暴露至少一种当前项目中值得调查的可达性或重复入口风险，或明确说明未发现风险。
- 后续 `ae:plan` 不需要重新决定首版目标、读者、数据来源和非目标。
- 首版不会因为自由文本提示词扫描产生大量误报。
- 图谱不会把未覆盖的数据源误报为确认安全。

## 范围边界

- 不实现代码变更；本阶段只定义需求。
- 首版不接入 `/ae-help`、TUI、运行时诊断或 CI 门禁；这不排除分析仓库中声明这些入口的结构化源码或配置。
- 首版不解析 `SKILL.md`、agent prompt 或 README 中的自然语言正文引用作为强关系。
- 首版不要求证明所有运行时 `.opencode/` 产物与真源一致；这属于资产一致性健康检查方向。
- 首版不要求自动修复孤儿资产或断链引用。

## 关键决策

- 首版选择“可视化优先”: 先让维护者理解工作流拓扑，再考虑测试门禁。
- 使用场景选择“仓库文档”: 产物应是 Markdown + Mermaid 或等价仓库文档，而不是运行时 UI。
- 边关系选择“结构化边”: 只把代码常量、catalog、命令注册、frontmatter、文件路径、review catalog/selector 等结构化来源作为强证据。
- 风险状态选择“覆盖感知”: 未发现风险时必须同时说明覆盖是否完整。

## 依赖 / 假设

- 仓库已有资产名称常量化约束，结构化来源可作为首版图谱的可信输入。
- Mermaid 图足以表达首版拓扑；如果图过大，规划阶段可以拆成多张子图。
- 自由文本引用仍有价值，但应在后续阶段作为弱证据扩展，而不是首版强依赖。
- 首版图谱表达的是源码真源的结构化可达性，不等同于运行时可用性证明。
