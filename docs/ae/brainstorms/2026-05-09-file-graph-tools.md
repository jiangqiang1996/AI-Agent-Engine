# 文件关系图谱工具

## AI 解析契约
- canonicalKind: requirements
- humanEquivalent: true
- stableIdsRequired: true
- noImplicitScope: true

## 问题框架
开发者在大型项目中难以追踪文件之间的依赖关系。修改一个文件时，不清楚会影响哪些其他文件；重构时难以识别循环依赖和孤立节点，项目迁移时难以梳理模块边界。需要一个工具自动解析项目文件关系，建立可查询的图谱数据，支持项目分析和重构迁移场景。

## 用户与场景
- **场景 1：项目分析** — 开发者接手新项目时，通过查询关系图谱快速了解项目全貌，识别核心模块和依赖链路
- **场景 2：重构迁移** — 重构或迁移项目时，通过影响范围分析评估变更波及面，确保不遗漏关联文件
- **场景 3：并发访问** — 查询关系数据的同时，另一个会话正在维护（更新）关系数据，需要保证读写不冲突

## 需求

**解析能力**
- R1. 支持解析代码文件的 import/require/include 等导入语句，建立文件级依赖关系 → 验收: 能正确识别 TS/JS/Python/Java/Go 等语言的导入语句，输出源文件和目标文件的依赖边
- R2. 支持解析文档文件（Markdown）中的文件引用链接 → 验收: 能识别 `[text](path)` 和 `[text][ref]` 格式的相对路径链接
- R3. 支持解析 AE 资产引用（技能/命令/工具/代理的 ae:xxx 引用） → 验收: 能识别 SKILL.md、命令、代理中的 ae:xxx 格式引用，建立资产间依赖关系
- R4. 支持解析目录结构关系，建立文件-目录层级图 → 验收: 能正确反映文件在目录树中的位置关系
- R5. 支持可配置的解析深度：浅层（正则匹配导入语句）和深层（AST 解析，用于更准确识别 re-export、类型引用等复杂文件级关系） → 验收: 通过参数控制解析深度，深层模式能识别 re-export 和类型引用

**存储能力**
- R6. 使用 SQLite 存储关系数据，采用完整图结构：节点表 `files`（文件属性）和边表 `relations`（关系类型和元数据） → 验收: 数据库包含 files 和 relations 两个核心表
- R7. 数据库文件保存在项目根目录下 `.ae/graph.db` → 验收: 文件位置符合约定
- R8. 支持增量更新，基于 Git diff 识别变更文件，仅重新解析变更部分 → 验收: 执行增量解析时只处理 Git diff 中的变更文件；非 Git 项目时降级为全量解析并提示

**配置能力**
- R9. 排除规则配置在 ae.jsonc 文件中 → 验收: 配置项在 `ae.jsonc` 的 `graph.exclude` 字段中
- R10. 运行时检测常见排除目录（node_modules、dist、build、.git、coverage、__pycache__、.next、.nuxt）并询问用户是否排除 → 验收: 首次扫描遇到未在 ae.jsonc 中配置的上述目录时，通过 opencode 工具确认机制询问用户
- R11. 用户确认排除后自动保存到 ae.jsonc → 验收: 确认后配置自动写入文件，后续扫描不再询问

**查询能力**
- R12. 支持查看单个文件的依赖和被依赖关系 → 验收: 能输出文件的直接依赖和反向依赖列表
- R13. 支持影响范围分析：修改文件 X 会影响哪些文件 → 验收: 能输出完整的影响链（直接和间接依赖）
- R14. 支持健康检查：检测循环依赖和孤立节点 → 验收: 能输出循环依赖链和孤立文件列表
- R18. 支持条件筛选查询：按文件类型、目录路径、关系类型等条件筛选节点和边 → 验收: 能输出满足条件的文件列表或关系列表
- R19. 支持路径查找：查询两个文件之间的最短依赖路径 → 验收: 能输出从源文件到目标文件的最短依赖链
- R20. 支持核心模块识别：识别被依赖最多的文件（入度最高的节点） → 验收: 能输出 Top N 核心模块及其被依赖次数
- R21. 支持关系统计：按关系类型分组统计（导入数、引用数、目录包含数等） → 验收: 能输出各类型关系的数量统计
- R22. 支持模式匹配：查找特定模式的依赖链（如循环链、长链） → 验收: 能输出符合指定模式的依赖链列表

**并发与容错**
- R15. 解析过程中意外终止或断电后，重新执行应能正常工作而非报错 → 验收: 中断后重新执行能自动恢复，不出现数据库锁定或数据不一致错误
- R16. 增量解析应具有幂等性，重复执行相同输入应产生相同结果 → 验收: 连续两次执行结果一致
- R17. 支持读写并发：查询操作和维护（更新）操作同时进行时，查询应能读到一致的快照数据，不阻塞也不报错 → 验收: 维护过程中执行查询，能返回上一次完整解析的结果；维护完成后，后续查询能看到最新数据
- R23. 支持多会话并发：同一工作空间多个 opencode 会话同时执行解析或查询命令时，不应产生数据库损坏或数据不一致 → 验收: 并发执行时使用数据库锁或 WAL 模式保证一致性，后执行的解析等待前一个完成后自动获取最新数据
- R24. 工作空间边界约束：禁止在工作空间 A 解析工作空间 B 的关系，除非 B 是 A 的子目录 → 验收: 传入的路径参数必须在当前工作空间内，否则返回错误提示；支持显式声明子目录工作空间

## 非功能需求
- NFR1. 工具自身解析性能：1000 个文件的项目应在 30 秒内完成首次解析 → 验收: 性能测试通过
- NFR2. 数据库大小：1000 个文件的项目数据库应小于 10MB → 验收: 磁盘占用检查通过
- NFR3. 兼容性：支持 Windows/macOS/Linux 平台 → 验收: 跨平台测试通过

## 成功标准
- 开发者能通过一条命令了解项目文件关系全貌
- 修改文件前能快速评估影响范围
- 能识别项目中的循环依赖和孤立文件
- 重构迁移时能清晰识别模块边界和依赖链路

## 范围边界

### 范围内
- 文件级依赖关系解析（导入语句、文档引用、AE 资产引用）
- SQLite 存储和查询
- 增量更新机制（Git diff）
- 排除规则配置
- 读写并发支持

### 范围外
- 符号级关系解析（函数调用链、类继承图）
- 运行时动态依赖分析
- 业务代码运行时性能分析
- 可视化图形输出（后续可扩展）

### 约束
- 使用 opencode 自定义工具实现，不引入外部 CLI 依赖
- 工具内部使用代码解析确保准确性

## 关键决策
- D1. 使用 SQLite 而非内存图 → 理由: 持久化存储，支持增量更新，跨会话复用
- D2. 基于 Git diff 增量更新 → 理由: 与开发者工作流一致，准确性高；非 Git 项目降级为全量解析
- D3. 配置存储在 ae.jsonc → 理由: 统一项目配置入口，避免新增配置文件
- D4. 完整图结构：节点表 `files` + 边表 `relations` → 理由: 支持丰富的节点属性和关系类型查询
- D5. 深层 AST 解析仅用于更准确识别文件级关系（re-export、类型引用），不扩展到符号级 → 理由: 控制首版复杂度，符号级分析可作为后续扩展

## 依赖 / 假设

### 依赖
- opencode 插件系统支持自定义工具
- SQLite 驱动（better-sqlite3 或类似库）

### 假设
- ae.jsonc 配置文件已存在或可创建
- 首版仅支持 Git 项目的增量更新，非 Git 项目降级为全量解析

## 术语表
| 术语 | 定义 |
|------|------|
| 节点 | 文件或目录在图谱中的表示，存储于 `files` 表 |
| 边 | 文件之间的依赖、引用或包含关系，存储于 `relations` 表 |
| 增量更新 | 基于 Git diff 仅重新解析变更文件而非全量重建 |
| 影响链 | 修改某文件后，直接和间接受影响的文件序列 |
| 工作空间 | opencode 会话的根目录，工具只能解析该目录及其子目录的文件关系 |
