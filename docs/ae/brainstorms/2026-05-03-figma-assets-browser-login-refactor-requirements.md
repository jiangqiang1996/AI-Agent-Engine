# ae:figma-assets 浏览器登录下载重构

## 问题框架

当前 `ae:figma-assets` 的主路径是用户显式提供 Figma token 后调用官方 Images API，并用 `collect` 模式作为手动导出降级路径。用户希望彻底重构该实现方式，使目标体验转为：代理通过 `agent-browser` 打开 Figma，由用户在浏览器中完成登录和授权，然后从已授权页面下载素材到当前工作区。

本次方向不是复用 Trae CN 的私有资源，而是深度复刻其可迁移实现思路：浏览器侧完成用户授权和素材发现，工具侧负责受控下载、写盘、校验和摘要。只读扫描 Trae 安装目录时发现了 Figma 相关打包代码、认证 header 处理、`@ies/semi-d2c-figma` / `@ies/semi-d2c-figma-adapter` / `@ies/semi-d2c-preset-figma` 和通用下载能力线索，但这些只能作为第三方依赖与架构参考，不得成为运行时对 Trae 安装目录或 Trae 内部服务的依赖。

## 需求

**默认用户体验**
- R1. `ae:figma-assets` 应新增 `mode: browser` 作为浏览器登录授权路径，并在能力验证通过后成为新的默认主路径。 → 验收: 用户提供 Figma URL 或节点来源后，流程先引导完成 `ae:setup`，再用 `agent-browser` 打开 Figma 页面，并要求用户在浏览器中自行完成登录、二次验证、组织授权或访问申请；若能力验证未通过，`browser` 必须标记为实验或不可用，而不是替换现有默认路径。
- R2. 流程应清楚区分“用户登录完成”和“素材已下载完成”。 → 验收: 页面可访问只代表授权状态满足继续条件；最终成功必须基于本轮新增素材文件、manifest 和 checksum 校验，而不是基于页面打开成功或点击过下载按钮。
- R3. 用户不应再被迫提供 Figma API token 才能走通过验证的浏览器主流程。 → 验收: 当 `browser` 能力门禁通过时，默认帮助文案和工具描述不把 `FIGMA_OAUTH_TOKEN`、`FIGMA_API_KEY` 或 `FIGMA_TOKEN` 描述为首选输入；这些凭证路径只能作为可选兼容或降级路径。

**浏览器驱动素材获取**
- R4. 工具应通过 `agent-browser` 识别 Figma 页面状态。 → 验收: 能分类报告未登录、登录中、无权限、文件不存在、页面加载失败、节点不可见、节点可导出、下载入口不可自动化等状态；无法分类时返回可恢复的失败说明。
- R5. 素材下载必须来自用户已授权的页面上下文或由页面暴露的可下载资源。 → 验收: 工具不得绕过 Figma 权限，不得伪造登录，不得读取浏览器 token、cookie、localStorage、sessionStorage 或账号标识；如需要网络资源 URL，必须来自本轮可见页面操作或浏览器自动化可观测事件，并经过 allowlist 与大小限制校验。
- R6. 首版应优先支持可验证的浏览器下载事件或可观测资源下载，而不是不可验证的系统默认下载目录猜测。 → 验收: 若 `agent-browser` 无法控制或返回下载产物路径，流程必须停止并提示改用明确的降级路径；不得去扫描用户全局下载目录寻找疑似文件。
- R7. 节点选择与导出范围应由用户显式确认。 → 验收: 当 Figma URL 中包含 `node-id` 时默认针对该节点；缺少节点时，流程应要求用户确认导出当前选中节点、当前页面可见资源或手动指定节点，不自动遍历整个 Figma 文件。
- R8. 浏览器自动化必须使用隔离会话承载用户登录态。 → 验收: 默认使用临时浏览器上下文或等价隔离 profile；运行结束清理登录态、缓存、下载记录和临时文件；不得复用、读取或导出用户日常浏览器 profile。

**Trae 思路复刻边界**
- R9. 允许把 Trae 安装目录作为只读研究来源，但运行时不得依赖 Trae 内部资源。 → 验收: 研究输出只保留脱敏结论、第三方依赖名称和可公开验证的行为假设；交付代码不得调用 Trae 可执行文件、读取 Trae 用户数据、加载 Trae 打包文件、依赖 Trae 扩展目录或复用 Trae 私有服务。
- R10. 若 Trae 内部使用第三方开源依赖，可评估引入对应第三方依赖。 → 验收: 不得引入未经用途、公开可获得性和许可证风险评估的第三方依赖；不得因为 Trae 包含某依赖就默认加入项目。
- R11. 复刻目标是行为链路，不是私有实现复制。 → 验收: 任何依赖、协议、URL、header、算法或行为模式进入计划前，必须能在公开 Figma 文档、公开 npm 包、开源仓库或独立实验中验证；Trae 观察只能作为待公开验证假设，不得作为唯一依据。

**产物与验证**
- R12. 所有素材产物必须写入工作区内专用 Figma 输出目录。 → 验收: 输出目录默认仍为 `.figma` 或等价受控目录；每次运行使用隔离 run 目录；拒绝写入工作区外、符号链接逃逸、非 Figma 专用目录或用户全局下载目录。
- R13. 下载资源必须满足最小安全策略。 → 验收: 仅允许 HTTPS 和明确的 Figma 官方页面/静态资源域名集合；禁止内网、localhost、`file:`、`data:`、`javascript:` 等来源；每次重定向后重新校验；设置 Content-Type、扩展名、单文件大小、超时和总下载量上限。
- R14. 下载文件名和内容处理必须防止路径与内容风险。 → 验收: 下载文件名必须重新生成或严格净化；若处理归档文件，解压前校验每个条目的规范化路径并拒绝绝对路径、`..`、符号链接和超限文件；SVG/HTML 等可执行或可嵌脚本内容必须标记风险或限制类型。
- R15. manifest 应记录浏览器路径的证据状态。 → 验收: manifest 能标识本轮使用了 `agent-browser`、下载来源类型、脱敏页面来源、素材数量、文件大小、SHA-256、失败分类和是否保存了本地证据；不得记录敏感账号、token、cookie、签名 URL、完整私有 URL、完整 DOM 或带身份语义的响应头。
- R16. 本地证据保存应默认最小化。 → 验收: 默认不保存截图、HAR、完整 DOM 或网络响应体；如为调试保存，必须由用户显式确认，写入工作区受控目录，自动脱敏 URL、文本和资源名，并在 manifest 中记录证据类型和删除方式。
- R17. `validate` 应继续作为独立校验能力存在。 → 验收: 即使主路径改为浏览器下载，`validate` 仍能校验 latest manifest 与 run manifest、文件大小和 SHA-256，并能发现历史残留或被篡改文件。
- R18. 失败输出应可恢复且不泄露敏感信息。 → 验收: 对未完成 setup、用户取消登录、权限不足、下载不可控、资源 URL 不安全、文件过大、写盘失败、checksum 不匹配等情况输出明确下一步，且仅展示脱敏路径和失败类别。

**兼容与迁移**
- R19. API token 路径应作为兼容模式保留，但不能遮蔽已验证的浏览器主路径。 → 验收: 保留 `mode: api`、`mode: collect` 和 `mode: validate`；新增 `mode: browser`；当浏览器能力门禁通过时，默认值迁移为 `browser`，旧 `api` 模式在说明中标为显式凭证兼容路径。
- R20. 手动 `collect` 降级路径应保留。 → 验收: 当浏览器下载能力无法验证时，工具能提示用户手动从 Figma 导出到工作区内目录，再通过 `collect` 收集并生成相同格式的 manifest。

## 成功标准

- 在 `agent-browser` 下载能力门禁通过后，用户可以在不提供 Figma API token 的情况下，通过浏览器登录授权完成 Figma 素材下载到当前工作区。
- 工具输出能明确说明本轮采用浏览器主路径、用户完成了哪个可验证授权状态、下载了哪些脱敏素材、manifest 在哪里、校验是否通过。
- 实现不依赖 Trae 安装目录、Trae 内部命令、Trae 用户数据或 Trae 私有服务；只允许借鉴经过公开来源或独立实验验证的第三方开源依赖和行为模式。
- 任何无法通过浏览器自动化安全验证的下载场景都不会被伪造成成功，而是降级到 API 兼容模式或手动 collect 模式。

## 范围边界

- 本次重构目标是 `ae:figma-assets` 的素材获取链路，不包含像素级设计还原；视觉同步继续由 `figma-design-sync` 承担。
- 不绕过 Figma 登录、付费、组织、文件或节点权限。
- 不读取、复制、打印、持久化或跨进程转移浏览器敏感态。
- 不扫描用户全局下载目录、浏览器 Profile、Trae 数据目录或系统凭证存储。
- 不把 Trae CN 安装目录作为运行时依赖；该目录只用于本次需求阶段和规划阶段的只读研究线索，且不得复制、提交、日志输出或摘要化泄露 Trae 私有代码、用户配置、账号标识、缓存或凭证。
- 不承诺首版支持自动遍历整个 Figma 文件或批量导出所有节点。

## 关键决策

- 目标主路径改为浏览器登录下载: 用户明确希望彻底重构当前 API token 优先的实现，降低凭证配置负担，并贴近 Trae 的用户体验；但默认值迁移必须以 `agent-browser` 下载能力验证通过为前提。
- 深度复刻但不依赖 Trae: 可研究 Trae 的行为链路和第三方依赖选择，但新实现必须是 opencode 原生能力。
- 下载成功以工作区产物为准: 浏览器页面状态、点击动作和截图只能作为过程证据，不能替代素材文件、manifest 和 checksum。
- 保留 API 与 collect 降级: 浏览器下载受 `agent-browser` 能力和 Figma UI 变化约束，保留兼容路径能避免单点失败。

## 依赖 / 假设

- 用户对目标 Figma 文件或节点拥有合法访问权限，并愿意在自动化浏览器中完成登录。
- 当前会话在执行任何 `agent-browser` 命令前必须先完成 `ae:setup`。
- `agent-browser` 需要具备足够的页面导航、交互、下载事件或可观测资源能力；具体能力边界需在规划阶段验证。
- `agent-browser` 是首版唯一允许的浏览器自动化执行层；`chrome-remote-interface`、Playwright 下载事件模型、Figma 官方 API、以及 Trae 安装中出现的 `@ies/semi-d2c-*` 相关第三方依赖只能作为研究对象，除非后续计划明确变更架构并通过审查。

## 待定问题

### 推迟到规划

- [影响 R1/R3/R6/R19][技术] 本轮最小验证显示 `agent-browser download` 对本地 HTTP attachment 场景返回 `Download was canceled`，但 `agent-browser eval` 可在浏览器页面上下文中通过 `fetch` 读取同源资源字节。规划阶段应优先设计“浏览器授权状态确认 + 可观测资源 fetch/受控写盘”路径，而不是依赖 `download` 命令事件落盘。
- [影响 R7][产品] 缺少 `node-id` 时，首版优先要求用户手动指定节点，还是允许导出当前页面选中节点；若选择后者，必须定义可审计的节点摘要确认方式。
- [影响 R10/R11][技术] Trae 安装中出现的第三方 Figma/D2C 依赖是否开源、许可是否可接受、是否与素材下载需求直接相关。
- [影响 R13/R14][技术] 下载资源安全策略和文件内容限制如何落到测试用例与错误分类。
