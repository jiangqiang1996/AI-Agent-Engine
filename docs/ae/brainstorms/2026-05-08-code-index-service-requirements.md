# 项目级代码索引后台服务

## 问题框架

AI 在处理大型代码库时，需要频繁扫描文件以理解代码结构、符号定义和调用关系。这种重复扫描导致：
- **响应延迟**：每次查询都需要遍历文件系统，耗时长
- **上下文浪费**：大量 token 用于描述文件结构，而非核心逻辑
- **精度不足**：无法精确查询符号定义、调用链、依赖关系等

代码索引服务通过预扫描和增量更新，为 AI 提供快速、精确的代码查询能力。

## 需求

### 核心能力

- R1. **SQLite 索引存储** → 验收: 使用 SQLite 存储文件元数据、符号定义、引用关系、依赖关系；每个工作空间的索引数据存储在各自工作空间的 .opencode/code-index/ 目录下
- R2. **AST 解析与关系提取** → 验收: 使用通用解析器（如 Tree-sitter）支持多种语言的 AST 解析，包括常见编程语言（TypeScript、JavaScript、Python、Java、Go、Rust 等）、配置文件（Markdown、YAML、JSON 等）以及 AE 技能、工具、代理、命令引用；提取函数、类、变量、接口、类型、枚举等符号及其引用关系
- R3. **增量更新** → 验收: 文件变化时仅更新变化的文件，而不是全量重建索引；当索引与实际文件不一致时，以文件为准
- R4. **高级查询能力** → 验收: 支持查找定义、查找引用、依赖分析、调用链（最大深度 10 层）、影响范围分析，每个查询能力有明确的输入输出格式
- R4f. **HTTP 查询接口** → 验收: 服务内置 Web 服务并通过 HTTP 提供查询接口，支持查询服务是否启动、查询指定工作空间索引状态、执行定义/引用/依赖/调用链等高级查询；服务运行后的进程间交互均通过 HTTP 协议完成，启动前和停止后的本地进程状态允许通过锁文件或 PID 文件判断
- R4g. **HTTP 本机安全边界** → 验收: HTTP 服务默认仅绑定 loopback 地址；非公开接口必须使用本地随机 token 或等价能力令牌；禁用宽松 CORS；状态变更接口必须校验 token 和请求来源；错误信息不得暴露不必要的绝对路径或敏感内容
- R4h. **敏感文件默认排除** → 验收: 默认不索引 `.env*`、密钥、证书、私钥、凭证文件、依赖目录、构建产物和其他疑似敏感文件；用户可通过 ae.jsonc 扩展索引范围，但索引器不得记录疑似秘密值本身
- R4b. **错误处理与恢复** → 验收: SQLite 损坏时自动重建索引，AST 解析失败时记录错误并跳过文件；daemon 崩溃后的自动重启仅限用户已手动启动服务后的运行生命周期内，停止服务后或 opencode 重启时不得自动拉起服务
- R4c. **索引清理策略** → 验收: 支持按时间或大小清理旧索引数据，可配置清理周期
- R4d. **索引版本管理** → 验收: 支持 schema 升级时的数据迁移或重建
- R4e. **相对路径存储** → 验收: 索引中不得出现绝对路径，只能根据当前工作空间存储相对路径

### 生命周期管理

- R5. **独立服务** → 验收: 索引服务是一个完全独立的服务，可以脱离 opencode 运行；opencode 通过工具命令控制服务进程的启动和停止
- R6. **手动启动** → 验收: 索引服务不会随 opencode 启动而自动启动，必须通过命令手动启动；反复执行 start 命令时，如果服务已启动或正在启动，命令提示“服务已启动”或“服务正在启动”并直接结束，不重复启动新进程
- R7. **手动停止** → 验收: 支持通过命令手动停止索引服务
- R8. **工作空间注册** → 验收: 只能通过命令手动注册工作空间到服务，服务才会维护对应工作空间的索引；注册数据存入全局 SQLite（存储在全局 opencode 配置路径下），下次启动时不需要重新注册
- R9. **注册数据管理** → 验收: 支持通过命令维护注册数据（查看列表、添加、删除、修改配置）
- R10. **多线程索引** → 验收: 使用 Node.js Worker Threads 实现多工作空间并行索引，一个工作空间创建索引时不得阻塞其他工作空间
- R11. **故障隔离** → 验收: 一个工作空间的索引创建失败不得影响其他工作空间，自动重试最多 3 次，重试失败后记录错误并跳过
- R12. **缓存创建与更新** → 验收: 支持通过命令、技能或工具手动创建指定工作空间缓存、更新指定工作空间缓存；当服务未启动时只提示用户先执行 start，不得由 create/update/query 等非 start 操作隐式启动服务

### 配置与集成

- R13. **ae.jsonc 配置** → 验收: ae.jsonc 是唯一的索引范围配置源，支持 .gitignore 标准的通配符和排除配置（包括取反模式、注释等）；不再使用独立的 .codeindexignore 文件
- R14. **可配置索引范围** → 验收: 支持 .gitignore 标准的通配符和排除配置（包括取反模式、注释等），配置源为 ae.jsonc
- R15. **系统注入** → 验收: 通过 system transform 注入索引可用性、查询方法、更新状态、索引完整性等信息；当服务未启动、正在启动或 HTTP 服务不可用时，只注入降级状态和手动启动提示，不得触发服务启动
- R16. **技能与工具集成** → 验收: 所有命令均可手动执行，也可以注册为技能或工具让 AI 执行；技能使用位置参数区分不同操作（如 /ae-code-index start/stop/status/register/unregister/create/update/query/config/clean/rebuild/list）
- R16b. **SQLite 直查技能** → 验收: 提供一个面向 AI 的技能，借助 sql-tool 直接连接工作空间 `.opencode/code-index/` 下的 SQLite 索引库执行只读查询；该技能用于高级排查和临时分析，不替代 HTTP 查询接口；必须以 SQLite 只读模式打开数据库，禁止多语句、写入语句、ATTACH、load_extension、writable_schema 等危险操作，并返回可验证的只读连接提示

### 更新策略

- R17. **文件监听 + 防抖** → 验收: 使用 chokidar 监听文件变化，采用 500ms 防抖策略（单文件变化场景）
- R18. **定时一致性检查** → 验收: 服务定期检查索引与文件的一致性，自动更新不一致的部分
- R19. **统一更新队列** → 验收: 所有更新请求进入统一队列，避免并发冲突
- R19b. **会话结束更新 Hook** → 验收: opencode 会话结束时通过 hook 自动触发已注册工作空间的缓存更新请求；如果服务未启动或 HTTP 服务不可用，hook 只记录跳过原因，不得启动服务或阻塞会话结束

### 用户体验

- R20. **非阻塞启动** → 验收: start 命令立即返回，服务在后台启动，索引完成后通过 HTTP 状态接口确认可用；如果服务已经启动或正在启动，start 命令提示当前状态并直接结束
- R21. **停止确认** → 验收: stop 命令时如果服务正在工作，询问用户是立即停止还是等待完成
- R22. **索引状态反馈** → 验收: 查询时如果索引正在更新，提示用户可选择阻塞等待更新完成或不使用索引直接执行

## 成功标准

- AI 能够在 100ms 内响应符号定义、引用关系等查询（基于本地 SQLite 查询，不含网络延迟）
- 单文件变化后增量更新在 5 秒内完成（基于中等规模项目，约 1000 个文件）
- 用户可通过命令手动控制索引服务的生命周期和工作空间注册
- 系统注入让 AI 了解索引可用性并正确使用查询工具

## 范围边界

- **包含**：常见编程语言（TypeScript、JavaScript、Python、Java、Go、Rust 等）、配置文件（Markdown、YAML、JSON 等）以及 AE 技能、工具、代理、命令引用
- **不包含**：远程代码库索引（仅索引本地工作空间）
- **不包含**：实时协作编辑支持
- **不包含**：索引数据的版本控制或备份
- **工作空间定义**：包含 .git 或 package.json 的最顶层目录
- **monorepo 支持**：以根目录为工作空间，不拆分子 package
- **依赖分析范围**：文件级依赖（import/require）和符号级依赖（函数调用、类继承）
- **调用链深度**：最大 10 层

## 关键决策

- **存储选 SQLite**：轻量级、无需额外服务、支持复杂查询
- **运行模型为完全独立服务**：可以脱离 opencode 运行，opencode 通过工具命令控制服务进程的启动和停止；服务必须由命令手动启动，不随 opencode 自动启动，非 start 操作和 hook 不得隐式启动服务
- **进程交互使用 HTTP**：索引服务内置 Web 服务，对外提供 HTTP 接口；服务运行后的探活、服务状态、索引状态和查询请求均通过 HTTP 协议完成；启动前和停止后的生命周期判断允许使用锁文件或 PID 文件
- **HTTP 接口默认本机私有**：HTTP 服务默认仅允许本机访问，并通过本地能力令牌保护非公开接口，避免暴露代码索引和项目结构
- **系统注入只建议 AI 查询工具，不暴露直接 SQL**：简化 AI 使用方式
- **技能、工具与命令统一**：所有命令均可手动执行，也可以注册为技能或工具让 AI 执行；缓存创建和更新是独立操作，不承担启动服务职责
- **SQLite 直查作为辅助入口**：提供一个技能借助 sql-tool 只读查询 SQLite 索引，满足排查和临时分析需求；常规查询仍优先走 HTTP 接口，直查技能必须在连接层和语句层强制只读
- **注册数据持久化**：使用全局 SQLite 存储注册数据（存储在全局 opencode 配置路径下），重启后不需要重新注册
- **索引数据分散存储**：每个工作空间的索引数据存储在自己的目录中，便于清理和管理
- **相对路径存储**：索引中不得出现绝对路径，只能存储相对路径，确保可移植性
- **配置职责分离**：ae.jsonc 是唯一的索引范围配置源，不再使用独立的 .codeindexignore 文件
- **统一入口**：一个技能或工具包含所有命令的功能，通过位置参数区分不同操作
- **通用解析器**：使用 Tree-sitter 支持多种语言的 AST 解析

## 依赖 / 假设

- opencode 支持 `experimental.chat.system.transform` hook 和会话结束 hook
- Node.js 环境支持 chokidar 文件监听
- SQLite 驱动（如 better-sqlite3）可在目标环境运行
- Node.js 环境可运行本地 HTTP Web 服务，并允许本机进程通过 HTTP 访问该服务
- Node.js 支持 worker_threads 模块
- Tree-sitter 可在目标环境运行，支持所需的语言解析
