# Swagger 解析技能重构增强需求

## 问题框架

接口联调时，开发者经常拿到的 Swagger / OpenAPI 文档并不只是一份简单 JSON。常见来源包括本地 JSON/YAML 文件、远程 URL、Swagger UI 背后的 OpenAPI 地址、带查询参数的导出链接，以及包含内部、相对文件或远程 `$ref` 的多文件规格。当前 `ae:swagger-parser` 已能解析工作区内 JSON 与远程 JSON，并输出概览或接口详情，但能力边界仍偏首版：不支持 YAML，不覆盖 OpenAPI 3.1 语义差异，引用展开有限，联调输出也缺少请求样例、响应样例和可操作的诊断提示。

本次重构目标是把技能从“首版 JSON 摘要工具”升级为“面向真实 Swagger/OpenAPI 文档的联调前解析助手”。它应优先解决文档来源多样、规格差异、引用复杂和输出不够可执行的问题，同时避免膨胀为 SDK 生成器、接口测试器或完整规范验证平台。

## 需求

**输入格式与来源**
- R1 [P0]. 技能应接受本地 JSON、YAML 和 YML 文件路径作为输入，并解析其中的接口契约。 → 验收: 用户提供工作区内 `.json`、`.yaml` 或 `.yml` 文件时，技能能识别格式并输出接口摘要；本地路径和相对 `$ref` 必须基于真实路径做边界校验，拒绝符号链接逃逸；路径不存在、路径为空、内容为空、格式非法或路径越过允许边界时，返回可恢复的中文错误提示。
- R2 [P0]. 技能应接受无需额外业务鉴权即可访问的远程 HTTP(S) URL 返回的 JSON 或 YAML 规格内容。 → 验收: 远程响应为 JSON/YAML 文本时可解析；网络失败、非 2xx 响应、响应为空、响应过大、响应超时、重定向不可用、内容类型与实际格式不一致或格式非法时，返回明确失败原因。
- R3 [P0]. 技能应兼容直接规格 URL 和常见导出链接。 → 验收: 支持带查询参数的 JSON/YAML 规格 URL；当用户提供疑似 Swagger UI HTML 页面或带片段的 UI 页面链接时，不把 HTML 当规格解析，也不承诺自动爬取页面，而是提示用户提供实际 OpenAPI JSON/YAML 地址或可导出的规格文件。
- R4 [P0]. 技能应限制输入读取的安全与资源边界。 → 验收: 本地输入默认限制在工作区内；远程输入仅支持 HTTP(S)，并具备协议、重定向、超时、响应大小、私网/本机地址访问限制和敏感 URL 展示脱敏；触发限制时不输出已读取的敏感内容。

**规范版本与结构覆盖**
- R5 [P0]. 技能应识别 Swagger 2.0、OpenAPI 3.0.x 和 OpenAPI 3.1.x 的规格根结构。 → 验收: 能根据 `swagger: "2.0"`、`openapi: "3.0.x"` 和 `openapi: "3.1.x"` 判定版本；缺少 `paths`、版本字段非法或根节点无效时，按统一诊断体系说明原因。
- R6 [P0]. 技能应抽取 Swagger 2.0 与 OpenAPI 3.x 的核心联调结构。 → 验收: 能解析接口、参数、请求体、响应、认证、servers/basePath 和标签；遇到未覆盖结构时明确区分“未声明”“结构无效”和“暂不支持”。
- R7 [P1]. 技能应覆盖常见参数、请求体和响应内容形态。 → 验收: 支持 path/query/header/cookie 参数、Swagger 2.0 body/formData、OpenAPI requestBody、多 content type、常见状态码响应和 default 响应；缺失说明时标注为未提供。
- R8 [P1]. 技能应解析联调摘要所需的基础 schema 字段元数据。 → 验收: 摘要能展示对象、数组、枚举、nullable、required、default、example/examples；复杂结构无法完整展开时说明降级原因而不是静默丢失。
- R9 [P2]. 技能应对组合 schema 提供有限摘要。 → 验收: oneOf、anyOf、allOf 能以可读方式展示候选或合并来源；无法安全合并或展开时明确标注为组合结构并说明未完整展开。
- R10 [P2]. 技能应为 OpenAPI 3.1 的 JSON Schema 差异提供有限展示矩阵。 → 验收: `type` 数组、`const`、`examples` 等联调常用信息应尽量展示；`if/then/else`、`dependentSchemas`、`unevaluatedProperties`、`$dynamicRef` 等验证语义允许降级为“暂不展开的 JSON Schema 约束”，不要求完整验证。
- R11 [P0]. 技能应识别接口认证与全局配置。 → 验收: 摘要包含 base URL / servers、全局或接口级认证要求、常见安全方案名称和位置；规格未声明认证时明确标注为未声明。

**引用解析与降级**
- R12 [P0]. 技能应支持当前文档内部 `$ref` 的可控解析。 → 验收: 内部引用应在有限深度内展开；循环引用、缺失引用、过深结构或超出预算时输出可读降级说明。
- R13 [P1]. 技能应支持相对文件 `$ref` 的安全解析或明确降级。 → 验收: 相对文件引用不得越过工作区边界，必须基于真实路径校验；引用解析失败不影响主文档中其他接口的摘要输出。
- R14 [P2]. 技能应支持远程 `$ref` 的安全解析或明确降级。 → 验收: 远程引用默认仅允许同源或用户显式允许的安全范围；必须限制总引用数、总字节数、总耗时、最大重定向次数和最大域名数量；跨域引用、私网地址、超预算或解析失败时，只输出脱敏后的引用位置和降级原因。

**联调摘要与输出模式**
- R15 [P0]. 技能应输出面向接口联调的接口清单概览。 → 验收: 概览至少包含接口定位键（如 `GET /users/{id}`）、接口名称或描述、标签分组、接口数量统计、规格版本、可用 servers/base URL 和可用于继续筛选的提示。
- R16 [P0]. 技能应在无状态模式下提供可导航索引。 → 验收: 大文档概览被截断时，仍应输出标签列表、路径前缀分布、已展示数量、剩余数量和可复制的下一步筛选示例，使用户无需缓存或分页 token 也能继续收窄。
- R17 [P0]. 技能应为单个接口输出关键请求信息。 → 验收: 详情摘要包含路径参数、查询参数、请求头、Cookie 参数、请求体字段、必填项、字段类型、字段说明、示例值、content type 和认证要求。
- R18 [P0]. 技能应输出关键响应信息。 → 验收: 详情摘要包含主要状态码、响应体结构、字段类型、字段说明、示例响应和 default/error 响应；当响应结构被截断或无法展开时说明原因。
- R19 [P1]. 技能应提供低成本的联调辅助展示。 → 验收: 在接口详情中可展示 curl 或 HTTP 请求样例、最小请求体样例和认证占位符；样例必须使用占位值，不自动发起业务请求，不声称请求可直接成功。
- R20 [P0]. 技能应支持筛选参数标准化和多条件组合。 → 验收: `method` 大小写不敏感并标准化为 HTTP 方法；多条件默认 AND；筛选无结果时返回候选建议而不是空结果。
- R21 [P0]. 技能应支持路径、标签和关键词筛选。 → 验收: `path` 优先精确匹配 OpenAPI path 模板，未命中时做包含匹配并返回候选；`tag` 按标签名匹配；`keyword` 搜索 path、summary、description 和 operationId。
- R22 [P0]. 技能应默认控制输出长度，避免大规格文件一次性刷屏。 → 验收: 大型文档默认输出概览、总量统计、截断说明和下一步筛选示例；显式详情模式命中多个接口时只输出有限多接口请求摘要，超过预算时提示继续收窄。

**诊断、脱敏与用户恢复**
- R23 [P0]. 技能应建立统一诊断分类与恢复提示。 → 验收: 对输入、网络、格式、版本、结构、引用、筛选无结果、HTML 页面误传、安全限制、预算超限等错误类型给出中文原因和下一步建议；不暴露内部堆栈或敏感内容。
- R24 [P0]. 技能应对所有用户可见输出应用统一脱敏。 → 验收: 对 examples、default、description、server URL、headers、query、cookies、request/response 示例和错误诊断中的疑似密钥、凭证、Cookie、Token、密码和敏感个人信息做统一检测和脱敏，不回显原始敏感片段。
- R25 [P0]. 技能应保留无状态的大文档继续模型。 → 验收: 本轮不承诺跨调用缓存、分页 token 或持久会话状态；超出概览或输出预算时，提示用户重新调用并提供 path、method、tag 或 keyword 筛选示例。

## 发布切片

**MVP 必须可独立交付**
- 用户给一个本地或远程 JSON/YAML 规格文件，技能能安全读取、识别格式和规格版本，并在失败时给出可恢复诊断。
- 用户能看到可导航接口概览，并能通过 `method + path` 查看单接口详情。
- 单接口详情至少覆盖核心请求参数、请求体、响应、认证、内部 `$ref` 有限展开、输出预算和基础脱敏。
- MVP 覆盖 Swagger 2.0 与 OpenAPI 3.0 的主流联调结构；OpenAPI 3.1 在 MVP 中至少应能识别版本并对未展开结构明确降级。

**首版增强应优先补齐**
- OpenAPI 3.1 的常见 JSON Schema 差异展示。
- 相对文件 `$ref` 的安全解析。
- 大文档标签和路径前缀导航索引。
- curl 或 HTTP 请求样例、示例请求体和示例响应展示。

**后续增强可延期**
- 远程 `$ref` 的同源或显式授权解析。
- 组合 schema 的更完整摘要。
- 更细粒度的多接口候选建议和复杂筛选体验。
- 更完整的脱敏规则矩阵和恶意规格测试集。

## 成功标准

- 用户拿到 JSON、YAML、本地文件、远程 URL 或常见导出链接时，能通过技能快速判断是否是有效 Swagger/OpenAPI 规格，并获得下一步可操作摘要。
- 用户在联调前能通过一次详情调用了解目标接口的请求方式、参数、请求体、响应、认证和示例占位值。
- 面对 Swagger 2.0、OpenAPI 3.0.x 和 OpenAPI 3.1.x 文档时，技能能覆盖主流联调信息，并对未覆盖结构给出明确降级说明。
- 面对内部、相对文件或远程 `$ref` 时，技能能在安全边界内尽量展开，无法展开时不影响其他接口摘要。
- 大型规格默认输出可导航概览，不刷屏；用户可以通过筛选逐步收窄。
- 输入异常、网络异常、规格不完整或格式误传时，技能给出可恢复提示，而不是输出空摘要或内部错误。

## 范围边界

- 不生成 SDK、类型定义、客户端代码或测试脚手架。
- 不自动发起业务接口请求；技能只解析和整理规格文档。
- 不承诺成为完整 OpenAPI 规范验证器；只输出与联调摘要相关的结构诊断。
- 不把 Swagger UI 页面抓取和自动发现规格 URL 作为核心能力；本轮只在误传 HTML 页面时给出纠正提示。
- 不要求支持远程 Swagger URL 的业务鉴权、代理、浏览器 Cookie、SSO 或自定义证书；访问失败时提示用户改用本地文件或当前运行环境无需额外鉴权即可访问的规格 URL。
- 不维护跨调用缓存、分页 token 或“继续上一页”的持久状态；用户通过重新调用并增加筛选条件继续查看。
- 不把 Postman 集合、Insomnia 配置或 OpenAPI diff 作为本轮必需产物。

## 关键决策

- 本轮选择“全面增强，但输入格式优先落地”: 用户明确希望重构并增强，且“所有格式”至少包含 JSON/YAML、规范版本、引用形式和导出入口；其中输入格式是最直接阻塞可用性的能力。
- 保持“联调摘要优先”: 解析覆盖服务于快速理解和联调，不扩展为代码生成或接口执行，避免维护成本失控。
- 引用解析采用安全优先的降级模型: `$ref` 是真实规格中的高频痛点，但外部文件和远程引用会引入越界读取、SSRF 和输出爆炸风险，因此需求要求可控解析和明确降级，而非无条件全量展开。
- 默认继续采用无状态输出: 大规格继续模型通过筛选参数完成，避免引入缓存一致性、会话状态和分页 token 复杂度。
- 使用 P0/P1/P2 区分本轮落地优先级: P0 是重构后必须可靠的核心能力，P1 是明显增强联调体验的能力，P2 是复杂规格的有限覆盖或安全降级能力。
- P0 不等于单次提交范围: 规划阶段应优先形成可独立交付的 MVP，再按首版增强和后续增强推进，避免一次性重写成大而全的解析平台。

## 考虑过的替代方案

- 只补 YAML 输入: 成本最低，但无法解决 OpenAPI 3.1、引用复杂和联调样例不足的问题，容易让“支持所有格式”的用户预期继续落空。
- 做完整规范验证器: 覆盖更彻底，但偏离联调摘要目标，且会显著增加错误分类、规范细节和维护成本。
- 自动抓取 Swagger UI 页面并发现规格 URL: 对部分用户方便，但页面形态差异大，容易引入爬取和鉴权问题；本轮更适合作为错误恢复提示而非核心解析能力。

## 依赖 / 假设

- 用户主要希望解析 Swagger/OpenAPI 规格文档，而不是转换 Postman、HAR 或自定义网关文档。
- 用户在需要解析远程文档时会提供当前环境可访问的 URL，或能改用本地导出文件。
- OpenAPI 3.1 的 JSON Schema 细节可以在联调摘要层做有限展示，不要求完整验证所有 JSON Schema 2020-12 语义。
- 本次重构可能需要引入 YAML 或 OpenAPI 解析相关依赖，或替换当前最小解析器；规划阶段必须对照既有依赖策略决定允许的依赖类型和外部 resolver 默认行为。
- 外部最佳实践研究本轮未能通过网络工具验证；上述增强点基于常见 Swagger/OpenAPI 使用形态和当前仓库能力对照。
