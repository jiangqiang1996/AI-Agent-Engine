# Swagger 解析技能需求

## 问题框架

接口联调时，开发者经常需要在 Swagger / OpenAPI 文档中查找接口路径、方法、参数、认证方式、响应结构和错误信息。当前缺少一个面向联调场景的 AE 技能，能够直接读取本地 Swagger JSON 文件或远程 URL，并把规格内容整理成可执行联调前的高信噪比摘要。

首版目标是降低阅读接口文档和定位接口契约的成本，不承担代码生成、SDK 生成或自动发起请求。

## 需求

**输入来源**
- R1. 技能应接受本地 Swagger / OpenAPI JSON 文件路径作为输入，并解析其中的接口契约。 → 验收: 用户提供工作区内 JSON 路径时，技能能输出接口摘要；路径不存在、路径为空、内容为空、内容不是有效 JSON 或路径越过允许边界时，返回可恢复的中文错误提示。
- R2. 技能应接受远程 Swagger / OpenAPI URL 作为输入，并解析响应中的接口契约。 → 验收: 用户提供 HTTP(S) URL 时，技能能获取并解析 JSON；网络失败、非 2xx 响应、响应为空、响应过大、响应超时、重定向不可用或响应不是有效 JSON 时，返回明确失败原因。
- R3. 技能应限制输入读取的安全与资源边界。 → 验收: 本地输入默认限制在工作区内；远程输入仅支持 HTTP(S)，并具备协议、重定向、超时、响应大小和私网/本机地址访问限制；触发限制时不输出已读取的敏感内容。

**联调摘要**
- R4. 技能应输出面向接口联调的接口清单概览。 → 验收: 概览至少包含接口定位键（如 `GET /users/{id}`）、接口名称或描述、标签分组、接口数量统计和可用于继续筛选的提示。
- R5. 技能应为单个或多个接口输出关键请求信息。 → 验收: 详情摘要包含路径参数、查询参数、请求头、请求体字段、必填项、字段类型和字段说明；缺失说明时明确标注为未提供。
- R6. 技能应输出关键响应信息。 → 验收: 详情摘要包含主要状态码、响应体结构、字段类型和字段说明；当规格只提供引用结构时，在有限深度内输出可读摘要，遇到循环引用、过深结构或无法解析引用时说明截断或无法展开原因。
- R7. 技能应识别接口认证与全局配置。 → 验收: 摘要包含 base URL / servers、全局或接口级认证要求、常见请求头；规格未声明认证时明确标注为未声明；疑似真实密钥、Token、Cookie 或密码必须脱敏为占位符。

**联调使用体验**
- R8. 技能应支持用户按接口路径、方法、标签或关键词筛选输出范围。 → 验收: 筛选支持单条件和多条件组合；路径和方法用于精确定位，标签和关键词用于收窄候选；输出只包含匹配接口，并在无匹配时给出候选建议或可调整的筛选提示。
- R9. 技能应默认控制输出长度，避免大规格文件一次性刷屏。 → 验收: 大型 Swagger 文档默认输出概览、总量统计、截断说明和下一步筛选示例，而不是完整展开所有接口详情。
- R10. 技能应对 Swagger 2.0 与 OpenAPI 3.x 的常见结构保持兼容。 → 验收: 对 `swagger: "2.0"` 和 `openapi: "3.x"` 文档都能解析接口、参数、请求体、响应和认证信息；遇到未覆盖结构时明确区分“未声明”“结构无效”和“暂不支持”。

**输出模式与降级**
- R11. 技能应固定概览与接口详情的触发规则。 → 验收: 无筛选时默认输出概览；`method + path` 唯一命中时输出接口详情；筛选命中多个接口时输出候选概览并提示继续收窄；用户显式要求详情但命中多个接口时，不默认展开全部详情。
- R12. 技能应固定首版筛选语义。 → 验收: `method` 大小写不敏感并标准化为 HTTP 方法；`path` 优先精确匹配 OpenAPI path 模板，未命中时做包含匹配并返回候选；`tag` 按标签名匹配；`keyword` 搜索 path、summary、description 和 operationId；多条件默认 AND。
- R13. 技能应采用无状态的大文档继续模型。 → 验收: 首版不承诺跨调用缓存、分页 token 或持久会话状态；超出概览或输出预算时，提示用户重新调用并提供 path、method、tag 或 keyword 筛选示例。
- R14. 技能应固定首版 `$ref` 降级边界。 → 验收: 首版只要求展开当前 JSON 文档内引用；外部文件或远程 `$ref` 标注为暂不支持并保留原始 `$ref`；循环引用在循环点标注“循环引用，已停止展开”；超过深度预算时标注“已按深度预算截断”。

## 成功标准

- 用户在联调前能通过一次技能调用了解目标接口的请求方式、参数、响应和认证要求。
- 面对大型接口文档时，技能能先给出可导航概览，再通过筛选获得局部详情。
- 输出产物明确区分“概览”和“接口详情”，后续规划不需要再发明摘要形态。
- 输出模式、筛选规则、无状态继续模型和 `$ref` 降级方式在需求层已固定，计划阶段只需确定具体实现与默认数值。
- 输入异常、网络异常、规格不完整时，技能给出可恢复提示，而不是输出空摘要或内部错误。
- 首版保持聚焦，不引入代码生成、自动调用接口或持久缓存等额外复杂度。

## 范围边界

- 不生成 SDK、类型定义、客户端代码或测试脚手架。
- 不自动发起业务接口请求；技能只解析和整理规格文档。
- 不把 curl、HTTP Client 文件或请求模板作为首版必需产物；如规划阶段确认成本很低，可作为接口详情中的增强展示，但不得替代摘要目标。
- 不要求支持 YAML 作为首版输入，除非后续规划确认成本很低。
- 不要求完整覆盖 OpenAPI 规范的所有边缘字段；首版优先覆盖接口联调最常用信息。
- 不把远程 Swagger URL 的鉴权、代理或证书处理作为首版核心能力；如访问失败，应提示用户改用本地 JSON 或提供可访问 URL。
- 不要求首版维护跨调用缓存、分页 token 或“继续上一页”的持久状态；用户通过重新调用并增加筛选条件继续查看。

## 关键决策

- 首版选择“联调摘要优先”: 这是接口联调场景的最高杠杆能力，能先解决阅读和定位问题，同时避免代码生成带来的维护成本。
- 同时支持本地文件和远程 URL: 用户原始需求明确包含两类来源，且这是技能可用性的基础边界。
- 默认限制大文档输出: Swagger 文档通常很大，默认完整展开会降低可读性并浪费上下文。
- 远程读取和本地读取必须带安全边界: Swagger 文档可能来自不可信来源，解析技能不能成为 SSRF、任意文件读取或敏感信息泄露通道。
- 优先复用成熟 OpenAPI 解析能力: 首版应聚焦摘要组织和联调体验，除非规划阶段证明必要，否则不自建完整规范解析器。

## 依赖 / 假设

- 输入文档主要为 JSON 格式的 Swagger 2.0 或 OpenAPI 3.x。
- 用户在需要远程解析时会提供当前环境可访问的 URL。
- 后续规划阶段需要决定该能力作为新增 `ae:<name>` 技能实现，还是依托脚本、工具或技能内指令组合实现。
- 后续规划阶段需要确定具体预算值，例如最大文件大小、最大响应体大小、请求超时、引用展开深度、默认概览数量和输出字符上限。
