# opencode 原生 Figma 素材导出技能

## 问题框架

用户希望把前序调研得到的 Trae CN Figma 素材链路原理迁移为 opencode 原生能力，使代理能够在不调用 Trae 这类外部工具的前提下，使用 opencode 的 tools 或技能组织流程，并在需要页面自动化时允许使用 agent-browser 辅助打开 Figma、确认登录态、触发可授权交互和验证落盘结果。

这个能力的重点不是复用 Trae 私有命令，也不是依赖 Trae WebView，而是复刻其可迁移原理：在用户已授权的 Figma 页面或接口中获取素材字节，将素材写入当前工作区的稳定目录，并生成可验证的执行摘要。Trae 的调研结论只作为参考模型：浏览器侧拿到素材、工具侧落盘、技能侧做门禁和验证；实际实现必须由 opencode tools 和技能流程组成，agent-browser 仅在所选路径需要页面自动化或状态确认时参与。

## 需求

**技能入口与适用场景**
- R1. 新技能应明确适用于“在 opencode 环境中，从用户有权访问的 Figma URL 或节点导出素材到当前工作区”的任务。 → 验收: 用户提供 Figma URL、节点 ID 或明确的 Figma 设计来源时，技能能说明何时适用、需要哪些输入、可选导出方式、输出会落到哪里。
- R2. 新技能应明确不替代 `figma-design-sync` 的像素级设计同步，也不替代 `ae:test-browser` 的 Web 验收。 → 验收: 技能文档中清楚声明非目标，避免把素材下载、设计对齐、浏览器验收混为一个流程。
- R3. 新技能应明确禁止调用 Trae、Trae CN、Trae 内部命令或 Trae 安装目录中的任何实现。 → 验收: 技能文档把 Trae 标记为“参考原理来源”，而不是执行依赖；运行流程中不得要求安装或打开 Trae。

**agent-browser 辅助流程**
- R4. 技能应仅在选择 Web UI 路径或需要页面状态确认时使用 agent-browser 导航到目标 Figma 页面，并识别登录态、权限态和页面是否进入可操作状态。 → 验收: 文档包含 agent-browser 可执行步骤，并在登录页、申请访问页、权限不足、404/403、页面未加载完成时停止或要求用户处理；API 路径和手动导出收集路径不得强制依赖 agent-browser。
- R5. 技能应把 agent-browser 定位为“可授权页面自动化”而不是素材落盘能力或权限绕过工具。 → 验收: 文档明确 agent-browser 负责导航、状态确认、截图/快照证据和可见 UI 交互；不得声称 agent-browser 能绕过 Figma 权限、读取浏览器凭证、直接访问 Figma 私有素材，或在未验证下载控制能力时把点击下载视为素材已落盘。

**opencode 原生导出链路**
- R6. 技能应把 Trae 原理抽象为 opencode 原生链路：输入解析、授权页面确认、素材获取、工作区落盘、产物校验和摘要输出。 → 验收: 技能能用简洁流程图或步骤说明这条链路，且每一步都不依赖 Trae。
- R7. 技能应明确首版默认可执行边界：优先支持“用户通过配置显式授权的 Figma 官方接口路径”，并保留“用户手动导出后由 opencode 收集校验”作为降级路径；Web UI 自动化只作为页面辅助或未来增强，除非规划阶段确认下载目录控制和下载事件可验证。 → 验收: 文档包含三条候选路径的选择矩阵，但清楚标注首版默认路径、降级路径和非首版增强路径；每条路径都必须要求用户已有授权。
- R8. 技能应定义标准运行时产物：`.figma/assets/*`、`.figma/manifest.json`、可选截图证据和执行摘要。 → 验收: 文档区分主交付物“技能文档”和运行时产物，并说明是否生成代码产物不是当前技能的默认成功条件。
- R9. 技能应验证并报告本次运行的新产物，避免把历史 `.figma` 残留误判为成功。 → 验收: 执行结束时必须基于运行开始时间、隔离输出路径或等价证据检查产物是否属于本次运行，并总结成功、部分成功或失败原因。

**安全与边界**
- R10. 技能应禁止读取或转移浏览器敏感态。 → 验收: 文档要求不得读取、复制、打印、持久化或跨进程传递 token、cookie、localStorage、sessionStorage、账号标识；不得从浏览器或 Figma 登录态中提取凭证。
- R11. 技能应定义 API 凭证处理规则。 → 验收: 若用户选择 API 路径，凭证可以通过项目配置、环境变量或用户明确授权的安全输入方式提供；凭证不得写入需求文档、技能文档、manifest、日志或最终报告，输出只能显示脱敏后的配置来源或认证模式。
- R12. 技能应定义脱敏输出规则。 → 验收: 日志、URL、路径、截图名和最终报告必须脱敏；最终报告默认只展示状态、文件数量、脱敏路径、失败类别和下一步，不展示完整私有 URL、账号、组织、token、设计画面或完整 DOM。
- R13. 技能应最小化私有设计内容暴露。 → 验收: 截图和 DOM 快照仅用于本地验证，不在最终回答中嵌入私有设计画面或完整 DOM；默认只报告状态、文件数量和脱敏路径。
- R14. 技能应约束 Figma URL、文件 key、nodeId、输出文件名和手动导入来源的路径安全。 → 验收: 这些输入只允许安全字符集；所有输出路径必须规范化并确认位于当前工作区 `.figma/` 下；拒绝 `..`、绝对路径、路径分隔符、符号链接逃逸；收集用户手动导出文件时应先复制到隔离目录并记录 checksum。
- R15. 技能应在无法通过 opencode 原生方式获取素材时优雅降级，只给出可验证的失败原因和下一步，而不是伪造下载成功。 → 验收: 未登录、无设计权限、目标节点不存在、节点不可导出、Figma UI 无可自动化导出入口、未提供 API 凭证、API 凭证无效或限流、未生成本次 `.figma` 产物时，技能有明确失败分类。

## 成功标准

- 新技能让代理可以把“使用 opencode 原生流程导出 Figma 素材”作为独立流程执行，而不是每次重新逆向 Trae 实现或调用 Trae。
- 用户能从技能输出中看到：输入是什么、采用哪条授权导出路径、素材写到哪里、哪些文件已验证为本次运行产物、哪些产物可用于下一步实现或验证。
- 技能不会把 MCP、ImageX、Trae 后端代理或 Trae 私有命令误描述为必需链路；任何外部接口或凭证路径都必须由用户显式授权。

## 范围边界

- 当前交付优先是技能文档；是否新增 TypeScript 工具由规划阶段决定。
- 不调用 Trae、Trae CN、Trae 内部命令、Trae WebView 或 Trae 安装目录中的私有代码。
- 不做像素级 Figma 设计还原；该场景继续交给 `figma-design-sync`。
- 不要求绕过 Figma 登录、权限或组织访问控制。
- 不在技能中硬编码 Figma API token；API token 或 OAuth token 可以通过用户显式配置提供，且必须脱敏处理。
- 不承诺 agent-browser 能自动完成 Figma Web UI 中所有导出操作，也不把点击下载等同于文件已进入工作区；无法验证下载落盘时应降级为“指导用户导出 + opencode 收集校验”。

## 关键决策

- 交付形态选择“技能文档优先”: 当前目标是沉淀可执行流程，降低后续使用成本；是否新增工具留到规划阶段评估。
- 技术边界改为“复刻 Trae 原理，不调用 Trae”: 前序静态分析确认了浏览器侧导出、工具侧落盘、流程侧验证的模式；新技能只借鉴模式，不复用 Trae 私有实现。
- agent-browser 定位为可选辅助自动化: 它擅长打开页面、采集状态、辅助交互和截图；素材获取必须来自用户显式配置授权的官方接口路径、用户手动导出的本地文件，或未来经验证具备下载目录控制的 Web UI 自动化路径。
- 外部参考选择 `GLips/Figma-Context-MCP`: 该项目支持通过 Figma API key 或 OAuth token 获取节点渲染 URL、图片填充 URL，并将素材下载到受控目录；可借鉴其认证配置、路径约束、节点 ID 规范化、图片填充与节点渲染分流、下载结果摘要等模式，但不直接依赖其 MCP 服务作为必需链路。

## 依赖 / 假设

- 用户对目标 Figma 文件或节点有访问权限。
- 仅当选择 Web UI 辅助路径时，agent-browser 需要已安装，或可通过现有 `ae:setup` 流程安装。
- 执行前需要通过环境门禁确认目标页面可访问、当前工作区可写入 `.figma/`。
- 如果选择 API 路径，用户必须通过配置或安全输入明确提供并授权使用必要凭证；技能不得自行提取浏览器或 Figma 登录态。
