# ae:work 自动任务分解与并行执行

## 问题框架

当前 `ae:work` 的并行执行能力依赖计划文档中的实现单元结构。裸提示词进入时，LLM 需要自行推导任务拆分、文件映射和并行安全检查，导致：
- 几乎不会实际触发并行执行
- 文件冲突检测靠 LLM 推理，不可靠
- 没有标准化的子代理执行模板，派发约束容易遗漏

用户（AE 插件使用者）受影响：多文件任务执行慢，无法利用 opencode 的 Task 并行能力。

## 需求

**工具层**
- R1. 新增 `ae-task-analyzer` 工具，接收任务描述或计划文档路径，输出结构化任务列表 + 文件冲突矩阵 + 并行组 → 验收: 工具能从裸提示词输入输出至少 2 个任务单元及其文件范围；能从计划文档输入提取已有实现单元并标注并行组
- R2. 工具的文件冲突矩阵由代码库实际文件扫描（glob/grep）确定性计算；候选文件发现可接受 LLM 只读定位作为输入，但工具必须标注每个文件的来源（`tool_scan` 或 `llm_suggestion`） → 验收: 工具输出的每个任务单元包含具体的仓库相对路径文件列表，且每个文件有来源标注
- R3. 工具计算文件冲突矩阵：检测哪些任务单元共享同一文件，标记冲突 → 验收: 输出中每个并行组内的任务单元无文件交集；有交集的任务被分配到串行组
- R4. 工具输出包含每个任务单元的建议验证命令（基于文件类型推断测试命令） → 验收: 输出中每个单元有 `suggested_validation` 字段

**模板层**
- R5. 新增 `work-subagent-template.md`，标准化并行执行子代理的提示词结构 → 验收: 模板包含 `{allowed_files}`、`{forbidden_files}`、`{forbidden_commands}`、`{validation_commands}`、`{conflict_reporting}` 变量槽
- R6. 模板包含明确的约束声明：不得修改未分配文件、不得暂存/提交、不得启动共享资源、遇到冲突必须上报 → 验收: 模板中包含上述约束的完整文本

**技能层**
- R7. `ae:work` SKILL.md 的阶段 1 增加调用 `ae-task-analyzer` 的指令 → 验收: SKILL.md 中阶段 1 包含"调用 ae-task-analyzer 工具"的明确步骤
- R8. `ae:work` SKILL.md 的阶段 2 增加按并行组一次性并发派发子代理的指令，引用 `work-subagent-template.md` → 验收: SKILL.md 中阶段 2 包含"同一并行组的任务在同一轮消息中并发派发"的明确指令
- R9. `ae:work` SKILL.md 明确降级规则：并行组内任一子代理失败时，已完成结果保留，失败任务降级串行重试 → 验收: SKILL.md 中包含部分失败的处理流程

**一致性**
- R10. `ae-review-contract` 工具不受影响 → 验收: 现有 `ae-review-contract.tool.ts` 代码和测试无变更

## 成功标准

- 裸提示词进入 `ae:work` 时，工具自动输出可并行的任务分组，主代理能据此并发派发子代理
- 计划文档进入 `ae:work` 时，工具自动提取并行组，取代 LLM 自行推导
- 并行派发的子代理提示词标准化，约束不遗漏
- 文件冲突检测由工具完成，不依赖 LLM 推理

## 范围边界

- 不引入任务状态持久化、依赖图计算引擎或任务队列系统
- 不修改 `ae:review` 的并行机制
- 不新增 TypeScript 服务层（`src/services/`），核心逻辑在工具层实现
- 子代理的实际调度由 opencode 平台的 Task 能力负责，本需求不实现调度器
- 不处理跨任务的运行时数据共享（子代理之间无通信通道）

## 关键决策

- **独立工具而非服务层**：当前没有其他消费者需要任务分解逻辑，服务层是过早抽象。工具内部可提取纯函数便于测试，但不暴露为服务。
- **文件级拆分而非功能级拆分**：文件范围是并行安全检查的核心信号，功能级拆分依赖 LLM 语义理解，工具无法可靠实现。
- **新增子代理模板**：参考 `ae-review/references/subagent-template.md` 的成熟模式，确保并行执行约束标准化。

## 依赖 / 假设

- opencode 平台支持在同一轮消息中并发调用多个 Task 子代理
- 子代理执行期间文件不会被外部修改（单人开发场景）
- `ae:work` 的主代理能正确解读工具输出并构造子代理提示词
- 若 opencode Task 并发能力不可用，工具仍输出并行组标注，但 SKILL.md 降级为串行执行并保留冲突矩阵作为安全检查依据
