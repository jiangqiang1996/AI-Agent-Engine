# github-trending-article

## 目标

参考内置样式模板（`references/article-template.md`），抓取 GitHub 趋势仓库数据，按模板格式生成一篇 Markdown 文章，保存到当前项目的 `ae/docs/` 子目录下。

## 适用场景

- 用户要求生成 GitHub 趋势榜 Markdown 文章。
- 需要可复用的"读取样式模板 + 抓取数据 + 生成文章"流程。

## 不适用场景

- 只想查看 GitHub 趋势而不需要生成文章。
- 需要发布到外部平台（本技能只生成本地 Markdown 文件）。
- 抓取非 GitHub 趋势的数据。

## 输入处理

1. **数据源**：默认 `https://github.com/trending`。github.com 不可达时自动降级为 GitHub 搜索接口（查询近7天新建仓库，按星标降序排列）。
2. **文章数量**：默认 TOP 10，用户可指定其他数量。
3. **输出目录**：固定为当前项目 `ae/docs/` 子目录，不存在时自动创建。

## 工作流程

### 第一步：读取参考样式

1. 读取本技能目录下的 `references/article-template.md`，获取文章格式模板。
2. 该文件包含标题格式、趋势总览段落、仓库条目格式、字段说明、活跃程度评级和完整示例，是文章格式的唯一真源，无需访问外部博客网站。

### 第二步：抓取 GitHub 趋势数据

1. 优先尝试访问 `https://github.com/trending`。
2. 若 github.com 不可达（连接超时等），自动降级为 GitHub 搜索接口：
   - 接口：`https://api.github.com/search/repositories?q=created:>YYYY-MM-DD&sort=stars&order=desc&per_page=10`
   - 日期取近7天前。
3. 从响应中提取每个仓库的：完整名称、地址、描述、星标数、派生数、主要语言、创建时间、话题。

### 第三步：生成 Markdown 文章

1. 按参考格式组织文章，标题包含日期括号。
2. 每个仓库包含：序号标题、信息表格、中文介绍（将英文描述翻译为中文，专有名词可保留）、活跃程度评级。
3. 活跃程度评级参考：
   - 🔥🔥🔥🔥🔥 爆火（近7天新增超1000星或派生数超星标数）
   - 🔥🔥🔥🔥 很活跃（近7天新增超500星）
   - 🔥🔥🔥 较活跃
   - 🔥🔥 一般
4. 文章内容使用中文；专有名词（如 MCP、TUI、ReAct）可保留英文。
5. 不包含抓取来源、抓取时间等元信息描述。

### 第四步：保存文件

1. 文件名格式：`GitHub 今日趋势仓库 TOP 10（YYYY-MM-DD）.md`，日期为抓取当天。
2. 保存到当前项目 `ae/docs/` 子目录下，目录不存在时先创建。
3. 文件名和标题中的日期保持一致。

### 第五步：清理与验证

1. 若启动了浏览器，完成后关闭浏览器释放资源。
2. 验证文件已写入正确路径。
3. 向用户汇报文件路径。

## 边界

- 只生成本地 Markdown 文件，不发布到外部平台。
- 不创建 GitHub Issue、PR、Release 等远程写操作。
- 浏览器操作遵循 `ae:playwright` 技能规范：启动浏览器用 `ae-async-bash`，其他命令用 bash 工具。
- github.com 不可达时才降级为搜索接口，降级时无需询问用户（参考文章已说明此降级方案）。
- 文章内容使用中文，但仓库地址、仓库名、编程语言名等保留原文。

## 验证方式

- 确认 `ae/docs/` 下生成了以文章名命名的 `.md` 文件。
- 确认文件名包含日期括号。
- 确认文章标题与文件名一致。
- 确认文章内容为中文，包含指定数量的仓库信息。
