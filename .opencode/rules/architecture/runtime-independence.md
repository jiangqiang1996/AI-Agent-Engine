# 运行时独立性规范

## 运行时独立性

- AE 插件的运行时实现必须独立于源码仓库布局，支持仅依赖桥接文件和 `dist` 目录完成加载与执行。
- 任何运行时代码只要涉及插件根目录解析、运行时资产定位、默认配置加载或内置资源发现，都不得把 `dist` 与桥接文件以外的仓库文件当作必需前提。
- 特别是不得把 `opencode.json` 作为插件根目录或运行时资产定位的硬依赖；如需兼容读取，只能作为可选兜底，不能影响脱离源码仓库后的可运行性。
- 新增或修改运行时相关代码时，必须优先基于实际分发结构推断路径，而不是基于源码目录、开发环境文件或仓库根标记做假设。
- 涉及运行时定位、加载或资源发现的改动，必须补充“仅桥接文件 + dist”场景的测试，防止编码阶段重新引入对源码文件的隐式依赖。

## 下游项目 AGENTS.md 边界

- 插件运行时不得把下游项目的 `AGENTS.md` 当作必需输入或结构化配置来源。
- 如需读取下游项目的 `AGENTS.md`，只能作为可选项目上下文；当文件缺失、格式未知、内容不相关或没有明确声明时，必须降级处理，不得假设存在固定字段、固定章节或固定规范语义。

## 用户规则注入边界

- AE 插件的运行时能力包含自动注入规则文件：内置 `src/assets/rules/**/*.md`、当前项目 `.opencode/rules/**/*.md`、全局 `~/.config/opencode/rules/**/*.md`。
- 上述项目级和全局规则目录属于插件明确支持的用户配置入口，不应被视为运行时独立性违规；代码必须把它们作为可选 glob 注入，目录或文件缺失时由 opencode 的 instructions glob 机制自然降级。

## 用户 builtin-opencode 配置边界

- AE 插件的运行时能力包含三层 builtin-opencode 配置：内置 `src/assets/config/ae.jsonc`、当前项目 `.opencode/ae.jsonc`、全局 `~/.config/opencode/ae.jsonc`。
- 当前项目和全局 `ae.jsonc` 属于插件明确支持的可选用户配置入口，不应被视为运行时独立性违规；文件缺失时必须自然降级到低优先级层。
- 该入口只允许读取固定文件名 `ae.jsonc`，不得扩大为默认读取本机 opencode 全局配置、其他全局技能、其他全局代理或当前源码仓库 `.opencode/` 下的调试资产。
- 除用户规则目录和 `ae.jsonc` 外，不得默认读取本机 opencode 全局配置、其他全局技能、其他全局代理或当前源码仓库 `.opencode/` 下的调试资产。

## src 运行时封闭边界

- `src/` 是打包后插件能力真源；除“用户规则注入边界”和“用户 builtin-opencode 配置边界”明确允许的可选入口外，`src` 内的运行时代码、提示词、命令、代理和规则不得依赖当前项目 `.opencode/`、当前项目 `AGENTS.md`、本机 opencode 全局配置，或本机环境中的其他技能与配置。
- 除明确生成或使用 `ae/` 下的插件工作流产物外，`src` 面向插件用户的能力不得引用或要求读取仓库其他目录文件。
- 如某项能力必须管理 opencode 项目配置，必须由用户明确触发为专项功能，并在代码、提示词或工具描述中标明这是配置管理行为，而不是插件运行时的默认依赖。

## 插件维护专项豁免

- `ae:install`、`ae:uninstall`、安装/桥接修复等专项维护能力，可以引用插件源码仓库、安装目录、桥接文件和本仓库注册文件，因为它们的任务目标就是维护 AE 插件本身。
- 上述豁免只适用于用户明确触发的维护路径，不适用于 `ae:work`、`ae:review`、门禁、普通工具描述和默认运行时注册逻辑。
- 专项维护能力引用 `.opencode/plugins/`、`~/.config/opencode/ai-agent-engine`、`src/assets/`、`npm run build`、`opencode.json` 等路径或命令时，必须清楚说明这是 AE 插件安装、更新、源码维护或项目级配置管理语境，不得写成普通下游项目的结构要求。
- 运行时代码仍不得把这些维护路径作为默认加载前提；维护技能可以把它们作为诊断或修复目标。
